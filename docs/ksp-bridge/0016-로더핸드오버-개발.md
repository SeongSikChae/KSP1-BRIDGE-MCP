# 로더핸드오버 개발

단축(바로 구현)으로 방안·설계 없이 진행한다(2026-11-13 사용자 결정).

## 배경

`reload_mod`에서 새 로직이 시작하지 못하고 이전 로직도 다시 시작하지 못하면, 또는 새 로직이 핸드오버를 받지 않으면, 로더(`src/KspBridge.Mod/LogicHost.cs`)의 `DropHandover`가 핸드오버를 버린다. 이때 plan이 있으면 다음 두 가지를 한다.

- `FlightInputHandler.state.mainThrottle`을 0으로 둔다.
- plan의 `sas_before`를 `FlightGlobals.ActiveVessel`에 적용한다.

plan의 `vessel_id`를 확인하지 않기 때문에, 활성 기체가 계획 기체가 아니면 다른 기체의 SAS를 바꾼다. 또 계획 기체가 활성 기체가 아니면 그 기체의 `ctrlState` 스로틀이 남는다. #9에서 추가한 RCS(`rcs_before`·`rcs_touched`)도 복원하지 않는다(ReadMe 알려진 제약).

## 결정 (사용자 합의)

1. **대상 기체**: 로드된 기체(`FlightGlobals.VesselsLoaded`) 중 `persistentId`가 plan `vessel_id`와 같은 기체다. 활성 기체가 아니어도 된다. 로직의 `AttitudeController.RestoreSas`가 계획 기체에 `SetGroup`하는 것과 같고, 로드된 기체로 한정한다는 점만 다르다(로직은 부착된 `_v`에 로드 여부를 보지 않고 적용한다). 대상 기체를 찾지 못하면 SAS·RCS·기체 스로틀은 건드리지 않는다.
2. **SAS**: 대상 기체에 `SetGroup(SAS, sas_before)`. 지금과 같이 모드(`sas_mode_before`)는 복원하지 않는다. SAS를 켜면 다음 `VesselAutopilot.Update`에서 stability로 켜진다.
3. **RCS**: `rcs_touched`가 true이고 `rcs_before`가 bool이면 복원한다. 로직의 `ManualControl.TrySetGroup`처럼 이미 같은 값이면 그대로 두고, 추가 액션 그룹 오버라이드가 RCS를 잡고 있으면 건드리지 않는다. 로더는 Logic을 참조하지 않으므로 오버라이드 판정식(`ManualControl.Overridden`)을 로더에 같은 식으로 둔다.
4. **스로틀**: 지금처럼 `FlightInputHandler.state.mainThrottle = 0`을 유지하고, 대상 기체의 `ctrlState.mainThrottle`도 0으로 둔다(로직의 `AttitudeController.ZeroThrottle`과 같음).
5. **유지**: plan 키가 없으면 아무것도 하지 않는다. 예외를 밖으로 던지지 않는다. 마지막에 `_context.Handover = null`.
6. **동작 격리**: 로직의 `Coordinator.Release`가 동작마다 `Safe(...)`로 감싸는 것처럼, 스로틀·SAS·RCS는 각각 따로 시도한다. 한 동작이 예외를 던져도 나머지는 실행하고, 실패한 동작은 note에 남긴다(검토 지적 1). `Release`의 워프 정지는 두지 않는다. `Coordinator.Stop`이 핸드오버를 쓰기 전에 브리지가 요청한 워프를 이미 끄기 때문이다.
7. **로그**: RCS는 `SetGroup` 뒤 값을 다시 읽어 바뀌지 않았으면 "rcs did not change (cooldown)"을 남긴다(`ManualControl.TrySetGroup`의 재확인·문구와 같음, 검토 지적 4). 계획 기체를 못 찾으면 note를 셋으로 나눈다(검토 지적 5).
   - `vessel_id`가 없거나 null: "plan vessel_id missing"
   - double이 아님: "plan vessel_id not a number (타입명 값)"
   - double인데 로드된 기체에 없음: "plan vessel 값 not loaded"
   - 탐색 중 예외: "vessel lookup failed"(메시지와 스택은 `LogError`에 남기고, not loaded를 붙이지 않는다)
   네 경우 모두 뒤에 ", vessel throttle/sas/rcs untouched"를 붙인다. RCS를 건드리지 않은 경우도 SAS처럼 "rcs untouched"를 남기고, 오버라이드면 Logic처럼 그룹 번호를 남긴다("rcs held by action group override N"). "같음"은 `TrySetGroup` 기준이다(Logic `RestoreRcs`는 문구를 버린다). 단계 실패는 Logic `Coordinator.Safe`처럼 단계마다 `Debug.LogError`로 스택까지 남기고, note에는 "단계 failed"만 붙인다(3차 검토 지적 1).
   - 입력 스로틀(`FlightInputHandler.state`)은 계획 기체를 못 찾아도 0으로 둔다. 로직 `ZeroThrottle`과 같고 지금 동작이므로 의도적 예외다(3차 검토 지적 6).
8. **`LoaderVersion` 0.0.3 → 0.0.4**: `ILogic` 인터페이스는 바뀌지 않지만, 로더 수정은 KSP 재시작으로만 반영되므로 배포·재시작 여부를 `get_status.loader_version`으로 확인하려고 올린다. Logic의 최소 요구 버전(`BridgeLogic` "loader 0.0.3 required")은 그대로 두므로, 새 Logic은 0.0.3 로더에서도 돈다. ReadMe의 `LoaderVersion` 규칙 문장도 "로더 동작이 바뀌어도 올라간다"로 넓힌다.

## 단위 1: DropHandover 대상 기체 확인과 RCS 복원

- **대상**: `src/KspBridge.Mod/LogicHost.cs` `DropHandover`, 새 private `Overridden`, `LoaderVersion`. `ReadMe.md` 알려진 제약 문장.
- **코드 초안**:

```csharp
public const string LoaderVersion = "0.0.4";

private static void DropHandover()
{
    if (_context.Handover == null) return;
    try
    {
        if (Json.Json.Parse(_context.Handover) is Dictionary<string, object> h
            && h.TryGetValue("plan", out object p) && p is Dictionary<string, object> plan)
        {
            string note = "throttle 0";
            // Like Logic Coordinator.Safe: each failed step is logged as an error with its stack.
            void Fail(string what, Exception e)
            {
                Debug.LogError("[KspBridge] handover drop step failed (" + what + "): " + e);
                note += ", " + what + " failed";
            }
            try { FlightInputHandler.state.mainThrottle = 0; } catch (Exception e) { note = "input throttle not zeroed"; Fail("throttle", e); }
            // Json numbers are double; only a loaded vessel with the plan's persistentId is touched.
            plan.TryGetValue("vessel_id", out object id);
            Vessel v = null;
            if (id == null) note += ", plan vessel_id missing";
            else if (!(id is double d)) note += ", plan vessel_id not a number (" + id.GetType().Name + " " + id + ")";
            else
            {
                try
                {
                    v = FlightGlobals.VesselsLoaded?.FirstOrDefault(x => x != null && x.persistentId == d);
                    if (v == null) note += ", plan vessel " + d.ToString("R") + " not loaded";
                }
                catch (Exception e) { Fail("vessel lookup", e); }
            }
            if (v == null) note += ", vessel throttle/sas/rcs untouched";
            else
            {
                try { v.ctrlState.mainThrottle = 0; } catch (Exception e) { Fail("vessel throttle", e); }
                try
                {
                    if (plan.TryGetValue("sas_before", out object s) && s is bool sas)
                    {
                        v.ActionGroups.SetGroup(KSPActionGroup.SAS, sas);
                        note += ", sas " + sas;
                    }
                    else note += ", sas untouched";
                }
                catch (Exception e) { Fail("sas", e); }
                try
                {
                    if (plan.TryGetValue("rcs_touched", out object t) && t is bool touched && touched
                        && plan.TryGetValue("rcs_before", out object r) && r is bool rcs && v.ActionGroups[KSPActionGroup.RCS] != rcs)
                    {
                        if (Overridden(v, KSPActionGroup.RCS)) note += ", rcs held by action group override " + v.GroupOverride;
                        else
                        {
                            v.ActionGroups.SetGroup(KSPActionGroup.RCS, rcs);
                            note += v.ActionGroups[KSPActionGroup.RCS] == rcs ? ", rcs " + rcs : ", rcs did not change (cooldown)";
                        }
                    }
                    else note += ", rcs untouched";
                }
                catch (Exception e) { Fail("rcs", e); }
            }
            Debug.Log("[KspBridge] handover dropped: " + note);
        }
    }
    catch (Exception e) { Debug.LogError("[KspBridge] handover drop failed: " + e); }
    _context.Handover = null;
}

// Same as Logic ManualControl.Overridden (the loader does not reference Logic).
private static bool Overridden(Vessel v, KSPActionGroup g)
{
    int n = v.GroupOverride;
    return GameSettings.ADDITIONAL_ACTION_GROUPS && n > 0 && v.OverrideDefault != null && n <= v.OverrideDefault.Length
        && (v.OverrideDefault[n - 1] || (v.OverrideActionControl[n - 1] & g) != 0);
}
```

- **ReadMe**: 알려진 제약의 첫 문장 "계획 중 KSP를 종료하거나 `reload_mod`의 새 로직과 이전 로직이 모두 시작하지 못하면, 로더는 SAS만 복원하고 RCS는 복원하지 않습니다."를 둘로 나눈다(검토 지적 2: 종료 경로 `LogicHost.Shutdown`은 `Stop()`만 부르고 `DropHandover`를 부르지 않는다).
  - "계획 중 `reload_mod`의 새 로직과 이전 로직이 모두 시작하지 못하면, 로더는 스로틀을 0으로 두고, 계획 기체가 로드돼 있을 때만 그 기체의 SAS 켜짐 여부와 계획이 바꾼 RCS를 복원합니다. SAS 모드는 복원하지 않습니다."
  - "계획 중 KSP를 종료하면 스로틀·SAS·RCS를 복원하지 않습니다."
- **ReadMe `LoaderVersion` 규칙(69행)**: "Mod와 Logic 사이 인터페이스(`ILogic`)가 바뀌면 Mod의 `LoaderVersion`이 올라가며"를 "Mod와 Logic 사이 인터페이스(`ILogic`)나 로더 동작이 바뀌면 Mod의 `LoaderVersion`이 올라가며"로 바꾸고, 뒤를 "이때는 KSP를 끈 상태에서 Mod를 배포하고 KSP를 한 번 재시작해야 합니다(인터페이스가 바뀌면 Logic도 함께 배포)"로 고친다(3차 검토 지적 4). 괄호 안 0.0.2 예시와 마지막 문장은 그대로 둔다.
