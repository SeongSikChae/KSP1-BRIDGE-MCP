# KspBridge 부품 테스트 — 방안

## 문제·목표
- "부품을 ○○ 조건에서 테스트" 계약(방열판 1.25m: 36~45km·1,960~2,340m/s, Mk16 낙하산: 4~7km·30~120m/s, 플리: 21~26km·400~510m/s 등)을 Claude가 수행할 수 없다.
  - 방열판처럼 단계(staging)로 켜지지 않는 부품은 게임 우클릭 메뉴의 "테스트 실행"을 눌러야 한다 — 모드에 이 기능이 없다.
  - 조건 구간이 짧다(재진입 36~45km는 수 초). 정확한 순간 실행은 모드가 해야 한다(역할 분담).
- "운반(haul)" 계약(방열판 0.625m를 19~24km·1,000~1,310m/s로 운반)은 부품을 싣고 조건을 지나면 자동 완료 — 조건 진행 상황만 보이면 된다.

## 조사 결과 (KSP 1.12.5 디컴파일)
- `ModuleTestSubject`(테스트 대상 부품 모듈)
  - `useStaging`: 단계로 켜질 때(`OnActive`) 테스트 — 엔진·디커플러·낙하산
  - `useEvent`: 우클릭 이벤트 `RunTestEvent`("테스트 실행")로 테스트 — 방열판 등. 단계 아이콘이 있는 부품이면 이벤트가 `force_activate`도 함(낙하산이면 펼침)
  - 비행 시작 5프레임 뒤 **수락된(Active) PartTest 계약**과 부품 이름을 맞춰 `isTestSubject`를 정하고, 운반 계약이 아니면 이벤트를 켠다 → **계약은 발사 전에 수락**해야 한다
- `Contracts.Parameters.PartTest`
  - `RunTest()` → `onTestRun` → 그 순간 **하위 조건(천체·상황·고도·속도)이 모두 Complete**일 때만 계약 완료. 조건 밖에서 실행하면 아무 일 없음(부품은 소모될 수 있음: 낙하산 펼쳐짐, 엔진 점화)
  - 하위 조건은 게임이 매 프레임 갱신 — 계약의 `parameters[].state`로 읽을 수 있음(list_contracts에 이미 보임)
  - 운반: 부품이 실린 기체로 하위 조건을 모두 만족하면 자동 완료

## 채택 방안
로직 DLL만 변경(`reload_mod` 배포)
1. **조회** `list_part_tests()`: 활성 기체의 테스트 대상 부품 — 부품 이름·제목·part id, 방식(staging/event/haul), 연결된 계약 id·제목, 하위 조건별 상태(Complete/Incomplete), 지금 실행하면 성공할지(`ready` = 하위 조건 모두 Complete)
2. **즉시 실행** `run_part_test(part)`: 스톡 "테스트 실행"과 같은 `RunTestEvent` 호출. `ready`가 아니면 기본 거부(부품 낭비 방지), `force=true`로 강제
3. **무장(자동 실행)** `arm_part_test(part)`: 모드가 매 물리 틱마다 `ready`를 보고 처음 참이 되는 틱에 실행 — 짧은 구간 테스트용. 트리거 목록에 함께 보이고 취소 가능. 워프 중이면 트리거와 같은 규칙(워프 정지 후 실행)
   - 대안: 트리거에 `part_test` 동작 타입만 추가(조건은 Claude가 고도·속도로 직접 지정) — 계약 조건과 어긋날 위험이 있음

## 결정 (2026-11-08 사용자)
- 실행 방식: 조회 + 즉시 실행 + 무장(조건이 모두 맞는 첫 틱에 자동 실행) 3개
- 조건 밖 즉시 실행: 기본 거부, `force=true`면 실행
