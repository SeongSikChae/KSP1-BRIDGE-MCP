# KspBridge 시간 가속 — 방안

## 문제·목표
- 궤도 비행에서 다음 사건(Ap 도달, 노드, 대기권 재진입)까지 수백~수천 초를 실시간으로 기다린다.
  - 예: 노드 검증 때 노드 3분 전까지 실시간 대기, 귀환 시 반 바퀴(약 15분) 대기
  - `wait_until`은 최대 120초라 여러 번 반복 호출해야 한다.
- Claude가 "어느 시점까지 빨리 감기"를 지정하면 모드가 그 시점 직전에 정확히 1배속으로 돌아와야 한다(역할 분담: 타이밍은 모드가 실행).

## 조사 결과 (KSP 1.12.5 디컴파일, `TimeWarp`)
- 상태: `TimeWarp.CurrentRate`, `CurrentRateIndex`, `WarpMode`(HIGH = 레일 1~100,000배, LOW = 물리 1~4배), `MaxRate`, `MaxPhysicsRate`
- 배속 지정: `TimeWarp.SetRate(index, instant)` — 고도 한계(`GetAltitudeLimit`), 대기권·가속 중·충돌 임박·SOI 전이 임박이면 내부에서 낮춘다(`ClearToSaveStatus` 사유)
- 목표 시각까지: `TimeWarp.fetch.WarpTo(UT, maxTimeWarping, minTimeWarping)` — 스톡 "여기까지 워프"와 같은 코루틴. 배속을 자동으로 올렸다 내려 목표 UT에서 1배속으로 정지. `CancelAutoWarp()`로 취소
- 레일 워프 중에는 엔진 추력이 없다(스로틀 > 0이면 레일 워프 불가 `NOT_UNDER_ACCELERATION`)
- 트리거는 FixedUpdate에서 검사하므로 고배속 레일 워프 중에는 조건이 한 틱에 크게 넘어갈 수 있다(예: 1,000배속이면 틱당 약 20초)

## 채택 방안
로직 DLL에 핸들러 추가(로더 변경 없음, `reload_mod` 배포)

1. **조회**: `get_vessel_state`에 `warp {rate, index, mode, auto_warp}` 추가
2. **목표 시각까지 워프** `warp_to(target, lead)`
   - target: `ut`(숫자) / `ap` / `pe` / `node`(첫 노드) / `soi`(다음 SOI 전환)
   - lead: 목표 몇 초 전에 멈출지(기본 30초) → `WarpTo(목표 UT − lead)`
   - 즉시 반환. 도착은 `wait_until`로 확인하거나 아래 3번 트리거로 이어간다
3. **트리거 보호**: 워프 중에도 무장(armed) 트리거가 있으면 매 틱 조건을 보고, 참이 되면 워프를 즉시 1배속으로 내리고 동작 실행 — 동작이 늦게 실행되는 대신 워프를 멈춘다(선택지 참고)
4. **직접 배속** `set_warp(rate, physics=false)` / `stop_warp()` — 스톡 허용 범위 안에서만, 거부되면 사유 반환
5. **대기 연장**: `wait_until` timeout은 실시간 기준 유지(120초). 워프 중에는 같은 시간에 게임 시간이 더 흐르므로 별도 변경 없음

## 결정 (2026-11-08 사용자)
- 트리거와 워프: 조건이 참이 되는 틱에 워프를 1배속으로 내리고 동작 실행(무장 트리거가 있어도 워프 허용)
- 범위: `warp_to`(ut/ap/pe/node) + `soi` 대상 + `set_warp`/`stop_warp` + 물리 워프(2~4배) 모두 포함

## 비범위
워프 중 자동 자세 유지 보장(레일 워프에서는 자세가 고정됨), 다른 기체로 전환, KSC·추적 기지 장면 워프
