# KspBridge 승무원·SAS 상태 감시 — 방안

## 문제·목표
- KB Orbiter 1H 재진입(2026-11-08): 분리 직후 `set_sas_mode retrograde` → 응답은 retrograde였으나 이후 stability_assist, 사령선 앞쪽이 진행 방향을 향한 채(방열판 뒤) 1,800m/s 구간 통과. Claude는 고도만 기다려 몰랐다.
- 원인을 확정할 정보(SAS가 실제로 조종 중인지, 승무원 기절·G)가 API에 없다. 재진입처럼 자세가 중요한 구간에서 이상을 바로 알고 대응해야 한다.

## 조사 결과 (KSP 1.12.5 디컴파일)
- `VesselAutopilot.Update`(매 프레임)
  - SAS 그룹 ON인데 자동조종이 꺼져 있으면 `Enable()` = **stability_assist로** 다시 켬
  - 현재 모드를 쓸 수 없으면(`CanSetMode` false) stability_assist로, 그것도 안 되면 SAS OFF + 화면 메시지
  - `CanSetMode`: 조종사 능력 레벨(`AvailableAtLevel`), prograde/retrograde는 속도 벡터 유효성
- `VesselSAS.VesselModified`(분리 등 `onVesselWasModified`): 잠기지 않은 모드(`lockedMode=false` — prograde·retrograde 등)면 `DisconnectFlyByWire` → **모드 값은 남아도 SAS가 조종하지 않을 수 있음**
- 승무원 G: `ProtoCrewMember.geeForce`, `gExperienced`(누적), `GExperiencedNormalized`(1 = 기절 한계), `inactive`/`inactiveTimeEnd`(기절), `outDueToG`. KSP.log에는 기록 안 됨
- 유력 원인: 분리 처리 전(같은 순간)에 retrograde를 건 것 → 분리 이벤트가 SAS 조종을 끊음. G-LOC는 SAS가 꺼지지 않고 stability로 남은 점에서 가능성 낮음(확정 아님)

## 채택 방안
로직 DLL만 변경(`reload_mod`)
1. **상태 조회** `get_vessel_state`에 추가
   - `g_force`(기체 현재 G)
   - `crew[]`: 이름·직업·레벨·`conscious`(inactive 아님)·`inactive_for`(남은 초)·`g_load`(누적 G 정규화, 1 = 기절)
   - `sas`: `requested`(API로 마지막 요청한 모드)·`actual`·`flying`(자동조종 enabled이고 fly-by-wire 연결)·`available_modes`
2. **이상 기록**: 매 물리 틱 비교해 요청과 실제가 달라지거나 SAS가 조종을 멈추면 이벤트 기록(UT·MET·이전/이후·추정 사유: 조종사 기절/레벨 부족/기체 변경). `get_vessel_state.sas.events`(최근 10개)
3. **모드 유지(기본 켜짐)**: 요청한 모드가 풀렸고 다시 걸 수 있으면(`CanSetMode`) 모드가 다시 건다 — 분리 직후 끊김·기절 후 회복 모두 대응
4. **조건 필드**: `g_force`, `g_load_max`(승무원 중 최대)를 트리거·wait_until에 — 예: G가 높아지기 전 경고·대응

## 결정 (2026-11-08 사용자)
- 자동 모드 유지: 기본 켜짐(set_sas_mode로 건 모드를 유지, set_sas off·다른 모드 요청으로 해제)
- 조건 필드 `g_force`, `g_load_max` 포함
