# KspBridge 비행 안전 하네스 설계 — 묶음 B (이상 감지·궤도 기준 자세·노드 실행)

선행: [0035-비행안전하네스-방안.md](0035-비행안전하네스-방안.md) · 묶음 A [0036](0036-비행안전하네스-설계.md)

방안 5번(이상 감지·조건 조합), 3번(궤도 기준 자세·받음각 제한), 4번(노드 실행)을 다룹니다. 구현 순서는 5 → 3 → 4입니다(4번이 3번의 `node` 프레임을 씁니다).

## 구조
| 층 | 파일 | 변경 |
|---|---|---|
| Logic(조건) | `Flight/Condition.cs` (새 파일) | `{field, op, value}` / `{all:[…]}` / `{any:[…]}` 파싱·평가 |
| Logic(이상) | `Flight/AnomalyMonitor.cs` (새 파일) | 부품 파괴 수, 자세 오차 지속 시간, flameout 관찰 |
| Logic(대기) | `Handlers/WaitHandler.cs` | 조건 조합, `abort_on` |
| Logic(트리거) | `Flight/TriggerManager.cs` | `when`에 조건 조합 |
| Logic(자세) | `Attitude/AttitudeController.cs`, `Handlers/AttitudeHandler.cs` | `frame`, 오프셋, `max_aoa_deg`, 시간 가속 뒤 오차 기록 |
| Logic(노드 실행) | `Flight/NodeExecutor.cs` (새 파일), `Handlers/NodeHandler.cs` | 상태 기계, 연소 시간 계산 |
| Logic(필드) | `Flight/FlightFields.cs` | `node_exec`, `node_dv_remaining`, `attitude_error` |
| Logic | `Routes.cs` | 새 라우트, `Version` `0.12.0` → `0.13.0` |
| Logic(수명) | 애드온 `FixedUpdate`, `reload_mod` 해제 목록 | `AnomalyMonitor`, `NodeExecutor` 등록·해제 |
| App(MCP) | `CareerTools.cs` 등 | `wait_until`·`add_trigger`·`set_attitude` 인수, 새 도구 `execute_node`, `cancel_node` |
| 테스트 | `tests/KspBridge.App.Tests` | 새 도구 → HTTP 매핑, 인수 직렬화 |

## 1. 조건 조합 (방안 5)
### 형식
```json
{"field": "altitude_asl", "op": "<=", "value": 5000}
{"all": [ {"field": "situation", "op": "==", "value": "FLYING"}, {"any": [ {...}, {...} ]} ]}
```
- 노드는 `field`(단일) 또는 `all`/`any`(배열, 1개 이상) 중 하나만 가집니다. 중첩 깊이 제한 4.
- 결과 `value`: 단일이면 지금처럼 값, 조합이면 `{field: value}` 사전(조합 안 모든 필드).
- `wait_until`: MCP 인수에 `condition`(객체)을 추가합니다. 기존 `field/op/value` 인수는 그대로 받고, 둘 다 오면 오류.
- `add_trigger`: `when`이 조합 노드도 받습니다. `repeat`의 false → true 감지는 조합 결과 기준.

## 2. 이상 감지 (방안 5)
### `wait_until`의 `abort_on`
- 값: `part_lost`, `control_lost`, `flameout`의 목록. **기본 `["part_lost", "control_lost"]`**(사용자 결정; `attitude_error`는 판정을 바꾸며 `control_lost`로 이름을 바꿈). `[]`이면 끕니다.
- 감지되면 즉시 돌아오고 `met: false`, `reason: "anomaly"`, `anomaly: {type, detail}`를 줍니다.

| 종류 | 판정 |
|---|---|
| `part_lost` | 대기 시작 뒤 활성 기체 부품의 `onPartDie`(파괴). 분리·스테이징은 제외 |
| `control_lost` | **조종 응답 판정**(구현 회귀, 2026-11-08 사용자 결정): 자세 유지 또는 SAS가 켜져 있고, pitch/yaw 축 중 하나에서 최종 조종 입력(`vessel.ctrlState`)이 \|입력\| ≥ 0.9로 2.5초 이어지는데 그 축의 각가속도가 입력 방향으로 평균 0.01 rad/s² 미만(또는 반대)일 때. 큰 회전·지나침 뒤 되돌아오기는 입력 방향으로 가속하므로 통과하고, 조향 수단 없음·전력 고갈·공력에 밀린 뒤집힘은 감지합니다. 각도 오차 기준(15°·3초, 수렴 여부)은 정상 회전에서 오검지(시험 비행 1의 180° 회전)하고 기체마다 기준값이 달라 폐기 |
| `flameout` | 대기 시작 때 연소 중이던 엔진이 연료 고갈로 꺼짐(`any_flameout` 거짓 → 참) |

- `AnomalyMonitor`는 `onPartDie` 카운터(기체 ID별)와 자세 오차 초과 시작 시각을 유지합니다. 대기는 시작 시 스냅숏을 잡고 차이로 판정합니다.
- 결과에 `anomaly`가 있으면 비행 기록에도 `anomaly` 이벤트를 남깁니다.

## 3. 궤도 기준 자세 (방안 3)
### `set_attitude` 인수
| 인수 | 설명 |
|---|---|
| `frame` | `surface`(기본, 기존 pitch/heading), `prograde`, `retrograde`, `normal`, `antinormal`, `radial_in`, `radial_out`(궤도 속도 기준), `surface_prograde`, `surface_retrograde`(지표 속도 기준), `node`(첫 기동 노드 방향) |
| `pitch_offset`, `yaw_offset` | `surface` 외 프레임에서 기준 방향을 돌리는 각(°). pitch는 기수를 지역 위쪽으로 올리는 방향(축 `Cross(dir, up)`, `dir`이 `up`과 거의 평행이면 궤도 법선), yaw는 지역 위쪽 축 기준 |
| `max_aoa_deg` | 선택. 동압 1 kPa 이상일 때 목표 방향을 지표 속도 방향에서 이 각 안으로 자릅니다 |
| `roll` | 기존과 같음 |

- `frame != surface`이면 `pitch`, `heading`은 받지 않습니다(주면 오류).
- 기준 벡터는 매 물리 프레임 다시 계산합니다. 속도가 0.5 m/s 미만이거나 노드가 없으면 직전 목표를 유지하고 `Describe`에 `frame_invalid` 사유를 냅니다.
- `own`, `sas` 모드 모두 같은 `TargetDirection`을 씁니다(SAS는 `SetTargetOrientation`이라 조종사 레벨 제한이 없습니다).
- `Describe`에 `frame`, 오프셋, `max_aoa_deg`, `aoa_limited`(이번 프레임에 잘렸는지)를 더합니다.

### 시간 가속 뒤 자세 오차
- 자세 유지 중 레일 가속이 끝나 기체가 풀리면(packed → unpacked) 오차를 재고, 비행 기록에 `attitude_after_warp` 이벤트를 남깁니다. 15°를 넘으면 2절의 `attitude_error` 판정이 그대로 이어집니다.

## 4. 노드 실행 (방안 4)
### 도구
- `execute_node(tolerance = 0.1, warp = true, remove_when_done = true)` → `POST /api/node/execute`. 즉시 계획을 돌려주고 게임 안에서 끝까지 진행합니다(사용자 결정: 비동기).
- `cancel_node` → `POST /api/node/cancel`. 스로틀 0, 자세 유지 해제.
- 진행은 `wait_until`의 필드 `node_exec`(상태 문자열), `node_dv_remaining`(m/s)로 봅니다.

### 응답 (계획)
```json
{"node_dv": 812.4, "burn_time": 41.2, "half_dv_time": 19.8, "ignite_ut": 123456.7,
 "stage_dv": 950.0, "warnings": []}
```

### 상태 기계 (`FixedUpdate`)
| 상태 | 동작 | 다음 |
|---|---|---|
| `aligning` | `AttitudeController`를 `frame=node`, `own`으로 켬 | 오차 < 2° **이고** 각속도 < 0.01 rad/s이면 `waiting` |
| `waiting` | `warp`이면 점화 30초 전까지 `TimeWarp.fetch.WarpTo`. 정렬·회전 정지가 끝난 뒤에만 가속을 시작합니다 | UT ≥ `ignite_ut`이면 `burning` |
| `burning` | `ThrottleLock`. 남은 Δv를 1초 안에 낼 수 있으면 스로틀을 비례로 줄임(최소 0.05) | 남은 Δv < `tolerance`, 또는 남은 Δv 벡터가 처음 방향과 반대(내적 < 0)이면 `done` |
| `done` | 스로틀 0, 자세 유지 해제, 선택 시 노드 삭제 | — |
| `aborted` | 스로틀 0, 사유 기록(`flameout`, `vessel_changed`, `cancelled`, `node_removed`, `node_changed`, `overridden`) | — |

- **가속 중 자세 어긋남 방지(검토 회귀)**: 노드 연소 방향은 관성 좌표계 벡터라 노드 시각까지 변하지 않고, 레일 가속 중 기체도 관성 기준 자세를 유지합니다. 그래서 가속 **전에** 정렬과 회전 정지를 끝내면 가속 뒤에도 어긋나지 않습니다(지표 기준 자세가 가속 뒤 어긋나는 것과 다름). 이 가정은 노드 실행 인게임 검증에서 가속 직후 오차로 확인합니다.
- 연소 시간: 현재 단 활성 엔진의 추력 `F`, 유효 비추력 `Isp`로 `ṁ = F / (Isp·g0)`, `m1 = m0·exp(−Δv/(Isp·g0))`, `t = (m0 − m1)/ṁ`. 점화 시각은 `노드 UT − (Δv/2를 내는 데 걸리는 시간)`.
- 남은 Δv: `node.GetBurnVector(orbit)`의 크기.
- **자동 스테이징 없음**: 현재 단 Δv(게임 `VesselDeltaV`)가 노드 Δv보다 작으면 계획의 `warnings`에 넣고 실행은 합니다. 연료가 떨어지면 `aborted: flameout`.
- 비행 기록에 `node_exec` 이벤트(상태 전환마다)를 남깁니다. `reload_mod`는 실행을 `aborted`로 끝내고 해제 목록에 넣습니다.

## 결정 (2026-11-08 사용자)
- 범위: 묶음 B = 방안 5·3·4번
- 이상 감지 기본 켜기: `abort_on` 기본 `part_lost`, `attitude_error` (flameout은 요청 시)
- 조건 조합: `all`/`any` 중첩
- 진행 방향: 명시 프레임(궤도 속도 `prograde` 등, 지표 속도 `surface_prograde` 등, `node`)
- 노드 실행: 비동기 + 상태 필드

### 세부 값 (설계 합의로 확정)
- 자세 오차 이상 기준 15°·3초, 정렬 완료 2°, 받음각 제한 적용 동압 1 kPa
- 노드 실행 자동 스테이징 없음, 단 Δv 부족은 경고
- 취소 도구 이름 `cancel_node`

## 의존성
- KSP `Assembly-CSharp`: `ManeuverNode.GetBurnVector`, `TimeWarp.WarpTo`, `GameEvents.onPartDie`, `Vessel.obt_velocity`/`srf_velocity`, `Orbit.GetOrbitNormal`, `Vessel.dynamicPressurekPa`
- 새 패키지 없음

## 검증 계획
- `dotnet build`, `dotnet test`(새 도구 매핑·인수)
- 인게임(`reload_mod`):
  1. 조건 조합: `wait_until`에 `all`(고도·상황)로 대기 → 둘 다 참일 때만 `met`
  2. 이상 감지: 자세 유지 중 조향 불가 기체를 크게 돌려 `attitude_error`로 조기 반환. 부품 파괴(낙하 충돌)로 `part_lost`
  3. 궤도 기준 자세: 궤도에서 `frame=prograde`, `retrograde`, `normal` 각각 오차 < 3°. 대기 중 `surface_prograde` + `max_aoa_deg=5`에서 받음각 ≤ 5°
  4. 시간 가속 뒤: 자세 유지 중 레일 가속 → 해제 시 `attitude_after_warp` 기록
  5. 노드 실행: 원지점 순환화 노드 → `execute_node` → `node_exec=done`, 남은 Δv < 0.1 m/s, 근지점 오차 기록

## 위험
- 동체 받음각 제한은 기체마다 거동이 달라 이득(`settings.cfg`) 조정이 필요할 수 있습니다.
- `WarpTo` 중 노드 시각이 바뀌면(노드 수정) 계획이 어긋납니다. 실행 중 노드 UT·Δv가 바뀌면 `aborted: node_changed`로 끝냅니다.
- 추력이 매우 작은 기체는 연소 시간이 길어 점화 시각 근사 오차가 커집니다.
