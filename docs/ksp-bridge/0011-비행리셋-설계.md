# 비행리셋 설계

이슈: [#8](https://github.com/SeongSikChae/KSP1-BRIDGE-MCP/issues/8) · 방안: [0010-비행리셋-방안.md](0010-비행리셋-방안.md)

## 게임 동작 (디컴파일, Assembly-CSharp)

| 게임 기능 | 경로 | 조건 |
|---|---|---|
| Revert to Launch | `FlightDriver.RevertToLaunch()` (post-init 백업으로 비행 씬 다시 로드) | `FlightDriver.CanRevertToPostInit` && `Parameters.Flight.CanRestart` (`PauseMenu.drawStockRevertOptions`). 미션 게임은 `drawMissionsRevertOptions`라 다름 |
| Revert to Editor | `FlightDriver.RevertToPrelaunch(facility)` (pre-launch 백업을 persistent로 저장 후 조립동 시작) | `Parameters.Flight.CanLeaveToEditor` && `FlightDriver.CanRevertToPrelaunch` && `ShipConstruction.ShipConfig != null`, facility = `ShipConstruction.ShipType`(VAB/SPH 외면 불가) |
| Space Center 버튼 | `AltimeterSliderButtons.returnToSpaceCenter`: persistent 저장 → `LoadScene(SPACECENTER)` | `FlightGlobals.ClearToSave() == CLEAR` && `Parameters.Flight.CanLeaveToSpaceCenter` |
| 비행 씬 회수 버튼 | `AltimeterSliderButtons.recoverVessel` → `GameEvents.OnVesselRecoveryRequested` → `VesselRetrieval`: persistent 저장 → `LoadScene(SPACECENTER)` → 렌더 프레임 8개 뒤 `onVesselRecovered.Fire(pv, quick:false)` + `DestroyImmediate`, persistent 저장 | 버튼 활성: `Vessel.IsRecoverable` = `LandedOrSplashed && mainBody.isHomeWorld`. 누를 때: `ClearToSave() == CLEAR` && `CanLeaveToSpaceCenter` |
| 우주센터 마커 회수 | `KSCVesselMarkers.RecoverVessel`: `RecoverVesselFromFlight(v.protoVessel, CurrentGame.flightState)` → persistent 저장 → 다음 프레임 `RefreshMarkers()` | 마커는 `onVesselWillDestroy`만 들어서 직접 갱신해야 함. 마커 초기 생성은 `Awake` + 15프레임(`DelayedCallback(15, SpawnVesselMarkers)`). 우리도 우주센터에서 회수하면(발사 지점 회수, 비행 씬 회수 모두) `RefreshMarkers`를 게임처럼 지연 호출하되 초기 생성 뒤로 미룬다(GUIReady 뒤 30프레임 이후, 최소 1프레임). 저장은 공개 3인자 `SaveGame`(시작 씬 4인자는 internal이고 스톡 게임에서는 쓰이지 않음). 비행 씬 회수 시점은 GUIReady 뒤 렌더 프레임 8개(`Time.frameCount` 차이)로 게임과 맞춘다 |
| 추적소 회수 | `SpaceTracking.OnRecoverConfirm`: Fire(false) → 지도 표식(`scaledTargets`) 정리 → `DestroyImmediate` → 목록 재구성 → 저장 | 화면 상태 정리가 함께 있어 이번 범위에서 다루지 않음 |
| 회수 결과 | `VesselRecovery`(ScenarioModule, SPACECENTER·FLIGHT·TRACKSTATION·EDITOR)의 `OnVesselRecovered(pv, quick)`: 승무원 회수와 `onVesselRecoveryProcessing`(Funding `AddFunds`, R&D `SubmitScienceData`)는 quick과 무관. `quick=false`일 때만 `MissionRecoveryDialog.CreateFullDialog` | 계약(`RecoverKerbal`·`RecoverPart`)도 `onVesselRecovered`로 완료될 수 있음 |
| 발사 지점 검사 | `EditorLogic`의 `LaunchSiteClear(site, displayName)`: 게임 상태 미지정 시 `HighLogic.CurrentGame.flightState`에서 `ShipConstruction.FindVesselsLandedAt(flightState, site)` | |
| 비행 시작 시 회수 | `FlightDriver`(NEW_FROM_FILE): 디스크 persistent의 발사 지점 기체를 `RecoverVesselFromFlight(pv, state)`(quick:false)로 회수 | 대화상자에서 계속을 누른 경우 |
| persistent 저장 | `GamePersistence.SaveGame`: `Parameters.Flight.CanAutoSave`가 false면 경고만 남기고 `""` 반환. SPACECENTER·FLIGHT에서는 `Game.Updated`가 `flightState`를 `FlightGlobals`로 다시 만듦 | |
| 씬 로드 | `HighLogic.LoadScene` → `SetLoadSceneEventsAndFlags` → `setLevelFlags`가 **요청 시점에** `LoadedScene`을 새 씬으로 바꿈. 실제 로드는 `bufferedLoad` 코루틴(비동기). 끝나면 `onLevelWasLoadedGUIReady`(LOADINGBUFFER 제외) | `LoadedScene`만으로는 로드 완료를 알 수 없음 |
| 비행 씬 초기화 | `FlightDriver`: Awake에서 `framesAtStartup`, Start에서 `CanRevertToPostInit = true`, PostInit 코루틴이 `framesBeforeInitialSave`(15)프레임 뒤 `PostInitState = new GameBackup(...)` → `onFlightReady.Fire()`. GUIReady는 그보다 먼저 옴 | GUIReady~onFlightReady 사이에는 `PostInitState`가 직전 비행 것(첫 비행이면 null) |
| 발사 지점 기체 찾기 | `FindVesselsLandedAt`는 `landedAt.Contains(site)`(부분 문자열) | |

## 도구·API

| MCP 도구 | HTTP | 씬 | 응답 |
|---|---|---|---|
| `revert_flight(target: launch\|editor)` | `POST /api/flight/revert {target}` | FLIGHT | `{accepted, target, facility?}` (editor면 VAB/SPH) |
| `leave_flight` | `POST /api/flight/leave` | FLIGHT | `{accepted}` (기체는 그 자리에 남음. 발사 지점 회수 실측 준비용) |
| `recover_vessel(site?)` | `POST /api/vessel/recover {site?}` | FLIGHT: 활성 기체(site는 읽지 않음). EDITOR·SPACECENTER: site 필수, `landedAt`이 site와 정확히 같은 기체만 | FLIGHT: `{accepted, vessel}` (결과는 `get_status.reset.recovery`). 그 밖: `{recovered: [결과]}` |
| `launch_craft(site?, clear_site?)` | `POST /api/editor/launch {site, clear_site}` | EDITOR | `{accepted, site, recovered: [결과]}` (`clear_site` true일 때만 `recovered`) |

회수 결과 하나: `{vessel, id, funds, science, reputation, crew: [이름]}`. `id`는 `get_flight`·`get_status`와 같은 `persistentId`다(대조 가능하게). 자금·과학·평판은 회수 전후 `Funding.Instance.Funds`·`ResearchAndDevelopment.Instance.Science`·`Reputation.Instance.reputation` 차이다(인스턴스가 없으면 null). 같은 이벤트로 완료된 계약 보상도 차이에 포함된다.

`launch_craft(clear_site:true)`는 회수를 먼저 하고 게임의 발사 전 검사를 실행한다. 검사 대화상자에서 멈추거나 취소되어도 회수는 되돌리지 않는다(도구 설명에 명시). `clear_site`는 게임 `LaunchSiteClear`와 같은 부분 문자열 판정을 쓴다(게임이 막는 기체를 모두 치우기 위함).

`leave_flight`·비행 씬 `recover_vessel`은 게임 버튼 판정을 통과할 때만 실행 중인 계획을 중단한다. 추력 비행 중처럼 판정에 걸리면 409이고 계획은 계속된다(도구 설명에 명시).

### 오류

| 코드 | 도구 | 상황 |
|---|---|---|
| 409 `not_in_flight`·`no_active_vessel` (기존 `Guard.ActiveVessel`) | revert_flight, leave_flight, recover_vessel(비행 씬) | 비행 씬 밖, 활성 기체 없음 |
| 409 `not_in_editor`·`editor_not_ready` (기존 `EditorScene.Require`) | launch_craft | 조립동 밖 (기존과 같음) |
| 409 `scene_not_allowed` (기존 `ApiException.SceneNotAllowed`) | recover_vessel | FLIGHT·EDITOR·SPACECENTER 밖(추적소 포함) |
| 409 `no_game` (기존 코드와 같은 이름) | recover_vessel | 불러온 게임이 없음(메인 메뉴) |
| 409 `scene_loading` | revert_flight, leave_flight, recover_vessel, launch_craft(clear_site) | 씬 로드가 요청된 뒤 아직 끝나지 않음(`get_status.reset.scene_ready` false) |
| 409 `not_supported` | revert_flight, leave_flight, recover_vessel, launch_craft | 미션·미션 빌더·재개 불가 시나리오 게임(`CraftFiles.Launch`와 같은 판정). 또한 발사 지점 회수(recover_vessel site, clear_site)에서 `SpaceCenter.Instance`가 없음(결정 15) |
| 409 `revert_unavailable` | revert_flight | 위 표의 조건 불충족. message에 이유: `no_post_init_state`, `restart_disabled`, `no_prelaunch_state`, `leave_to_editor_disabled`, `unknown_facility` |
| 409 `leave_unavailable` | leave_flight, recover_vessel(비행 씬) | `ClearToSave()`가 CLEAR가 아님(message에 상태 이름) 또는 `CanLeaveToSpaceCenter` false |
| 409 `not_recoverable` | recover_vessel(비행 씬) | 활성 기체가 `IsRecoverable`이 아님(비행 중, 궤도, 다른 천체) |
| 409 `save_disabled` | recover_vessel, launch_craft(clear_site) | `CanAutoSave` false: persistent에 저장할 수 없음 |
| 409 `recovery_pending` | revert_flight, leave_flight, recover_vessel | 비행 씬 회수가 진행 중 |
| 400 | revert_flight, recover_vessel | 알 수 없는 target, site 누락(비행 씬 밖), 발사 지점이 아닌 site(`PSystemSetup.IsLaunchSite` 또는 시설 발사 지점 `SpaceCenterFacilityLaunchSites`에 없음) |

## 구조

```
App.Tools  FlightTools.RevertFlight / LeaveFlight / RecoverVessel, EditorTools.LaunchCraft(+clear_site)
   │ HTTP
Logic      FlightHandler  POST /api/flight/revert   → FlightReset.Revert(target)
                          POST /api/flight/leave    → FlightReset.Leave()
                          POST /api/vessel/recover  → FlightReset.Recover(site)
           EditorHandler  POST /api/editor/launch   → CraftFiles.Launch(site, clearSite)
           Flight/FlightReset (신규)
             - 씬 로드 추적: onGameSceneLoadRequested → _sceneLoading = true, _requestedScene = scene.
               요청한 씬의 준비 신호에서만 false: FLIGHT는 onFlightReady(PostInit 백업 뒤), 그 밖은 onLevelWasLoadedGUIReady. (Logic 시작 시 false)
             - 공통 전처리 순서(revert·leave): 회수 대기 중 거부 → 씬 로드 중 거부 → 씬·활성 기체(Guard) → 게임·모드 판정.
               recover_vessel은 게임 판정(no_game)을 씬 판정보다 먼저 한다. launch_craft(clear_site)는 기존 조립동 검사 뒤 씬 로드만 본다.
             - Leave는 게임 Space Center 버튼처럼 CanAutoSave를 판정하지 않는다(회수가 없어 저장 실패가 기체 부활로 이어지지 않음)
             - Revert: 조건 판정 → Coordinator.Abort("revert") (실행 중일 때) → FlightDriver.RevertToLaunch / RevertToPrelaunch
             - Leave: ClearToSave·CanLeaveToSpaceCenter → Abort("leave") → 저장 → LoadScene(SPACECENTER)
             - RecoverAtSite(site): SpaceCenter.Instance 존재 → CanAutoSave → FindVesselsLandedAt(CurrentGame.flightState) → 각 pv: 전후 차이 측정 + RecoverVesselFromFlight(pv, flightState, quick:true) → 하나라도 회수했으면 finally에서 저장
             - RecoverActive: IsRecoverable → Leave와 같은 판정 → CanAutoSave → Abort("recover") → 저장 → 대기 기록 → LoadScene(SPACECENTER) (저장이 실패하면 대기가 남지 않게)
             - 우주센터 로드(GUIReady) 뒤 렌더 프레임 8개(Time.frameCount 변화로 셈): 대기 기체를 찾아 onVesselRecovered(pv, quick:true) → DestroyImmediate → 저장, 결과 기록
             - 대기 중 다른 씬 로드 요청(onGameSceneLoadRequested, SPACECENTER 외) → failed scene_changed.
               대기 중 SPACECENTER가 다시 요청되면 로드 대기로 되돌린다(_loaded false, 300초 제한 다시 시작)
             - 시간 제한(Tick과 Status 양쪽에서 평가): 로드 요청 → GUIReady 300초, GUIReady → 회수 30초. 넘으면 failed timeout
             - 회수 이벤트를 발생시킨 뒤에는 예외가 나도 저장한 뒤 실패로 기록(이중 보상 방지)
             - Status(): scene_ready / can_revert_launch / can_revert_editor / can_recover / recovery
```

- 비행 씬 회수는 게임 경로(`VesselRetrieval`)와 같은 순서를 따르되 `quick:true`로 회수 결과 창을 막는다.
- 계획 중단은 기존 `Coordinator.Abort(reason, ...)`를 쓴다. 씬 전환 훅(`FlightScene.OnScene`)도 계획을 `scene`으로 중단하지만, 그보다 먼저 `revert`·`recover`·`leave`로 중단해 이유를 남긴다.
- 게임 이벤트 핸들러는 인스턴스 메서드로 등록한다(`FlightScene`과 같은 이유). 프레임 카운트는 `BridgeLogic.FixedUpdate`에서 호출되는 `Tick`이 `Time.frameCount`가 바뀐 경우만 센다(로더 인터페이스는 바꾸지 않음).

## get_status

`get_status`의 Logic 상태에 `reset`을 추가한다(예외는 `reset_error`로 격리).

```json
"reset": {
  "scene_ready": true,
  "requested_scene": "FLIGHT",
  "loading_seconds": null,
  "can_recover": false,
  "can_revert_launch": false,
  "can_revert_editor": true,
  "revert_editor_facility": "VAB",
  "revert_unavailable": ["restart_disabled"],
  "recovery": {"state": "pending|done|failed", "vessel": "...", "id": "...", "funds": 0, "science": 0, "reputation": 0, "crew": [], "error": null}
}
```

- `scene_ready`: 씬 로드가 요청된 뒤 그 씬의 준비 신호(비행 씬은 `onFlightReady`, 그 밖은 GUIReady)를 받기 전이면 false. `requested_scene`은 마지막으로 요청된 씬(Logic 시작 뒤 요청이 없으면 null), `loading_seconds`는 로드 중일 때 요청 뒤 경과 초(아니면 null). 씬 전환 도구의 폴링 기준은 "`requested_scene`이 목적 씬이고 `scene_ready`"다. `launch_craft`는 게임이 씬 로드를 한 프레임 늦게 요청하므로(`EditorLogic`의 `DelayedCallback(1, …StartWithNewLaunch)`) 응답 직후에는 `requested_scene`이 아직 FLIGHT가 아니고 `scene_ready`는 이전 값 true다. 발사 전 검사 대화상자에서 멈추면 EDITOR에 머물고 `input_locks`에 발사 잠금(`EDITOR_LAUNCH`)이 보인다.
- `FlightDriver.Start`가 PostInit 전에 예외로 끝나는 등 준비 신호가 오지 않으면 `scene_ready`가 false로 남는다(추정 경로). 이때 탈출 수단은 `reload_mod`(Logic 재시작 시 false로 초기화)이며, 도구 설명과 ReadMe에 "`loading_seconds`가 오래 늘어나면 `reload_mod`"를 적는다. 씬을 바꾸는 도구 뒤에는 이 값이 true가 될 때까지 폴링한다(`scene` 이름은 요청 시점에 이미 바뀜).
- `can_revert_*`·`can_recover`는 비행 씬에서 로드가 끝났고 일반 게임(미션·시나리오 아님)일 때만 판정하고, 그 밖에서는 false다. 미션 게임이면 `revert_unavailable`에 `not_supported`를 넣는다.
- `can_recover` = `IsRecoverable` && `ClearToSave(logMsg:false) == CLEAR` && `CanLeaveToSpaceCenter` && `CanAutoSave` && 회수 대기 없음. 폴링 때 게임 로그가 쌓이지 않게 `logMsg:false`를 쓴다.
- `recovery`는 마지막 비행 씬 회수 하나만 둔다. 없으면 null.

## reload_mod·씬 전환

- 비행 씬 회수 대기 중 `reload_mod`: 대기 상태를 Handover로 넘기지 않는다. 우주센터에 기체가 남고(persistent에 저장된 상태), `recovery`는 사라진다. 사용자는 `recover_vessel(site)`로 처리한다.
- 대기 중 우주센터가 아닌 씬의 로드가 요청되면 `failed`, error `scene_changed`. 대기 중에는 씬을 바꾸는 이 기능의 도구를 409 `recovery_pending`으로 거부한다.
- 렌더 프레임 8개 뒤 기체를 찾지 못하면 `failed`, error `vessel_not_found`. 로드 300초·회수 30초 제한을 넘기면 `failed`, error `timeout`(FixedUpdate가 멈춰도 `get_status`가 판정).
- 비행 씬 시작 뒤 15프레임 안에 사용자가 게임 화면에서 다시 FLIGHT를 요청하면, 이전 FlightDriver의 늦은 `onFlightReady`가 새 로드의 표시를 일찍 풀 수 있다(추정). 도구는 그 구간에 `scene_loading`으로 막혀 사용자 조작으로만 생기므로 수용한다.
- `reload_mod`로 Logic이 새로 시작되면 `_sceneLoading`은 false로 시작한다. 로드 도중 reload하면 그 로드가 끝날 때까지 `scene_loading` 보호가 꺼진다(드문 경우라 수용, 다음 로드 요청부터 정상).

## 결정 목록

| # | 결정 | 근거 |
|---|---|---|
| 1 | Revert·Leave·비행 씬 회수 조건은 게임 버튼과 같은 판정을 쓴다 | 게임 화면에서 가능한 것만 허용, 설정 우회 없음 |
| 2 | 비행 씬 회수는 우주센터로 옮겨 회수(게임 순서), `quick:true` | 결과 창이 화면 입력을 기다리지 않게. 비행 씬에서 기체를 직접 지우는 경로는 게임에 없음. 비고: `OnVesselRecoveryRequested`는 발생시키지 않으므로 그 이벤트를 듣는 다른 모드는 반응하지 않음(`onVesselRecovered`는 발생) |
| 3 | 발사 지점 회수는 현재 씬에서 `RecoverVesselFromFlight(quick:true)` 후 persistent 저장 | 게임의 `KSCVesselMarkers.RecoverVessel`과 같은 경로. `LaunchSiteClear`가 `CurrentGame.flightState`를 읽고, 발사가 persistent를 로드함 |
| 4 | 회수 결과는 자금·과학·평판의 전후 차이(계약 보상 포함) | 게임이 결과를 반환하지 않음(이벤트로만 반영) |
