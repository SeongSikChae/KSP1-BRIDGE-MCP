# KspBridge 비행 자동 실행 — 방안

선행: `0004`~`0006` 커리어 1단계, `0007`~`0009` 기술 연구

## 문제
- 대기권 탈출 비행 3회에서 엔진 차단·감속 종료가 수 초~수십 초 늦었다.
  - 1차: Ap 85km 목표가 121km까지 넘어감, 고공(68km)에서 감속해 연료 낭비 → 충돌
  - 3차: 감속 종료를 `speed_surface`로 기다리는 동안 0을 지나 재상승, 연료 소진 → 낙하산 미전개 충돌 착륙
- 원인: 조건 확인(wait_until) 후 동작(set_throttle)을 Claude가 다음 호출로 실행 → 응답 지연만큼 늦음

## 역할 분담 (사용자 합의)
- Claude: 사전 계산·설계, 중간 모니터링, 계획 수정 (실시간 제어 아님)
- 모드: 조건 도달 순간(같은 물리 갱신)에 동작 실행, 실제 상태 기반 폐루프 종료

## 채택 방안
1. **예측값 제공**: 상태 조회에 현재 추력·질량·추중비(가속도), 정지 거리(v²/2(a−g)), 필요 연소 시간, 지면 충돌까지 시간을 포함 → Claude가 점화 고도·목표를 미리 계산
2. **조건 도달 즉시 실행**: 조건(field op value)과 동작(throttle, stage, attitude 해제 등)을 모드에 등록 → FixedUpdate마다 검사해 만족 즉시 실행
   - 종료 조건은 시간이 아니라 실제 상태(예: `speed_vertical >= -5`, `apoapsis >= 80000`)로 판단 → 질량 감소·공기 저항 오차 자동 보정

## 비범위
- 완전 자동 착륙·자동 상승 궤적(PID 기반 호버링, 중력 선회) — 필요 시 다음 단계
- 시간 가속

## 설계에서 정할 것
- 등록 방식: `wait_until` 확장(대기 중에만 감시) vs 별도 트리거(등록 후 해제까지 감시, 여러 개)
- 예측값 범위와 공기 저항 반영 여부
- 동작 종류(throttle, stage, release_attitude, set_attitude, sas)
