# KspBridge 비행 안전 하네스 개발 계획 — 묶음 A (분리 부품·기체 분석)

선행: [0035-비행안전하네스-방안.md](0035-비행안전하네스-방안.md) · [0036-비행안전하네스-설계.md](0036-비행안전하네스-설계.md)

## 회귀 기록 (2026-11-08 검토)
- `get_stages`의 `OperatingStageInfo`에는 Δv가 있는 단만 있어 분리만 하는 단의 `drops`가 빠집니다. 설계를 고쳐 모든 단을 담는 최상위 `staging` 배열을 따로 둡니다(단위 3).
- 단위 2의 `out facts`를 없애고 `warnings` 목록을 넘겨 단을 도는 자리에서 경고를 더합니다(단위 2·3·4).

## 구현 중 회귀 기록 (2026-11-08)
- 설계 시 분리 규칙을 `Subtree()`에서 **폭발 노드 기준**(비행 중과 같은 연결 끊기 + 루트에서 닿지 않는 쪽 분리)으로 통일했습니다. Δv 추정의 질량·연료 계산(`burnSet`)도 같은 규칙을 씁니다(사용자 결정).
  - 확인: 방열판(`HeatShield1`)은 `isOmniDecoupler = true`라 자기 단에서 자기도 떨어집니다. TD-12는 `explosiveNodeID = top`이라 아래쪽과 함께 떨어집니다.
- 접지점은 `Collider`(UnityEngine.PhysicsModule 미참조) 대신 `MeshFilter.sharedMesh.bounds` 꼭짓점을 씁니다.
- 대칭 부품의 접지점 경고는 부품 종류마다 한 번만 냅니다.
- 시험 기체에서는 `OperatingStageInfo`에도 분리만 하는 단(Δv 0)이 들어 있었습니다. `staging`은 그대로 두며, 이 경우 `stages`와 단 목록이 겹칠 뿐입니다.

Logic은 Unity·KSP 어셈블리에 묶여 단위 테스트가 없습니다. 각 단위는 `dotnet build`와 인게임 확인(`reload_mod` 후 HTTP 호출)으로 검증합니다.

## 단위 1. 분석 입력 형태와 조향 능력
- **대상**: `src/KspBridge.Logic/Craft/CraftAnalysis.cs`(새 파일) — `AnalysisPart`, `CraftAnalysis.FromBuilt`, `CraftAnalysis.FromVessel`, `CraftAnalysis.Control`
- **코드 초안**:

```csharp
public sealed class AnalysisPart
{
    public Part Part;            // prefab (design) or live part (flight)
    public Vector3 Pos;          // root-relative, up = craft axis
    public Quaternion Rot = Quaternion.identity;
    public double Mass;
    public AnalysisPart Parent;
    public readonly List<AnalysisPart> Children = new List<AnalysisPart>();
    public int Istg;
    public bool IsEngine => Part.FindModuleImplementing<ModuleEngines>() != null;
}

public static List<AnalysisPart> FromBuilt(List<BuiltPart> parts)
{
    Dictionary<BuiltPart, AnalysisPart> map = parts.ToDictionary(b => b, b => new AnalysisPart
    {
        Part = b.Prefab, Pos = b.Pos, Rot = b.Rot, Istg = b.Istg,
        Mass = CraftEstimator.Mass(new[] { b }),
    });
    foreach (BuiltPart b in parts.Where(b => b.Parent != null))
    {
        map[b].Parent = map[b.Parent];
        map[b.Parent].Children.Add(map[b]);
    }
    return parts.Select(b => map[b]).ToList();
}

public static List<AnalysisPart> FromVessel(Vessel v)
{
    Transform root = v.rootPart.transform;
    // ... same mapping: Pos = root.InverseTransformPoint(p.transform.position),
    //     Rot = Quaternion.Inverse(root.rotation) * p.transform.rotation,
    //     Mass = p.mass + p.GetResourceMass(), Istg = p.inverseStage
}

public static Dictionary<string, object> Control(IEnumerable<AnalysisPart> attached, IEnumerable<AnalysisPart> burning)
{
    List<ModuleGimbal> gimbals = burning.Select(p => p.Part.FindModuleImplementing<ModuleGimbal>()).Where(g => g != null).ToList();
    double torque = attached.SelectMany(p => p.Part.FindModulesImplementing<ModuleReactionWheel>()).Sum(w => (double)w.PitchTorque);
    int surfaces = attached.Count(p => p.Part.FindModuleImplementing<ModuleControlSurface>() != null);
    int rcs = attached.Count(p => p.Part.FindModuleImplementing<ModuleRCS>() != null);
    return new Dictionary<string, object>
    {
        ["gimbal_engines"] = gimbals.Count,
        ["gimbal_range_deg"] = gimbals.Count == 0 ? 0.0 : gimbals.Max(g => (double)g.gimbalRange),
        ["reaction_wheel_torque"] = torque,
        ["control_surfaces"] = surfaces,
        ["rcs_thrusters"] = rcs,
        ["steerable"] = gimbals.Count > 0 || torque > 0 || surfaces > 0 || rcs > 0,
    };
}
```

- `Stages`에 `List<AnalysisPart> analysis`와 역매핑 `back`(AnalysisPart → BuiltPart)을 만들어 씁니다. 엔진이 없는 단(`engines.Count == 0`)에도 `drops`·`control`을 넣습니다.
- 단별 경고는 `Stages(List<BuiltPart> parts, List<string> warnings)`로 목록을 받아 그 자리에서 더합니다(검토 회귀). `CraftAnalysis.StageWarnings(int stage, IEnumerable<Part> dropped, bool hasEngine, bool steerable, List<string> warnings)`를 단위 2·3이 함께 씁니다.

```csharp
public static void StageWarnings(int stage, IEnumerable<Part> dropped, bool hasEngine, bool steerable, List<string> warnings)
{
    if (hasEngine && !steerable)
        warnings.Add("stage " + stage + ": no steering (no gimbal, reaction wheel, control surface or RCS)");
    foreach (Part p in dropped.Where(IsProtected))
        warnings.Add("stage " + stage + " drops protected part: " + p.partInfo.title);
}
private static bool IsProtected(Part p) => p.FindModuleImplementing<ModuleAblator>() != null
    || p.FindModuleImplementing<ModuleParachute>() != null || p.FindModuleImplementing<ModuleCommand>() != null;
```
- **검증**: `dotnet build`. 인게임 `build_craft` dry run(분리기 1개 + 열차폐가 분리기 아래인 기체) → 해당 단 `drops`에 분리기·열차폐가 있고, 짐벌 없는 엔진 단 `control.steerable`이 false
- **선행 단위**: 1

## 단위 3. 단별 `drops`·`control` — 비행 중 (`get_stages`)
- **대상**: `Handlers/StageHandler.cs` `GetStages`, `CraftAnalysis.Drops(Vessel, int stage, HashSet<Part> attached)`
- **코드 초안**:

```csharp
public static List<Part> Drops(Vessel v, int stage, HashSet<Part> attached)
{
    HashSet<(Part, Part)> cut = new HashSet<(Part, Part)>();
    foreach (Part d in attached.Where(p => p.inverseStage == stage).ToList())
    {
        ModuleDecouple sd = d.FindModuleImplementing<ModuleDecouple>();
        if (sd != null)
        {
            IEnumerable<Part> others = sd.isOmniDecoupler
                ? Neighbors(d)
                : new[] { d.FindAttachNode(sd.explosiveNodeID)?.attachedPart }.Where(p => p != null);
            foreach (Part o in others) { cut.Add((d, o)); cut.Add((o, d)); }
        }
        else if (d.FindModuleImplementing<ModuleAnchoredDecoupler>() != null && d.parent != null)
        {
            cut.Add((d, d.parent)); cut.Add((d.parent, d));
        }
    }
    HashSet<Part> kept = Reachable(v.rootPart, attached, cut);   // BFS over parent/children, skipping cut edges
    return attached.Where(p => !kept.Contains(p)).ToList();
}

private static IEnumerable<Part> Neighbors(Part p) => p.children.Concat(p.parent == null ? Enumerable.Empty<Part>() : new[] { p.parent });
```

- `GetStages`는 기존 `stages`(OperatingStageInfo) 행을 그대로 두고, 최상위 `staging` 배열을 따로 만듭니다(검토 회귀). `attached = v.parts`로 시작해 `s = v.currentStage - 1`부터 `0`까지 **모든 단**을 돌며 `Drops`를 빼고 누적하고, `{stage, drops, control}`을 넣습니다. 점화 엔진은 `attached` 중 `inverseStage >= s`인 엔진입니다. 단마다 `CraftAnalysis.StageWarnings`로 `warnings`에 더합니다.

```csharp
List<object> staging = new List<object>();
HashSet<Part> attached = new HashSet<Part>(v.parts);
for (int s = v.currentStage - 1; s >= 0; s--)
{
    List<Part> dropped = CraftAnalysis.Drops(v, s, attached);
    attached.ExceptWith(dropped);
    // ... control from attached / burning engines, StageWarnings(...)
    staging.Add(new Dictionary<string, object> { ["stage"] = s, ["drops"] = dropped.Select(p => (object)p.partInfo.title).ToList(), ["control"] = control });
}
```

- **검증**: `dotnet build`. 인게임: 단위 2의 기체(분리만 하는 단 포함)를 발사대에 올려 `GET /api/stages` → `staging`에 엔진 없는 분리 단도 있고 `drops`가 dry run과 같은지, 기존 `stages` 행은 이전과 같은지
- **선행 단위**: 1

## 단위 4. 기체 분석·경고
- **대상**: `CraftAnalysis.Analyze(List<AnalysisPart>)`, `CraftAnalysis.Warnings(...)`, `CraftHandler.Build`, `StageHandler.GetStages`
- **코드 초안**:

```csharp
public static Dictionary<string, object> Analyze(List<AnalysisPart> parts, out List<string> warnings)
{
    warnings = new List<string>();
    double m = parts.Sum(p => p.Mass);
    Vector3 com = parts.Aggregate(Vector3.zero, (a, p) => a + p.Pos * (float)p.Mass) / (float)m;

    CenterOfLiftQuery q = new CenterOfLiftQuery
    {
        refVector = Vector3.up, refAltitude = 0, refStaticPressure = 1, refAirDensity = 1.225,
    };
    Vector3 lifted = Vector3.zero; float lift = 0;
    foreach (AnalysisPart p in parts)
    {
        foreach (ILiftProvider lp in p.Part.FindModulesImplementing<ILiftProvider>())
        {
            q.Reset(); q.refVector = WorldUp(p);              // craft up in the part's frame
            lp.OnCenterOfLiftQuery(q);
            if (q.lift <= 0) continue;
            lifted += ToRoot(p, q.pos) * q.lift; lift += q.lift;
        }
    }
    Vector3? col = lift > 0 ? lifted / lift : (Vector3?)null;
    // ... lowest point: collider bounds corners -> ToRoot(p, corner).y, skip LaunchClamp
    // ... warnings: col.y - com.y > 0, non-engine lowest < lowest engine - 0.05
}
```

- `ToRoot(p, x)`: 설계 시는 `p.Pos + p.Rot * (x - prefabOrigin)`, 비행 중은 `root.InverseTransformPoint(x)`. `AnalysisPart`에 `Func<Vector3, Vector3> ToRoot`를 두어 `FromBuilt`/`FromVessel`에서 채웁니다.
- 단별 경고(조향 불가, 보호 부품 분리)는 단위 2·3에서 이미 `warnings`에 더해졌습니다. 이 단위는 기체 전체 경고(안정성, 접지점)만 더합니다.
- `CraftHandler.Build`: `result["analysis"] = CraftAnalysis.Analyze(CraftAnalysis.FromBuilt(parts), out var w); warnings.AddRange(w);`
- `StageHandler.GetStages`: 최상위 `analysis`, `warnings` 추가.
- **검증**: `dotnet build`. 인게임:
  1. 꼬리 날개를 엔진 아래로 낸 기체 dry run → 접지점 경고
  2. ~~같은 기체를 VAB에 열어 CoM/CoL 마커와 비교~~ → 같은 기체의 설계 시(dry run)와 비행 중(`get_stages`) `analysis` 일치로 대체(2026-11-08 사용자 결정). VAB 양력중심 마커도 같은 `OnCenterOfLiftQuery`를 쓰고, 화면 마커로는 0.1 m 판정이 어렵습니다. 결과: CoM y −1.307 / −1.269(차이는 탑승 커벌 질량), `col_minus_com` −0.83 / −0.87. 게임 `vessel.CoM`과의 직접 비교는 무게중심이 중요한 묶음에서 합니다
  3. 설계 시 `col`이 `null`이면(프리팹 응답 없음) 설계 0036 위험 항목대로 `null` 유지를 확인하고 사용자에게 보고
- **선행 단위**: 2, 3
