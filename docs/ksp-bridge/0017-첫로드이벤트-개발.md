# 첫로드이벤트 개발

단축(바로 구현)으로 방안·설계 없이 진행한다(2026-11-13 사용자 결정).

## 배경

KSP 기동 직후 KSP.log에 다음 오류가 남는다(#10 검증 중 2026-11-13 15:35:06 관찰).

```
[ERR] [KspBridge] flight release step failed: System.NullReferenceException
  at Planetarium.GetUniversalTime ()
  at KspBridge.Flight.FlightEvents.Add (...)
  at KspBridge.Flight.Coordinator+<>c.<Resume>b__29_1 ()
  at KspBridge.Flight.Coordinator.Safe (...)
```

- KSP 기동 시 로더는 핸드오버 없이(`context.Handover == null`) Logic을 시작한다. `BridgeLogic.StartCore`는 그래도 `Coordinator.Resume(Handover.Parse(null))`을 부른다.
- `Resume`은 `h.Plan == null`이면 `FlightEvents.Add("logic_reloaded", -1, Reloaded(false))`를 무조건 남긴다(`Coordinator.cs:517`).
- 이때는 로딩 화면이라 `Planetarium`이 없어서 `FlightEvents.Add`의 `Planetarium.GetUniversalTime()`(`FlightEvents.cs:49`)이 NRE를 낸다. `Safe`가 잡아 동작은 계속되지만 LogError가 남는다.
- 근본 원인은 reload가 아닌 첫 로드에 reload 이벤트를 남기려 한 것이다.

## 결정 (사용자 합의)

1. **존재 여부**: `HandoverState`에 `Present`(bool)를 둔다. `Handover.Parse`는 입력 문자열이 비어 있지 않으면 true로 둔다. 파싱 실패·형식 불일치여도 넘겨받은 문자열이 있었으면 true다(reload였다는 사실은 그대로이기 때문이다).
2. **이벤트**: `Resume`의 계획 없음 분기에서 `h.Present`일 때만 `logic_reloaded {resumed:false}`를 남긴다. 핸드오버가 없는 시작에는 아무 이벤트도 남기지 않는다. 핸드오버가 없는 시작은 다음 경우다(검토 지적 수용).
   - KSP 첫 로드(대상 경로)
   - reload에서 새·이전 로직이 모두 시작하지 못해 로더가 핸드오버를 버리고 `_logic = null`이 된 뒤의 `reload_mod`(`LogicHost.Reload`의 `previous == null`)
   - KSP 기동 때 Logic 로드가 실패한 뒤 처음 성공한 `reload_mod`
   - `Coordinator.Stop`의 핸드오버 직렬화 3단계가 모두 실패한 경우(사실상 없음)
   첫 로드가 아닌 셋은 `Planetarium`이 있어 NRE는 없지만 `logic_reloaded`도 남지 않는다. 클라이언트는 epoch 변경과 `reload_mod`의 `version_before` null로 알 수 있다. 이 경우까지 이벤트를 남기려면 로더 쪽 정보(로드 횟수 등)가 필요해 범위가 커지므로 수용한다. 계획이 있는 분기(`resumed:true`, `no_thrust`, `reload_incompatible`)는 핸드오버가 있어야만 들어가므로 바꾸지 않는다.
3. **이벤트 세션**: `FlightEvents.Restore(h.Events, h.Seq, h.Epoch)`는 그대로 부른다. 첫 로드에도 새 epoch가 생기고 seq는 0에서 시작한다.
4. **대안 기각**: `FlightEvents.Add`가 `Planetarium` 없음을 감추는 방법(Ut를 NaN으로)은 오류만 숨기고 의미 없는 이벤트가 남으므로 쓰지 않는다.
5. **버전**: Logic `Routes.Version` 0.2.24 → 0.2.25(Logic 변경마다 올리는 관례). 로더·`ILogic`은 바뀌지 않으므로 `reload_mod`로 배포된다.

## 단위 1: 첫 로드에 logic_reloaded를 남기지 않음

- **대상**: `src/KspBridge.Logic/Flight/Handover.cs` `HandoverState`·`Handover.Parse`, `src/KspBridge.Logic/Flight/Coordinator.cs` `Resume`, `src/KspBridge.Logic/Routes.cs` `Version`.
- **코드 초안**:

```csharp
// Handover.cs
public sealed class HandoverState
{
    /// <summary>A handover string was passed; false when the logic starts without one (first load after KSP start, or a reload after the loader dropped the handover).</summary>
    public bool Present;
    public string Epoch;
    // ... existing ...
}

public static HandoverState Parse(string json)
{
    HandoverState s = new HandoverState { Present = !string.IsNullOrEmpty(json) };
    if (!s.Present)
    {
        return s;
    }
    // ... existing ...
}

// Coordinator.Resume
Safe(() => FlightEvents.Restore(h.Events, h.Seq, h.Epoch));
if (h.Plan == null)
{
    // No handover (first load after KSP start, or after a dropped handover): no reload event (and Planetarium may not exist yet).
    if (h.Present)
    {
        Safe(() => FlightEvents.Add("logic_reloaded", -1, Reloaded(false)));
    }
    return;
}

// Routes.cs
public const string Version = "0.2.25";
```

- **검증**:
  - `dotnet build KspBridge.slnx` 오류 0
  - `dotnet test tests/KspBridge.App.Tests` 통과(App 테스트는 Logic을 다루지 않으므로 회귀 확인용이다)
  - `reload_mod` 뒤 `get_status.version` 0.2.25
  - 계획 없이 `reload_mod`: `get_flight_events`에 `logic_reloaded {resumed:false}`가 남는다(핸드오버 있음 경로 유지).
  - 계획 중 `reload_mod`: `logic_reloaded {resumed:true}`, 계획 `running` 유지.
  - KSP 재시작(사용자 요청) 뒤:
    - `get_status.version` 0.2.25(새 DLL 로드 확인). 이때 #10의 0.0.4 로더도 함께 올라온다.
    - `<KspDir>\KSP.log`에서 `flight release step failed`가 0건.
    - `get_flight_events(since 0)`에 `logic_reloaded`가 없다.
    - 이어서 `reload_mod`를 한 번 하면 `logic_reloaded {resumed:false}`가 seq 1로 남는다(첫 로드 뒤 이벤트 세션 정상).
  - 검증하지 않는 경로: 새 로직 실패 뒤 이전 로직 재시작, 핸드오버가 버려진 뒤의 reload, 직렬화 3단계 실패는 재현이 어려워 독립 검토로 대신한다. `Handover.Parse`는 KSP 타입에 의존해 App 테스트로 단위 테스트할 수 없다.
