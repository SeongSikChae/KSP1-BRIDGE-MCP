# 비행제어 개발

이슈: [#2 비행제어: Planner/Coordinator/Controller 3계층 비행체 제어](https://github.com/SeongSikChae/KSP1-BRIDGE-MCP/issues/2)

## 공통

- **빌드·반영**: `dotnet build KspBridge.slnx`. 빌드하면 `KspDir\GameData`로 자동 배포된다. Logic은 `reload_mod`, Mod는 KSP 재시작, App.Tools는 `reload_app`(도구가 추가되면 클라이언트 재시작)으로 반영한다.
- **App 테스트**: `dotnet test tests/KspBridge.App.Tests`. 도구를 추가하는 단위는 `ExpectedTools.Loaded`와 `FlightToolsTests.ToolsMapToHttpRequests`를 같은 단위에서 갱신한다.
- **게임 검증**: Logic은 KSP 어셈블리에 묶여 있어 단위 테스트 프로젝트가 없다. 단위마다 MCP 도구(`launch_craft` → `submit_flight_plan` → `get_flight`·`get_flight_events`)로 게임 안에서 확인하고, 확인한 값(이벤트 순서, 수치)을 단위 완료 보고에 남긴다.
- **시험 기체** (단위 3 전에 기체 설계 도구로 만들어 저장한다):
  - A: 1단 액체 로켓(파일럿 포드가 루트, 리액션 휠, 탱크, 액체 엔진, 발사 클램프). 진공 기준 Δv 약 3,400 m/s 이상(단위 9·10 궤도 검증용). `check_craft`로 확인해 저장한다.
  - B: 방사 고체 부스터 2개 + 액체 2단 + 액체 상단 + 캡슐. 진공 기준 Δv 3,400 m/s 이상(발사부터 궤도 진입까지 완주 가능, `check_craft`로 확인). 상단 디커플러와 상단 엔진을 **같은 스테이지**에 둔다. 루트·조종 기준 부품은 최상단 포드이고, 포드 바로 아래에 캡슐 디커플러(포드와 상단 사이, 마지막 스테이지)를 둔다(포드가 루트, 그 아래 캡슐 디커플러 + 상단 + 1단인 일반 발사체+캡슐 구성). 고체 부스터(스톡, 추력 곡선 없음) 연소 종료 예측 검증도 이 기체로 한다.
  - C: 2단 액체 로켓. 조종 기준 부품(프로브 코어)을 1단(버리는 단)에 두고 "Control From Here"로 지정한 기체(분리 후 활성 기체가 바뀔 구성의 제출 거부 확인용, 저장만).
  - D: 일반 액체 2단 + 페어링. 1·2단 사이 디커플러와 2단 엔진을 **다른 스테이지**에 둔다(`ignite`의 `ActivateNextStage` 경로, 디커플러·엔진 분리 스테이지에서의 `circularize` 대기 확인용). 루트·조종 기준 부품은 상단 포드. 변형 D′: 페어링 분리 스테이지를 2단 엔진 스테이지 **앞**(디커플러 다음)에 둔 배치(`ignite_blocked` 확인용). 두 배치 모두 저장한다. 단별 Δv(진공, `check_craft`로 확인): 1단 약 2,800 m/s, 2단 1,000 m/s 이상. 원지점 80 km까지 상승한 뒤 1단에 남은 Δv가 원궤도화 Δv보다 작아 `circularize` 연소 중에 1단이 소진되게 한다(단위 10의 단 연소 종료 대기 확인용).
- **버전**: Logic을 바꾸는 단위마다 `Routes.Version`을 올린다(0.2.0부터).

// LogicHost: 아무도 인계를 받지 못함 → 실행 중 계획이 있었으면 마지막 스로틀이 남지 않게, SAS는 계획 시작 전 상태로
// plan 키가 없으면(계획 없음, 직렬화 실패 뒤 최소 인계) 사용자의 수동 스로틀·SAS를 건드리지 않음
private static void DropHandover()
{
    if (_context.Handover == null) return;
    try
    {
        // 최소 파싱: {..., plan: {..., sas_before: bool}}만 본다. 파싱 실패·plan 없음이면 아무것도 하지 않음
        if (Json.Parse(_context.Handover) is Dictionary<string, object> h
            && h.TryGetValue("plan", out object p) && p is Dictionary<string, object> plan)
        {
            try { FlightInputHandler.state.mainThrottle = 0; } catch { }
            if (plan.TryGetValue("sas_before", out object s) && s is bool sas)
                FlightGlobals.ActiveVessel?.ActionGroups.SetGroup(KSPActionGroup.SAS, sas);
        }
    }
    catch { }
    _context.Handover = null;
}

// Reload: 이전 Logic 재시작까지 실패한 catch (e2) 안
_logic = null;
// ...
DropHandover();

// Reload: 성공 경로(_logic = next 뒤). 새 Logic이 Handover를 소비하지 않았으면 정리
_logic = next;
DropHandover();

- **검증** (순서 주의: KSP를 재시작하기 **전에** 로더 확인부터 한다):
  1. 0.0.2 로더가 떠 있는 KSP에서 빌드해 새 Logic을 반영하고 `reload_mod` → `reload_failed`, 메시지에 `loader 0.0.3 required; restart KSP`. 이전 Logic이 그대로 동작하는지 `get_status`로 확인(`loader_version`이 아직 `0.0.2`).
     - **배포 절차**: `KspBridge.Logic.csproj`는 `KspBridge.Mod.csproj`를 `ProjectReference`로 참조하므로 Logic을 빌드하면 Mod도 빌드되고, Mod의 `DeployToKsp`(`AfterTargets="Build"`, 조건은 `$(KspDir)\GameData` 존재뿐이라 끄는 속성이 없음)가 `GameData\KspBridge\Plugins\KspBridge.Mod.dll`도 덮어쓴다. 로더(Mod) 어셈블리는 KSP 시작 때 한 번 로드되므로 실행 중 파일이 바뀌어도 다음 KSP 시작에만 반영된다. 그래서 KSP 실행 중 `dotnet build KspBridge.slnx`로 Logic(`PluginData\KspBridge.Logic.dll`)과 Mod 파일을 함께 배포해도, 실행 중인 로더는 0.0.2 그대로라 이 확인이 성립한다.
     - 실행 중 KSP가 `KspBridge.Mod.dll`을 잠가 Mod 복사가 실패하면(빌드 오류) Mod 컴파일 결과(`bin`)는 이미 생겼으므로 `dotnet build src/KspBridge.Logic/KspBridge.Logic.csproj -p:BuildProjectReferences=false`로 Logic만 다시 빌드·배포한다. 이때 GameData의 Mod 파일은 0.0.2 그대로이므로 2에서 KSP를 끈 뒤 `dotnet build KspBridge.slnx`로 다시 배포한다. 이 시점의 Logic은 아직 `context.Handover`를 거의 참조하지 않으므로 `MissingFieldException`이 나지 않는지는 단위 11 뒤에 다시 확인한다(단위 11 검증).

```csharp
public static class EngineModel
{
    // 엔진 배열 캐시: 키 = 기체 persistentId·currentStage·부품 수. 매 틱 경로는 이 배열을 for로 돌고 LINQ·할당을 쓰지 않는다
    static ModuleEngines[] _engines = new ModuleEngines[0];
    static uint _vesselId; static int _stage = int.MinValue, _parts = -1;
    public static ModuleEngines[] Engines(Vessel v)
    {
        if (v.persistentId == _vesselId && v.currentStage == _stage && v.parts.Count == _parts) return _engines;
        // 단위 6: _srbCache.Clear();   엔진 배열 키가 바뀔 때마다 SRB 예측 캐시도 비움(떨어진·다른 기체 엔진 참조가 남지 않게)
        _vesselId = v.persistentId; _stage = v.currentStage; _parts = v.parts.Count;
        _engines = v.FindPartModulesImplementing<ModuleEngines>().ToArray();   // 할당은 키가 바뀔 때만
        _igKeyValid = false;
        return _engines;
    }

    /// <summary>Ignited: lit including flamed out. Operational: can make thrust now (isOperational is false on flameout).</summary>
    public static bool IsIgnited(ModuleEngines e) => e.EngineIgnited;
    public static bool IsOperational(ModuleEngines e) => e.EngineIgnited && e.isOperational;

    public static bool AnyOperational(Vessel v)
    {
        ModuleEngines[] es = Engines(v);
        for (int i = 0; i < es.Length; i++) if (IsOperational(es[i])) return true;
        return false;
    }
    public static double ThrustSum(Vessel v)   // Telemetry "thrust": Operational().Sum(...) 대신
    {
        ModuleEngines[] es = Engines(v); double sum = 0;
        for (int i = 0; i < es.Length; i++) if (IsOperational(es[i])) sum += es[i].finalThrust;
        return sum;
    }

    /// <summary>Every cached accessor (Ignitable, HasPropellantCached) checks the key itself, so none depends on another being called first.
    /// Key: engine-array key (vessel persistentId, currentStage, part count) + flamed-out ignited count + ignited count.</summary>
    static void RefreshPropellant(Vessel v)
    {
        ModuleEngines[] es = Engines(v);                                  // 배열 키가 바뀌었으면 여기서 _igKeyValid = false
        int flamedOut = 0, ignited = 0;
        for (int i = 0; i < es.Length; i++)
            if (es[i].EngineIgnited) { ignited++; if (es[i].flameout) flamedOut++; }   // allowRestart=false 엔진은 flameout 때 Ignited에서 빠짐
        if (_igKeyValid && flamedOut == _igFlamedOut && ignited == _igIgnited) return;
        _igKeyValid = true; _igFlamedOut = flamedOut; _igIgnited = ignited;
        _ignitable = 0;
        _hasProp.Clear();                                                 // 엔진별 HasPropellant 결과(Dictionary<ModuleEngines, bool>)
        for (int i = 0; i < es.Length; i++)
        {
            bool has = HasPropellant(es[i]);                              // 무거운 자원 조회는 키가 바뀔 때만
            _hasProp[es[i]] = has;
            if (!es[i].flameout && has) _ignitable++;
        }
    }

    /// <summary>Engines in this and later stages that still have propellant and are not flamed out.</summary>
    public static int Ignitable(Vessel v) { RefreshPropellant(v); return _ignitable; }

    /// <summary>Used every tick by Spent and KeptHasEngine (unit 8) without a resource query.</summary>
    public static bool HasPropellantCached(ModuleEngines e)
    {
        RefreshPropellant(e.vessel);                                      // 키를 스스로 확인: Ignitable 호출 여부와 무관
        return _hasProp.TryGetValue(e, out bool has) && has;
    }

    /// <summary>Queries the part's resources by the engine's propellant definitions.
    /// Propellant.totalResourceAvailable is only refreshed for ignited engines (FixedUpdate: if (EngineIgnited) UpdatePropellantStatus()).</summary>
    public static bool HasPropellant(ModuleEngines e) =>
        e.propellants.Where(p => !p.ignoreForIsp).All(p =>
        {
            e.part.GetConnectedResourceTotals(p.id, p.GetFlowMode(), out double amount, out double max);   // 정확한 API는 구현 시 디컴파일로 확인("구현 시 확인")
            return amount > 0;
        });
}

public abstract class Condition
{
    /// <summary>Evaluates every leaf (timers update even when the result is already decided).</summary>
    public abstract bool Eval(Telemetry t, double ut);

    public static Condition Parse(object raw, string path)
    {
        if (raw is List<object> list) return new All(list.Select((x, i) => Parse(x, path + "[" + i + "]")).ToList());
        Dictionary<string, object> o = raw as Dictionary<string, object> ?? throw Plan.Invalid(path, "condition must be an object or array");
        if (o.TryGetValue("all", out object all)) return new All(ParseList(all, path + ".all"));
        if (o.TryGetValue("any", out object any)) return new Any(ParseList(any, path + ".any"));
        return Leaf.Parse(o, path);   // 모르는 변수, 문자열 변수의 대소 비교 → invalid_plan
    }
}

// Plan: invalid_plan 상세는 message 문자열 규약(Mod 응답 형식 변경 없음)
/// <summary>400 invalid_plan whose message starts with the error path, e.g. "steps[2].until: unknown variable foo".</summary>
public static ApiException Invalid(string path, string reason) => new ApiException(400, "invalid_plan", path + ": " + reason);

sealed class Any : Condition
{
    // ...
    public override bool Eval(Telemetry t, double ut)
    {
        bool result = false;
        foreach (Condition c in _items) result |= c.Eval(t, ut);   // 단락 평가 금지
        return result;
    }
}

sealed class Leaf : Condition
{
    // ...
    double _trueSince = double.NaN;
    public override bool Eval(Telemetry t, double ut)
    {
        bool now = Compare(t);   // 값 없음(NaN) → false
        if (!now) { _trueSince = double.NaN; return false; }
        if (double.IsNaN(_trueSince)) _trueSince = ut;
        return ut - _trueSince >= _forS;
    }

```csharp
public static class Coordinator
{
    static Plan _plan; static int _step; static IFlightMode _mode; static double _stepStartUt;
    static readonly Telemetry _t = new Telemetry();
    public static ModeCommand Command = ModeCommand.Idle;   // Controller가 읽음. struct라 첫 Submit 전에도 null 아님

    public static void Tick()
    {
        if (_plan == null || _plan.State != PlanState.Running) return;
        try
        {
            if (!HighLogic.LoadedSceneIsFlight) { Abort("scene", null, null); return; }   // 씬 훅을 놓친 경우
            Vessel v = FlightGlobals.ActiveVessel;
            if (v == null || v.persistentId != _plan.VesselId) { Abort("vessel_changed", null, null); return; }   // 조용히 넘기지 않음
            double ut = Planetarium.GetUniversalTime();
            Capture(v, ut);                                              // (a) 자세 목표 = 직전 Command.Attitude

            Condition hit = FirstTrue(_plan.Abort, _plan.Steps[_step].Abort, _t, ut);   // (b) 둘 다 평가
            if (hit != null) { Abort("condition", hit, null); return; }
            if (_plan.Steps[_step].TimeoutS is double to && ut - _stepStartUt > to) { Abort("timeout", null, null); return; }

            Command = ComputeCommand(v, ut, _plan, _mode, send: true);   // (c)(d)(e)

            if (Command.WarpToUt is double w) Warp.Request(v, w);       // (f) 사용자 취소 래치면 Request가 무시
            else if (Warp.Requested) Warp.Stop();                        //     우리가 건 가속만 해제(사용자 가속은 두고)
            Warp.Sync();

            Step s = _plan.Steps[_step];                                 // (g)
            if (s.Until != null ? s.Until.Eval(_t, ut) : _mode.Done) NextStep(v, ut);
        }
        catch (NoThrustException e) { Abort("no_thrust", null, e.Message); }   // 일반 catch보다 먼저
        catch (Exception e) { Abort("error", null, e.Message); }
    }

    static void NextStep(Vessel v, double ut)
    {
        Warp.Stop(); Warp.ClearLatch();
        FlightEvents.Add("step_completed", _step, StepData(_step));       // 마지막 단계도 먼저 남김
        if (_step + 1 >= _plan.Steps.Count) { Complete(); return; }   // Release 후 plan_completed
        _mode = BeginStep(v, _plan, _step + 1, ut);                    // Begin + on_start 요청 등록(이벤트 없음: Submit 시험 계산도 부름)
        _step++; _stepStartUt = ut;
        FlightEvents.Add("step_started", _step, StepData(_step));
        Capture(v, ut);
        Command = ComputeCommand(v, ut, _plan, _mode, send: true);    // 같은 틱에 새 단계 첫 명령
    }

    static void Capture(Vessel v, double ut)
    {
        _t.Capture(v, Command.Attitude, ut);   // 이 단위에서 자세 목표 인자 추가(값 계산은 단위 4)
        _t.PrevCommandThrottle = Command.Throttle;   // 직전 틱 최종 명령(Override 뒤). circularize 종료 게이트
        _t.PrevModeThrottle = Command.ModeThrottle;  // 직전 틱 Mode 원래 스로틀(덮어쓰기 전). none → ignite 진입
        _t.Num["step_time"] = ut - _stepStartUt;
    }

    /// <summary>Single command path for Tick, NextStep, Submit/ReplaceSteps and Resume:
    /// stager first, then the mode, the shared no-thrust rule, then the stager's throttle override.</summary>
    static ModeCommand ComputeCommand(Vessel v, double ut, Plan plan, IFlightMode mode, bool send)
    {
        AutoStager.Update(v, _t, plan, ut, send);          // (c) on_start 요청, 연소 종료 감지·전이·작동 요청·확인. send=false면 ActivateNextStage를 보내지 않음
        _t.Str["staging"] = AutoStager.StateName;           //     갱신된 상태로 다시 채움
        _t.StagingPending = AutoStager.Pending;             //     staging != none || on_start 요청 대기
        ModeCommand cmd = mode.Update(v, _t);               // (d)
        cmd.ModeThrottle = cmd.Throttle;                    //     덮어쓰기 전 원래 값(다음 틱 PrevModeThrottle)
        if (cmd.Throttle > 0 && !EngineModel.AnyOperational(v))      //     추력 없음: 모든 Mode 공통, 여기서만 판정
        {
            if (!_t.StagingPending) throw new NoThrustException();
            cmd.Throttle = 0;                               //     스테이징이 엔진을 가져올 때까지 자세만 유지
        }
        return AutoStager.Override(cmd);                    // (e) 직렬 separate·settle이면 스로틀 0
    }

    public static object Submit(Vessel v, Plan plan)
    {
        // 1. 바꾸기 전: 검증(Plan.Parse에서 끝남)과 첫 명령 계산. 실패하면 상태를 바꾸지 않고 400/409
        double ut = Planetarium.GetUniversalTime();
        Dictionary<string, object> stagerBefore = AutoStager.Save();
        IFlightMode mode = BeginStep(v, plan, 0, ut);       // 새 Mode 인스턴스만 만듦(_plan·_mode는 그대로)
        Capture(v, ut);
        ModeCommand first;
        FlightEvents.BeginTrial();                          // 시험 계산의 이벤트(stage_burnout·staged·out_of_stages 등)는 임시 버퍼로
        List<FlightEvent> trial;
        try { first = ComputeCommand(v, ut, plan, mode, send: false); trial = FlightEvents.EndTrial(); }   // 작동 요청은 등록만, 실제 요청은 첫 Tick
        catch (NoThrustException) { FlightEvents.EndTrial(); AutoStager.Load(stagerBefore); throw new ApiException(409, "no_thrust", "no operational engine and no staging pending"); }
        catch { FlightEvents.EndTrial(); AutoStager.Load(stagerBefore); throw; }   // 버림: 되돌린 상태에서 Tick이 같은 이벤트를 다시 남김(중복 방지)

        // 2. 바꾼 뒤: 같은 catch로 감쌈. Running 전환 전에 실패해도 Abort가 Release를 부름(Controller가 연결된 채 남지 않음)
        try
        {
            if (Warp.Requested) Warp.Stop();                 // 전체 교체: 우리가 건 가속만 해제(사용자 가속 유지)
            Warp.ClearLatch();                               // 이전 계획의 취소 래치를 넘기지 않음
            // ... 기존 계획 plan_replaced, _plan·_mode·_step 교체, Running, Controller 연결(교체 시 재연결 없음), plan_started·step_started
            Command = first;                                 // 교체 직후 1틱 스로틀 0 방지
            FlightEvents.Commit(ref trial);                  // 성공: plan_started·step_started 뒤에 seq를 매겨 커밋
        }
        catch (NoThrustException e) { FlightEvents.Commit(ref trial); Abort("no_thrust", null, e.Message); }   // 스테이저 상태는 이미 바뀜: 커밋 뒤 중단
        catch (Exception e) { FlightEvents.Commit(ref trial); Abort("error", null, e.Message); }
        return PlanResult();
    }
    // FlightEvents: BeginTrial 뒤 Add는 seq 없이 임시 목록에 쌓고, EndTrial이 그 목록을 돌려주며 시험 모드를 끝냄(실패 경로는 버림).
    // Commit(ref list)는 순서대로 seq를 매겨 링 버퍼에 넣고 list를 null로(두 번 불려도 한 번만 들어감)

    /// <summary>Never throws. Releases control whatever the plan state is (a half-done Submit included);
    /// only the state change and the event need a running plan.</summary>
    public static void Abort(string reason, Condition hit, string message)
    {
        bool running = _plan != null && _plan.State == PlanState.Running;
        if (running) _plan.State = PlanState.Aborted;
        Release();
        if (running) Safe(() => FlightEvents.Add("plan_aborted", _step, new Dictionary<string, object>
            { ["reason"] = reason, ["condition"] = hit?.Describe(), ["message"] = message }));
    }

    static void Complete()
    {
        _plan.State = PlanState.Completed;
        Release();
        Safe(() => FlightEvents.Add("plan_completed", _step, null));
    }

    /// <summary>Common release for Abort, Complete and failed Submit. Never throws, no state check.
    /// Order: throttle 0 → warp off → SAS restore → OnFlyByWire off.</summary>
    static void Release()
    {
        Command = ModeCommand.Idle;                                // 스로틀 0·자세 없음
        Safe(() => AttitudeController.ZeroThrottle());             // 1. 스로틀 0: FlightInputHandler.state와 _v.ctrlState 둘 다
        Safe(() => Warp.Stop());                                   // 2. 가속 해제 (단위 9 전에는 스텁)
        Safe(() => AttitudeController.RestoreSas());               // 3. SAS 복원: _v가 null이 되기 전에
        Safe(() => AttitudeController.Detach());                   // 4. OnFlyByWire 해제 (_v = null)
        Safe(() => AutoStager.Reset(PlanVessel()));               // 비우기 전에 보낸 요청의 staged를 남김. PlanVessel: 활성 기체가 계획 기체일 때만, 아니면 null
    }
}

/// <summary>Stage activation = request + confirm. ActivateStage silently does nothing while CanSeparate is false
/// and starts a StagingCooldownTimer (0.5625 s) cooldown on success (decompile checked).</summary>
public sealed class StageRequest
{
    public enum Result { Waiting, Done, Failed }
    const int MaxTries = 2;                       // 요청 1회 + 재요청 1회
    static double ConfirmS => PhysicsGlobals.StagingCooldownTimer + 1;
    int _stageBefore = -1; double _firstUt = double.NaN, _lastSendUt = double.NaN; int _tries;

    public Result Tick(Vessel v, double ut, bool send)
    {
        if (double.IsNaN(_firstUt)) { _firstUt = ut; _stageBefore = v.currentStage; }   // 첫 시도부터 시간 제한
        if (v.currentStage < _stageBefore) return Result.Done;   // 호출자가 staged 이벤트·전이
        bool expired = _tries >= MaxTries ? ut - _lastSendUt > ConfirmS        // 재요청 뒤에도 확인 안 됨
                                          : ut - _firstUt > ConfirmS * MaxTries;  // 쿨다운·잠금으로 요청조차 못 함
        if (expired) return Result.Failed;                       // 호출자가 stage_failed
        bool due = _tries == 0 || ut - _lastSendUt > ConfirmS;   // 확인 시간 안에 안 줄면 재요청(한 틱에 두 번 보내지 않음)
        if (send && due && StageManager.CanSeparate)             // 쿨다운이면 보내지 않고 기다림
        {
            StageManager.ActivateNextStage();
            _lastSendUt = ut; _tries++;
        }
        return Result.Waiting;
    }
    // Save/Load: {stage_before, first_ut, last_send_ut, tries} (reload 인계)
}

const float KStop = 0.8f, OmegaMax = 0.5f, Kp = 4f, Ki = 0.4f;
static Vector3 _integral;

/// <summary>Attitude control pauses only on rails warp or while packed; physics warp keeps control.</summary>
public static bool Suspended(Vessel v) =>
    v.packed || (TimeWarp.WarpMode == TimeWarp.Modes.HIGH && TimeWarp.CurrentRateIndex > 0);

static void Fly(FlightCtrlState s)
{
    // ... SAS 끔·스로틀 (단위 3)
    if (c.Attitude == null) return;                    // 자세 인자 없는 attitude: 스로틀만
    if (Suspended(_v)) { _integral = Vector3.zero; return; }   // attitude_error도 이때 NaN
    Vector3 err = AxisErrors(_v, c.Attitude.Value);   // rad, (x=pitch, y=roll, z=yaw), ReferenceTransform 로컬.
                                                      // 부호: 목표로 돌려면 angularVelocity[i]가 sign(err[i]) 방향이어야 함
    Vector3 torque = AvailableTorque(_v);             // 축별 Σ (|pos| + |neg|) / 2
    Vector3 moi = _v.MOI;
    Vector3 omega = _v.angularVelocity;
    float[] input = new float[3];
    bool holdRoll = c.Attitude.Value.HasRoll;
    for (int i = 0; i < 3; i++)
    {
        float alpha = Mathf.Max(torque[i] / Mathf.Max(moi[i], 1e-3f), 1e-3f);
        float target = i == 1 && !holdRoll
            ? 0f                                                                      // roll 목표 없음: 각속도 0으로 감쇠
            : Mathf.Sign(err[i]) * Mathf.Min(Mathf.Sqrt(2 * alpha * Mathf.Abs(err[i])) * KStop, OmegaMax);
        float e = target - omega[i];
        _integral[i] = Mathf.Clamp(_integral[i] + e * TimeWarp.fixedDeltaTime, -1, 1);
        float a = Kp * e + Ki * _integral[i];
        input[i] = Mathf.Clamp(-a / alpha, -1, 1);      // 양의 입력 = −축 토크 (디컴파일 확인)
    }
    s.pitch = input[0];
    s.roll = input[1];
    s.yaw = input[2];
}

public static object ReplaceSteps(Vessel v, List<Step> steps, bool includeCurrent)
{
    if (_plan == null || _plan.State != PlanState.Running) throw new ApiException(409, "no_plan", "no running flight plan");
    if (v.persistentId != _plan.VesselId) throw new ApiException(409, "vessel_mismatch", "the plan belongs to another vessel");
    // steps는 Plan.ParseSteps(raw, "steps")로 파싱: 오류 경로 인덱스는 새 배열 기준(steps[i]...)
    if (steps.Count == 0 && includeCurrent) throw Plan.Invalid("steps", "must not be empty when include_current is true");
    int keep = includeCurrent ? _step : _step + 1;   // 빈 steps + include_current:false = 남은 단계 삭제(현재 단계가 마지막)
    List<FlightEvent> trial = null;
    if (includeCurrent)
    {
        // 바꾸기 전: Submit과 같이 새 첫 단계의 명령을 먼저 계산. 실패하면 계획·AutoStager를 바꾸지 않고 409 no_thrust 등

        IFlightMode mode = BeginStep(v, _plan.WithSteps(keep, steps), _step, ut);   // 새 Mode만 만듦
        Capture(v, ut);
        ModeCommand first;
        FlightEvents.BeginTrial();                                               // Submit과 같이 시험 계산 이벤트는 임시 버퍼로
        try { first = ComputeCommand(v, ut, _plan.WithSteps(keep, steps), mode, send: false); trial = FlightEvents.EndTrial(); }
        catch (NoThrustException) { FlightEvents.EndTrial(); AutoStager.Load(stagerBefore); throw new ApiException(409, "no_thrust", "no operational engine and no staging pending"); }
        catch { FlightEvents.EndTrial(); AutoStager.Load(stagerBefore); throw; }   // 실패: 임시 이벤트 버림
        try
        {
            _plan.ReplaceSteps(keep, steps); _mode = mode; _stepStartUt = ut;   // Controller 재연결 없음
            Warp.Stop(); Warp.ClearLatch();                                      // NextStep과 같게

{

    for (int i = 0; i < es.Length; i++)
        if (IsResponsive(es[i]) && es[i].engineAccelerationSpeed > 0) max = Math.Max(max, Math.Log(10) / es[i].engineAccelerationSpeed);
    return max;
}

/// <summary>Δv still added after commanding throttle 0 now: ∫ F·e^(−k t) dt / m = F / (k·m).</summary>
public static double TailoffDv(Vessel v)
{
    ModuleEngines[] es = Engines(v); double sum = 0;
    for (int i = 0; i < es.Length; i++)
        if (IsResponsive(es[i]) && es[i].engineDecelerationSpeed > 0) sum += es[i].finalThrust / es[i].engineDecelerationSpeed;
    return sum / v.totalMass;   // kN/t = m/s²
}

const double G0 = 9.80665;

/// <summary>Max thrust at the current pressure: maxFuelFlow·Isp(p)·g0 with thrustPercentage (maxThrust is the vacuum rating).</summary>
static double ThrustNow(ModuleEngines e, double isp) => e.maxFuelFlow * e.thrustPercentage / 100 * isp * G0;

static double IspNow(Vessel v, ModuleEngines e) => e.atmosphereCurve.Evaluate((float)(v.staticPressurekPa * 0.00986923));   // kPa → atm

public static double BurnTime(Vessel v, double dv)
{
    double f = 0, fOverIsp = 0;
    ModuleEngines[] es = Engines(v);
    for (int i = 0; i < es.Length; i++)
    {
        ModuleEngines e = es[i];
        if (!IsOperational(e)) continue;
        double isp = IspNow(v, e);
        if (isp <= 0) continue;
        double fe = ThrustNow(e, isp);
        f += fe; fOverIsp += fe / isp;
    }
    if (f <= 0) return double.PositiveInfinity;
    double ve = f / fOverIsp * G0;                       // 추력 가중 평균 Isp
    return v.totalMass * (1 - Math.Exp(-dv / ve)) / (f / ve);
}

static readonly Dictionary<ModuleEngines, SrbForecast> _srbCache = new Dictionary<ModuleEngines, SrbForecast>();
// Engines(v)가 엔진 배열 키(persistentId·currentStage·부품 수) 변화를 감지할 때마다 _srbCache.Clear() (단위 2 초안의 자리): 떨어진·다른 기체 엔진 참조가 남지 않게

/// <summary>SRB burnout prediction from remaining propellant, computed once per tick and cached per engine.
/// Stock (no thrustCurve): closed form, constant flow until fuel runs out. thrustCurve (mods): integrate.</summary>
public static SrbForecast Srb(ModuleEngines e)
{
    double ut = Planetarium.GetUniversalTime();
    if (_srbCache.TryGetValue(e, out SrbForecast c) && c.Ut == ut) return c;   // 같은 틱의 AutoStager·gravity_turn이 재계산하지 않게
    double f = FuelFraction(e);              // 추진제별 남은 양 / 용량 최솟값(부품 자원 직접 조회)
    double cap = PropellantMass(e);          // 추진제 총 용량(t), 같은 비율로 줄어든다고 봄
    SrbForecast r;
    if (!e.useThrustCurve)
    {
        double mdot = e.maxFuelFlow * e.thrustPercentage / 100;          // t/s, 일정
        double burn = mdot > 0 ? f * cap / mdot : 0;                      // 남은 연료 / 유량
        r = new SrbForecast(ut, burnoutS: burn, impulse: mdot * IspNow(e.vessel, e) * G0 * burn);   // kN·s
    }
    else r = IntegrateCurve(e, f, cap, ut, dt: 0.1, maxS: 600);   // 아래 루프. 600초를 넘으면 600초로 봄(곡선 오류 방어)
    _srbCache[e] = r;
    return r;
}

static SrbForecast IntegrateCurve(ModuleEngines e, double f, double cap, double ut, double dt, double maxS)
{
    double t = 0, impulse = 0;
    while (t < maxS)
    {
        double flow = e.thrustCurve.Evaluate((float)f);                 // flowMultiplier
        if (flow < e.flameoutBar || f * cap < Required(e) * e.ignitionThreshold) break;   // 즉시 꺼짐(디컴파일 확인)
        double mdot = e.maxFuelFlow * flow * e.thrustPercentage / 100;
        impulse += mdot * IspNow(e.vessel, e) * G0 * dt;
        f -= mdot * dt / cap; t += dt;
    }
    return new SrbForecast(ut, burnoutS: t, impulse: impulse);
}

/// <summary>SRB Δv minus gravity loss while they burn: g·sin(γ)·burnout_s. SrbRemainingDv is the impulse part only.</summary>
public static double SrbNetDv(Vessel v)
{
    ModuleEngines[] es = Engines(v);
    double impulse = 0, burnout = 0; int n = 0;
    for (int i = 0; i < es.Length; i++)
    {
        if (!IsSolid(es[i])) continue;
        SrbForecast s = Srb(es[i]);
        impulse += s.Impulse; burnout = Math.Max(burnout, s.BurnoutS); n++;
    }
    if (n == 0) return 0;
    double r = v.orbit.pos.magnitude, g = v.mainBody.gravParameter / (r * r);
    double sinGamma = v.obt_speed > 1 ? v.verticalSpeed / v.obt_speed : 1;   // 비행경로각
    return Math.Max(0, impulse / v.totalMass - g * sinGamma * burnout);     // impulse / totalMass = SrbRemainingDv
}

/// <summary>Apoapsis gain from adding dv along the current orbital velocity (vis-viva).</summary>
public static double ApRise(Vessel v, double dv)
{
    if (dv <= 0) return 0;
    Vector3d r = v.orbit.pos, vel = v.orbit.vel;
    return ApR(r, vel + vel.normalized * dv, v.mainBody.gravParameter) - ApR(r, vel, v.mainBody.gravParameter);
}

static double ApR(Vector3d r, Vector3d vel, double mu)
{
    double eps = vel.sqrMagnitude / 2 - mu / r.magnitude;
    if (eps >= 0) return double.PositiveInfinity;          // 탈출 궤도
    double a = -mu / (2 * eps), h = Vector3d.Cross(r, vel).magnitude;
    double e = Math.Sqrt(Math.Max(0, 1 + 2 * eps * h * h / (mu * mu)));
    return a * (1 + e);                                     // 중심 기준 반경(원지점 고도 차는 반경 차와 같음)
}

```csharp
const double SeparateThrottleWaitS = 2;   // 스로틀 감쇠 대기 상한: 넘으면 그대로 분리

/// <summary>Tick order (c): burnout detection and state transitions, before the mode runs.</summary>
public static void Update(Vessel v, Telemetry t, Plan plan, double ut, bool send)
{
    bool newTick = ut > _lastUt; _lastUt = ut;   // 같은 물리 틱에 두 번 불려도(Submit 직후 Tick) 틱 수를 한 번만 셈
    if (_onStart != null)                        // on_start 요청 먼저: 끝날 때까지 시퀀스 전이를 멈춤(요청이 겹치지 않게)
    {
        switch (_onStart.Tick(v, ut, send))
        {
            case StageRequest.Result.Done: FlightEvents.Add("staged", ..., reason: "on_start"); _onStart = TakeQueued(); break;
            case StageRequest.Result.Failed: FlightEvents.Add("stage_failed", ...); _onStart = TakeQueued(); break;   // 단계는 계속
        }   // TakeQueued: 보낸 요청 뒤에 등록된 요청을 꺼냄(없으면 null). 꺼낸 요청은 다음 틱부터 Tick(같은 틱 재요청 방지)
        if (_onStart != null) return;
    }
    if (_state == StagingState.None && !plan.AutoStage) return;
    StagingOptions o = plan.StagingOptions;
    switch (_state)
    {
        case StagingState.None:
            if (_latch != null && _latch.Matches(v)) break;   // out_of_stages·ignite_blocked·stage_failed 뒤: currentStage·Ignited 집합이 그대로면 재감지 안 함
            _latch = null;
            if (BurnedOut(v))
            {
                Enter(StagingState.Tailoff, ut);
                _parallel = IsParallel(v); FlightEvents.Add("stage_burnout", ...);
            }
            else if (t.PrevModeThrottle > 0 && !EngineModel.AnyOperational(v) && NextStageHasEngine(v))
                Enter(StagingState.Ignite, ut);                // 점화 주체 보장. 직전 Mode 원래 스로틀 > 0일 때만(덮어쓰기 전 값: on_start 대기 중 스로틀 0 덮어쓰기와 무관)
            break;
        case StagingState.Tailoff:
            bool srbStillBurning = SpentSideSrbBurning(v, o.MaxTailoffS);   // 병렬 SRB: 모두 꺼질 때까지. _spentEngines를 for로 돌며 !flameout && Srb(e).BurnoutS <= max
            if ((!srbStillBurning && SpentThrust(v) < o.TailoffRatio * SpentMaxThrust(v)) || ut - _since > o.MaxTailoffS)
            { Enter(StagingState.Separate, ut); _ticks = 0; }
            break;
        case StagingState.Separate:
            if (_request == null)   // 다음 스테이지 판정은 요청 전에만: 작동하면 같은 호출 안에서 currentStage가 줄어 next가 바뀜
            {
                // 둘 다 참일 때만 분리: 다 쓴 엔진을 떼어낼 디커플러, 분리 뒤 남는 쪽(K_next)에 쓸 엔진(병렬 코어 또는 이후 스테이지 엔진)
                // 아니면 분리하지 않음: 마지막 상단 소진 뒤 캡슐 디커플러·낙하산 자동 작동(되돌릴 수 없음) 방지
                if (!NextStageDecouplesFlamedOutEngine(v) || !KeptHasEngine(v)) { EndWithLatch(v, "out_of_stages", ut); break; }   // 추력이 필요하면 no_thrust로 중단
                if (!_parallel)
                {
                    if (newTick) _ticks++;                                   // 스로틀 0은 Override가 넣음
                    bool throttleDown = _ticks >= 2
                        && v.ctrlState.mainThrottle == 0 && FlightInputHandler.state.mainThrottle == 0
                        && KeptThrottleDown(v);   // _keptEngines를 for로: Ignited인 것의 currentThrottle < 0.01 (다 쓴 쪽 J 제외, LINQ 없음)
                    if (!throttleDown && ut - _since < SeparateThrottleWaitS) break;   // 2초 넘으면 그대로 요청
                }
                _before = new HashSet<uint>(FlightGlobals.Vessels.Select(x => x.persistentId));
                _request = new StageRequest();
            }
            switch (_request.Tick(v, ut, send))                              // 요청 중에는 결과로만 전이. 쿨다운이면 이 상태에서 대기
            {
                case StageRequest.Result.Done:
                    _request = null; FlightEvents.Add("staged", ..., reason: "separate");
                    Enter(_parallel ? StagingState.Ignite : StagingState.Settle, ut); break;
                case StageRequest.Result.Failed:
                    _request = null; EndWithLatch(v, "stage_failed", ut); break;
            }
            break;
        case StagingState.Settle:
            if (Separated(v, o.SettleDistance) || ut - _since > o.MaxSettleS) Enter(StagingState.Ignite, ut);
            break;
        case StagingState.Ignite:
            if (_request == null && EngineModel.AnyOperational(v))          // 병렬 분리 뒤 코어 등: 작동 불필요
            { FlightEvents.Add("staging_completed", ...); Enter(StagingState.None, ut); break; }   // ignited = t.PrevModeThrottle > 0
            if (_request == null)   // 다음 스테이지 엔진 판정도 요청 전에만
            {
                if (!NextStageHasEngine(v)) { EndWithLatch(v, "ignite_blocked", ut); break; }   // 페어링 등: 작동 안 함, staging_completed 없음
                _request = new StageRequest();
            }
            switch (_request.Tick(v, ut, send))                              // 직전 분리 0.56초 안이면 쿨다운 뒤 작동
            {
                case StageRequest.Result.Done:
                    _request = null; FlightEvents.Add("staged", ..., reason: "ignite");
                    FlightEvents.Add("staging_completed", ...);   // ignited = t.PrevModeThrottle > 0 (직전 틱 Mode 원래 스로틀, 관성 상승이면 false)
                    Enter(StagingState.None, ut); break;
                case StageRequest.Result.Failed:
                    _request = null; EndWithLatch(v, "stage_failed", ut); break;
            }
            break;
    }
}

/// <summary>Reset/Clear call this first: a request already sent whose stage drop happened before its confirm tick
/// still leaves its staged event. v = plan vessel (null when the active vessel is not the plan vessel → no event).</summary>
static void RecordSent(Vessel v)
{
    if (v == null) return;
    if (_request != null && _request.Sent && v.currentStage < _request.StageBefore)
        FlightEvents.Add("staged", ..., reason: _state == StagingState.Separate ? "separate" : "ignite");
    if (_onStart != null && _onStart.Sent && v.currentStage < _onStart.StageBefore)
        FlightEvents.Add("staged", ..., reason: "on_start");
}
public static void Reset(Vessel v) { RecordSent(v); /* 아래 표의 Reset 열 */ }
public static void Clear(Vessel v) { RecordSent(v); /* 아래 표의 Clear 열 */ }

/// <summary>Tick order (e): cold staging holds throttle 0 while separating and settling; attitude stays.</summary>
public static ModeCommand Override(ModeCommand cmd)
{
    if (!_parallel && (_state == StagingState.Separate || _state == StagingState.Settle)) cmd.Throttle = 0;
    return cmd;
}

/// <summary>Telemetry.StagingPending: a sequence is running or an on_start stage request awaits confirmation.
/// With auto_stage, "previous mode throttle > 0 + no lit engine + engine in the next stage" already entered Ignite in Update,
/// so later-stage engines alone never wait.</summary>
public static bool Pending => _state != StagingState.None || _onStart != null || _onStartQueued;

static void EndWithLatch(Vessel v, string kind, double ut)
{
    FlightEvents.Add(kind, _step, new Dictionary<string, object> { ["stage"] = v.currentStage });
    _latch = new BurnoutLatch(kind, v.currentStage, IgnitedPartIds(v));   // 이벤트 1회만. 래치를 걸 때 한 번만 할당(Engines 배열 순회)
    // BurnoutLatch.Matches(v): 매 틱 Engines 배열을 for로 돌며 currentStage·Ignited 집합이 같은지 비교(할당 없음)
    Enter(StagingState.None, ut);
}

/// <summary>Spent = flameout || (staged && !EngineIgnited && !HasPropellant). allowRestart=false engines (mods) call Shutdown after
/// flameout = true; Shutdown keeps the flag, so the first term catches them (they leave Ignited). The second term is a fallback for an
/// engine off without the flag and out of fuel. allowShutdown=false engines (SRB) return from Shutdown at once and stay Ignited
/// (ModuleEngines decompile checked).</summary>
static bool Spent(Vessel v, ModuleEngines e) => e.flameout
    || (e.part.inverseStage >= v.currentStage && !e.EngineIgnited && !EngineModel.HasPropellantCached(e));   // 접근자가 키를 스스로 확인하는 캐시

static bool BurnedOut(Vessel v)
{
    ModuleEngines[] es = EngineModel.Engines(v);
    int spent = 0, burning = 0;
    for (int i = 0; i < es.Length; i++)                                   // 매 틱: 할당 없는 for
    {
        if (Spent(v, es[i])) spent++;
        else if (es[i].EngineIgnited) burning++;                          // flameout 아닌 Ignited
    }
    return (spent > 0 && burning == 0)                                    // 켜진 엔진 ≥ 1이 모두 연료 고갈(평소엔 Ignited 전부 flameout)
        || NextStageDecouplesFlamedOutEngine(v);                          // 부스터: J_next에 Spent 엔진
}

public static bool NextStageHasEngine(Vessel v) { RefreshSets(v); return _nextHasEngine; }   // 캐시: inverseStage == currentStage − 1인 엔진 부품

static bool Separated(Vessel v, double distance)
{
    // 후보 = 분리 뒤 새로 생긴 기체 (대상 기체는 바뀌지 않음: 활성 기체가 바뀌면 vessel_changed로 중단). settle 매 틱이라 for 루프
    int n = 0;
    List<Vessel> all = FlightGlobals.Vessels;
    for (int i = 0; i < all.Count; i++)
    {
        Vessel x = all[i];
        if (_before.Contains(x.persistentId) || x == v || !x.loaded) continue;
        n++;
        if (MinPartDistance(x, v) < distance || Vector3d.Dot(x.obt_velocity - v.obt_velocity, x.CoMD - v.CoMD) <= 0) return false;
    }
    return n > 0;                                                         // 빈 집합을 참으로 보지 않음 → max_settle_s까지 대기
}

```csharp
/// <summary>J_n = D_n: the side cut off from the root is always thrown away; the root side stays the original Vessel
/// (design "분리 부품 집합 계산", ModuleDecouple/ModuleAnchoredDecoupler decompile checked; layouts verified on craft B and D).</summary>
public static HashSet<Part> Jettison(Vessel v, int n) => Cut(v, n);

/// <summary>D_n: parts cut off from the root when stage n fires.</summary>
public static HashSet<Part> Cut(Vessel v, int n)
{
    HashSet<Part> cut = new HashSet<Part>();
    foreach (Part d in v.parts)
    {
        if (d.inverseStage != n) continue;
        ModuleDecouplerBase m = d.FindModuleImplementing<ModuleDecouplerBase>();   // ModuleDecouple·ModuleAnchoredDecoupler(방사) 공통 기반, 같은 규칙
        if (m == null) continue;
        if (m.isOmniDecoupler) { AddTree(cut, d); continue; }             // ModuleDecouplerBase 필드: 자신 + 자식 전부
        AttachNode node = m.explosiveNodeID == "srf" ? d.srfAttachNode : d.FindAttachNode(m.explosiveNodeID);   // ModuleDecouplerBase.OnStart와 같게
        Part other = node?.attachedPart;
        if (other == null) continue;
        if (other == d.parent) AddTree(cut, d);                           // 상대가 부모: 디커플러와 그 하위 트리
        else AddTree(cut, other);                                         // 아니면 상대 부품의 하위 트리
    }
    return cut;
}
// 매 틱 판정은 RefreshSets(v) 뒤 캐시를 for 루프로 씀. next = v.currentStage - 1, Kept = 나머지(R_n)
// IsParallel: _keptEngines 중 Operational, NextStageDecouplesFlamedOutEngine: _spentEngines 중 Spent,
// KeptHasEngine: 두 항 모두 _keptEngines(K_next)만 순회. Operational이거나, 아직 작동하지 않은 스테이지(inverseStage < currentStage)의 미점화 엔진 중 HasPropellantCached
//   (버리는 쪽 J_next의 sepratron 같은 나중 스테이지 엔진은 세지 않음)
// KeptThrottleDown: _keptEngines 중 Ignited의 currentThrottle < 0.01 (직렬 분리 대기에서 다 쓴 쪽 J 제외)

// 캐시: J/D/K는 기체 persistentId·currentStage·부품 수가 바뀔 때만 다시 계산. 매 틱 판정은 캐시한 집합을 for 루프로 돌며 엔진 상태만 봄(LINQ 할당 없음)
static uint _setVessel; static int _setStage = int.MinValue, _setParts = -1;
static bool _nextHasEngine;
static readonly HashSet<Part> _spent = new HashSet<Part>();          // J_next
static readonly List<ModuleEngines> _spentEngines = new List<ModuleEngines>(), _keptEngines = new List<ModuleEngines>();
static void RefreshSets(Vessel v)
{
    if (v.persistentId == _setVessel && v.currentStage == _setStage && v.parts.Count == _setParts) return;
    _setVessel = v.persistentId; _setStage = v.currentStage; _setParts = v.parts.Count;
    _spent.Clear(); _spent.UnionWith(Cut(v, v.currentStage - 1));
    _spentEngines.Clear(); _keptEngines.Clear(); _nextHasEngine = false;
    ModuleEngines[] es = EngineModel.Engines(v);
    for (int i = 0; i < es.Length; i++)
    {
        (_spent.Contains(es[i].part) ? _spentEngines : _keptEngines).Add(es[i]);
        if (es[i].part.inverseStage == v.currentStage - 1) _nextHasEngine = true;
    }
}

| --- | --- | --- |
| 보낸 요청의 기록(비우기 전) | `_request`·`_onStart`가 보낸 요청(`Sent`)이고 `currentStage < stage_before`면 `staged` 이벤트 | 같음 |
| 래치 `_latch` | 비움 | 비움 |
| `_state`(+`_since`, `_ticks`, `_before`) | `None`·초기값 | `None`·초기값 |
| `_request`(시퀀스 작동 요청) | null | null |
| `_parallel` | false | false |

- **검증**:
  - 기체 B(`auto_stage:true`): 부스터 flameout → `stage_burnout` → 코어 스로틀 유지한 채 분리(`staged {reason:"separate"}`), `settle` 없음. 두 SRB가 모두 꺼진 뒤에 분리되고, flameout부터 분리까지 0.5초 이내(`stage_burnout`·`staged` 이벤트 ut 차이). 부스터 분리 뒤 `staged`·`staging_completed`가 나오고 `out_of_stages`·`ignite_blocked` 래치가 걸리지 않음(작동 직후 줄어든 `currentStage`로 다음 스테이지를 다시 판정하지 않음).
  - 2단 연소 종료 → 스로틀 0 → 2틱 이상 뒤 분리 → 다 쓴 단과 2 m 이상 벌어질 때까지 스로틀 0 → 점화. 이벤트·`staging` 순서가 `separate` → `staged {reason:"separate"}` → `settle` → `ignite`(로그). 상단 디커플러·엔진 같은 스테이지 구성(기체 B)도 이격 뒤에 점화한다(`settle` 끝 이전 틱은 `thrust` 0, `staged`와 `thrust > 0` 첫 틱 사이 간격 > 0).
  - 발사 전(엔진 꺼짐)과 관성 상승 중(스로틀 0)에는 `stage_burnout`이 나오지 않음.
  - 기체 D(`auto_stage:true`, 디커플러·2단 엔진 다른 스테이지): 1단 연소 종료 → 분리 → `settle` → `ignite`에서 `ActivateNextStage`로 2단 엔진 점화(`staged {reason:"ignite"}`, `staging_completed {ignited:true}`). 페어링 스테이지는 2단 엔진 뒤라 시퀀스가 건드리지 않음.
  - 기체 D′(페어링 스테이지가 2단 엔진 스테이지 앞): 분리 뒤 `ignite`가 페어링을 작동하지 않고 `ignite_blocked {stage}` 1회, `staging_completed` 없음, `staging`이 `none`. 스로틀을 원하는 단계라 같은 틱에 `plan_aborted {reason:"no_thrust"}`(스로틀 0, SAS 복원). 이어서 `auto_stage:true`이고 `on_start:["stage"]`가 든 스로틀 > 0 단계(`attitude` `throttle:1` 등)의 새 계획을 `submit_flight_plan`으로 제출하면(중단 뒤 다시 출발하려면 `on_start:["stage"]`가 필수. 중단 뒤 `Command`가 Idle이라 `PrevModeThrottle`이 0이므로 `auto_stage:true`만으로는 점화에 들어가지 못한다. D′는 엔진 없는 스테이지가 페어링 하나라 `on_start` 하나면 되고, `auto_stage:false`면 엔진 스테이지까지 `on_start` 단계 2개가 필요) 페어링이 분리되고 래치가 풀린다. 같은 상태에서 `on_start` 없이 `auto_stage:true`, `throttle:1` 계획을 제출하면 409 `no_thrust`(계획 시작 안 함). 409는 `ignite_blocked` 뒤에만 해당한다. `out_of_stages`·`stage_failed` 뒤 `on_start` 없이 다시 제출하면 `Reset`으로 래치가 풀리고 다 쓴 엔진이 flameout으로 남아 있어 시험 계산에서 연소 종료가 다시 감지되므로 제출은 성공하고, `out_of_stages`면 같은 이벤트 뒤 다시 `no_thrust`로 중단, `stage_failed`면 작동을 다시 시도한다(`KeptHasEngine`이 막으므로 되돌릴 수 없는 분리는 없음). `on_start` 대기 중 명령 스로틀은 0으로 덮이지만 `PrevModeThrottle`(Mode 원래 스로틀)이 1이라, 페어링 `staged {reason:"on_start"}` 확인한 같은 `Update`(같은 틱)에서 `none → ignite`로 들어가(다음 틱으로 미루면 그 틱에 `Pending`이 거짓이라 `no_thrust`) 2단 엔진 스테이지를 작동한다(`staged {reason:"ignite"}`, `staging_completed {ignited:true}`). `no_thrust` 중단이 없다.

  - 직렬 분리에서 남은 엔진의 `currentThrottle`이 내려가지 않는 경우의 2초 상한은 상수를 임시로 줄인 빌드 대신 코드 리뷰로 확인한다.
  - 작동 요청·확인: `staged`는 `currentStage` 감소를 확인한 틱에만 나온다(로그로 요청 틱과 확인 틱 비교). 기체 B 병렬 분리 직후 `ignite`, 기체 D 분리 직후 `ignite`처럼 직전 스테이징 0.56초 안의 작동 요청이 무시되지 않고 쿨다운 뒤 실제로 작동한다(`staged {reason:"ignite"}`, 스테이지 감소). 쿨다운 동안 `staging`은 그 상태(`ignite`)에 머문다.
  - 점화 진입 조건(`none → ignite`는 직전 Mode 원래 스로틀 `PrevModeThrottle` > 0일 때만): 기체 D 발사대에서 `auto_stage:true`, `attitude`(`throttle:0`) 계획 → 스테이지 작동 없음(`staged` 없음, `staging`이 `none`). 같은 기체에서 `on_start` 없이 `throttle:1`로 제출 → 직전 Mode 스로틀(계획 없음이라 `Command`가 Idle)이 0이라 점화 진입이 없어 409 `no_thrust`(첫 점화는 `on_start:["stage"]`). `auto_stage:false`로 같은 제출도 409 `no_thrust`. 비행 중 스로틀 > 0에서 점화된 엔진이 없어지고 다음 스테이지에 엔진이 있으면 `ignite`로 들어가 작동하는지는 코드 리뷰로 확인한다.
  - 직렬 분리 대기: `separate`에서 분리 요청 직전 틱의 `vessel.ctrlState.mainThrottle`·`FlightInputHandler.state.mainThrottle`이 0이고, 다 쓴 쪽을 뺀 점화 엔진의 `currentThrottle` < 0.01(로그).
  - "구현 시 확인": 요청 뒤 `currentStage`가 줄어드는 틱. 기체 B·D에서 `Cut`·`Jettison` 결과 부품 목록이 실제 분리된 부품과 같은지(로그). 기체 B의 방사 디커플러(`ModuleAnchoredDecoupler`)도 같은 explosiveNode 규칙으로 SRB 쪽이 `Cut`에 들어가는지 포함.
  - 분리 부품 집합 캐시: `RefreshSets`가 `currentStage`·부품 수가 바뀐 틱에만 다시 계산하고(로그로 재계산 횟수 = 스테이지 작동 횟수 수준), 매 틱 판정 경로에 LINQ 할당이 없음(코드 리뷰).
  - 원지점이 목표에 도달한 상태에서 연소 종료 → 분리만 하고 `staging_completed {ignited:false}`.
  - 기체 C(조종 부품이 1단): `auto_stage:true` 계획 제출 → 400 `invalid_plan`, message가 `auto_stage:`로 시작하고 `(control_part_jettisoned)`로 끝남. 같은 기체에 `auto_stage:false` 계획은 받아들여짐(수동 분리로 활성 기체가 바뀌면 `vessel_changed`로 중단).
  - 기체 B(포드가 루트, 그 아래 캡슐 디커플러 + 상단 + 1단인 일반 발사체+캡슐 구성): `auto_stage:true` 계획이 받아들여짐. 캡슐 디커플러 스테이지의 `Cut`이 상단 쪽(포드 제외)이라 조종 부품 검사에 걸리지 않는다.
  - 다음 스테이지에 다 쓴 엔진을 떼어낼 디커플러가 없는 상태에서 연소 종료(예: 기체 A `throttle:1` 단계 중 연료 소진) → `out_of_stages {stage}` 이벤트 1회, `staging`이 `none`, 같은 틱에 `plan_aborted {reason:"no_thrust"}`. 스로틀 0 단계에서 래치가 걸린 경우는 위 "래치 뒤 스로틀 0 단계" 항목으로 확인.
  - 마지막 분리 방지: 기체 B로 궤도 진입 뒤 `attitude`(`throttle:1`, `auto_stage:true`) 단계로 상단 연료를 소진 → `out_of_stages {stage}` 1회, 캡슐 디커플러·낙하산이 작동하지 않음(`staged` 없음, `currentStage`·부품 수 그대로, 포드가 상단에 붙어 있음), 같은 틱에 `plan_aborted {reason:"no_thrust"}`. 남는 쪽(`K_next` = 포드)에 엔진이 없고 이후 엔진 스테이지도 없기 때문이다.
  - 버리는 쪽의 나중 스테이지 엔진: 버리는 쪽(`J_next`)에 sepratron 같은 아직 작동하지 않은 스테이지의 연료 있는 엔진이 있어도 남는 쪽에 쓸 엔진이 없으면 마지막 분리를 하지 않음(`out_of_stages`). 코드 리뷰(`KeptHasEngine`의 두 항이 모두 `_keptEngines`만 순회) 또는 기체 B의 상단(버리는 쪽)에 아직 작동하지 않은 스테이지의 sepratron을 단 시험 배치로 확인(`staged` 없음, 포드가 상단에 붙어 있음).
  - `Spent`(코드 리뷰, 스톡에 `allowRestart = false` 엔진이 없음): flameout 뒤 `EngineIgnited`가 false가 된 엔진도 `flameout` 플래그가 남아 첫 항으로 `BurnedOut`·`NextStageDecouplesFlamedOutEngine`에서 다 쓴 엔진으로 잡히고(두 번째 항은 보조), 기체 B의 SRB는 flameout 뒤에도 `Ignited`에 남으며(`allowShutdown = false`), `HasPropellant`는 캐시 값(`HasPropellantCached`)만 씀.
  - 매 틱 할당 없음(코드 리뷰): `Update`·`Override`·`BurnedOut`·`Separated`·`KeptThrottleDown` 경로에 LINQ·`ToList`·새 컬렉션이 없음(`_before` 생성은 작동 요청 때 한 번). `RefreshSets` 키에 기체 `persistentId`가 있음.
  - `Reset`·`Clear`가 위 표의 상태를 비우는지(코드 리뷰). 계획 중단 뒤 새 계획 제출 시 이전 래치·요청이 남지 않음(로그).
  - 보낸 요청의 기록 보존(확인 틱 전에 중단을 맞추기 어려움): 코드 리뷰 + 단위 3의 확인 지연 훅. 훅을 켠 빌드에서 `on_start` 요청 송신 직후(스테이지는 이미 감소) `abort_flight` → `staged {reason:"on_start"}`가 `plan_aborted {reason:"user"}` 앞에 1회 나옴. 시퀀스 `ignite` 요청 송신 직후 중단도 `staged {reason:"ignite"}` 1회. 활성 기체가 계획 기체와 다르면 이벤트 없이 비움(코드 리뷰).
  - 분리 직후 `stage_dv`가 null인 틱이 있어도 `stage_dv` 중단 조건이 발동하지 않음.
  - `stage_dv` null 비율 실측: 기체 B 자동 비행(`auto_stage:true`, 발사부터 `gravity_turn` 끝까지)에서 1초 간격으로 `stage_dv`를 기록해 null 비율과 가장 긴 null 구간을 단위 완료 보고에 남긴다. 규칙은 "값 없음(null)"으로 확정되어 있고, null 비율이 높으면(예: 연소 중 대부분) "마지막 유효값 + `stage_dv_age_s`"로 바꾼다. 바꾸면 설계(0005) "조건" 표의 `stage_dv` 행과 `get_flight` 예시를 갱신하고(`stage_dv_age_s` 추가) `Telemetry`에 반영한다.

### 9. `coast`와 시간 가속

- **대상**: `Flight/Modes/CoastMode.cs`(변수별 목표 UT로 `WarpToUt`만 채움, `Warp`를 부르지 않음), `Flight/Warp.cs`(스텁을 채움, 사용자 취소 래치), `Coordinator.Tick`의 (f) `Warp.Request`/`Warp.Stop`·`Warp.Sync` 호출, `Coordinator.NextStep`의 `Warp.Stop`·`Warp.ClearLatch`, `Coordinator.Describe`(`plan.warp`를 `Warp.On`으로 채움)

```csharp
public static class Warp
{
    static bool _wasOn;       // 이벤트용 직전 값. 판단은 항상 실제 값으로
    static bool _requested;   // 우리가 건 가속(WarpTo)이 살아 있음
    public static bool Requested => _requested;
    static bool _cancelled;   // 사용자 취소 래치: 단계 안에서는 다시 요청하지 않음
    /// <summary>Real rails warp only (physics warp is not counted and never stopped by us).</summary>
    public static bool On => TimeWarp.WarpMode == TimeWarp.Modes.HIGH && TimeWarp.CurrentRateIndex > 0;
    /// <summary>WarpTo waiting for the next TimeWarp.Update, or autoWarp running (rate not raised yet counts too).</summary>
    static bool Pending => TimeWarp.fetch.setAutoWarp || AutoWarpEngaged();
    // AutoWarpEngaged: private TimeWarp.autoWarpEngaged 리플렉션, 또는 InputLockManager에 "TimeWarpTo"(WARPTO_LOCK) 잠금이 있는지.
    // 어느 쪽을 쓸지는 "구현 시 확인"(단위 9)

    /// <summary>Every tick (order f): follow the real state; our warp ending without our Stop latches (user cancel).</summary>
    public static void Sync()
    {
        bool on = On || Pending;
        if (_wasOn && !on)
        {
            FlightEvents.Add("warp_stopped", ...);
            if (_requested) { _requested = false; _cancelled = true; }   // 목표 도달로 스스로 끝난 경우도 같게 봄
        }
        _wasOn = on;
    }

    public static void Request(Vessel v, double targetUt)
    {
        if (_cancelled) return;
        bool allowed = v.altitude > (v.mainBody.atmosphere ? v.mainBody.atmosphereDepth : 0)
                       && FlightInputHandler.state.mainThrottle == 0
                       && EngineModel.ThrustSum(v) <= 0    // 추력 내는 엔진 없음(캐시 배열 순회). 레일 한도: geeForce > GThreshold, 대기권, 고도 한도
                       && !AutoStager.Pending;             // 스테이징 중 가속 금지: 시퀀스 진행 중이거나 on_start 요청 대기
        // 남은 15초 미만: 새로 요청하지 않고 우리가 건 가속을 해제(보통의 해제 시점, 래치 없음). 사용자 가속은 두고
        if (!allowed || targetUt - Planetarium.GetUniversalTime() < 15) { if (_requested) Stop(); return; }
        if (!_requested) { TimeWarp.fetch.WarpTo(targetUt - 10);   // 하한: 15초 경계를 한 틱에 넘어도 목표 10초 전에는 멈춤 _requested = true; _wasOn = true; FlightEvents.Add("warp_started", ...); }
    }

    /// <summary>Releases rails warp and a pending WarpTo; leaves the user's physics warp alone.</summary>
    public static void Stop()
    {
        bool ours = _requested;
        _requested = false;
        if (!ours && !On && !Pending) return;  // 우리가 요청했으면 On·Pending 판정과 무관하게 해제
        TimeWarp.fetch.setAutoWarp = false;   // WarpTo는 다음 Update에 시작: 그 전 취소 대비
        TimeWarp.fetch.CancelAutoWarp();      // autoWarp 코루틴·입력 잠금 해제
        if (On) TimeWarp.SetRate(0, true);    // 레일 가속일 때만
        Sync();                               // warp_stopped (래치는 걸지 않음: _requested를 먼저 내림)
    }

    public static void ClearLatch() => _cancelled = false;   // NextStep에서 단계가 바뀔 때
    public static bool Cancelled => _cancelled;              // reload 인계(단위 11)
    public static void LoadLatch(bool cancelled) => _cancelled = cancelled;
}

// CoastMode: Begin·Load에서 until 조건 트리를 잡아 둠(_until). Warp는 부르지 않고 WarpToUt로만 알림
/// <summary>Target UT for one time leaf, or null when the leaf never becomes true by waiting
/// (decreasing vars only with < and <=, increasing vars only with > and >=).</summary>
static double? LeafTargetUt(Leaf l, Telemetry t, double ut)
{
    bool down = l.Op == "<" || l.Op == "<=", up = l.Op == ">" || l.Op == ">=";
    switch (l.Var)
    {
        case "time_to_apoapsis":  return down ? ut + t.Num["time_to_apoapsis"] - l.Value : (double?)null;
        case "time_to_periapsis": return down ? ut + t.Num["time_to_periapsis"] - l.Value : (double?)null;
        case "met":               return up ? ut + (l.Value - t.Num["met"]) : (double?)null;
        case "step_time":         return up ? (ut - t.Num["step_time"]) + l.Value : (double?)null;   // stepStartUt + X
        default: return null;
    }
}

/// <summary>Combines leaf targets by the until tree: leaves already true or past (target <= ut) and non-warp leaves drop out;
/// all = max of the rest, any = min of the rest; a group with nothing left has no target.</summary>
static double? TargetUt(Condition c, Telemetry t, double ut)
{
    if (c is Leaf l)
        return LeafTargetUt(l, t, ut) is double w && !double.IsNaN(w) && w > ut ? w : (double?)null;
    double? r = null;
    for (int i = 0; i < c.Children.Count; i++)                         // 매 틱: 할당 없는 for
        if (TargetUt(c.Children[i], t, ut) is double w)
            r = r == null ? w : (c.IsAll ? Math.Max(r.Value, w) : Math.Min(r.Value, w));
    return r;
}

public ModeCommand Update(Vessel v, Telemetry t)
{
    double ut = Planetarium.GetUniversalTime();
    double? warpTo = _warp && _until != null ? TargetUt(_until, t, ut) : null;
    return new ModeCommand(_target, 0) { WarpToUt = warpTo };
}

"구현 시 확인": autoWarp 진행 여부 판정 방법(리플렉션 또는 `WARPTO_LOCK`)과 그 결과.
- **선행 단위**: 7

### 10. `circularize`

- **대상**: `Flight/Modes/CircularizeMode.cs`(고정 방향 `_lockedDir`, 완료 판정과 판정 게이트, `WarpToUt`. 추력 없음 대기·중단은 Coordinator 공통 판정이라 Mode에 없음)
- **코드 초안**:

```csharp
public ModeCommand Update(Vessel v, Telemetry t)
{
    double ut = Planetarium.GetUniversalTime();
    if (!_burning)
    {
        bool pastAp = v.orbit.timeToAp > v.orbit.period / 2;          // 시작할 때 이미 원지점을 지남
        double utAp = ut + v.orbit.timeToAp;
        double dvAp = Math.Sqrt(v.mainBody.gravParameter / v.orbit.ApR) - v.orbit.getOrbitalVelocityAtUT(utAp).magnitude;
        double burn = EngineModel.BurnTime(v, dvAp);
        ResetStall();                                                  // 대기 틱: 종료 판정 카운터 초기화
        if (double.IsInfinity(burn)) return new ModeCommand(AttitudeTarget.Vector(Horizontal(v)), 1);   // 추력 요구: 대기·no_thrust는 Coordinator 판정
        double start = utAp - burn / 2 - EngineModel.SpoolUpS(v) / 2;
        if (!pastAp && ut < start)                                     // 가속은 WarpToUt로만 요청(Coordinator가 Warp 호출)
            return new ModeCommand(AttitudeTarget.Vector(Horizontal(v)), 0) { WarpToUt = start };
        _burning = true;                                               // start < ut 또는 원지점 지남 → 즉시 연소(WarpToUt 없음 → Coordinator가 해제)
    }

    Vector3d r = v.orbit.pos, vel = v.orbit.vel;
    Vector3d h = Vector3d.Cross(r, vel).normalized;
    Vector3d vCirc = Vector3d.Cross(h, r).normalized * Math.Sqrt(v.mainBody.gravParameter / r.magnitude);
    Vector3d dv = vCirc - vel;                                         // 현재 위치 기준 벡터 Δv
    double dvMag = dv.magnitude, ecc = v.orbit.eccentricity;

    if (_lockedDir == null && dvMag < 10) _lockedDir = dv.normalized;  // 10 m/s 아래: 방향 고정(Orbit 좌표)
    bool done = dvMag <= EngineModel.TailoffDv(v) + _tolerance;
    // 직전 틱 최종 명령 스로틀(Override 뒤, Coordinator.Capture가 채움) > 0이고 지금 추력이 있는 틱만 판정
    bool fired = t.PrevCommandThrottle > 0 && t.Num["thrust"] > 0;
    if (_lockedDir != null && fired)
    {                                                                  // _prevDv·_prevEcc 초기값은 +∞
        _eccFlat = ecc < _prevEcc - EccTolerance ? 0 : _eccFlat + 1;
        done |= dvMag > _prevDv                                        // Δv가 다시 커지기 시작(지나침)
             || _eccFlat >= EccFlatTicks;                              // 이심률이 연속으로 낮아지지 않음
        _prevDv = dvMag; _prevEcc = ecc;
    }
    else ResetStall();                                                 // 대기·추력 없음·스로틀 0 틱: 카운터 초기화
    if (done) { Done = true; return new ModeCommand(null, 0); }

    AttitudeTarget att = AttitudeTarget.Vector((_lockedDir ?? dv.normalized).xzy);   // Orbit 좌표 → 월드 (obt_velocity = orbit.vel.xzy)
    double accel = EngineModel.MaxAccel(v);
    if (accel <= 0) return new ModeCommand(att, 1);                    // 추력 요구(자세 게이트 없음): 대기·no_thrust는 Coordinator 판정
    float throttle = (float)Clamp01(dvMag / (accel * 2));             // 마지막 2초분부터 감속
    double err = t.Num["attitude_error"];
    if (double.IsNaN(err) || err > 5) throttle = 0;                    // 자세가 맞을 때까지 연소하지 않음(값 없음 포함). 고정 뒤에는 목표가 움직이지 않음
    return new ModeCommand(att, throttle);
}

const int EccFlatTicks = 5;            // 단위 10 실측으로 조정
const double EccTolerance = 0;         // 이심률 정체 허용 오차, 단위 10 실측으로 조정
void ResetStall() { _prevDv = _prevEcc = double.PositiveInfinity; _eccFlat = 0; }

public Dictionary<string, object> Save() => new Dictionary<string, object>
{
    ["burning"] = _burning,
    ["locked_dir"] = _lockedDir is Vector3d d ? new List<object> { d.x, d.y, d.z } : null,
    ["prev_dv"] = _prevDv, ["prev_ecc"] = _prevEcc, ["ecc_flat"] = _eccFlat,
};
// Load: 위 키를 그대로 복원(locked_dir null이면 고정 전, prev_dv·prev_ecc의 null은 +∞: Json.Serialize가 ∞를 null로 씀)
```

- **검증**: 기체 A로 단위 9 계획 뒤에 `circularize` → 근지점 ≥ 75 km, 이심률 < 0.01, `plan_completed`. 연소 시작 직후 `attitude_error` > 5°인 동안 스로틀 0(로그). 기체 B + `auto_stage:true`로 발사부터 궤도까지 한 계획으로 완주. 엔진을 모두 끈(연료 0) 상태에서 `circularize`(기체 A, 남은 스테이지에 엔진 없음) → 앞 단계 뒤에 이어지면 `plan_aborted {reason:"no_thrust"}`, 단독 제출이면 409 `no_thrust`(계획 시작 안 함). 경계:
  - 원지점을 지난 뒤(`time_to_apoapsis > period/2`) `circularize`를 시작 → 대기 없이 바로 연소(한 바퀴 기다리지 않음).
  - 원지점 직전(계산한 시작 시각이 이미 지남)에 시작 → 바로 연소.
  - 단 연소 종료 대기(기체 D, 단별 Δv를 정해 둔 기체라 결과가 결정적): 전제로 `circularize` 시작 틱의 `stage_dv`(1단 남은 Δv)가 0보다 크고 남은 원궤도화 Δv보다 작음(로그). `circularize` 연소 중 1단 연소 종료 → 연소 종료를 감지한 같은 틱부터 `separate`·`settle`·`ignite` 동안 `no_thrust` 없이 스로틀 0·자세 유지로 대기(틱 순서 (c)가 (d)보다 먼저), 2단 점화 뒤 이어서 연소.
  - 방향 고정: 남은 Δv가 10 m/s 아래로 내려간 뒤 자세 목표가 바뀌지 않고(로그), 그 뒤 `attitude_error` > 5°로 스로틀이 0이 되는 틱이 없음. 완료 이유(Δv ≤ tolerance, Δv 증가, 이심률 정체)를 로그로 남긴다.
  - 종료 게이트: 자세 게이트로 스로틀 0인 틱, 스테이징 대기 틱(AutoStager가 0으로 덮어쓴 틱 포함), `thrust` 0인 틱에는 `ecc_flat`이 0으로 돌아가고 Δv 증가·이심률 정체로 끝나지 않음(로그). 고정 뒤 틱별 이심률 변화를 기록해 `EccFlatTicks`(5)와 `EccTolerance`를 조정하고 결과를 단위 완료 보고에 남긴다.
  - 코드 리뷰: Mode 필드(`_burning`, `_lockedDir`, `_prevDv`, `_prevEcc`, `_eccFlat`)와 `Save`/`Load` 키(`burning`, `locked_dir`, `prev_dv`, `prev_ecc`, `ecc_flat`, 설계 "reload 인계"와 같음)가 일치.

public static IList<string> Stop(LogicContext ctx)
{

    Safe(() => { if (Warp.Requested) Warp.Stop(); });               // 직렬화 전에, 우리가 건 가속만: warp_stopped가 인계 이벤트에 들어감(스로틀·SAS 유지, 사용자 가속 유지)
    try { ctx.Handover = Json.Serialize(Handover.Capture()); }       // {format, epoch, events, seq, plan?}: Dictionary·List만

    {

        // plan 없이라도 seq가 이어지게: 이벤트 버퍼(plan_aborted 포함)까지, 안 되면 {format, epoch, seq}만
        try { ctx.Handover = Json.Serialize(Handover.CaptureEvents()); }   // {format, epoch, events, seq}
        catch { Safe(() => ctx.Handover = Json.Serialize(new Dictionary<string, object>
            { ["format"] = Handover.Format, ["epoch"] = FlightEvents.Epoch, ["seq"] = FlightEvents.LastSeq })); }
    }
    Safe(() => AttitudeController.Detach());   // OnFlyByWire만 해제. 이어받기: 스로틀·SAS 유지
    Safe(() => FlightScene.Unhook());
    Safe(() => AutoStager.Clear(PlanVessel()));   // 보낸 요청은 이미 인계됨: 여기서 남긴 staged는 아래 FlightEvents.Clear로 버려지고 새 Logic이 인계받은 요청으로 1회 남김
    Safe(() => { _plan = null; _mode = null; FlightEvents.Clear(); });   // static 비움
    released.Add("flight control handed over");
    return released;
}

```csharp
// Coordinator.Resume: 밖으로 예외를 던지지 않는다. 실패는 reload_incompatible로 처리
// (StartCore의 catch로 나가면 이전 Logic이 같은 Handover로 다시 이어받아, 이미 보낸 스테이지 작동 같은 되돌릴 수 없는 부작용이 겹친다)
public static void Resume(HandoverState h)
{
    Safe(() => FlightEvents.Restore(h.Events, h.Seq, h.Epoch));   // epoch 없음(인계 없음·파싱 실패)이면 새 난수 id
    if (h.Plan == null) { Safe(() => FlightEvents.Add("logic_reloaded", -1, Reloaded(false))); return; }
    Vessel v = FlightGlobals.ActiveVessel;
    try
    {
        if (h.Incompatible || !HighLogic.LoadedSceneIsFlight || v == null || v.persistentId != h.Plan.VesselId)
            throw new InvalidOperationException("handover does not match");
        // 1. 실패할 수 있는 일 먼저: static 상태를 바꾸지 않음
        Plan plan = Plan.Restore(h.Plan, v);               // 계획 재파싱·검증(plan_id 유지), 단계·타이머
        IFlightMode mode = plan.CreateMode(h.Plan.Step);
        mode.Load(v, h.Plan.ModeState);                    // Begin 대신
        // 2. 그 뒤에 스테이저 복원·Running 전환
        AutoStager.Load(h.Plan.Staging);                   // state·before·parallel·ticks·last_ut·latch·request·on_start_request·on_start_queued
        Warp.LoadLatch(h.Plan.WarpCancelled);
        _plan = plan; _mode = mode; _step = h.Plan.Step; _stepStartUt = h.Plan.StepStartUt;
        _plan.State = PlanState.Running;
        Command = h.Plan.Command;                          // 직전 명령 복원: 자세는 AttitudeTarget.Vector(인계 방향), 스로틀·Mode 스로틀
        double ut = Planetarium.GetUniversalTime();
        Capture(v, ut);                                    // attitude_error 값 있음, PrevCommandThrottle·PrevModeThrottle = reload 전 값
        Command = ComputeCommand(v, ut, _plan, _mode, send: true);   // Tick과 같은 경로: 첫 OnFlyByWire 전에 Command를 채워 스로틀 끊김 방지
        AttitudeController.Attach(v, sasBefore: h.Plan.SasBefore);   // 이미 꺼진 SAS를 원래 상태로 기록하지 않음
        AttitudeController.LoadIntegral(h.Plan.ControllerIntegral); // Attach 뒤: 인계받은 적분값으로 PID를 이어감
        FlightEvents.Add("logic_reloaded", _step, Reloaded(true));
    }
    catch (NoThrustException e)                            // 계획은 맞게 이어받았고 추력만 없음: reload_incompatible가 아님
    {
        Safe(() => AttitudeController.Adopt(v, h.Plan.SasBefore));   // Attach 전이라 SAS 복원 대상을 둠
        Safe(() => FlightEvents.Add("logic_reloaded", _step, Reloaded(false)));
        Abort("no_thrust", null, e.Message);               // Release(스로틀 0·SAS 복원) 뒤 plan_aborted {reason:"no_thrust"}
    }
    catch (Exception e) { Incompatible(v, h.Plan.VesselId, h.Plan.SasBefore, h.Plan.Command.Throttle, e.Message, h.Plan.StagingRaw); }   // StagingRaw: 인계 staging 원본(Load 전 실패 대비)   // command.throttle: 인계 직전 명령
}

/// <summary>Never throws: every step is guarded. Touches throttle·SAS·warp only on the handed-over vessel;
/// on another vessel only the global input throttle is zeroed when the handed-over command throttle was above 0.</summary>
static void Incompatible(Vessel v, uint planVesselId, bool? sasBefore, double handedThrottle, string message,
                         Dictionary<string, object> handedStaging)
{
    _plan = null; _mode = null;
    // 재검증·mode.Load 실패로 AutoStager.Load 전에 왔으면 인계된 요청이 메모리에 없다.
    // 인계 staging의 request·on_start_request(stage_before, sent)만 읽어 같은 판정으로 staged를 남긴다.
    Safe(() => AutoStager.RecordHandedRequests(v != null && v.persistentId == planVesselId ? v : null, handedStaging));
    Safe(() => AutoStager.Clear(v != null && v.persistentId == planVesselId ? v : null));   // 보낸 요청이 작동했으면 staged를 남긴 뒤 비움
    if (v != null && v.persistentId == planVesselId)
    {
        Safe(() => AttitudeController.Adopt(v, sasBefore));   // 연결 전에 실패했으면 v·sas_before를 복원 대상으로 둠(이미 연결됐으면 그대로)
        Release();                                            // 스로틀 0·가속 해제·SAS 복원·OnFlyByWire 해제·Command Idle
    }
    else
    {
        Command = ModeCommand.Idle;                           // 다른 기체(또는 없음): SAS·ctrlState·가속은 건드리지 않음
        if (handedThrottle > 0) Safe(() => FlightInputHandler.state.mainThrottle = 0);   // 인계 스로틀이 남아 있던 전역 입력만 0으로
    }
    Safe(() => FlightEvents.Add("logic_reloaded", -1, Reloaded(false)));
    Safe(() => FlightEvents.Add("plan_aborted", -1, new Dictionary<string, object> { ["reason"] = "reload_incompatible", ["message"] = message }));
}
```

- **검증**:
  - 기체 B 상승 중 `reload_mod` → `logic_reloaded {resumed:true}`, 스로틀·자세가 끊기지 않고 같은 단계에서 이어서 완주. SAS를 켠 채 계획을 시작했으면 완주 뒤 SAS가 켜짐(인계받은 `sas_before`).
  - 스테이징 `settle` 중 reload → 시퀀스가 이어짐.
  - `coast` 가속을 사용자가 취소한 뒤 같은 단계에서 reload → 다시 가속하지 않음(`_cancelled` 인계).
  - `circularize` 연소 중 reload → 연소가 끊기지 않음(`_burning` 인계), 한 바퀴 대기 없음. 방향 고정 뒤 reload → 고정 방향이 그대로(로그로 reload 전후 자세 목표 비교).
  - 기체 B 직렬 `separate` 대기 중 reload → 분리 대기 틱 수·`_parallel`이 이어져 스로틀 0 상태에서 분리. 래치 인계: 단위 8 "래치 뒤 스로틀 0 단계" 계획에서 `out_of_stages` 뒤 스로틀 0 단계(`attitude` `throttle:0` 또는 `coast`) 중 reload → `out_of_stages`가 다시 나오지 않고 계획이 계속됨. reload 전후 `get_flight`의 `plan.id`가 같음.
  - 계획 없이 reload → `logic_reloaded {resumed:false}`, `get_flight_events?since=<reload 전 마지막 seq>`가 reload 뒤 이벤트만 반환(seq 이어짐).
  - `Handover.format`을 바꾼 빌드로 reload → `reload_mod` 자체는 성공, `logic_reloaded {resumed:false}`·`plan_aborted {reason:"reload_incompatible"}`, 스로틀 0, SAS 복원.
  - Mode `Load`에서 일부러 예외를 내는 빌드로 reload → 위와 같이 `reload_incompatible`(reload 성공). `AutoStager`가 복원되지 않음(`staging`이 `none`), 계획 없음(`plan.state: idle`), 스테이지 작동 요청이 나가지 않음.
  - 엔진 연소 중 reload → 첫 틱 스로틀이 0으로 떨어지지 않음(로그로 reload 전후 `mainThrottle` 확인). `circularize` 연소 중(자세 게이트 사용) reload도 같고, 첫 틱 `attitude_error`가 값 있음(인계한 `command`로 복원, 로그).
  - `Handover.Capture`에서 일부러 예외를 내는 빌드를 띄운 뒤 그 다음 reload → 스로틀 0, SAS 복원, reload 뒤 계획 없음(`plan.state: idle`). `get_flight_events?since=<reload 전 마지막 seq>`에 `plan_aborted {reason:"error"}`와 `logic_reloaded {resumed:false}`가 나오고 seq가 이어짐(`plan` 없는 인계). 이벤트 직렬화도 실패하게 한 빌드에서는 이벤트는 비지만 seq는 이어짐(`{format, seq}`, 코드 리뷰 가능).
  - 계획 없이 수동 스로틀을 올린 상태에서 인계를 소비하지 않는 Logic으로 reload → `DropHandover`가 스로틀·SAS를 건드리지 않음(`plan` 키 없음).
  - 새 Logic `Start`에서 일부러 예외를 내는 빌드로 reload → `reload_failed`, 이전 Logic이 같은 계획을 이어받아 계속 비행(훅 이중 연결 없음: 스로틀·자세 정상).
  - 스테이지 작동 요청이 확인을 기다리는 중 reload(0.56초 쿨다운 창 안에 `reload_mod`를 맞추기 어려움): 코드 리뷰 + 개발 중 전용 확인 지연 훅(단위 3과 같은 훅, 단위 완료 전 제거)으로 확인한다. 훅은 `StageRequest`의 `currentStage` 감소 확인을 송신 뒤 5초 보류한다. 훅을 켠 빌드에서 `ignite` 요청 송신 직후 `reload_mod` → `request`가 인계되어 재요청 없이 이어지고 `staged`가 한 번만 나옴, 스테이지 1개 감소.
  - `coast` 가속 중 reload → reload 전 마지막 이벤트로 `warp_stopped`가 나오고 `get_flight_events`에서 reload 뒤에도 보임(인계 직렬화 전 `Warp.Stop`). 스로틀·SAS는 유지.
  - 인계 Load의 null 복원(코드 리뷰): 모든 `Load`가 double을 `D(...)`로 읽어 null을 기본값(NaN, `prev_dv`·`prev_ecc`는 +∞)으로 되돌림. `StageRequest`의 `first_ut`·`last_send_ut`가 NaN인 요청(아직 시작 전)을 인계해도 첫 시도부터 다시 셈.
  - 적분값 인계: 자세 유지 중 reload 전후 `AttitudeController` 적분값이 같음(로그, `Attach` 뒤 `LoadIntegral`).
  - Incompatible의 기체 확인: 인계 `vessel_id`와 다른 기체가 활성인 상태(코드 리뷰, 게임에서 같은 프레임에 만들기 어려움)에서는 `Adopt`·SAS 복원·`ctrlState` 변경·`Release`를 하지 않고 `logic_reloaded {resumed:false}`·`plan_aborted {reason:"reload_incompatible"}` 이벤트를 남김. 인계 `command.throttle > 0`이면 전역 `FlightInputHandler.state.mainThrottle`만 0이 되고, 0이면 스로틀도 건드리지 않음.
  - Resume 중 추력 없음(코드 리뷰 또는 인계 직전에 연료를 0으로 만든 기체로 reload): `ComputeCommand`가 `NoThrustException`을 던지면 `reload_incompatible`가 아니라 `logic_reloaded {resumed:false}` 뒤 `plan_aborted {reason:"no_thrust"}`, 스로틀 0, SAS가 `sas_before`로 복원(`Adopt` 뒤 `Abort`).
  - 사용자 가속 유지: 계획 없이 사용자가 레일 가속을 건 상태에서 `reload_mod` → 가속이 유지되고 `warp_stopped`가 없음(`Coordinator.Stop`은 `Warp.Requested`일 때만 `Warp.Stop`).
  - `epoch`: reload 전후 `get_flight_events`의 `epoch`가 같음. 인계 직렬화가 `{format, epoch, seq}`로 떨어진 경우도 같음(코드 리뷰).
  - 로더 재확인(단위 1에서 옮김): 0.0.2 로더 KSP가 실행 중일 때 이 단위까지 반영한 Logic을 단위 1의 배포 절차로 반영하고(실행 중 로더는 바뀌지 않음) `reload_mod` → `reload_failed`, 메시지가 `loader 0.0.3 required; restart KSP`이고 `MissingFieldException`이 아님.
  - 계획 실행 중 인계를 소비하지 않는 Logic으로 reload(또는 복구 실패) → Mod `DropHandover`가 스로틀 0, SAS를 `sas_before`로 복원(로그).
- **선행 단위**: 1, 10

### 12. `get_status` 확장·ReadMe

- **대상**: `BridgeLogic.Status`, `FlightTools.GetStatus` 설명, `ReadMe.md`
