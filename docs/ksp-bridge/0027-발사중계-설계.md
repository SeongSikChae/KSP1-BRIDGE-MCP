## 구성
- **Logic(net472)**

  - 새 파일 `Handlers/BroadcastHandler.cs`: 라우트 처리
  - `BridgeLogic`: Start에서 훅을 걸고, FixedUpdate에서 `Tick`, Stop에서 훅을 풉니다.
  - `Routes`: 라우트 3개를 추가하고 버전을 0.10.0으로 올립니다.
  - 배포는 `reload_mod`로 합니다. 로더는 바꾸지 않습니다.

  - 새 폴더 `Broadcast/`:

  - 새 파일 `BroadcastTools.cs`
  - 바꿀 곳:

## Logic: 이벤트 버퍼
- `BroadcastEvents`는 static이며 FlightRecorder와 같은 스타일입니다.
- 상태: `armed`, `seq`, 이벤트 리스트(최대 500개, 오래된 것부터 버립니다), `altitudes[]`, 돌파한 고도 집합, 분리 횟수
- 이벤트 형식: `{seq, type, rt(=Time.realtimeSinceStartup), ut, met, ...}`

| type | 훅·시점 | 추가 필드 |
|---|---|---|
| liftoff | `onVesselSituationChange` PRELAUNCH→FLYING 또는 LANDED→FLYING(발사대) | vessel |
| separation | `onStageSeparation` 활성 기체만 | index(1부터, arm 이후 순번) |
| situation | `onVesselSituationChange` ORBITING / LANDED / SPLASHED / SUB_ORBITAL→ORBITING | situation, body |
| soi | `GameEvents.onVesselSOIChanged` (새 훅) | from, to |
| altitude | `Tick`: 고도가 기준을 처음 넘을 때 1회 | meters, atmosphere(bool, 대기권 경계면 true) |

- 활성 기체가 아닌 이벤트는 무시합니다(분리된 잔해 등).
- 대기권 경계는 arm 시점에 `body.atmosphereDepth`로 정합니다. 기본 기준 고도는 `[10000, atmosphereDepth]`입니다.
- 이벤트 시간은 arm 이후 `Time.realtimeSinceStartup` 기준입니다(시간 가속과 무관한 실시간).

### 라우트
| 메서드 | 경로 | 본문/쿼리 | 응답 |
|---|---|---|---|
| POST | `/api/broadcast/arm` | `{altitudes?: number[]}` | `{armed:true, vessel, body, altitudes}` |
| GET | `/api/broadcast/events` | `?since=N` | `{events:[{...,ageMs}], last}` |
| POST | `/api/broadcast/disarm` | - | `{armed:false, count}` |

- `ageMs = (지금 realtime − 이벤트 rt) × 1000`. App은 `받은 시각 − ageMs`로 이벤트의 실제 발생 시각을 정합니다.
- 비행 씬이 아니면 arm이 `not_in_flight` 오류를 냅니다(기존 ApiException 패턴).

```yaml

  FfmpegPath: C:\tools\ffmpeg\bin\ffmpeg.exe
  OutputDir: broadcasts    # ContentRootPath 기준
  WindowTitle: Kerbal Space Program
  FrameRate: 30
  Font: Malgun Gothic
  Speech:
    Region: koreacentral   # https://{Region}.tts.speech.microsoft.com/cognitiveservices/v1
    ApiKey: <평문 입력 → 기동 시 DEKENC:로 암호화>
    Voice: ko-KR-Haena:MAI-Voice-2-Flash
OsKms:
  CredentialService: KspBridge.App
  CredentialAccount: kek
  Salt:                    # 최초 기동 시 생성·기록
  Iterations: 600000
  SecretsDekFilePath: secrets/dek.bin
```
- `Broadcast`는 선택 섹션입니다. 없으면 기존 동작 그대로이고 KMS 부트스트랩도 하지 않습니다.
- `Broadcast.Speech.ApiKey`가 있으면 `OsKms`가 필수입니다. 이 조건은 기존 Validate 패턴으로 검사합니다.
- 키 처리 흐름은 skill `dotnet-kms-config-secrets` B와 같습니다:
  1. `StartsWithFromPrefix`로 암호문인지 확인합니다.
  2. 평문이면 `Encrypt`하고 YAML을 다시 씁니다.
  3. `Decrypt`해서 메모리에만 둡니다.
  4. 키 값은 로그에 남기지 않습니다.
- 사용자 결정: 백엔드는 B(OsKms)입니다.

## App: TTS
- `SpeechClient`는 타입 지정 HttpClient입니다.
  - 요청: `POST https://{Region}.tts.speech.microsoft.com/cognitiveservices/v1`
  - 헤더: `Ocp-Apim-Subscription-Key`, `Content-Type: application/ssml+xml`, `X-Microsoft-OutputFormat: riff-24khz-16bit-mono-pcm`, `User-Agent: KspBridge`
- `Ssml.Build(voice, text)`: `<speak version="1.0" xml:lang="ko-KR"><voice name="{voice}">{XML 이스케이프된 text}</voice></speak>`
- 캐시: `{OutputDir}/tts-cache/{sha256(voice+text)[..16]}.wav`. 파일이 있으면 다시 호출하지 않습니다.
- 실패(HTTP 오류나 타임아웃)는 해당 문구의 음성만 빼고, 자막은 그대로 남깁니다. 실패 목록은 상태 조회에 보입니다.

## App: 문구 (`Narration`)
| 시점 | 자막·음성 |
|---|---|
| T-20 (countdown ≥ 20일 때만) | "{기체}, 발사 20초 전입니다." |
| T-10 | "발사 10초 전." |
| T-9…T-1 | "9" … "1" + 비프 |
| T-0 | "발사!" + 긴 비프 |
| liftoff | "{기체}{이/가} 발사되었습니다." |
| separation n | "{n}단이 분리되었습니다." |
| altitude | "고도 {km}킬로미터를 돌파했습니다." / atmosphere: "대기권을 벗어났습니다." |
| situation ORBITING | "{천체} 궤도에 진입했습니다." |
| situation LANDED | "{천체}에 착륙했습니다." |
| situation SPLASHED | "{천체}에 착수했습니다." |
| soi | "{천체} 영향권에 진입했습니다." |
- 조사: 마지막 글자가 한글이면 받침 유무로 이/가를 고릅니다. 그 밖에는 마지막 문자로 정합니다. 영문 자음과 숫자는 읽는 소리 기준의 간단한 표를 씁니다.
- countdown 기본값은 10초이고 범위는 3~30초입니다. 20 미만이면 T-20 문구를 뺍니다. 10 미만이면 첫 숫자부터 셉니다.

## App: 녹화·카운트다운 (`BroadcastSession.StartAsync`)
1. 이미 녹화 중이거나 합성 중이면 `busy` 오류를 냅니다.
2. 카운트다운 문구를 모두 미리 합성합니다(병렬, 캐시 사용).
3. 녹화를 시작합니다: `ffmpeg -y -f gdigrab -framerate {fps} -draw_mouse 0 -i "title={WindowTitle}" -c:v libx264 -preset ultrafast -crf 18 -pix_fmt yuv420p {dir}/raw.mkv`
   - stdin은 리다이렉트합니다. 출력 폴더는 `{OutputDir}/{yyyyMMdd-HHmmss}-{기체}/`입니다.
   - 녹화 시작 0점은 ffmpeg stderr에 첫 `frame=` 줄이 나온 시점의 Stopwatch 값입니다. 3초 안에 나오지 않으면 실패로 보고 프로세스를 끝냅니다(창 제목 불일치 등).
4. `POST /api/broadcast/arm`
5. 카운트다운: 기준 시각을 잡고 `Task.Delay`로 다음 초 경계까지 기다립니다. 누적 오차가 생기지 않게 절대 시각 기준으로 계산합니다. 각 초마다 Cue(오프셋 = Stopwatch − 0점)를 기록합니다.
6. T-0에 `POST /api/stage`를 보내고 결과를 반환합니다. 실패해도 녹화는 계속하고, 오류 내용을 반환에 넣습니다.
7. 폴링 루프를 시작합니다. 250 ms마다 `/api/broadcast/events?since=last`로 이벤트를 받아 Cue로 바꿉니다.

## App: 중지·합성
- `stop_broadcast`:
  1. 폴링 루프를 멈춥니다.
  2. disarm을 보냅니다. 실패해도 계속합니다.
  3. ffmpeg stdin에 `q`를 보내고 10초 안에 끝나지 않으면 Kill합니다.
  4. 백그라운드 작업을 시작하고 `{id, dir, state:"composing"}`을 바로 반환합니다.
- 백그라운드 작업:
  1. 이벤트 Cue의 음성을 합성합니다.
  2. `subs.ass`를 씁니다. 자막 표시 시간은 cue 시각부터 `max(음성 길이, 2.5초)`까지이고, 다음 cue와 겹치면 앞 자막을 거기서 끊습니다.
  3. 최종 ffmpeg를 실행합니다:
     ```
     ffmpeg -y -i raw.mkv -i cue1.wav -i cue2.wav ... -f lavfi -t 0.15 -i sine=f=1000 ...
       -filter_complex "[1:a]adelay=12340|12340[a1];...;[a1][a2]...amix=inputs=N:normalize=0[aout];
                        [0:v]subtitles=subs.ass:fontsdir=...[vout]"
       -map [vout] -map [aout] -c:v libx264 -preset veryfast -crf 20 -c:a aac final.mp4
     ```
     - 비프는 위치마다 `sine` 입력을 따로 둡니다(T-9…T-1은 0.15초 1 kHz, T-0은 0.6초).
     - 입력이 많으면 명령줄이 길어지므로 `-filter_complex_script` 파일을 씁니다.
  4. 끝나면 `raw.mkv`는 남겨 두고 상태를 `done`으로 바꿉니다. 실패하면 `failed`와 stderr 마지막 20줄을 남깁니다.
- 음성 길이는 WAV 헤더에서 data 크기 ÷ byte rate로 계산합니다(별도 라이브러리 없이).

## MCP (App, `BroadcastTools`)
| 도구 | 인자 | 동작·반환 |
|---|---|---|
| `start_broadcast` | `craftName?`(기본: arm 응답의 vessel), `countdownSeconds=10`, `altitudes?`(m 배열) | 녹화 시작 → 카운트다운 → T-0 점화. `{dir, ignited, stage, cues}` 반환. 설명에 "점화 전 get_stages로 Δv를 점검한 뒤 호출"을 적습니다. Destructive |
| `stop_broadcast` | - | 녹화 중지 → 합성 시작. `{id, dir, state}` |
| `get_broadcast_status` | - | `{state: idle/countdown/recording/composing/done/failed, dir, elapsed, cues, ttsFailures, output, error}` ReadOnly |

- `BroadcastSession`은 싱글턴으로 DI에 등록합니다. 툴 클래스는 기존처럼 `KspBridgeClient`와 `BroadcastSession`을 주입받습니다.
- ffmpeg 실행은 `IProcessRunner` 인터페이스 하나 뒤에 둡니다. 테스트가 실제 프로세스 없이 인수와 순서를 검증할 수 있게 하기 위해서입니다.

## 구현 중 변경 (2026-11-08)
- **ffmpeg 최소 버전 7.0**: `-filter_complex_script`는 ffmpeg 7부터 없어졌습니다(9.0.1에서 `Unrecognized option` 확인). 대신 `-/filter_complex filter.txt`를 씁니다. 처음 적었던 5.0 요구는 7.0으로 올립니다.
- **오디오 길이**:
  - 설계 초안의 `-shortest`를 그대로 쓰면 영상이 마지막 음성 시점에서 잘립니다.
  - 그래서 `amix` 뒤에 `apad`를 붙여 오디오를 영상 끝까지 늘리고, 그다음 `-shortest`로 끝을 맞춥니다.
  - 합성 전에 각 음성을 24 kHz mono로 맞춥니다(`aresample`, `aformat`).
  - 실제 ffmpeg 9.0.1로 확인한 결과: 15초 영상, 오디오 14.98초, 2초 지점 프레임에 한글 자막이 보였습니다.
- **녹화 0점**: 검토 회귀 1을 반영해 `받은 시각 − frame/fps`로 계산합니다.
- **합성 경로**:
  - 검토 회귀 2를 반영해 중계 폴더에서 ffmpeg를 실행합니다.
  - 음성 WAV는 캐시에서 `tts/NNN.wav`로 복사해서, ffmpeg에는 상대 경로만 넘깁니다.
- **OsKms `CredentialService`는 URI 형식이어야 합니다**: Git Credential Manager의 대상 이름 규칙 때문입니다. 기본값은 `kspbridge-app://kek`입니다(KMS 기본값 `bizadm-kms://kek`와 같은 형식).
- **분리 이벤트 집계**: `onStageSeparation`은 디커플러 하나마다 발생합니다. 그래서 0.5초 안에 연달아 온 이벤트는 한 번의 분리로 셉니다(방사형 부스터 등).
- **`Speech` 섹션이 없을 때**: 음성 없이 자막만 입힙니다.
- **녹화 방식: `gdigrab` → `gfxcapture` (실게임 검증 결과)**:
  - 첫 실게임 중계(KB Hammer Orbiter 2, 궤도 진입)에서 합성 결과 자체는 정상이었습니다(영상과 오디오 모두 186초, 자막 17개).
  - 그런데 화면에는 KSP 창 위에 떠 있던 Claude 창이 찍혔습니다. `gdigrab`은 창 영역의 화면을 그대로 복사하기 때문입니다.
  - 그래서 ffmpeg의 `gfxcapture`(Windows Graphics Capture)로 바꿉니다. 이 방식은 창 자체를 캡처하므로, 가려진 KSP 창도 정상으로 찍히는 것을 확인했습니다.
  - 인수는 `-f lavfi -i gfxcapture=window_title=^…$:max_framerate=N:capture_cursor=0,hwdownload,format=bgra -r N`입니다.
- **카운트다운 문구와 음성 (2026-11-08 사용자 결정, 실게임 청취 후)**:
  - 기존 "발사 10초 전."은 1.8초짜리라 1초 뒤 "9"와 겹쳤습니다. 그래서 카운트다운을 다음처럼 바꿉니다.
    - T-10부터 매초 한자어 숫자를 읽습니다(십, 구 … 일). 자막에는 10, 9 … 1로 표시합니다.
    - T-0에는 긴 비프음만 냅니다. 처음에는 "발사!"를 읽게 했지만, 바로 이어지는 이륙 안내("○○가 발사되었습니다.")와 겹쳐서 사용자 제안으로 뺐습니다. 실게임 3차 녹화에서 받아쓰기로 확인한 결과입니다.
    - "발사 N초 전" 안내는 T-20에만 남깁니다.
  - 자막 문구와 실제로 읽을 문구를 나눴습니다(`Cue.Say`). 단 번호도 한자어로 읽습니다(`1단` → "일단").
  - 음성은 SSML 스타일(`mstts:express-as`)과 속도(`prosody rate`)를 설정할 수 있게 했습니다(`Speech.Style`, `Speech.Rate`).
  - MAI 음성 비교 결과:
    - Harper MAI-Voice-2.1(narrator, +30%)과 Flash 모두, 숫자 하나를 따로 읽게 하든 카운트다운 전체를 한 문장으로 읽게 하든 반복이나 오독이 생겼습니다(받아쓰기 확인: "칠. 칠", "사 사", "십→집").
    - 같은 문장을 다시 합성할 때마다 결과도 달랐습니다.
    - `ko-KR-SunHiNeural`은 11개를 모두 정확하게, 매번 같은 길이로 읽었습니다.
  - 사용자 선택에 따라 모든 안내를 SunHi(+10%)로 통일합니다.
  - 실게임 3차 녹화(SunHi, 20초 카운트다운)의 최종 영상을 초 단위로 잘라 받아쓰기했습니다. 십…일 10개가 모두 정확했고, 각 숫자는 해당 초가 시작되고 0.3~0.5초 안에 끝났습니다.
  - 비행 이벤트 안내는 앞 음성이 아직 나오고 있으면 그 음성이 끝난 뒤(0.2초 간격)로 미룹니다(`BroadcastSession.Space`). 카운트다운 문구(`Cue.Fixed`)는 정해진 초를 지킵니다.
- **이륙 문구의 이름**: 이륙 안내에 기체 이름(vessel) 대신 `start_broadcast`의 `craftName`을 씁니다.
- **음성 이름과 리전 (2026-11-08 사용자 결정)**:
  - Microsoft Learn에서 모델 이름이 MAI-Voice-2.1과 MAI-Voice-2.1-Flash로 바뀌었습니다. 그래서 기본 음성을 `ko-KR-Haena:MAI-Voice-2.1-Flash`로 바꿉니다.
  - MAI 음성은 koreacentral에서 지원하지 않습니다. 권장 리전은 southeastasia이고, 설정 예시도 southeastasia로 바꿉니다.
- **독립 검토 반영**:
  - T-0 직전에 녹화 프로세스가 살아 있는지 확인합니다. 녹화가 멈췄으면 점화하지 않고 `record_failed`를 반환합니다.
  - arm 응답 파싱과 취소 처리를 정리 경로(try) 안으로 옮겨, 상태가 `countdown`에 영구히 걸리지 않게 했습니다.
  - 형식이 잘못된 events 응답은 무시합니다. 그래도 폴링 루프는 멈추지 않습니다.
  - 폴링 루프를 시작한 뒤에 상태를 `recording`으로 바꿉니다(start와 stop이 겹치는 경합 방지).
  - MCP 서버가 종료되면(DisposeAsync) 진행 중인 녹화를 `q`로 끝내고 disarm합니다. 이 경우 합성은 하지 않습니다. 앱이 크래시하는 경우는 처리하지 않습니다.
  - 대기가 없는 천체에서는 LANDED/PRELAUNCH에서 SUB_ORBITAL로 바뀔 때도 이륙으로 판정합니다.
  - 분리 이벤트는 활성 기체이거나, 활성 기체에서 200 m 안에 있는 기체에서 난 것만 셉니다.
  - 비행 중에 arm하면 이미 지난 고도는 안내하지 않습니다.
  - KMS: Salt를 DEK 파일보다 먼저 YAML에 기록합니다(스킬 순서). YAML은 임시 파일에 쓴 뒤 교체합니다.
