# 비행안정 방안

이슈: [#24 비행 계획: 자세 진동, 이상 상태(진동·제어 상실·추력 낭비) 감시 부재, 접근 단계 원거리 kill 연소와 노드 대기 중 가속 중단](https://github.com/SeongSikChae/KSP1-BRIDGE-MCP/issues/24)

## 문제

#15 3단계 실측(`KspBridge-XferT`·`KspBridge-XferC` 발사·랑데부)에서 다음이 드러났다.

1. **자세 진동·오버슈트**: 조종면(`tailfin` 4개, `ModuleControlSurface`)과 Skipper 짐벌을 함께 쓰는 기체가 상승 중 계속 흔들렸고 롤이 -87°까지 돌아갔다. 조종면이 없는 추적 기체도 `execute_node` 기수 회전 때 오차가 172° → 5° → 36° → 6.5° → 14.8° → 0.17°로 넘나들었다.
2. **이상 상태 감시 부재**: 공기역학적으로 불안정해 뒤집힌 기체가 연료를 다 쓸 때까지(`no_thrust`) 계획을 계속했다. 표본으로 읽은 `attitude_error`(0.02~1.5°)로는 진동이 드러나지 않았다.
3. **`approach` 원거리 kill**: `rendezvous_phase` 노드 실행 직후 `approach`가 같은 틱에 `wait` → `kill`(185,949 m, 556.8 m/s)로 넘어가 약 200 m/s를 낭비하고 랑데부를 깨뜨렸다.
4. **`execute_node` 재가속 없음**: 노드 200 s 전 워프가 멈춘 뒤 기수 회전이 끝나도 남은 시간을 1배속으로 기다렸다.

### 코드 조사로 확인한 원인 (방안 시점)

- 3: `ApproachMode.cs:127`의 대기 조건 `ut < wake && Dot(rel, relV) > 0`이 "지금 거리가 줄고 있는가"만 본다. 전이 직후 거리가 잠시 늘어나는 구간이면 최근접이 한참 뒤여도 바로 `Kill`로 들어간다. `kill` 단계에는 거리 가드가 없다. 대기 시각은 현재 상대속도 기준 연소시간 전체를 빼서(설계 0032 결정 22는 `/2`) `wake`가 과거가 될 수 있다.
- 4: 대기 분기는 정렬 여부와 무관하게 바로 워프를 요청한다. 워프가 목표 시각에 스스로 끝나도 `Warp.Sync`가 사용자 취소로 보고 래치를 걸어 같은 단계에서 다시 요청하지 못한다(`Warp.cs:61-79`). `circularize`·`approach` 대기도 같은 경로다.
- 1: 자체 PI 제어기(`AttitudeController`, 미분항 없음)가 반작용 휠·짐벌·조종면·RCS 토크를 `ITorqueProvider`로 구분 없이 합산한다. 동압·스로틀에 따라 크게 변하는 조종면·짐벌 토크가 그대로 게인 계산(`alpha = torque / moi`)에 들어가 실제보다 크거나 작게 잡힐 수 있다(추정, 실측으로 확인 필요).
- 2: 각속도 이력·진동 감지가 없고 `get_flight`에 각속도가 없다. 지금은 계획 `abort` 조건에 `attitude_error`를 쓰는 방법뿐이다.

## 목표

- `approach`는 최근접 지점 근처까지 기다린 뒤에만 상대속도 상쇄를 시작한다.
- 자동 워프로 기다리는 단계는 정렬을 마친 뒤 남은 대기 시간을 다시 가속한다.
- 비행 계획이 제어 상실·뒤집힘을 감지하면 연료를 다 쓰기 전에 멈추고, 진동·추력 낭비는 이벤트로 알린다.
- 에이전트가 표본 몇 개로 놓치지 않도록 최근 구간의 진동·오차 요약을 읽을 수 있다.
- 조종면 + 짐벌 기체의 상승에서 진동이 사라지거나 줄어든다.

## 결정 (사용자 합의)

### 1. 문서·구현 분할

방안은 #24 전체로 이 문서 하나를 쓴다. 설계·개발은 아래 구현 단계마다 따로 만들고 단계별로 끝낸다.

1. `approach` 원거리 kill + 자동 워프 재가속(`execute_node`·`circularize`·`approach` 대기 공통) — 원인이 코드로 확인된 버그
2. 이상 상태 감시 + `get_flight` 최근 구간 요약
3. 자세 제어기 진동 — 실측으로 원인을 확인한 뒤 보정

2단계의 감시가 3단계 실측의 측정 도구가 되므로 이 순서로 한다.

### 2. 이상 상태 대응: 기본 중단 + 조절

- 뒤집힘·지속적 제어 상실은 기본으로 계획을 중단한다(`plan_aborted`, 새 사유).
- 진동·추력 낭비는 경고 이벤트만 낸다.
- 계획(또는 단계)에서 한계값을 조정하거나 감시를 끌 수 있다.
- 감지 지표와 기본 한계값(자세 오차 추세, 각속도 부호 반복·진폭, 피치·받음각 한계, 추력 대비 원지점·속도 증가율)은 2단계 설계에서 정한다.

### 3. 자세 진동 대책: 토크 모델 보정

- 제어기가 조종면 토크는 동압에, 짐벌 토크는 현재 스로틀(추력)에 맞춰 반영하고, 각속도 감쇠를 보강한다.
- 조종면 부품 설정(권한·축)은 건드리지 않는다.
- 3단계 설계 전에 2단계 감시로 진동을 실측해 원인을 확인하고 보정 내용을 확정한다.

### 4. `approach` 대기 기준: 최근접 기준 대기 + 가드

- 거리 증감과 무관하게 `최근접 − 상쇄시간/2`(엔진 준비 시간 포함)까지 기다린다(필요하면 워프).
- `kill`은 그 시각 이후에만 시작한다.
- `kill` 시작 때 현재 거리가 예측 최근접보다 훨씬 크면(기준은 1단계 설계) 연소하지 않고 중단 이벤트를 낸다.

## 비범위

- 조종면 부품 설정(권한·축) 자동 변경
- SAS·`vessel.Autopilot`으로 제어기 교체
- 새 비행 모드 추가
- 사용자 취소를 확실히 가려내는 기능. 사용자 취소와 KSP 자체 종료를 구분할 수 없으므로 자동 워프가 예상 밖으로 끝나면 단계당 1회만 다시 걸고, 같은 단계의 두 번째 종료부터는 사용자 취소로 보고 다시 걸지 않는다(1단계 설계 결정 2, 사용자 합의)

## 완료 조건 (이슈 기준)

- 조종면 + 짐벌 기체의 `gravity_turn`에서 진동이 사라지거나, 진동이 감지되어 이벤트로 보고됨을 실측
- 조종면 없는 불안정 기체의 상승에서 제어 상실을 감지해 연료를 다 쓰기 전에 알리거나 멈춤을 실측
- `rendezvous_phase` 노드 실행 직후 `approach`가 최근접 지점 근처까지 기다린 뒤 kill을 시작함을 실측
- `execute_node`가 회전 후 남은 대기 시간을 가속함을 실측
- App 테스트(`dotnet test tests/KspBridge.App.Tests`) 통과
