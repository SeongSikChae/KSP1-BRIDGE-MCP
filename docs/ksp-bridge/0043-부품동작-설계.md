# 부품동작 설계 (2단계: 부속 상위 제어 + action group)

이슈: [#15](https://github.com/SeongSikChae/KSP1-BRIDGE-MCP/issues/15)
방안: [0040-부품동작-방안.md](0040-부품동작-방안.md)
1단계 설계: [0041-부품동작-설계.md](0041-부품동작-설계.md)

방안 결정 1의 2단계(부속 제어 · action group)만 다룬다. 1단계 도구(`get_vessel_parts`, `invoke_part_event`, `get_commnet`)는 이 설계가 정한 항목 추가 외에는 바꾸지 않는다. 연료 전달(3단계)은 별도 설계 문서로 다룬다.

## 게임 동작 (디컴파일, Assembly-CSharp)

### action group (`ActionGroupList`, `FlightInputHandler`)

- 그룹 상태는 `vessel.ActionGroups.groups[GetGroupIndex(group)]`(bool), 그룹마다 `cooldownTimes`가 있다.
- `ToggleGroup(group)`
  1. 현재 UT가 그 그룹 쿨다운 전이면 로그만 남기고 아무것도 바꾸지 않는다.
  2. `ADDITIONAL_ACTION_GROUPS`이고 `vessel.GroupOverride > 0`이면 override 목록(`groupStates[n-1]`)을 뒤집고, 그 그룹이 override 대상(`OverrideDefault` 또는 `OverrideActionControl`)이면 그룹 상태는 그대로 둔다.
  3. 아니면 그룹 상태를 뒤집는다.
  4. 뒤집힌 값이 true면 `KSPActionType.Activate`, false면 `Deactivate`로 `BaseAction.CreateActionList(v.parts, group, n, overrideDefault, include: true)`의 action을 모두 `Invoke`한다.
  5. 쿨다운을 `UT + param.Cooldown`으로 둔다.
  - 상태를 먼저 뒤집고 action을 차례로 부르며 예외를 잡지 않는다. action 하나가 예외를 던지면 그룹 상태는 이미 바뀌었고 앞쪽 action만 실행됐으며 쿨다운은 설정되지 않는다.
- `SetGroup(group, active)`: 상태가 이미 같으면 아무것도 하지 않고, 다르면 `ToggleGroup`.
- `CreateActionList`: 부품 수준 `Part.Actions`와 **활성 모듈**(`isEnabled`)의 `Actions`에서 `active`이고 advanced tweakable 규칙을 통과하며 그 그룹에 배정된 action을 고른다.
- 플레이어 키(`FlightInputHandler.Update`, EVA가 아닐 때)
  - Custom01~10: `CUSTOM_ACTION_GROUPS` 잠금이 풀려 있으면 `ToggleGroup`.
  - Abort: `GROUP_ABORT`, Gear: `GROUP_GEARS`, Light: `GROUP_LIGHTS`이 풀려 있으면 `ToggleGroup`.
  - Brakes: `GROUP_BRAKES`가 풀려 있으면 키 누름에 `SetGroup(true)`, 뗌에 `SetGroup(false)`.
  - 키 처리에는 `IsControllable` 검사가 없다. 조종 상태는 아래 잠금으로 반영된다.
- 조종 잠금(`Vessel`, `vessel_noControl_<id>`)
  - 조종 불가(`ControlLevel.NONE`): `ALL_SHIP_CONTROLS`. 위 그룹 잠금과 `TWEAKABLES_ANYCONTROL`·`TWEAKABLES_FULLONLY`·`ACTIONS_SHIP`가 모두 들어 있다.
  - 부분 조종(무인, 신호 없음): 자세·추력·LINEAR·바퀴·`TWEAKABLES_FULLONLY`(SAS·RCS 조건부)만 잠근다. action group 잠금과 `TWEAKABLES_ANYCONTROL`은 풀려 있다.
- 창 포커스 잠금 `flightDriver_ApplicationFocus`는 1단계 설계와 같이 판정에서 세지 않는다.

### 비행 중 PAW field 변경 (`UIPartActionFieldItem`, `UIPartAction*` 컨트롤)

- 표시: `CanActivateField`(1단계 설계와 같음). 활성 기체 부품은 `fld.guiActive`, advanced tweakable 규칙.
- 컨트롤: `field.uiControlFlight`. 컨트롤 종류별 항목(`UIPartActionFloatRange`, `UIPartActionToggle`, `UIPartActionCycle`, `UIPartActionChooseOption`, `UIPartActionFloatEdit`, `UIPartActionScaleEdit`, `UIPartActionMinMaxRange` 등)은 값이 바뀔 때 `control.requireFullControl`이면 `TWEAKABLES_FULLONLY`, 아니면 `TWEAKABLES_ANYCONTROL` 잠금이 풀려 있어야 값을 쓴다.
- `SetFieldValue(newValue)`: editor와 같은 순서다(`PartSettings.SetField` 주석 참조). `(control.affectSymCounterparts & UI_Scene.Flight) != 0`이면 대칭 부품에 먼저 값을 쓰고(같은 index·같은 타입 모듈, 아니면 같은 클래스 첫 모듈) 그 field의 `uiControlEditor`·`uiControlFlight`의 `onSymmetryFieldChanged`를 부른다. 바뀐 값이 있으면 자기 field에 쓰고 `control.onFieldChanged(field, old)`. editor가 아니므로 `onEditorShipModified`는 없다.
- 부품 수준 field(`Part.Fields`)는 대칭 부품에 값만 쓰고 이벤트는 부르지 않는다.
- 게임도 이 순서 중 콜백 예외를 잡지 않는다. 예외가 나면 대칭 부품만 바뀌었거나 자기 값까지 바뀐 상태로 멈춘다.
- 예: `ModuleEngines.thrustPercentage`(UI_FloatRange 0~100), `ModuleParachute.deployAltitude`(UI_FloatRange 50~5000), `ModuleParachute.automateSafeDeploy`(int, UI_Cycle 3단계, advanced tweakable, 대칭 전파 `UI_Scene.All`).
- 낙하산 안전 전개: `automateSafeDeploy >= deploymentSafeState`일 때만 펼친다(`deploymentSafeState`: SAFE, RISKY, UNSAFE, NONE). 즉 "안전할 때 전개"는 이 field와 `Deploy` event 조합으로 게임이 판단한다. 이 판단은 게임 코드이며 이 설계가 구현하지 않는다.

### 자원 흐름 토글 (`UIPartActionResource`)

- 비행 PAW는 `UIPartActionWindow.CanActivateResource`(`maxAmount != 0`, 활성 기체 부품, `isVisible`)를 통과한 자원만 행을 만든다(완료 전 검토 R1 반영).
- 그 행에서 자원 정의의 `resourceFlowMode != NO_FLOW`이고 `!resource.hideFlow`일 때만 버튼이 있다.
- 누르면 `control?.requireFullControl`이면 `TWEAKABLES_FULLONLY`, 아니면 `TWEAKABLES_ANYCONTROL` 잠금이 풀려 있을 때 `resource.flowState = !flowState`. 비행 PAW는 이 항목을 `AddResourceFlightControl`에서 `Setup(..., control: null, r)`로 만들므로 실제 판정은 항상 `TWEAKABLES_ANYCONTROL`이다. 대칭 부품에는 전파하지 않는다.

### 주요 상태 멤버 (state 보강 대상)

- `ModuleParachute`: `deploymentState`(STOWED, ACTIVE, SEMIDEPLOYED, DEPLOYED, CUT), `deploymentSafeState`(SAFE, RISKY, UNSAFE, NONE).
- `ModuleLight`: `isOn`(bool).
- `ModuleWheels.ModuleWheelDeployment`: `stateString`(KFSM 상태 이름: `Deployed`, `Retracted`, `Deploying...`, `Retracting...`, `Inoperable`), `position`(0~1).
- `ModuleEngines`(파생 포함): `EngineIgnited`, `flameout`, `staged`, `thrustPercentage`.

## 결정 (사용자 합의)

### 1. 상위 도구: 범용 비행 field 설정 1개

- `set_vessel_part_field`로 비행 중 PAW field를 바꾼다. 추력 제한, 낙하산 전개 고도·안전 전개 설정 등을 모두 이것으로 한다.
- 대칭 전파·범위 검사·잠금 판정은 게임 PAW 컨트롤(`uiControlFlight`)과 같게 한다.
- 용도별 도구(`set_thrust_limit`, `deploy_parachute` 등)는 두지 않는다. 낙하산 "안전할 때 전개"는 `automateSafeDeploy` 설정 후 `invoke_part_event`의 `Deploy`로 한다.

### 2. action group 도구: 조회 + 변경, 대상 그룹 Custom01~10·Light·Gear·Brakes·Abort

- `get_action_groups`: 모든 그룹(SAS·RCS·Stage 포함)의 상태·쿨다운·그룹에 묶인 부품 action 목록.
- `set_action_group(group, action)`: `action`은 `toggle`·`on`·`off`. 대상은 Custom01~10, Light, Gear, Brakes, Abort만이다. SAS·RCS는 기존 `set_sas`·`set_rcs`, Stage는 staging 의미가 달라 제외하고 400으로 거부한다.

### 3. override가 걸린 그룹: 기존처럼 거부

- 기존 `ManualControl.TrySetGroup` 경로를 쓴다. override 대상 그룹이면 409 `group_locked`, 쿨다운으로 바뀌지 않으면 409 `group_locked`(cooldown).
- 게임 키처럼 override 목록만 뒤집는 동작은 하지 않는다. 되돌릴 수 없는 상태를 만들지 않기 위해서다(`TrySetGroup` 주석과 같은 이유).

### 4. `get_vessel_parts` field 항목에 조작 정보 추가

- 각 field 행에 `editable`(bool)과 컨트롤 범위·선택지를 덧붙인다. 기존 키(`field`, `title`, `units`, `value`, `error`)는 그대로 둔다.
- 선택지는 `options`(현지화 표시 이름)이고, text field에는 넣을 원래 값 `option_values`를 함께 준다(계획 문서 검토 R1 반영: 표시 이름만으로는 text field에 넣을 값을 알 수 없다).

### 5. 자원 흐름 잠금: 별도 도구 `set_resource_flow`

- `set_resource_flow(part_id, resource, enabled)`. 게임처럼 그 부품 하나만 바꾼다. 흐름 버튼이 없는 자원(행이 없는 `maxAmount` 0·`!isVisible`, NO_FLOW, `hideFlow`)은 거부한다.
- 잠금 거부 코드는 `flow_locked`다(field가 아니므로 `field_locked`와 나눈다, 계획 문서 검토 R1 반영).

### 6. state 보강 대상 추가: 낙하산·조명·착륙 기어·엔진

- 1단계의 `ModuleDeployablePart`·`ModuleDockingNode`에 더해 위 "주요 상태 멤버"의 네 모듈 계열에 `state`를 넣는다. 언어와 관계없이 action group·field 변경 결과를 확인하기 위해서다.

## 도구·API

| MCP 도구 | HTTP | 비고 |
|---|---|---|
| `get_action_groups()` | `GET api/flight/action_groups` | 신규, 읽기 전용 |
| `set_action_group(group, action)` | `POST api/flight/action_group` 본문 `{group, action}` | 신규 |
| `set_vessel_part_field(part_id, module, field, value, module_index?)` | `POST api/flight/part_field` 본문 `{part_id, module, field, value, module_index}` | 신규 |
| `set_resource_flow(part_id, resource, enabled)` | `POST api/flight/resource_flow` 본문 `{part_id, resource, enabled}` | 신규 |
| `get_vessel_parts` | 기존 | field 행에 조작 정보, state 보강 대상 추가 |

모두 `Guard.ActiveVessel()`을 먼저 통과해야 한다(409 `not_in_flight`·`no_active_vessel`). 비행 계획 실행 여부는 검사하지 않는다(방안 결정 8). `set_action_group`은 EVA 기체에서 409 `eva_not_supported`(게임 키 처리도 EVA에서는 하지 않음, 기존 `RequireManual`과 같은 코드).

- land 계획 실행 중 Gear(계획 문서 검토 R1, 사용자 결정: 허용하고 설명에 적기): 착륙 모드는 기어를 한 번 펼친 뒤(`_gearDone`)에는 다시 펴지 않는다. 그 뒤 `set_action_group`으로 Gear를 끄면 계획은 기어 없이 착지한다. 막지 않고 도구 설명에 적는다.

### 입력 규칙

- `part_id`, `module_index`: 1단계 입력 규칙과 같다.
- `group`: `Custom01`~`Custom10`, `Light`, `Gear`, `Brakes`, `Abort`(대소문자 무시). `SAS`·`RCS`·`Stage`는 400(대신 쓸 도구를 메시지에). 그 밖의 이름은 400(허용 이름 목록을 메시지에).
- `action`: `toggle`·`on`·`off`. 아니면 400.
- `value`: JSON 숫자·bool·문자열. 변환 규칙은 editor `set_part_field`(`PartSettings.Convert`)와 같다.
- `enabled`: bool. 아니면 400.

### `get_action_groups` 응답

```json
{
  "vessel": "Lander-1", "id": 123,
  "override": 0,
  "groups": [{
    "group": "Gear", "on": false, "cooldown": 0.0, "settable": true, "locked": false,
    "actions": [{"part_id": 456, "part": "SmallGearBay", "module": "ModuleWheelDeployment", "index": 3, "action": "ActionToggle", "title": "Toggle Gear"}]
  }]
}
```

- 그룹 순서는 `KSPActionGroup` 비트 순서(Stage, Gear, Light, RCS, SAS, Brakes, Abort, Custom01~10)다. `None`과 `REPLACEWITHDEFAULT`는 넣지 않는다.
- `override`: `ADDITIONAL_ACTION_GROUPS`가 꺼져 있으면 0, 켜져 있으면 `vessel.GroupOverride`.
- `on`: `v.ActionGroups[group]`. `cooldown`: `CooldownTimeRemaining(group)`(초).
- `settable`: `set_action_group` 대상 그룹이면 true.
- `locked`: 그 그룹의 키 입력 잠금(위 표, 포커스 잠금 제외) 또는 override 대상이면 true. 대상 밖 그룹은 null.
- `actions`: 게임 `ToggleGroup`이 부를 목록과 같은 식(`BaseAction.CreateActionList(v.parts, group, n, overrideDefault, true)`)으로 고른다. 부품 수준 action은 `module: "Part"`, `index: null`. `action`은 `BaseAction.name`, `title`은 `guiName`.

### `set_action_group` 처리

1. `Guard.ActiveVessel()`, EVA면 409 `eva_not_supported`.
2. 인자 검사(입력 규칙).
3. 목표값: `toggle`이면 `!on`, `on`이면 true, `off`면 false. 현재와 같으면 잠금과 관계없이 아무것도 하지 않고 200(`changed: false`).
4. 바꿔야 할 때 그룹 키 잠금(포커스 잠금 제외)이 걸려 있으면 409 `group_locked`(`input_locked`, 조종 불가 잠금이면 메시지에 no control). (완료 전 검토 R1에서 3·4 순서를 바꿨다.)
5. `ManualControl.SetGroupChecked(v, group, want)` — override는 409 `group_locked`, 쿨다운으로 바뀌지 않으면 409 `group_locked`.
   - 그룹의 action이 예외를 던지면(게임 동작 참조) 실행 기록(`error` 포함)을 남기고 500 `action_failed`로 응답한다. 메시지에 예외와 실행 뒤 그룹 상태(`on`)를 넣는다. 그룹 상태는 이미 바뀌었을 수 있으므로 재시도 전에 `get_action_groups`로 확인하라고 도구 설명에 적는다.
6. 응답: `{group, action, before, on, changed, cooldown, actions, vessel_changed}`.
   - `actions`: 바뀐 경우 실행 직전에 `get_action_groups`와 같은 방식으로 고른 목록(실행된 action). 바뀌지 않은 경우(`changed: false`) 실행한 action이 없으므로 빈 배열.
   - `vessel_changed`: 실행 뒤 활성 기체 id가 실행 전과 다르면 true.

Undock·분리 action으로 활성 기체가 바뀌는 경우의 비행 계획 처리는 1단계와 같이 기존 `Coordinator` 처리를 따른다.

### `set_vessel_part_field` 처리

1. `Guard.ActiveVessel()`.
2. 인자 검사. `module`·`field`는 비어 있지 않은 문자열.
3. 부품·모듈 결정: `invoke_part_event` 4단계와 같다(`module: "Part"`는 부품 수준 `Part.Fields`). 단, 고른 모듈이 비활성이면 409 `field_not_editable`(`module disabled`)이다.
4. `Fields[field]`가 없거나 PAW 표시 규칙(`guiActive`, advanced tweakable)을 통과하지 못하면 404 `field_not_found`(메시지에 그 모듈의 표시 field 목록).
5. `uiControlFlight`가 없거나 `UI_Label`·`UI_ProgressBar`·`UI_ColorPicker`(색상 선택 창을 여는 컨트롤로 string 값 자체는 쓰이지 않음, 완료 전 검토 R1 반영)이거나 `!controlEnabled`이거나, field 타입이 값 변환이 지원하는 타입(bool, string, enum, float, double, int)이 아니면 409 `field_not_editable`.
6. 잠금: `requireFullControl`이면 `TWEAKABLES_FULLONLY`, 아니면 `TWEAKABLES_ANYCONTROL`(포커스 잠금 제외). 걸려 있으면 409 `field_locked`.
7. 값 변환·범위 검사: editor `PartSettings.Convert`·`CheckRange`를 그대로 쓴다(400).
8. 쓰기: 위 `SetFieldValue` 순서. 대칭 전파 조건은 `affectSymCounterparts & UI_Scene.Flight`. 쓴 뒤 `MonoUtilities.RefreshPartContextWindow`로 열린 PAW를 다시 그린다.
   - 쓰기·콜백 중 예외가 나면 실행 기록(`error`, 값을 쓴 대칭 부품 id, 자기 값 기록 여부 포함)을 남기고 500 `field_failed`로 응답한다. 메시지에 예외와 이미 값이 바뀐 부품 id를 넣는다. 열린 PAW 다시 그리기는 예외와 관계없이 한다.
9. 응답: `{part_id, part, module, index, field, old, value, changed, values: [{part_id, value}]}`. `values`는 그 부품과 대칭 부품에서 다시 읽은 값이다.

### `set_resource_flow` 처리

1. `Guard.ActiveVessel()`.
2. 부품을 찾는다(404 `part_not_found`). `part.Resources[resource]`가 없으면 404 `resource_not_found`(자원 목록을 메시지에).
3. `maxAmount == 0`, `!isVisible`, `info.resourceFlowMode == NO_FLOW` 또는 `hideFlow`면 409 `flow_not_toggleable`.
4. `TWEAKABLES_ANYCONTROL` 잠금(포커스 잠금 제외)이 걸려 있으면 409 `flow_locked`.
5. `flowState = enabled`. 응답: `{part_id, part, resource, before, flow_enabled}`.

### `get_vessel_parts` 추가 항목

- field 행: `editable`(`set_vessel_part_field` 5·6단계를 통과하면 true)과 컨트롤 정보
  - `UI_FloatRange`: `min`, `max`, `step`(`stepIncrement`)
  - `UI_FloatEdit`: `min`, `max`(`stepIncrement`가 없는 컨트롤이라 `step`은 넣지 않는다)
  - `UI_ScaleEdit`: `min`, `max`(intervals 양끝)
  - `UI_Toggle`: 추가 없음(bool)
  - `UI_Cycle`·`UI_ChooseOption`: `options`(`Localizer.Format`한 표시 이름 배열, `UI_ChooseOption`은 `display`가 없으면 `options`). string field에는 넣을 원래 값 `option_values`(`stateNames`·`options`)도 넣는다. int field는 `options`의 index를 넣는다는 것을 도구 설명에 적는다.
  - `editable`이 false면 범위·선택지 키를 넣지 않는다.
- state 보강
  - `ModuleParachute`: `{deployment_state, safe_state}`(enum 이름)
  - `ModuleLight`: `{on}`
  - `ModuleWheelDeployment`: `{wheel_state: stateString, position}`. `stateString`은 KFSM 상태 이름(`Deployed` 등)이라 `ModuleDeployablePart`의 `deploy_state`(enum 이름)와 값 형식이 달라 키를 따로 둔다.
  - `ModuleEngines` 계열: `{ignited, flameout, staged, thrust_limit}`
  - state가 생기면 표시 field·event가 없는 모듈도 목록에 나온다(1단계 `AddIfShown` 규칙 그대로).
- 자원 행: 기존 `flow_enabled`에 `flow_toggleable`(3단계를 통과하면 true)을 덧붙인다.

## 구조

### `ActionGroups` (신규, `src/KspBridge.Logic/Flight/ActionGroups.cs`)

- `List(Vessel v)`: `get_action_groups`
- `Set(Vessel v, RequestBody b)`: `set_action_group`. 변경은 `ManualControl.SetGroupChecked`만 쓴다.

### `PartStates` (변경)

- `SetField(Vessel v, RequestBody b)`: `set_vessel_part_field`
- `SetFlow(Vessel v, RequestBody b)`: `set_resource_flow`
- 모듈 결정(`FindTarget`)과 잠금 판정(`Unlocked`)을 event 실행과 같이 쓴다. 같이 쓰려고 모듈 결정 부분을 함수로 나누되, `invoke_part_event`의 응답·오류 코드·오류 문구는 바꾸지 않는다.
- `Fields`·`State`·`Resources`에 위 추가 항목.

### `PartSettings` (변경, editor)

- `Convert`·`CheckRange`를 `internal`로 바꿔 비행 field 설정이 같이 쓴다. editor 동작은 바꾸지 않는다.

### App 도구 (`src/KspBridge.App.Tools/FlightTools.cs`)

- `get_action_groups`(ReadOnly), `set_action_group`·`set_vessel_part_field`·`set_resource_flow`(Destructive). 설명에 응답 형식, 오류 코드, 대상 그룹, 낙하산 안전 전개 방법(field + `Deploy`), 계획 실행 중 기체가 나뉘면 계획이 중단될 수 있음, land 계획 중 Gear 변경을 계획이 되돌리지 않음, 500 실패 뒤에는 상태를 조회하고 재시도하라는 것을 적는다.
- `get_vessel_parts` 설명에 추가 항목을 적는다.
- `get_flight_events` 설명에 새 이벤트 종류와 data 형식을 추가한다.

### 실행 기록 (방안 결정 10)

- `set_action_group`: `FlightEvents.Add("action_group", step, {group, action, before, on, changed, actions, error})`. 실제로 바꾼 경우만 남긴다.
- `set_vessel_part_field`: `"part_field"`, `{part_id, part, module, index, field, old, value, counterparts, own, error}`(`counterparts`는 값을 쓴 대칭 부품 id, `own`은 자기 값을 썼는지). 바뀐 경우만.
- `set_resource_flow`: `"resource_flow"`, `{part_id, part, resource, before, flow_enabled}`. 바뀐 경우만.
- 500 실패(`action_failed`·`field_failed`)도 `error`를 넣어 남긴다. 성공 기록의 `error`는 null이다.
- step은 1단계와 같다(`Coordinator.Running ? Coordinator.StepIndex : -1`). 같은 내용을 `[KspBridge]` KSP.log 줄로 남긴다. 사전 검사 실패(4xx)는 남기지 않는다.

### 테스트

- App 테스트: 네 도구의 HTTP 경로·메서드·본문 직렬화(`FlightToolsTests`, 새 테스트 메서드), 도구 목록(`ExpectedTools`)에 네 도구 추가.
- 게임 실측(이슈 완료 조건 "부속 제어 실행·상태 반영" 포함)
  - 조명·착륙 기어·낙하산·엔진을 단 시험 기체를 발사대에서 쓴다.
  - `set_action_group` Light·Gear 토글 → `get_vessel_parts` state(`on`, `wheel_state`) 변화.
  - `set_vessel_part_field` 엔진 `thrustPercentage` → `thrust_limit` 변화. 대칭 전파는 컨트롤의 `affectSymCounterparts`에 따른다(`thrustPercentage`는 Editor만이라 비행 중에는 전파하지 않고, 조명 `blinkRate`처럼 Flight가 들어 있는 field는 전파한다).
  - 낙하산 `automateSafeDeploy`(advanced tweakable이 꺼져 있으면 `field_not_found`가 정상) 값 변경 → `Deploy` → `deployment_state`가 STOWED에서 바뀜. 발사대에서는 `deploymentSafeState`가 SAFE라서 field 값이 전개를 막는지는 확인할 수 없다. 이 판단은 게임 코드이므로 실측 범위 밖으로 기록한다. 펼친 낙하산은 되돌릴 수 없으므로 마지막에 한다.
  - `set_resource_flow` 탱크 연료 잠금 → `flow_enabled` false.
  - 거부 경로: `debug_input_lock`으로 `TWEAKABLES_ANYCONTROL`·`GROUP_LIGHTS` 잠금을 걸어 `field_locked`·`flow_locked`·`group_locked`(input_locked)와 `get_vessel_parts` `editable: false`·`get_action_groups` `locked: true`를 확인하고, 잠금을 풀어 원래대로 되는지 확인한다. 포커스 잠금은 세지 않는다는 것도 같이 본다(게임 창이 백그라운드인 상태에서 성공 경로가 동작).
  - 조종 불가 기체·override·쿨다운·`ambiguous_module`·계획 실행 중 분리는 MCP만으로 만들기 어렵다. 실측할 수 있는 기체가 없으면 미확인으로 기록한다.
  - Custom 그룹 실행은 그룹에 action이 배정된 기체에서 확인한다(editor 배정은 비범위이므로 배정된 craft가 필요). 없으면 실측 전에 사용자와 준비 방법을 정한다.
