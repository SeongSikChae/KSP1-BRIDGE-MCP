# KspBridge 발사 중계 — 인게임 소리 녹음 설계

방안: [0029-게임소리-방안.md](0029-게임소리-방안.md)

## 구성
- App(net10.0)만 바꿉니다. Logic과 Mod는 바꾸지 않습니다.
- 새 파일:
  - `Broadcast/ProcessLoopback.cs`: Windows 오디오 COM 인터롭과 캡처 루프
  - `Broadcast/GameAudioRecorder.cs`: `IGameAudioRecorder` 인터페이스와 구현. 시작·중지와 무음 채움을 담당합니다
- 바꿀 곳:
  - `BroadcastOptions`: `GameAudio`, `GameVolume`, `GameProcess`
  - `BroadcastSettings`: 같은 값 전달
  - `BroadcastSession`: 녹화 시작·중지와 함께 게임 소리 녹음을 시작·중지합니다. 상태 조회에 결과를 넣습니다
  - `FfmpegArgs.Compose`: 게임 소리 입력과 덕킹 필터를 추가합니다
  - `Program`: DI 등록
- 외부 패키지는 쓰지 않습니다. NAudio에는 프로세스 루프백 API가 없어서, 필요한 COM 인터페이스 몇 개만 직접 선언합니다.

## 프로세스 루프백 캡처 (`ProcessLoopback`)
- 활성화:
  ```
  ActivateAudioInterfaceAsync(L"VAD\\Process_Loopback", IID_IAudioClient,
      PROPVARIANT{VT_BLOB → AUDIOCLIENT_ACTIVATION_PARAMS{ActivationType=PROCESS_LOOPBACK,
          TargetProcessId=<KSP pid>, ProcessLoopbackMode=INCLUDE_TARGET_PROCESS_TREE}},
      completionHandler, out op)
  ```
  - 완료 핸들러는 `IActivateAudioInterfaceCompletionHandler`와 `IAgileObject`를 구현합니다.
  - `GetActivateResult`로 `IAudioClient`를 받고, 5초를 넘기면 실패로 봅니다.
- 초기화:
  - `IAudioClient.Initialize(SHARED, LOOPBACK | EVENTCALLBACK | AUTOCONVERTPCM, 200 ms, 0, WAVEFORMATEX{PCM, 2ch, 48000 Hz, 16-bit})`
  - 프로세스 루프백은 `GetMixFormat`을 지원하지 않아서 형식을 직접 지정합니다.
- 캡처:
  - `SetEventHandle`, `GetService(IAudioCaptureClient)`, `Start`로 시작합니다.
  - 전용 스레드가 이벤트를 기다리고 `GetNextPacketSize`, `GetBuffer`, `ReleaseBuffer`로 데이터를 꺼냅니다. `SILENT` 플래그가 붙은 패킷은 0으로 씁니다.
- KSP 프로세스는 `Process.GetProcessesByName(GameProcess)`로 찾습니다. 여러 개면 첫 번째를 씁니다.
- 실패 지점과 실패 이유:
  | 실패 지점 | 이유 |
  |---|---|
  | 프로세스 없음 | `game_process_not_found` |
  | 활성화 HRESULT | `activate_failed: 0x...` (장치 없음이나 OS 미지원) |
  | `Initialize` | `initialize_failed: 0x...` |
  - 어느 경우든 예외를 밖으로 던지지 않고 결과로 돌려줍니다.

## 무음 채움과 싱크 (`GameAudioRecorder`)
- 녹음을 시작한 시각 `audioStart`(`IClock` 초)를 기록합니다.
- 캡처 스레드는 100 ms마다 `expected = (clock.Now − audioStart) × 48000`을 계산합니다.
  - 지금까지 쓴 프레임이 `expected − 4800`(0.1초)보다 적으면 그 차이만큼 0을 씁니다. KSP가 소리를 내지 않는 구간을 채우기 위해서입니다.
  - 들어온 패킷은 그대로 씁니다.
- 중지할 때 `expected`까지 0을 채우고 WAV 헤더의 길이를 확정합니다.
- 합성할 때 게임 소리의 시작 오프셋은 `audioStart − zero`입니다. `zero`는 영상의 첫 프레임 시각입니다. 오프셋이 음수일 수 있어서 다음처럼 맞춥니다.
  - 양수면 `adelay=ms`
  - 음수면 `atrim=start=−offset`

## 합성 필터 (`FfmpegArgs.Compose`)
- 게임 소리가 있을 때(입력 인덱스 g):
  ```
  [g:a]aresample=24000,aformat=channel_layouts=mono,<adelay|atrim>,volume=<GameVolume>[game];
  <안내·비프 a1..aN>amix=inputs=N:normalize=0:dropout_transition=0,apad[nar];
  [nar]asplit=2[nar1][key];
  [game][key]sidechaincompress=threshold=0.02:ratio=8:attack=20:release=400[duck];
  [duck][nar1]amix=inputs=2:normalize=0:dropout_transition=0[aout]
  ```
  - 안내 음성(`key`)이 나올 때만 게임 소리가 약 1/8로 줄었다가 0.4초에 걸쳐 돌아옵니다.
- 게임 소리만 있고 안내가 없으면 `[game]apad[aout]`입니다.
- 출력 길이는 지금처럼 `-shortest`로 영상 길이에 맞춥니다.
- 오디오는 지금처럼 24 kHz 모노로 맞춥니다. 안내 음성 형식과 같게 하기 위해서이며, 게임 소리 스테레오는 모노로 합칩니다.

## 설정
```yaml
Broadcast:
  GameAudio: true          # KSP 프로세스 소리 녹음 (기본 true)
  GameVolume: 1.0          # 게임 소리 볼륨 (0..2)
  GameProcess: KSP_x64     # 프로세스 이름 (확장자 없음)
```
- `GameVolume`은 기존 `[Property(PropertyType.DOUBLE)]` 패턴으로 검증합니다. 범위를 벗어나면 기동 시 설정 오류로 처리합니다.

## 세션 연동
- `StartAsync`: 첫 프레임을 받아 `zero`를 잡은 직후, `GameAudio`가 true면 `gameAudio.Start(dir/game.wav, pid)`를 호출합니다.
  - 실패하면 `gameAudioError`를 기록하고 계속합니다.
  - 시작 응답에 `gameAudio: true/false`를 넣습니다.
- `StopAsync`: 화면 녹화를 멈춘 뒤 게임 소리 녹음을 멈춥니다. 이렇게 하면 게임 소리 길이가 영상 길이 이상이 됩니다.
- `DisposeAsync`: 서버가 종료될 때 게임 소리 녹음도 멈춥니다.
- `get_broadcast_status`에 `gameAudio`(bool)와 `gameAudioError`를 넣습니다.

## 구현 중 변경 (2026-11-08)
- **프로세스 확인**:
  - 사운드 장치가 없어도, 존재하지 않는 PID로도 활성화가 성공했습니다. 이때 무음 패킷이 실시간으로 계속 들어왔습니다(약 196 KB/s, 48 kHz × 4바이트와 일치).
  - 그래서 KSP가 실행 중인지는 녹음기가 `GetProcessesByName`으로 직접 확인합니다.
- **캡처 방식**: 이벤트 콜백(`EVENTCALLBACK`, `SetEventHandle`) 대신 10 ms 간격으로 패킷을 읽습니다. 무음을 채우는 쪽에서 시계를 기준으로 맞추므로 싱크에는 영향이 없습니다.
- **무음 채움 식**:
  - 설계에서는 `expected − frames − 0.1초`만큼 채우도록 했습니다. 이 식은 0.1초 뒤처진 상태를 계속 남깁니다.
  - 그래서 "차이가 0.1초를 넘으면 `expected`까지 채움"으로 바꿨습니다.
- **`unsafe` 미사용**: 패킷은 `Marshal.Copy`로 관리 버퍼에 복사합니다(프로젝트 설정 변경 없음).
- **덕킹 측정**:
  - 실제 ffmpeg로 게임 소리(300 Hz 사인파)만 따로 측정했습니다. 현재 값으로 안내가 나오는 동안 -21 dB에서 -41 dB로 약 20 dB 줄었습니다.
  - 세기는 실게임에서 들어 보고 조정합니다(결정 2).
- **실제 녹음기 실행**: 사운드 장치가 없는 상태에서 explorer를 대상으로 3초 동안 녹음했습니다. 흐른 시간 3.02초에 WAV 길이 3.03초였고, 형식은 48 kHz 16-bit 스테레오였습니다.
- **실게임 확인과 영상 싱크 수정**:
  - KSP 소리는 녹음됐습니다. `game.wav` 평균 -34 dB이고, 엔진 소리가 T-0 시각에 시작했습니다.
  - 그런데 영상이 시계보다 약 1.1초 늦었습니다. 점화 장면이 11.2초에 나왔고, 엔진 소리는 10.0초에 시작했습니다.
  - 원인: libx264 프레임 스레드가 약 1초 분량의 프레임을 쥐고 있어서, `frame=` 진행 줄의 프레임 수가 늦게 올라갑니다. 그래서 첫 프레임 시각(`zero`)이 늦게 잡혔습니다. 이 문제는 발사중계 기능에도 처음부터 있었습니다.
  - 녹화 인수에 `-tune zerolatency`를 넣었습니다. KSP 창을 단독으로 시험해 보니 진행 줄의 영상 시간이 경과 시간과 같았습니다(speed 1.0x). `raw.mkv`는 약 10% 커집니다.
  - 수정 후 실게임에서 다시 확인했습니다. T-0 명령은 10.55초, 엔진 소리는 10.75초, 화면의 첫 변화(G 계기)는 10.87초로, 소리와 화면의 차이가 0.12초였습니다. 화염이 눈에 띄게 커지는 것은 11.2초인데, 이는 KSP 화염 효과의 지연입니다.
- **게임 소리 크기**: 최종 영상에서 게임 소리가 평균 -31 dB로 작다는 사용자 의견을 반영했습니다. 설정 `GameVolume`을 2(+6 dB)로 올렸습니다. 코드의 기본값 1.0은 그대로 둡니다.
- **덕킹 설정 (사용자 요청)**: 결정 2의 덕킹 값을 설정으로 바꿀 수 있게 했습니다.
  - 키: `DuckThreshold`(0.001~1, 기본 0.02), `DuckRatio`(1~20, 기본 8, 1이면 끔), `DuckAttack`(ms, 0.01~2000, 기본 20), `DuckRelease`(ms, 0.01~9000, 기본 400)
  - 범위는 ffmpeg `sidechaincompress`가 받는 범위를 따릅니다. 범위를 벗어나면 기동할 때 설정 오류(종료 코드 2)로 처리합니다.
  - 코드에서는 `Ducking` 레코드로 `BroadcastSettings`와 `GameTrack`에 전달합니다.
- **`GameVolume` 상한 제거 (사용자 요청)**: 위의 "설정" 절에 적은 0..2 범위에서 상한 2를 없앴습니다. 0 이상만 검사합니다. 너무 크게 하면 소리가 깨질 수 있다는 점은 ReadMe에 적었습니다.
- **컴프레서와 리미터 (사용자 요청, 2026-11-08)**:
  - 게임 소리 체인: `...,<adelay|atrim>,acompressor=threshold=<10^(dB/20)>:ratio:attack:release,volume=<GameVolume>[game]`. 압축을 먼저 하고 볼륨을 나중에 적용합니다.
  - 최종 소리: 세 가지 경우 모두 섞은 결과를 `[mix]`로 내고, `[mix]alimiter=limit=0.891:level=0[aout]`를 붙입니다. -1 dBFS 리미터이고, 자동 레벨(level)은 끕니다.
  - 설정: `GameCompress`(기본 true), `CompThreshold`(dB, -60~0, 기본 -18, 사용자 지정), `CompRatio`(1~20, 기본 4), `CompAttack`(ms, 기본 5), `CompRelease`(ms, 기본 200). 범위를 벗어나면 설정 오류(종료 코드 2)로 처리합니다.
  - 측정(합성 신호: 엔진 소리 -39 dB와 0.5초 폭발음):
    - 엔진 소리는 그대로였습니다.
    - 폭발음 평균은 6.6 dB 줄었습니다.
    - `GameVolume` 6에서 기존 방식은 최고 0.0 dB(잘림)였고, 새 방식은 -1.0 dB였습니다.
  - 실제 합성과 같은 필터 체인(덕킹 포함)을 ffmpeg 9.0.1로 실행했고, 정상 종료했습니다.
