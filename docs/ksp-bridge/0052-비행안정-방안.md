# 비행안정 방안 — 3단계: 자세 제어기 진동

상위 방안: [0047-비행안정-방안.md](0047-비행안정-방안.md) 결정 3("토크 모델 보정", "3단계 설계 전에 2단계 감시로 진동을 실측해 원인을 확인하고 보정 내용을 확정한다"). 이슈 [#24](https://github.com/SeongSikChae/KSP1-BRIDGE-MCP/issues/24) 문제 1.

## 문제

- #15 실측: 조종면(`tailfin`)과 Skipper 짐벌을 함께 쓰는 기체가 상승 중 계속 흔들리고 롤이 -87°까지 돌아갔다. `execute_node` 기수 회전에서 오차가 172° → 5° → 36° → 6.5° → 14.8° → 0.17°로 넘나들었다.
- 2단계 실측(0051 "실측 결과", 0.2.54): 감시기 `oscillation` 경고가 다음 기체에서 났다.
  - StabU·StabH 스테이징 뒤 2단(LV-909 짐벌): 10 s 창 부호 전환 30회(약 1.5 Hz), 최대 각속도 약 0.1 rad/s, 자세 오차 진폭 약 0.5°.
  - StabR(반응휠만, 짐벌·조종면 없음) 고속 상승: 부호 전환 11~21회.
  - StabT(진공, 반응휠 + LV-909 짐벌) 선회 뒤.
  - 짐벌·조종면이 없는 기체에서도 나므로, 토크 모델 오차만으로는 설명되지 않는다.

## 현재 제어기 (`Flight/Control/AttitudeController.Steer`)

- 축마다 목표 각속도 `want = sign(err)·min(sqrt(2·alpha·|err|)·KStop, OmegaMax)`(`KStop` 0.8, `OmegaMax` 0.5 rad/s).
- `alpha = 가용 토크 / 관성모멘트`. 가용 토크는 모든 `ITorqueProvider`의 `GetPotentialTorque` 평균 크기 합(반작용휠·짐벌·조종면·RCS 구분 없음).
- 내부 루프: `e = want − ω`, `a = Kp·e + Ki·∫e`(`Kp` 4, `Ki` 0.4), 입력 `= −a/alpha`(±1 제한). 미분항 없음.

## 원인 후보

1. 오차 0 근처의 무한 이득: `sqrt` 곡선의 기울기가 오차 0에서 무한대라 목표 근처에서 리미트 사이클이 생길 수 있다. `alpha`가 큰 가벼운 기체일수록 심하다. 짐벌·조종면이 없는 StabR의 진동과 맞는다.
2. 토크 모델 오차(0047 추정): 짐벌 토크는 스로틀, 조종면 토크는 동압에 따라 크게 변하는데 그대로 합산해 `alpha`가 실제와 다르다.
3. 작동기 지연: 짐벌·반작용휠의 응답 속도와 물리 틱 지연으로 위상이 늦다.

## 결정

### 1. 측정 먼저: MCP 진단 도구 (사용자 합의)

- 원인을 가리기 전에 대책을 넣지 않는다(0047 결정 3 조건).
- 새 읽기 전용 진단 도구가 최근 수 초의 제어기 시계열을 MCP 응답으로 돌려준다. 내용은 축별 오차·각속도·목표 각속도·입력·가용 토크(제공자 종류별)·관성모멘트, 스로틀·동압이다. Player.log를 읽지 않고 MCP 응답만으로 판정한다(검증 방식 메모).
- 도구 형식·표본 주기·보관 길이는 설계에서 정한다.

### 2. 실측 기체 (사용자 합의)

| 기체 | 목적 |
|---|---|
| 조종면 + 짐벌 새 기체 | 이슈 완료 조건 대상(`gravity_turn` 상승) |
| StabU·StabH 2단 | 스테이징 뒤 짐벌 2단 진동 재현 |
| StabR(반응휠만) | 토크 모델과 무관한 원인 확인용 대조군 |
| StabT 궤도(진공) | 공력이 없는 조건의 대조군 |

### 3. 진행 순서

1. 진단 도구: 설계 → 개발 → 검토 → 구현(이 방안의 다음 문서).
2. 실측: 위 기체로 시계열을 모아 원인 후보 1~3을 판정하고 결과를 기록한다.
3. 보정: 판정된 원인에 맞춰 보정 설계를 따로 쓴다(후보: 0 근처 선형 구간, 짐벌·조종면 토크의 스로틀·동압 반영, 감쇠·지연 보상). 실측 근거 없는 보정은 넣지 않는다.

## 비범위

- 2단계 감시기 판정 변경(잔여 위험 처리는 별도).
- `gravity_turn` 프로파일 보정(#26).
- SAS·MechJeb 같은 외부 제어기 사용.

## 완료 조건 (3단계)

- 조종면 + 짐벌 기체의 `gravity_turn` 상승에서 진동이 사라지거나 줄어든다(감시기 `oscillation`·`plan.monitor` `sign_flips`로 전후 비교).
- 진공 선회(`execute_node`류)의 오버슈트가 줄어든다.
- `dotnet test tests/KspBridge.App.Tests` 통과.

판정:

1. **원인 1(오차 0 근처의 큰 이득): 확인.** 토크 모델이 맞는(`alpha_gain` 0.88~0.90) 진공의 가벼운 기체에서도 1.5 Hz 안팎, 0.4~0.7°의 리미트 사이클이 일관되게 난다. 진동 진폭에서 바깥 루프 이득(`want_slope_at_amp` 10~11 /s)이 안쪽 속도 루프 이득(`Kp` 4 /s)보다 2.5배 이상 크고, 여기에 2틱 지연이 겹친다. `alpha`가 작은 무거운 단(StabU 1단)은 진동이 거의 없다.
2. **원인 2(토크 모델 오차): 조종면에서 확인.** 휠·짐벌은 실측이 모델의 0.87~0.96배로 맞다. 조종면이 가용 토크의 대부분인 대기 구간(StabS)에서는 0.30~0.45배로, 모델이 실제보다 2~3배 크게 잡는다. 이슈 #15의 큰 진동(0.7 Hz, 2.8°)이 이 구간이다. 단위 4의 StabC처럼 전력이 0이어도 휠 토크를 그대로 세는 결함도 같은 계열이다.
3. **원인 3(작동기 지연): 확인.** 추가 지연은 휠 2틱, 무거운 짐벌 단 1틱, 대기 중 조종면 3~7틱. 조종면은 지연과 토크 과대평가가 함께 나타나며(편향 속도 제한으로 짧은 주기에서 목표 편향에 닿지 못하는 것으로 추정), 동압이 내려가면 둘 다 줄어든다.
4. **원인 밖: StabR.** 진동이 아니라 제어 능력 부족이다. 노즈콘 없는 기체의 공력 토크(`accel_bias` −1.14 rad/s²)가 휠 가용 각가속도(1.6~1.9)에 가까워 요 축이 끌려가다 뒤집혔다. 이 방안의 보정 범위가 아니다(상승 프로파일·동압 관리, #26).
