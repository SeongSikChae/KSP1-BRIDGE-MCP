# 기체전환 방안

이슈: [#19 비행 도구: 다른 기체로 전환](https://github.com/SeongSikChae/KSP1-BRIDGE-MCP/issues/19)

## 문제

MCP 도구는 활성 기체 하나만 다룬다. 궤도·다른 천체·지상에 이미 있는 기체(배치한 중계 위성, 분리한 상단, 랑데부 목표)로 제어 화면을 바꿀 방법이 없다.

- `list_vessels`는 FLIGHT 장면에서 활성 기체가 있을 때만 동작한다(`Guard.ActiveVessel`).
- `FlightGlobals.SetActiveVessel`, `FlightDriver.StartAndFocusVessel`은 코드 어디에서도 쓰지 않는다.
- 비행 계획은 제출한 기체의 `persistentId`에 고정된다. 활성 기체가 바뀌면 `vessel_changed`로 중단된다. 예외는 감시 중인 dock 단계의 결합 기체뿐이다(`Coordinator.Tick`, `FlightScene.OnVesselChange`).

## 목표

- 저장된 기체 목록을 비행 장면 밖에서도 조회한다.
- 기체 id로 그 기체를 활성 기체로 만든다.
- 전환 결과를 `get_status`·`get_flight`·`get_flight_events`로 확인한다.

## 결정 (사용자 합의)

### 1. 목록 조회: `list_vessels` 확장

새 도구를 만들지 않고 `list_vessels`를 Space Center·Tracking Station에서도 동작하게 한다.

- 비행 밖 장면에서도 게임이 불러 둔 기체 목록을 읽는다. 활성 기체가 없으므로 `active`는 false, `distance`는 null이다. 읽는 원본(`FlightGlobals.Vessels` 또는 저장 상태)은 설계에서 정한다.
- 목록과 전환(`switch_vessel`)은 같은 원본에서 기체를 찾는다. 목록에 나온 id는 전환에서도 찾을 수 있어야 한다.
- 기존 필드와 FLIGHT 장면의 응답은 바꾸지 않는다.

### 2. 실행 중인 비행 계획: 거부

비행 계획이 실행 중이면 전환 요청을 409 `plan_running`으로 거부한다. `abort_flight`를 먼저 호출해야 전환할 수 있다.

- 연소 중에 계획이 뜻하지 않게 중단되는 일을 막는다.
- revert·leave는 계획을 자동 중단하지만, 전환은 같은 비행을 이어 가는 동작이라 명시적 중단을 요구한다.

### 3. 전환 방식: 로드 범위로 분기

- 대상이 FLIGHT 장면에서 로드된 기체면 `FlightGlobals.SetActiveVessel`로 장면 재로드 없이 전환한다.
- 대상이 로드 범위 밖이거나 현재 장면이 비행 밖(Space Center·Tracking Station 등)이면 게임을 저장한 뒤 `FlightDriver.StartAndFocusVessel`로 그 기체의 비행 장면을 연다.

### 4. 시간 가속 중 전환: 1배속으로 낮추고 전환

시간 가속 중이면 전환 전에 1배속으로 낮춘 뒤 진행한다. 낮췄다는 사실을 응답에 표시한다.

### 5. 도구: `switch_vessel`

- 인자는 `vessel_id`(`list_vessels`의 `id`, persistentId)다.
- 기존 `set_target`과 같은 명명을 따른다.

### 6. 완료 판정: 즉시 accepted + `get_status` 폴링

launch·revert와 같은 패턴을 쓴다.

- 요청은 사전 검사를 통과하면 즉시 accepted를 돌려준다.
- 두 경로(재로드 없음·장면 재로드) 모두 `get_status`에 전환 상태(요청 대상, 진행·완료·실패, 오류 코드)를 둔다.
- 새 기체가 활성 기체가 되고 물리가 안정되면(unpacked) 완료로 표시한다. 정해진 시간 안에 완료되지 않으면 실패로 표시한다.
- 전환 시작·완료·실패를 `get_flight_events`에 남긴다.
- 완료 뒤 `get_flight`는 새 기체를 가리킨다.

### 7. 떠날 수 없는 상태의 기체를 남기는 전환: 거부

장면 재로드가 필요한 전환에서 현재 활성 기체가 대기권 안에서 비행 중이면(착륙·착수·궤도가 아님) 409로 거부한다.

- KSP는 대기권 안에서 레일 상태로 남겨진 기체를 삭제할 수 있다. 기체가 조용히 사라지는 일을 막는다.
- 판정은 stock 저장 가능 검사(`ClearToSave`)를 쓴다(설계 결정). 이 검사는 대기권 비행 외에도 가속 중(0.1g 초과), 지상 이동 중, 추락 직전, 사다리에 매달린 EVA를 함께 거부한다. 예: 궤도에서 수동으로 연소하는 중에는 로드 범위 밖 기체로 전환할 수 없다.
- 착륙·궤도 도달·회수 뒤에 전환한다.
- 재로드 없는 전환은 원래 기체가 로드 범위 안에 남으므로 이 검사를 하지 않는다.

### 8. 전환 대상 종류: Flag·SpaceObject 제외 전부

probe·ship·station·lander·rover·EVA·debris 등은 허용한다. 깃발(Flag)과 소행성 등(SpaceObject), 사라진 기체는 거부한다.

## 1차 범위

- `list_vessels`를 비행 밖 장면에서도 동작하게 확장
- `switch_vessel` 도구(로드 범위 안 전환, 장면 재로드 전환)
- 사전 검사: 실행 중인 계획, 대상 기체 존재·종류, 떠날 수 없는 상태의 현재 기체(재로드 전환), 장면 로드 중
- 시간 가속 1배속 낮춤
- `get_status` 전환 상태, `get_flight_events` 이벤트
- App 도구 정의·테스트

## 설계로 넘기는 항목

- `get_status`에서 전환 상태를 둘 위치와 필드 이름, 실패 오류 코드
- 장면 재로드 전환의 저장 방식(`persistent` 저장 여부)과 기존 `FlightReset` 장면 로드 추적 재사용 방식
- "대기권 안에서 비행 중" 판정 기준(situation, 고도·대기 높이)
- 완료 판정의 제한 시간
- reload(Logic 교체) 중에 진행 중인 전환 상태를 인계할지

## 비범위

- 실행 중인 비행 계획을 다른 기체로 넘기기(도킹 결합 인계는 기존 동작 유지)
- `[`/`]` 키 순환 전환, 지도 화면 선택
- 여러 기체를 동시에 조종
- 로드 범위(물리 범위) 설정 변경
