# KspBridge 비행제어 — 방안

## 문제·목표
KSP1에서 Claude가 우주선을 직접 만들고 조작하게 하려는 장기 목표의 1단계로, Claude가 게임 안 비행체의 상태를 읽고 조작할 수 있는 통로(게임 모드 + Claude용 MCP 서버)를 만든다.

## 환경
- KSP 1.12.5 (Steam): `F:\SteamLibrary\steamapps\common\Kerbal Space Program`
- GameData: Squad, SquadExpansion만 존재 (다른 모드 없음)
- 게임 런타임: Unity 2019.4 Mono → 모드 DLL은 **.NET Framework 4.7.2** 대상 (규칙 `dotnet/project-creation.md`의 net10.0 기본값에 대한 예외)
- 워크스페이스: `D:\Local\KSP\KSP1` (git 아님), .NET SDK 10.0.403

## 대안
| 대안 | 장점 | 단점 |
|---|---|---|
| **자체 모드 + MCP 서버** | 완전 통제, 필요한 기능만, 외부 모드 의존 없음 | 작업량 큼 |
| kRPC + MCP 래퍼 | 빠름 | kRPC 의존·버전 호환 확인 필요, 통제 제한 |
| 자체 모드만 (MCP 없음) | 단순 | Claude가 curl/스크립트로 호출해야 해 사용성 낮음 |

## 채택 방안: 자체 모드 + MCP 서버
```
Claude ──MCP(stdio)──> KspBridge.App (.NET 10) ──HTTP JSON (127.0.0.1:8085)──> KspBridge.Mod (KSP 플러그인, net472)
                                                                                  └ 메인 스레드 큐에서 KSP API 호출
```

### KspBridge.Mod (게임 플러그인)
- `[KSPAddon(KSPAddon.Startup.Flight, false)]` MonoBehaviour
- `HttpListener`를 백그라운드 스레드로 127.0.0.1에만 바인딩
- 요청은 `ConcurrentQueue`에 넣고 `Update()`에서 메인 스레드 실행 후 결과 반환 (KSP API는 메인 스레드 전용)
- 조회 (`FlightGlobals.ActiveVessel`): 고도, 지표/궤도 속도, 수직속도, Ap/Pe·도달 시간, 경사, 이심률, 주기, 천체, Situation, 질량, 자원(연료/전기), 현재 스테이지, SAS/RCS/스로틀, UT
- 조작: 스로틀(`FlightInputHandler.state.mainThrottle`), 다음 스테이지(`StageManager.ActivateNextStage`), SAS/RCS/액션그룹(`vessel.ActionGroups`), SAS 모드(`vessel.Autopilot.SetMode`)
- 기동 노드: `vessel.patchedConicSolver`로 노드 목록/추가(UT, prograde/normal/radial Δv)/삭제
- JSON: 스톡에 Newtonsoft가 없으므로 작은 자체 JSON writer/파서 (외부 DLL 의존 회피)
- 빌드 후 `GameData\KspBridge\Plugins\`로 복사 (KSP 경로는 MSBuild 속성 `KspDir`)

### KspBridge.App (MCP 서버)
- .NET 10 콘솔, stdio 전송, 공식 C# SDK `ModelContextProtocol` NuGet
- 도구: `get_vessel_state`, `set_throttle`, `activate_next_stage`, `set_sas`, `set_sas_mode`, `set_rcs`, `toggle_action_group`, `list_nodes`, `add_node`, `remove_node`
- 내부는 HttpClient로 모드 호출. 게임 미실행·비행 씬 아님 등은 명확한 오류 메시지로 반환
- 워크스페이스 `.mcp.json`에 등록해 Claude Code에서 사용
