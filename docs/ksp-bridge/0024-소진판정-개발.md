## 단위 1: 연료 판정 기준 (`EngineModel.HasPropellant`)

- **대상**: `EngineModel.HasPropellant(ModuleEngines e)`, 새 private `NeedPerTick(ModuleEngines e)`
- **코드 초안**:

```csharp
/// <summary>KSP's CheckDeprived at full throttle: every propellant but ignoreForIsp has at least ratio × one full-throttle tick
/// × ignitionThreshold above minResToLeave. thrustCurve engines also need the curve at the remaining fraction ≥ flameoutBar.</summary>
public static bool HasPropellant(ModuleEngines e)
{
    double need = NeedPerTick(e);
    double fraction = 1;
    List<Propellant> props = e.propellants;
    for (int i = 0; i < props.Count; i++)
    {
        Propellant p = props[i];
        if (p.ignoreForIsp)
        {
            continue;
        }
        e.part.GetConnectedResourceTotals(p.id, p.GetFlowMode(), out double amount, out double max);
        if (!(amount - p.minResToLeave >= p.ratio * need * e.ignitionThreshold) || !(amount > 0))
        {
            return false;
        }
        if (!p.ignoreForThrustCurve)
        {
            fraction = Math.Min(fraction, max > 0 ? amount / max : 0);
        }
    }
    return !e.useThrustCurve || e.thrustCurve.Evaluate((float)fraction) >= e.flameoutBar;
}

/// <summary>Propellant volume one full-throttle physics tick asks for (RequiredPropellantMass without FuelUsage).
/// flowMultiplier above 1 (velocity curves) raises KSP's need, so it counts; below 1 it is held at 1 (never under KSP's bar).</summary>
private static double NeedPerTick(ModuleEngines e) =>
    e.maxFuelFlow * e.thrustPercentage / 100 * Math.Max(1.0, e.flowMultiplier) * e.multFlow * TimeWarp.fixedDeltaTime * e.mixtureDensityRecip;
```

  - `!(amount > 0)`은 `need`가 0인 엔진(`maxFuelFlow` 0 등)에서 기존 판정(`amount > 0`)을 유지하기 위한 하한이다.
  - thrustCurve 남은 비율은 `Propellants`와 같은 규칙(`ignoreForThrustCurve` 제외)을 쓴다. 비율 계산을 공용으로 뽑지 않고 루프 안에서 같이 구한다.
- **검증**:

  - 발사 전 `get_flight`의 `ignitable_engines`가 기존 값과 같다(시험 기체 A 1, B 전체 엔진 수).
  - 기체 A를 연료 소진까지 연소: flameout 틱에 `ignitable_engines` 1 → 0(기존과 같음).
- **선행 단위**: 없음

## 단위 2: 소진·점화 가능 판정 (`Spent`, `Ignitable`)

- **대상**: `EngineModel.RefreshPropellant`(`_ignitable` 계산), `AutoStager.Spent`
- **코드 초안**:

```csharp
// RefreshPropellant: a flamed-out engine counts only while still ignited (KSP relights it; a shut-down one never comes back)
bool has = HasPropellant(es[i]);
_hasProp[es[i]] = has;
if (has && (!es[i].flameout || es[i].EngineIgnited))
{
    _ignitable++;
}

// AutoStager
/// <summary>Spent = (flameout && (no propellant || shut down)) || (staged && !EngineIgnited && no propellant).
/// A flamed-out ignited engine with propellant left is a pause KSP lifts itself (UnFlameout), never a burnout (#13).
/// allowRestart = false engines are shut down by Flameout unless allowShutdown = false (Shutdown returns at once).</summary>
private static bool Spent(Vessel v, ModuleEngines e) =>
    (e.flameout && (!e.EngineIgnited || !EngineModel.HasPropellantCached(e)))
    || (e.part.inverseStage >= v.currentStage && !e.EngineIgnited && !EngineModel.HasPropellantCached(e));
```

  - `SpentThrust`·`NextStageDecouplesFlamedOutEngine`·`BurnedOut`은 `Spent`를 그대로 부르므로 바꾸지 않는다. `SpentSideSrbBurning`의 `!e.flameout`은 "아직 타는 SRB" 판정이라 그대로 둔다.
  - `KeptHasEngine`은 `HasPropellantCached`를 쓰므로 단위 1로 기준이 바뀐다. 코드는 그대로.
  - 캐시 키(엔진 배열 키 + flameout된 `Ignited` 수 + `Ignited` 수)는 유지. 연료 있는 일시 flameout은 flameout 수를 바꿔 그 틱에 다시 계산되고, KSP의 해제도 같다.
- **검증** (`debug.cfg` 켠 상태, #7 디버그 도구):
  - 실제 소진(회귀): 0006 시험 기체 B로 `auto_stage` 계획 연소 → `stage_burnout` → `staged {reason: separate}` → `staging_completed` 순서가 기존과 같다.
  - 일시 flameout은 단위 3에서 검증한다(이 단위만으로는 엔진 하나뿐인 단에서 `no_thrust` 중단이 나는 것이 정상, 검토 R1 지적 1). 이 단위에서는 엔진이 둘 이상 타는 단(시험 기체 B 병렬 부스터)에서 연료 남은 코어 엔진 하나를 `debug_engine_stop {mode flameout}` → `stage_burnout`·`separate`가 없고 `ignitable_engines`가 줄지 않음을 확인한다.
  - TestHold 기체(#7 단위 5): 연료 없는 엔진 B(점화·flameout)가 남는 쪽에 있을 때 상단 엔진 C 점화 후 B가 분리되는 동작이 그대로다(B는 실제로 연료가 없음).
  - thrustCurve·`allowRestart = false` 경로는 스톡 부품이 없어 코드 리뷰로 확인한다.
- **선행 단위**: 단위 1

## 단위 3: 일시 정지 상태 (`paused`, `max_flameout_pause_s`, 스로틀 유지)

- **대상**: `AutoStager`(`StagingState.Paused`, `StateName`, `StagingOptions`, `Update`의 `None`·`Paused` 분기, 새 private `PausedEngine`), `Coordinator.ComputeCommand`
- **코드 초안**:

```csharp
public enum StagingState { None, Tailoff, Separate, Settle, Ignite, Paused }   // appended: handover saves the int
// StateName: case StagingState.Paused: return "paused";

// StagingOptions
public double MaxFlameoutPauseS;
// Default: ..., MaxFlameoutPauseS = 3
// Parse: UnknownKeys(..., "max_flameout_pause_s"), MaxFlameoutPauseS = Plan.OptionalNumber(o, "max_flameout_pause_s", path, 0, 600, Default.MaxFlameoutPauseS)

// Update, case None (after the latch check)
if (BurnedOut(v))
{
    // ... existing ...
}
else if (!EngineModel.AnyOperational(v) && PausedEngine(v))
{
    Enter(StagingState.Paused, ut);   // before the ignition entry: never fire the next stage over a pause
    Event("flameout_pause", v);
}
else if (t.PrevModeThrottle > 0 && !EngineModel.AnyOperational(v) && NextStageHasEngine(v))
{
    // ... existing ...
}
break;

case StagingState.Paused:
    if (EngineModel.AnyOperational(v))
    {
        FlightEvents.Add("flameout_resumed", Coordinator.StepIndex, new Dictionary<string, object>
        {
            ["stage"] = v.currentStage,
            ["pause_s"] = Math.Round(ut - _pauseUt, 3),
        });
        ResetSequence(ut);
    }
    else if (!PausedEngine(v))
    {
        ResetSequence(ut);   // the engine ran dry, shut down or left meanwhile: the regular checks run again this tick,
        if (!plan.AutoStage)
        {
            break;           // the top-of-Update guard: a plan without auto_stage never starts a new sequence
        }
        goto case StagingState.None;   // so a burnout or an ignition entry keeps Pending true before ComputeCommand looks
    }
    else if (!(t.PrevModeThrottle > 0))
    {
        _since = ut;         // no thrust wanted: KSP cannot relight at throttle 0 and no_thrust cannot fire, so the wait restarts
    }
    else if (ut - _since > o.MaxFlameoutPauseS)
    {
        EndWithLatch(v, "flameout_timeout", ut);   // Pending false: throttle > 0 then aborts with no_thrust
    }
    break;

/// <summary>An ignited flamed-out engine with propellant left: KSP relights it once the throttle asks for propellant.</summary>
private static bool PausedEngine(Vessel v)
{
    ModuleEngines[] es = EngineModel.Engines(v);
    for (int i = 0; i < es.Length; i++)
    {
        if (es[i].flameout && es[i].EngineIgnited && EngineModel.HasPropellantCached(es[i]))
        {
            return true;
        }
    }
    return false;
}
```

  - `pause_s`는 진입 시각부터 잰다. `_since`는 대기 타이머로 스로틀 0 동안 다시 시작하므로 진입 시각은 별도 `_pauseUt`(진입 때 기록, `ResetSequence`에서 0, `Save`/`Load`에 `pause_ut`)로 둔다.
  - 일시 정지 엔진이 없어진 틱에 `none`의 판정(래치 → `BurnedOut` → `paused` → 점화 진입)을 같은 틱에 다시 해야 `ComputeCommand`가 같은 틱에 `no_thrust`를 던지지 않는다(검토 R2 지적 1). `ResetSequence`는 `_state`를 `None`으로 두므로 `goto case`로 이어진다. 다만 `Update` 첫머리의 "`None`이고 `auto_stage` 거짓이면 return" 가드는 switch 앞에서만 걸리므로, `goto` 앞에서 같은 조건이면 `break`한다(검토 R3 지적 1). 이때는 `auto_stage:false` 계획의 평소 동작대로 작동 엔진이 없고 스로틀 > 0이면 `no_thrust`다.
  - `paused`는 `Pending`(`_state != None`)이 참이다. `Override`는 `Separate`·`Settle`만 스로틀 0이라 바꾸지 않는다.

```csharp
// Coordinator.ComputeCommand
if (cmd.Throttle > 0 && !EngineModel.AnyOperational(v))
{
```
