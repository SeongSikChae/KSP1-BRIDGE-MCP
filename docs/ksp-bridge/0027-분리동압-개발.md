# 분리동압 개발

방안 0025, 설계 0026. 바뀌는 코드는 `src/KspBridge.Logic/Flight/AutoStager.cs`와 `src/KspBridge.App.Tools/FlightTools.cs`(도구 설명)다. 로더는 바꾸지 않는다.

## 공통 규칙

- 배포는 `dotnet build` 뒤 `reload_mod`(Logic)·`reload_app`(App.Tools). 씬 전환·reload 전에 `get_status`로 다른 비행이 진행 중인지 확인한다.
- 검증은 MCP 응답(`get_flight`, `get_flight_events`, `get_status`)과 KSP.log로만 한다.
- 매 틱 경로는 할당 없이 둔다(`IsParallel`은 캐시 집합 순회).
- #13 단위 2~5는 이 작업 뒤에 한다. `Spent`·`HasPropellantCached`는 건드리지 않는다.

## 단위 1: 동압 대기 (`AutoStager`)

- **대상**: `StagingOptions`(`MaxSeparateQ`, `MaxSeparateQWaitS`), `Update`의 `case StagingState.Separate`, 새 필드 `_heldUt`, `Completed`, `ResetSequence`, `Save`/`Load`
- **코드 초안**:

```csharp
// StagingOptions
public double MaxSeparateQ;        // kPa: a parallel separation waits while the dynamic pressure is above this
public double MaxSeparateQWaitS;   // s: then it separates anyway (separation_forced)
// Default (unit 1): ..., MaxSeparateQ = 1000 (no hold: today's behaviour), MaxSeparateQWaitS = 30 (provisional); unit 2 sets both from measurements
// Parse: UnknownKeys(..., "max_separate_q", "max_separate_q_wait_s")
//   MaxSeparateQ = Plan.OptionalNumber(o, "max_separate_q", path, 0, 1000, Default.MaxSeparateQ),
//   MaxSeparateQWaitS = Plan.OptionalNumber(o, "max_separate_q_wait_s", path, 0, 600, Default.MaxSeparateQWaitS),

private static double _heldUt;     // UT the dynamic-pressure wait began (0: none)

case StagingState.Separate:
    if (_request == null)
    {
        if (!NextStageDecouplesFlamedOutEngine(v) || !KeptHasEngine(v))
        {
            EndWithLatch(v, "out_of_stages", ut);
            break;
        }
        if (_parallel)
        {
            _parallel = IsParallel(v);   // the core may run dry while the boosters wait
            if (!_parallel)
            {
                _since = ut;             // serial from here: the throttle-down wait starts now (design 2)
                _ticks = 0;
            }
        }
        if (_parallel && !HeldForQ(v, o, ut))
        {
            break;
        }
        if (!_parallel)
        {
            // ... existing serial throttle-down wait ...
        }
        _before = VesselIds();
        _request = new StageRequest();
    }
    // ... existing request tick ...

/// <summary>Parallel separation gate (#16): above max_separate_q a booster dropped into the airflow decelerates faster than the
/// decoupler pushes it aside and hits the core. True = separate now.</summary>
private static bool HeldForQ(Vessel v, StagingOptions o, double ut)
{
    double q = v.dynamicPressurekPa;
    if (!(q > o.MaxSeparateQ))
    {
        return true;
    }
    if (_heldUt == 0)
    {
        _heldUt = ut;
        QEvent("separation_held", v, q);
    }
    if (ut - _heldUt < o.MaxSeparateQWaitS)
    {
        return false;
    }
    QEvent("separation_forced", v, q);
    return true;
}

private static void QEvent(string type, Vessel v, double q) =>
    FlightEvents.Add(type, Coordinator.StepIndex, new Dictionary<string, object> { ["stage"] = v.currentStage, ["q_kpa"] = Math.Round(q, 3) });

// Completed: ["held_s"] = _heldUt > 0 ? Math.Round(ut - _heldUt, 3) : 0.0

// Separate, StageRequest.Result.Done: the separation's dynamic pressure goes with its staged event (design 3)
case StageRequest.Result.Done:
    _request = null;
    FlightEvents.Add("staged", Coordinator.StepIndex, new Dictionary<string, object>
    {
        ["stage"] = v.currentStage,
        ["reason"] = "separate",
        ["q_kpa"] = Math.Round(v.dynamicPressurekPa, 3),
    });
    // ... existing parallel / serial transition ...
```

  - `RecordSent`·`RecordHandedRequests`가 reload·중단 때 대신 남기는 `staged {reason: separate}`에도 같은 `q_kpa`를 넣는다(그 시점 동압).

  - `held_s`는 대기 시작부터 `staging_completed`까지다. 병렬은 분리 완료 틱에 `ignite`로 들어가 작동 엔진이 있어 곧바로 `Completed`되므로 분리 시각과 한두 틱 차이다. 직렬 전환 뒤에는 `settle`까지 포함된다(이 경우는 `settle_s`와 함께 읽는다).
  - `_heldUt`는 `ResetSequence`에서 0, `Save`의 `held_ut`, `Load`의 `Handover.D(d, "held_ut", 0)`.
  - `separation_forced` 뒤에 요청이 `Failed`면 기존처럼 `stage_failed` 래치다.
- **검증**:
  - `dotnet build` 오류 0, `reload_mod` 성공.
  - TestB, 옵션 생략(기본 1000): 지금과 같이 `stage_burnout` → `staged {separate, q_kpa ≈ 44}` → `staging_completed {held_s: 0}`, `separation_held` 없음.
  - TestB, `max_separate_q: 20`: `separation_held {q_kpa ≈ 44}` → `staged {separate, q_kpa ≤ 20}` → `staging_completed {held_s > 0}`. 대기 중 `get_flight.propulsion.staging`이 `"separate"`, 스로틀 1 유지(병렬이라 `Override` 0이 아님).
  - TestB, `max_separate_q: 1, max_separate_q_wait_s: 1`: `separation_held` → 약 1초 뒤 `separation_forced` → `staged {separate}`.
  - 제출 검증: `max_separate_q: -1` → `invalid_plan`.
- **선행 단위**: 없음

## 단위 2: 기본값 실측

- **대상**: `StagingOptions.Default.MaxSeparateQ`·`MaxSeparateQWaitS`
- **코드 초안**:

```csharp
public static readonly StagingOptions Default = new StagingOptions
{
    TailoffRatio = 0.05, MaxTailoffS = 5, SettleDistance = 2, MaxSettleS = 3,
    MaxSeparateQ = /* measured: highest collision-free − 5 */, MaxSeparateQWaitS = /* measured: held_s × 2, 5 s steps, ≥ 30 */,
};
```

  - 기준선: 먼저 `max_separate_q` 1000(지연 없음)으로 띄워 0026 "충돌 판정 기준"으로 충돌 있음이 나오는지 확인한다(오늘 1·2회차와 같은 SRB-코어 충돌). 안 나오면 측정을 멈추고 기준을 다시 정한다.
  - 측정: TestB 같은 계획(`gravity_turn target_apoapsis 80000` → `coast` → `circularize`, `auto_stage`)을 `max_separate_q` 40·35·30·25·20 순으로 띄운다(`max_separate_q_wait_s`는 120으로 넉넉히 둬 강제 분리가 섞이지 않게). 값마다 `staged.q_kpa`, `staging_completed.held_s`, `separation_forced` 유무, 0026 "충돌 판정 기준"의 충돌 유무를 표로 이 문서에 남긴다. 처음으로 충돌이 없는 값에서 2회 더 띄워 재현을 확인하고, 재현에서 충돌이 나면 다음 값으로 내려간다.
  - 표에는 값마다 `kind: part` 충돌 전부를 `part`·`other`·`vessel_id`·`active`·`speed`와 함께 남기고, 0026 기준으로 코어가 한쪽인 충돌인지(충돌 있음) 잔해끼리인지 표시한다. 버린 쪽 부품의 표시 이름은 `get_part solidBooster.v2`·`get_part radialDecoupler`의 `title`로 정하고, 기준선 비행 이벤트에서 그 부품들의 `vessel_id`가 활성 기체와 다른지(버린 쪽에 붙어 감) 확인한다.
  - 기본값: `max_separate_q` = 재현까지 충돌이 없는 가장 높은 값(X) − 5 kPa. 이어서 X − 5를 `max_separate_q_wait_s` 120으로 한 번 더 띄워 `held_s`를 재고, `max_separate_q_wait_s` = 그 `held_s` × 2를 5초 단위로 올림(최소 30). 이 비행에서 충돌이 나면 기본값을 5 kPa 더 내려(X − 10, X − 15 …) 같은 비행을 하되, X처럼 2회 더 띄워 재현까지 충돌이 없어야 그 값으로 확정한다. 15 kPa 아래로 내려가야 하면 멈추고 사용자에게 묻는다.
  - 기준선에서 버린 쪽 부품 확인: TT-38K의 `vessel_id`가 활성 기체와 같으면(코어에 남음) 버린 쪽 이름 목록에서 TT-38K를 빼고 판정한다. 기준선 이벤트에 TT-38K가 `part`로 나오지 않아 확인할 수 없으면 1회차 근거(`TestB 잔해물`)로 목록을 유지하고 그 사실을 표에 적는다.
  - 20까지 모두 충돌이 나면 측정을 멈추고 방안(코어 스로틀 등)으로 돌아갈지 사용자에게 묻는다.
- **측정 결과** (2026-11-14, TestB, `gravity_turn 80000` → `coast` → `circularize`, `max_separate_q_wait_s` 120). 버린 쪽 부품 표시 이름(`get_part` title): `RT-10 "해머" 고체연료 부스터`, `TT-38K 방사형 디커플러`. 기준선에서 TT-38K는 잔해 기체(`vessel_id` 3278133200, 활성 2192678543)에 붙어 감 → 목록 유지.
