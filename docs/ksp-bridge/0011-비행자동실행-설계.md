# KspBridge 비행 자동 실행 — 설계

선행: `0010-비행자동실행-방안.md`

사용자 결정: 별도 트리거, 동작 4종(스로틀·스테이지·자세 설정/해제·SAS/액션 그룹), 예측값에 공기 저항 포함

## 1. 예측값 (`GET /api/vessel`의 `prediction`, 트리거·wait_until 조건 필드로도 사용)
| 필드 | 의미 |
|---|---|
| `thrust_kn` | 활성 엔진의 현재 기압 최대 추력(추력 제한 반영) |
| `max_accel` | thrust/mass (m/s²) |
| `twr` | max_accel / 현재 위치 중력 |
| `drag_accel` | 측정 항력 가속도 = 측정 가속도 − 중력 − 현재 추력 가속도 (속도 반대 방향 성분) |
| `stop_time`, `stop_distance`, `stop_dv` | 지금 최대 추력으로 수직 하강을 멈추는 데 드는 시간·거리·Δv |
| `time_to_impact` | 추력 없이 지면 충돌까지 시간 |
| `burn_margin` | `altitude_terrain − stop_distance` (0 근처가 점화 시점) |

계산: 수직 1차원 수치 적분(dt 0.05s, 최대 600s)
- 중력: 고도별 GM/r²
- 질량: 연료 흐름(엔진 maxFuelFlow × 추력 제한)으로 감소, 연료 소진 시 추력 0
- 추력: 고도별 기압에서 엔진 Isp로 재계산
- 항력: `CdA = drag_accel × m / (½ρv²)`를 현재 상태에서 추정해 `½ρ(h)v²·CdA/m` 적용. ρ 작거나 속도 낮으면(동압 < 50Pa) 항력 0
- 하강 중이 아니면 stop_* 와 time_to_impact는 null
- 한계: 수평 속도·자세 변화 무시, 항력 계수 일정 가정 → 종료는 반드시 실제 상태 조건으로

## 2. 트리거
### HTTP
- `POST /api/triggers` `{name?, when:{field, op, value}, actions:[...], repeat:false}` → `{id, ...}`
- `GET /api/triggers` → `{triggers:[{id, name, when, actions, state: armed|fired|failed, fired_met, fired_value, error}]}`
- `DELETE /api/triggers/{id}`, `DELETE /api/triggers` (전체)
- 조건 필드: wait_until과 같은 필드(`altitude_asl`, `altitude_terrain`, `apoapsis`, `periapsis`, `time_to_ap`, `speed_surface`, `speed_vertical`, `met`, `situation`, `stage_flameout`) + 예측값 필드
- 동작
  - `{type:"throttle", value:0..1}`
  - `{type:"stage"}`
  - `{type:"attitude", mode:"own"|"sas", pitch, heading, roll?}`, `{type:"release_attitude"}`
  - `{type:"sas", on:bool}`, `{type:"action_group", group, on?}` (on 생략 = 토글)
### 실행
- 등록 시 활성 vessel에 묶음. 매 FixedUpdate(메인 스레드)에서 armed 트리거 조건 검사 → 만족한 그 tick에 동작을 순서대로 실행
- `repeat:false`(기본)는 한 번 실행 후 fired, true면 조건이 거짓→참이 될 때마다 실행
- 동작 실패는 해당 트리거 failed + error, 나머지 동작은 중단
- 활성 vessel 변경·장면 전환 시 모든 트리거 제거
- 기존 핸들러 로직 재사용(ControlHandler/AttitudeController/StageManager)

## 3. MCP 도구
| 도구 | HTTP |
|---|---|
| `add_trigger(when, actions, name?, repeat=false)` | POST /api/triggers (Destructive: 스테이징 등 실행) |
| `list_triggers()` | GET /api/triggers |
| `remove_trigger(id?)` | DELETE /api/triggers[/id] |
- `get_vessel_state` 설명에 prediction 추가, `wait_until` 필드 설명에 예측 필드 추가

## 4. 사용 예 (재진입 감속)
1. 상승: `add_trigger(apoapsis >= 80000 → throttle 0)` 후 스로틀 1
2. 하강: `add_trigger(burn_margin <= 300 → throttle 1)`, `add_trigger(speed_vertical >= -5 → throttle 0, stage)` 
3. Claude는 wait_until·list_triggers로 결과만 확인

## 5. 검증
- 단위 테스트: 도구→HTTP 매핑
- 게임: Flea로 `stage_flameout → stage`(낙하산), Hopper로 `apoapsis >= 목표 → throttle 0` 오차(목표 대비 Ap 초과 < 1km), 하강 `burn_margin` 점화·`speed_vertical >= -5` 차단 후 낙하산 전개
