# KspBridge 비행제어 — 설계

선행: `0001-비행제어-방안.md`

## 결정 목록
| # | 항목 | 결정 | 근거 |
|---|---|---|---|
| D1 | HTTP API 형태 | 기능별 경로 (`/api/...`) | curl 디버깅 쉬움, MCP 도구와 1:1 |
| D2 | 포트·인증 | `settings.cfg` 포트(기본 8085), 토큰 없음, 127.0.0.1만 바인딩 | 로컬 전용 |
| D3 | 스레드 모델 | 큐 + `Update()` 처리, 요청당 5초 타임아웃 | 일시정지 중에도 동작 |
| D4 | 공유 계약 | 공유 프로젝트 없음, 이 문서가 JSON 계약 | 프로젝트 수 최소 |
| D5 | 서버 수명 | `Startup.Instantly` + `DontDestroyOnLoad`로 게임 시작부터 상주, 비행 씬이 아니면 `not_in_flight` 오류 | 씬 전환마다 포트 재바인딩을 피하고, 연결 실패(게임 미실행)와 씬 문제를 구분 |
| D6 | App 템플릿 | 규칙 `dotnet/console-app-template.md` 적용, 단 **Serilog Console 싱크는 stderr로만** 출력 | stdio MCP는 stdout이 프로토콜 채널 |

> D5는 방안의 `Startup.Flight`를 바꾼 것이다. 검토에서 확인한다.

## 1. 구성 요소
```
Claude Code ──stdio(MCP)──> KspBridge.App.exe ──HTTP──> 127.0.0.1:{port} KspBridge.Mod.dll (KSP 프로세스)
```

### 1.1 KspBridge.Mod (net472)
| 파일 | 역할 |
|---|---|
| `KspBridgeAddon.cs` | `[KSPAddon(Instantly, true)]`, `DontDestroyOnLoad`, 설정 로드, 서버 시작/종료(`OnDestroy`), `Update()`에서 디스패처 펌프 |
| `Settings.cs` | `GameData/KspBridge/settings.cfg` (ConfigNode) 읽기. 없으면 기본값 |
| `HttpServer.cs` | `HttpListener` 백그라운드 스레드, 라우팅, 응답 작성 |
| `MainThreadDispatcher.cs` | `ConcurrentQueue<WorkItem>`; HTTP 스레드는 `Enqueue` 후 `ManualResetEventSlim.Wait(5s)`; `Update()`가 큐를 비우며 실행 |
| `Json/JsonWriter.cs`, `Json/JsonReader.cs` | 최소 JSON 직렬화/파싱(객체·배열·숫자·문자열·bool·null) |
| `Handlers/VesselHandler.cs` | 상태 조회 |
| `Handlers/ControlHandler.cs` | 스로틀·스테이지·SAS·RCS·액션그룹 |
| `Handlers/NodeHandler.cs` | 기동 노드 |

참조: `KSP_x64_Data/Managed`의 `Assembly-CSharp.dll`, `Assembly-CSharp-firstpass.dll`, `UnityEngine.dll`, `UnityEngine.CoreModule.dll` (Private=false). 경로는 MSBuild 속성 `KspDir`(기본 `F:\SteamLibrary\steamapps\common\Kerbal Space Program`). 빌드 후 `$(KspDir)\GameData\KspBridge\Plugins\`로 DLL 복사, `settings.cfg`는 `GameData\KspBridge\`로 복사.

`settings.cfg`:
```

    port = 8085

```

## 2. HTTP 계약

### 2.1 공통
- 요청·응답 `Content-Type: application/json; charset=utf-8`
- 성공: `{"ok":true,"data":{...}}` (HTTP 200)
- 실패: `{"ok":false,"error":{"code":"...","message":"..."}}`

| code | HTTP | 상황 |
|---|---|---|
| `not_in_flight` | 409 | 비행 씬이 아님 |
| `no_active_vessel` | 409 | 활성 비행체 없음 |
| `bad_request` | 400 | 본문 파싱 실패, 필드 누락·범위 오류 |
| `not_found` | 404 | 없는 경로, 없는 노드 index |
| `method_not_allowed` | 405 | 경로는 있으나 메서드가 다름 (검토 반영) |
| `timeout` | 504 | 5초 안에 메인 스레드 처리 안 됨 |
| `internal` | 500 | 처리 중 예외 (메시지에 예외 요약, KSP.log에 전체) |

- 단위: 거리 m, 속도 m/s, 시간 s, 각도 deg, 질량 t, 자원은 KSP 단위

### 2.2 엔드포인트
| 메서드 경로 | 본문 | 동작 |
|---|---|---|
| `GET /api/status` | - | `{"scene":"FLIGHT","has_active_vessel":true,"version":"0.1.0"}` (씬 무관하게 응답) |
| `GET /api/vessel` | - | 상태 조회 (2.3) |
| `POST /api/throttle` | `{"value":0.0~1.0}` | `FlightInputHandler.state.mainThrottle` |
| `POST /api/stage` | `{}` | `StageManager.ActivateNextStage()`, 응답에 새 `current_stage` |
| `POST /api/sas` | `{"enabled":true}` | `ActionGroups.SetGroup(KSPActionGroup.SAS, ...)` |
| `POST /api/sas/mode` | `{"mode":"prograde"}` | `Autopilot.SetMode(...)`; SAS 꺼져 있으면 켠 뒤 설정. 지원 안 되는 모드(레벨 부족 등) → `bad_request` |
| `POST /api/rcs` | `{"enabled":true}` | `KSPActionGroup.RCS` |
| `POST /api/action-group` | `{"group":"custom01"\|...,"action":"toggle"\|"on"\|"off"}` | `custom01~10, gear, light, brakes, abort` |
| `GET /api/nodes` | - | 노드 목록 (2.4) |
| `POST /api/nodes` | `{"ut":..}` 또는 `{"in_seconds":..}` + `{"prograde":..,"normal":..,"radial":..}` (기본 0) | `patchedConicSolver.AddManeuverNode(ut)` 후 `DeltaV = (radial, normal, prograde)`, `UpdateFlightPlan()`; 생성 노드 반환 |
| `DELETE /api/nodes/{index}` | - | 해당 노드 `RemoveSelf()` |

SAS 모드 문자열 ↔ `VesselAutopilot.AutopilotMode`: `stability_assist, prograde, retrograde, normal, antinormal, radial_in, radial_out, target, anti_target, maneuver`

### 2.3 `GET /api/vessel` data
```json
{
  "name": "Kerbal X", "situation": "FLYING", "ut": 12345.6, "met": 120.5,
  "body": "Kerbin",
  "altitude_asl": 10234.5, "altitude_terrain": 10200.1,
  "speed_surface": 450.2, "speed_orbital": 620.3, "speed_vertical": 120.4,
  "mass": 45.2,
  "orbit": { "apoapsis": 80000, "periapsis": -500000, "time_to_ap": 60.2, "time_to_pe": 900.1,
             "inclination": 0.1, "eccentricity": 0.9, "period": 1800, "sma": 300000 },
  "attitude": { "pitch": 45.0, "heading": 90.0, "roll": 0.0 },
  "control": { "throttle": 1.0, "sas": true, "sas_mode": "prograde", "rcs": false,
               "gear": false, "light": false, "brakes": false },
  "stage": { "current": 3, "count": 5 },
  "resources": [ { "name": "LiquidFuel", "amount": 300, "max": 360 } ]
}
```
- `apoapsis`/`periapsis`는 해수면 기준 고도(`orbit.ApA`, `orbit.PeA`). 탈출 궤도면 `apoapsis`·`time_to_ap`·`period`는 `null`
- `attitude`는 지표 기준(`vessel.srfRelRotation` 기반 계산), 정의는 개발 단계에서 확정
- `resources`는 비행체 전체 합계

### 2.4 노드 항목
```json
{ "index": 0, "ut": 13000.0, "time_to": 654.4,
  "prograde": 120.0, "normal": 0.0, "radial": 0.0, "delta_v": 120.0,
  "orbit_after": { "apoapsis": 80000, "periapsis": 75000, "body": "Kerbin" } }
```
- `orbit_after`는 노드 이후 궤도가 계산되지 않았으면 `null`, 탈출 궤도면 `apoapsis`가 `null`, `body`는 그 궤도의 기준 천체 (검토 반영)

## 3. 스레드·수명
1. 게임 시작 시 애드온 1회 생성, `DontDestroyOnLoad`. 포트 바인딩 실패 시 KSP.log에 오류만 남기고 게임은 계속
2. HTTP 스레드: 요청 수신 → 라우트 매칭 → 본문 파싱 → `WorkItem` 큐 등록 → 최대 5초 대기 → 결과 직렬화·응답. 타임아웃 시 `WorkItem`을 취소 표시해 늦게 실행되지 않게 한다
3. `Update()`: 큐의 모든 항목을 실행. 비행 씬·활성 비행체 확인은 핸들러 실행 직전에 메인 스레드에서
4. 게임 종료(`OnDestroy`/`OnApplicationQuit`): 리스너 Stop, 대기 중 요청에 `internal` 응답

## 4. MCP 도구 ↔ HTTP
| 도구 | HTTP | 인자 |
|---|---|---|
| `get_status` | `GET /api/status` | - |
| `get_vessel_state` | `GET /api/vessel` | - |
| `set_throttle` | `POST /api/throttle` | `value` (0~1) |
| `activate_next_stage` | `POST /api/stage` | - |
| `set_sas` | `POST /api/sas` | `enabled` |
| `set_sas_mode` | `POST /api/sas/mode` | `mode` (enum 문자열) |
| `set_rcs` | `POST /api/rcs` | `enabled` |
| `set_action_group` | `POST /api/action-group` | `group`, `action` |
| `list_maneuver_nodes` | `GET /api/nodes` | - |
| `add_maneuver_node` | `POST /api/nodes` | `ut` 또는 `inSeconds`, `prograde`, `normal`, `radial` |
| `remove_maneuver_node` | `DELETE /api/nodes/{index}` | `index` |

도구는 모드 응답의 `data` JSON을 그대로 텍스트로 반환하고, 실패는 `code: message`로 반환한다.
