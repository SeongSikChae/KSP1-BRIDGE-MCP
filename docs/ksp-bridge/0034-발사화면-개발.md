# KspBridge 발사대 화면 셋팅 개발 계획

선행: [0032-발사화면-방안.md](0032-발사화면-방안.md) · [0033-발사화면-설계.md](0033-발사화면-설계.md)

## 회귀 기록 (2026-11-08)
- 1차 구현(스테이지 창 강제 펼침 + 스테이지 상세 패널)은 인게임 확인에서 스테이지 모드 하단 패널이 메뉴버 패널을 덮었습니다.
- 방안 회귀: 메뉴버 모드만 쓰고, Δv는 Δv 앱으로 보여 줍니다. 단위 1만 바꾸고 단위 2·3은 그대로 둡니다(이미 구현·통과). 단위 3의 도구 설명 문구만 고칩니다.
- 2차 구현(메뉴버 모드 + Δv 앱 + 자원 창)은 인게임 확인에서 Δv 앱이 자원 창을 덮었습니다. 메뉴버 모드에서도 좌측 스테이지 창이 보이는 것을 확인했습니다.
- 방안 회귀 2: 메뉴버 모드 + 좌측 스테이지 상세 패널 + 자원 창. 스테이지 영역 강제 펼침과 Δv 앱은 쓰지 않습니다.

## 단위 1. Logic 처리부 `UiHandler`
- **대상**: `src/KspBridge.Logic/Handlers/UiHandler.cs`, `UiHandler.SetupLaunch()`
- **코드 초안**:

```csharp
return new Dictionary<string, object>
{
    ["maneuver_mode"] = Step(ManeuverMode),
    ["deltav_info"] = Step(DeltaVInfo),
    ["resources"] = Step(Resources),
};

private static void DeltaVInfo()
{
    StageManager s = StageManager.Instance;
    s.EnableDeltaVTotal(true);
    s.EnableDeltaVHeadings(true);
    s.EnableInfoPanels(true);
    s.ToggleInfoPanels(true);
}

private static void Resources()
{
    ResourceDisplay r = ResourceDisplay.Instance;
    if (r == null || r.appLauncherButton == null)
    {
        throw new InvalidOperationException("resource app is not ready");
    }
    if (!r.IsShowing)
    {
        r.appLauncherButton.SetTrue(true);
    }
}
```

- 지울 것: `OpenApp()`(배타 끄기 포함). `ManeuverMode()`, `Step()`은 그대로 둡니다.
- **검증**: `dotnet build src/KspBridge.Logic` 성공
- **선행 단위**: 없음

## 단위 4. 인게임 검증
- **대상**: 실행 중인 KSP(빌드가 `GameData/KspBridge/PluginData`에 배포)
- **절차**:
  1. `reload_mod` → `get_status`의 `version` 확인
  2. `revert_to_launch`로 UI를 처음 상태로 되돌림(점화하지 않음)
  3. `POST /api/ui/launch` 호출(MCP 서버 재시작 전이면 HTTP로 직접) → 세 항목 `ok` 확인
  4. KSP 창 클라이언트 영역만 PowerShell로 캡처해 확인: 좌측 하단 메뉴버 패널(Ap/Pe)이 다른 패널에 가리지 않음, 좌측 스테이지 상세 패널 보임, 우측 상단 자원 창 보임
  5. 발사대 비행체 회수(`recover_vessel`)
- **검증**: 세 항목 `ok`이고 화면 확인 통과. 실패하면 결과를 보고하고 방안으로 되돌림
- **선행 단위**: 3
