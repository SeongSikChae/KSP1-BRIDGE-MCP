# 소진판정 설계

방안: 0022-소진판정-방안.md (점화 엔진은 flameout이면서 연료가 없을 때만 소진, `ignitable_engines`도 같은 기준, 연료 있는 flameout은 상한까지 일시 정지 대기, 공기 부족도 일시 정지).

## KSP 동작 (KSP 1.12 `ModuleEngines` 디컴파일 확인)

| 항목 | 동작 |
|---|---|
| 추진제 부족 flameout | `RequestPropellant(massFlow)` → `CheckDeprived`: 추진제마다 `totalResourceAvailable < ratio × (massFlow × mixtureDensityRecip) × ignitionThreshold`면 `Flameout`. `totalResourceAvailable = max(0, 연결 잔량 − minResToLeave)`. `ignitionThreshold` 기본 0.1(RAPIER 공기 모드 0.33) |
| 한 틱 필요 질량 | `massFlow = RequiredPropellantMass(currentThrottle) × FuelUsage`, `RequiredPropellantMass = maxFuelFlow × throttle × flowMultiplier × multFlow × fixedDeltaTime`. `currentThrottle`은 `thrustPercentage`를 포함한다 |
| 자동 해제 | `CheckDeprived`가 거짓이면 매 틱 `UnFlameout()`. `EngineIgnited`가 참이어야 하고 스로틀 0 틱(`num3 == 0`)은 판정을 건너뛰어 flameout이 그대로 남는다 |
| 다시 켜지지 않음 | `Flameout`에서 `allowRestart == false`면 `Shutdown()`. `Shutdown`은 `allowShutdown == false`면 바로 반환한다. 실제로 꺼진 엔진(`EngineIgnited` false)은 `CalculateThrust`가 돌지 않아 해제되지 않는다 |
| 유량 배수 flameout | `flowMultiplier < flameoutBar`면 `Flameout`(잔량 무관). thrustCurve 엔진은 남은 연료 비율로 곡선이 내려가 이 경로로 꺼지면 다시 켜지지 않는다 |
| IntakeAir | 일반 PROPELLANT라 `CheckDeprived`에 들어간다. 스톡 제트·RAPIER 공기 모드 cfg는 모두 `ignoreForIsp = True` |
| 비활성 탱크 | `GetConnectedResourceTotals`는 flowState가 false인 탱크를 잔량·용량에서 뺀다 |

`amount > 0` 기준은 잔량이 한 틱 필요량의 10% 미만으로 남은 채 꺼지는 경우(부동소수 잔여, 다른 엔진과 공유한 탱크, `minResToLeave`)를 "연료 있음"으로 본다.

추력 없음 규칙(`Coordinator.ComputeCommand`): Mode 스로틀 > 0이고 작동 엔진이 없으면 `StagingPending`이 거짓일 때 `no_thrust`로 중단하고, 참이면 스로틀을 0으로 눌러 자세만 유지한다.

## 결정

| # | 결정 | 근거 |
|---|---|---|
| 1 | `EngineModel.HasPropellant(e)`를 KSP 기준으로 바꾼다. `ignoreForIsp`가 아닌 추진제마다 `연결 잔량 − minResToLeave ≥ ratio × need × ignitionThreshold`이고 잔량 > 0. `need = maxFuelFlow × thrustPercentage/100 × max(1, flowMultiplier) × multFlow × fixedDeltaTime × mixtureDensityRecip`(최대 스로틀 한 틱 필요 부피). thrustCurve 엔진(`useThrustCurve`)은 추가로 `thrustCurve(남은 비율) < flameoutBar`면 연료 없음(`EngineModel`의 SRB 곡선 식과 같은 남은 비율) | flameout 순간 `currentThrottle`이 0이라 최대 스로틀로 계산한다. 낮은 스로틀로만 탈 잔량은 소진으로 본다. `flowMultiplier`가 1보다 크면(속도 곡선 엔진) KSP 기준이 높아지므로 반영하고, 1 미만이면 1로 둬 우리 기준이 KSP보다 낮아지지 않게 한다(검토 R1 지적 3). `FuelUsage`는 스톡 기본 1이라 뺀다 |
| 2 | 다 쓴 엔진: `Spent = (flameout && (!HasPropellant \|\| !EngineIgnited)) \|\| (staged && !EngineIgnited && !HasPropellant)` | flameout이면서 실제로 꺼진 엔진(`allowRestart = false`이고 `allowShutdown = true`)은 연료가 있어도 다시 켜지지 않는다. `allowShutdown = false`(SRB)는 점화 상태로 남아 KSP가 해제한다(검토 R1 지적 2). 미점화 항은 유지 |
| 3 | 같은 `HasPropellant`를 지금 쓰는 모든 곳에 그대로 쓴다: `Spent` 두 항, `KeptHasEngine`, `Ignitable`. `Ignitable = Σ ((!flameout \|\| EngineIgnited) && HasPropellant)` | 판정 기준 하나(방안 결정 2). 연료 있는 일시 flameout 엔진은 점화 가능으로 센다 |
| 4 | `HasPropellantCached` 캐시 키(엔진 배열 키 + flameout된 `Ignited` 수 + `Ignited` 수)는 유지 | 연료 고갈 flameout·KSP 해제 모두 flameout 수를 바꿔 그 틱에 다시 계산된다. 추가 자원 조회 없음 |
| 5 | 일시 정지 엔진 = `flameout && EngineIgnited && HasPropellantCached`. 스테이징 상태 `paused`(`StagingState.Paused`, 조건 변수 `staging` 값 `"paused"`)를 둔다. `none`에서 `BurnedOut`이 거짓이고, 작동 엔진이 없고, 일시 정지 엔진이 있으면 `paused`로 들어가고 `flameout_pause {stage}` 이벤트를 낸다. 판정 순서는 `BurnedOut` → `paused` 진입 → 기존 점화 진입 | `Pending`이 참이 되어 `no_thrust`가 나지 않고, 점화 진입보다 먼저라 다음 스테이지를 작동시키지 않는다. 작동 엔진이 하나라도 있으면 추력 없음 규칙에 걸리지 않으므로 들어가지 않는다 |
| 6 | `paused`에서 작동 엔진이 생기면(KSP 해제) `flameout_resumed {stage, pause_s}`를 내고 `none`으로 돌아간다. 일시 정지 엔진이 없어졌는데 작동 엔진도 없으면(그 사이 실제 소진·종료·부품 소실 등) 이벤트 없이 `none`으로 돌아가 같은 틱에 `none`의 판정을 다시 한다(계획의 `auto_stage`가 거짓이면 다시 판정하지 않는다: `none`에서 새 시퀀스를 시작하지 않는 기존 규칙). 대기 시간은 Mode 스로틀 > 0(지난 틱)인 동안만 재고, 스로틀 0이면 다시 시작한다. 스로틀 > 0이 `max_flameout_pause_s` 이어지면 `flameout_timeout`으로 래치를 걸고 끝낸다(`out_of_stages`와 같은 래치) | 같은 틱에 다시 판정해야 그 틱의 추력 없음 규칙에 걸리지 않는다(검토 R2 지적 1). 스로틀 0에서는 KSP가 해제할 수 없고 `no_thrust`도 나지 않으므로 기다릴 시간에 넣지 않는다. 래치 뒤 `Pending`이 거짓이라 Mode가 스로틀 > 0을 원하면 그 틱에 `no_thrust`. 래치는 스테이지나 점화 엔진 집합이 바뀔 때까지 다시 감지하지 않아 이벤트가 반복되지 않는다 |
| 7 | `staging_options.max_flameout_pause_s`: 기본 3, 범위 0~600(다른 시간 항목과 같은 범위) | 사용자 결정(계획마다 조절). KSP는 연료가 있으면 다음 틱에 해제하므로 3초면 충분하다 |
| 8 | `Coordinator.ComputeCommand`는 스테이징 상태가 `paused`면 작동 엔진이 없어도 스로틀을 0으로 누르지 않고 Mode 값을 그대로 보낸다. `AutoStager.Override`는 `paused`에서 스로틀을 바꾸지 않는다 | KSP는 스로틀 0 틱에 해제 판정을 건너뛴다. 연료 있는 엔진이 다시 켜질 수 있게 스로틀을 유지한다 |

## 영향

- `AutoStager.Spent`의 판정이 바뀌어 `BurnedOut`, `SpentThrust`(tailoff), `NextStageDecouplesFlamedOutEngine`에 함께 적용된다.
- 공기를 잃은 제트 엔진(연료 있음)은 분리하지 않고 `paused` → `flameout_timeout` → (스로틀 > 0이면) `no_thrust`가 된다(방안 결정 4).
- 0005-비행제어-설계.md: `ignitable_engines` 설명, "연료 있는 엔진" 문단, "엔진 집합" 표의 `Spent` 행과 아래 설명, `staging_options` 행·예시, 스테이징 상태 표(`paused` 행), 이벤트 표(`flameout_pause`·`flameout_resumed`·`flameout_timeout`), 결정 31·49를 새 정의로 고친다.
- `submit_flight_plan` 도구 설명(`src/KspBridge.App.Tools/FlightTools.cs`)과 ReadMe의 `staging_options` 기본값 목록에 `max_flameout_pause_s 3`을 넣고, `get_flight_events` 도구 설명의 이벤트 종류 목록에 `flameout_pause`·`flameout_resumed`·`flameout_timeout`을 넣는다. `ignitable_engines`를 설명하는 도구 설명·ReadMe 문구는 없다.
- 0020-디버그도구-개발.md: `debug_engine_stop {flameout}`으로 연료 남은 엔진의 소진을 앞당기는 절차와 TestD `flameout` 결과(`stage_burnout` → `separate`)는 이번 변경으로 기대 결과가 바뀐다는 주석을 단다(검토 R1 지적 4).

## 검증

- 실제 소진: 0006 burnout·tailoff·separate 시험 기체로 `stage_burnout` → `separate` → `staging_completed`가 그대로 나온다.
- 일시 flameout(TestD, #7 단위 5 `flameout`과 같은 기체): 연료가 남은 하단 엔진에 `debug_engine_stop {mode flameout}` → `flameout_pause` → `flameout_resumed`(또는 기록), `stage_burnout`·`separate` 없음, 계획 계속.
- 대기 상한: 스로틀 > 0인데 연료 남은 flameout이 풀리지 않는 경우 `flameout_timeout` 1회 뒤 `no_thrust`. 스로틀 0 단계에서는 `paused`가 유지되고 `flameout_timeout`이 나지 않는다. 재현 방법은 개발에서 정한다.
- `ignitable_engines`: 일시 flameout 직후 줄지 않는다.
- TestHold 기체(#7 단위 5): 연료 없는 엔진 B는 지금처럼 분리된다.
- thrustCurve·`allowRestart = false` 경로는 스톡 부품이 없어 코드 리뷰로만 확인한다.
- App 테스트(`dotnet test tests/KspBridge.App.Tests`) 통과.
