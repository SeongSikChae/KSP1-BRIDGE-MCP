# 시간 가속 도구 개발 계획

이슈 #5. 사용자가 키로 하는 시간 가속 조작(배율 설정, 물리 가속 전환, 가속 중지)을 명령으로 재현하고, 실제 가속 상태를 `get_flight`로 읽는다. 목적은 두 가지다.

- 비행 계획의 `coast` 가속(0006 단위 9)과 사용자 조작의 상호작용(사용자 취소 래치, 사용자 물리·레일 가속 유지)을 화면·키 입력 없이 MCP로 검증한다.
- AI가 계획 밖에서 시간을 보낼 때(궤도 대기 등) 쓸 수 있게 한다.

사용자 지시("이슈 등록 후 구현")로 방안·설계를 건너뛰고 개발 계획부터 잡는다.

## 공통

- 이 도구는 계획의 `Warp.Request`를 거치지 않는다. 계획 쪽(`Warp`)에서는 사용자 조작과 구별되지 않는다. 그래서 `Warp.Requested`를 바꾸지 않고, 계획이 건 가속을 이 도구로 내리면 사용자 취소와 같게 래치가 걸린다(0005 "시간 가속" 규칙 그대로).
- 키 입력과 같은 게임 경로를 쓴다(`TimeWarp` 디컴파일 확인).
  - 중지(`TIME_WARP_STOP` 키): `CancelAutoWarp()` → `setRate(0)`. 키는 `autoWarpEngaged`일 때만 취소되므로, 시작 전(`setAutoWarp`만 켜진 프레임)의 WarpTo도 막도록 `setAutoWarp = false`를 먼저 둔다(`Warp.Stop`과 같은 순서).
  - 물리 가속 전환(Alt+`.`): private `bool setMode(Modes)`(배율이 0일 때). 반환값이 false면 거부(409). 레일로 돌아갈 때 `setMode(Modes.HIGH)`.
  - 배율: public `TimeWarp.SetRate(index, instant: true)`. 키 입력은 한 단계씩 보간해 올리지만, 도구는 목표 단계로 바로 정한다(차이: 중간 단계 메시지·보간 없음). 게임이 고도·가속도 한도로 더 낮은 배율을 쓸 수 있으므로 응답은 요청값이 아니라 그 시점의 실제 값이고, 한도가 다음 Update에 적용될 수 있어 검증은 `get_flight`로 다시 읽어 비교한다.
  - WarpTo(계획 또는 사용자)가 대기·진행 중(`Warp.Pending`)이면 배율 변경(rate > 0)은 409 `warp_to_running`. 사용자 키도 WarpTo 중에는 배율을 바꾸지 못하고 중지만 된다(autoWarp 코루틴이 배율을 덮어씀). 중지(rate 0)는 언제나 허용.
- 메인 스레드 라우트(기존 Route 방식). 비행 씬·활성 기체가 없으면 `Guard.ActiveVessel()`의 기존 오류.
- `get_flight.plan.warp`는 단위 9대로 `Warp.On`(실제 레일 가속. 사용자가 건 레일 가속 포함)이다. 계획이 건 것인지는 `warp_started`·`warp_stopped` 이벤트로 본다. 새 `time_warp` 묶음은 계획과 무관한 전체 상태다.

## 작업 단위

### 1. Logic: `TimeWarpControl`·라우트·`get_flight.time_warp`

- **대상**: `Flight/TimeWarpControl.cs`(새 파일), `Flight/Warp.cs`(`Pending`을 `internal`로), `Handlers/FlightHandler.cs`(`POST /api/time_warp`), `Flight/Coordinator.cs`(`Describe`에 `time_warp` 묶음), `Routes.cs`(Version)
- **코드 초안**:

```csharp
public static class TimeWarpControl
{
    // Looked up by parameter type (no AmbiguousMatchException at type init); null is checked where it is used.
    private static readonly MethodInfo SetModeMethod = typeof(TimeWarp).GetMethod("setMode",
        BindingFlags.Instance | BindingFlags.NonPublic, null, new[] { typeof(TimeWarp.Modes) }, null);

    /// <summary>Like the player's keys: 0 stops (a pending or running warp-to too); otherwise switches rails/physics at rate 0 and sets the rate.</summary>
    public static object Set(int rateIndex, bool physics)
    {
        TimeWarp w = TimeWarp.fetch ?? throw new ApiException(409, "not_available", "time warp is not available");
        if (rateIndex == 0)
        {
            w.setAutoWarp = false;   // a WarpTo that has not started yet
            w.CancelAutoWarp();
            TimeWarp.SetRate(0, true);
            return Describe();
        }
        if (Warp.Pending) throw new ApiException(409, "warp_to_running", "a warp-to is running; stop it with rate_index 0 first");
        TimeWarp.Modes mode = physics ? TimeWarp.Modes.LOW : TimeWarp.Modes.HIGH;
        float[] rates = physics ? w.physicsWarpRates : w.warpRates;
        if (rateIndex < 0 || rateIndex >= rates.Length) throw ApiException.BadRequest("rate_index must be an integer in [0, " + (rates.Length - 1) + "]");
        if (TimeWarp.WarpMode != mode)
        {
            if (SetModeMethod == null) throw new ApiException(409, "not_available", "switching rails/physics warp is not available");
            if (TimeWarp.CurrentRateIndex > 0) TimeWarp.SetRate(0, true);   // the game switches only at a low rate
            if (!(bool)SetModeMethod.Invoke(w, new object[] { mode }))
                throw new ApiException(409, "mode_switch_refused", "the game refused to switch to " + (physics ? "physics" : "rails") + " warp");
        }
        TimeWarp.SetRate(rateIndex, true);
        return Describe();
    }

    /// <summary>get_flight.time_warp and the set_time_warp result.</summary>
    public static Dictionary<string, object> Describe() => new Dictionary<string, object>
    {
        ["mode"] = TimeWarp.WarpMode == TimeWarp.Modes.LOW ? "physics" : "rails",
        ["rate_index"] = TimeWarp.CurrentRateIndex,
        ["rate"] = (double)TimeWarp.CurrentRate,
        ["auto_warp"] = Warp.Pending,   // warp-to (ours or the user's) pending or running
    };
}
```

```csharp
// FlightHandler: rate_index must be an integer (2.7 or 1e12 is 400, not truncated)
yield return new Route("POST", "/api/time_warp", (m, b, q) =>
{
    Guard.ActiveVessel();
    double r = b.GetDouble("rate_index");
    if (r != Math.Floor(r) || r < 0 || r > 100) throw ApiException.BadRequest("rate_index must be an integer in [0, 100]");
    return TimeWarpControl.Set((int)r, b.Has("physics") && b.GetBool("physics"));
});
```

- `get_flight`: 최상위에 `time_warp` 묶음(`plan`과 별도. 계획이 없어도 나옴).
- **검증**:
  - 궤도의 기체: `set_time_warp {rate_index: 3}` → 응답 `mode rails`, `rate_index 3`; 이어서 `get_flight.time_warp`가 같음. `{rate_index: 0}` → `rate_index 0`.
  - `{rate_index: 2, physics: true}` → `mode physics`, `rate_index 2`. 이어서 `{rate_index: 3}` → 레일로 바뀜.
  - 대기권 안 레일 요청 → 게임이 막아 실제 `rate_index`가 요청보다 낮음(응답과 뒤이은 `get_flight` 둘 다 확인, 오류 아님).
  - `rate_index` 범위 밖·정수 아님(2.5) → 400. 모드 전환 거부는 `setMode`가 false인 경우로 409(재현이 어렵다면 코드 리뷰).
  - 계획 `coast` WarpTo 진행 중 `{rate_index: 3}` → 409 `warp_to_running`, 가속 상태 변화 없음.
  - `submit_flight_plan` 직후(WarpTo가 `setAutoWarp`만 켠 프레임)와 진행 중에 `{rate_index: 0}` → 가속이 시작되지 않거나 멈추고 `auto_warp` false.

### 2. App: `set_time_warp` 도구

- **대상**: `src/KspBridge.App.Tools/FlightTools.cs`
- **코드 초안**:

```csharp
[McpServerTool(Name = "set_time_warp", Destructive = true)]
[Description("Set time warp like the player's keys (not part of a flight plan): rate_index 0 stops warp and cancels a warp-to; " +
    "1.. sets the rails rate (or the physics rate with physics: true; switching mode passes through rate 0). The game may cap the rate " +
    "(altitude, acceleration): returns the actual {mode, rate_index, rate, auto_warp}, re-read get_flight.time_warp to confirm. " +
    "warp_to_running while a warp-to runs (stop it first). A flight plan treats this like the player: stopping a coast warp latches it " +
    "for the rest of the step; a step change or abort stops rails warp.")]
public Task<string> SetTimeWarp([Description("Rate index; 0 = stop")] int rate_index,
    [Description("Physics warp instead of rails (default false)")] bool physics = false, CancellationToken ct = default)
    => client.SendAsync(HttpMethod.Post, "api/time_warp", new { rate_index, physics }, ct);
```

- `get_flight` 설명에 `time_warp` 묶음을 추가한다.
- **검증**: `reload_app` 뒤 도구 목록에 `set_time_warp`. App 테스트 통과.

### 3. 단위 9 상호작용 검증 (이슈 #2 단위 9 미검증 항목)

- 계획 `coast` 가속 중 `set_time_warp {rate_index: 0}` → `warp_stopped`, `plan.warp` false, 같은 단계에서 `warp_started` 없음(래치). 다음 `coast` 단계에서 다시 `warp_started`.
- 사용자 물리 가속(`physics: true`) 상태로 단계 전환 → 물리 가속 유지, `plan.warp` false. 물리 가속 상태에서 `coast` 단계가 시작되면 계획 WarpTo가 레일로 동작하는지(또는 막히는지) 기록.
- 사용자 레일 가속 중 단계 전환 → 해제됨(설계: 단계 전환·중단은 레일 가속을 해제).
- 계획 없이 사용자 레일 가속 → `reload_mod` → `time_warp.rate_index` 유지, `warp_stopped` 없음. 사용자 레일 가속 중 `submit_flight_plan` → 유지.
- 우리 요청 없이 허용 조건이 아닐 때(목표까지 15초 미만) 사용자 레일 가속 → 계획이 해제하지 않음.
- 물리 가속 중 `attitude_error`에 값이 있고 자세 유지(0006 단위 4 미룬 검증).
