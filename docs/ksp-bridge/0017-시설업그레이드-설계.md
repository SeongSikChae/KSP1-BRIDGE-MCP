# KspBridge 시설 업그레이드 — 설계

선행: `0016-시설업그레이드-방안.md`

## HTTP (로직)
### GET /api/facilities
- 커리어 아니면 409 `not_career`. 어느 장면에서나 조회 가능하나 `upgrade_cost`는 KSC 장면에서만(그 외 null)
```json
{"funds": 401530, "facilities": [
  {"id": "mission_control", "level": 0, "max_level": 2, "upgrade_cost": 55000, "can_afford": true,
   "effects": {"current": {"active_contracts": 2, "flight_planning": false},
               "next":    {"active_contracts": 7, "flight_planning": true}}}
]}
```
- id: get_career와 같은 snake_case(`launch_pad`, `runway`, `vehicle_assembly_building`, `spaceplane_hangar`, `tracking_station`, `mission_control`, `research_and_development`, `astronaut_complex`, `administration`)
- 효과(GameVariables, 정규화 레벨 = level/max):
  | 시설 | 효과 키 |
  |---|---|
  | launch_pad / runway | `max_mass_t`, `max_size_m` [x,y,z] |
  | vehicle_assembly_building / spaceplane_hangar | `max_parts`, `action_groups`, `custom_action_groups` |
  | research_and_development | `science_cost_limit` |
  | mission_control | `active_contracts`, `flight_planning`(기동 노드) |
  | tracking_station | `patches_ahead`, `tracked_objects` |
  | astronaut_complex | `active_crew`, `eva` |
  | administration | `active_strategies` |
- 최대 레벨이면 `next` null

### POST /api/facilities/{id}/upgrade
- 순서: 커리어(409 `not_career`) → KSC 장면(409 `scene_not_allowed`) → id(404) → 최대 레벨(409 `max_level`) → 발사대·활주로 위 기체(409 `site_occupied`) → 자금(`CurrencyModifierQuery`, 409 `not_enough_funds`)
- 실행: `Funding.AddFunds(-cost, StructureConstruction)` → `UpgradeableFacility.SetLevel(level+1)`(같은 id의 모든 인스턴스)
- 응답: `{id, level_before, level_after, cost, funds}`

## 결과 (2026-11-08)
- 게임: 관제소·추적 기지·발사대 0→1, 자금 401,530→126,530, 다음 비용 갱신, 관제소 flight_planning true
- 검토(stock 디컴파일 대조) — 치명 없음, stock과 다른 점(low) — 로직 0.5.1에서 3건 모두 반영:
  - 점유 검사: 기존 발사대·활주로 검사 + 해당 시설의 `SpaceCenterBuilding`마다 `FindVesselsAtFacility`·`FindVesselsAtGrounds`(stock `includeGrounds: true`), 409 `site_occupied`에 기체 이름
  - 실행: 자금 차감 → 건물 `destructibles` 전부 `Reset()` → `SetLevel` → `GamePersistence.SaveGame("persistent")`
  - 게임 확인: reload 0.5.0→0.5.1, 관제소·발사대 업그레이드 요청이 점유 검사를 지나 `not_enough_funds`로 정상 거부. 실제 업그레이드 시 Reset·저장, 기체가 있을 때의 거부는 미확인
- 원래 지적:
  1. 파손 구조물 복구(`ResetStructures`) 없이 `SetLevel` — 파손 시설 업그레이드 시 파손 상태가 남을 수 있음
  2. 점유 검사는 발사대·활주로만(stock은 모든 시설 부지)
  3. 업그레이드 직후 `SaveGame` 없음 — 다음 저장 전 크래시 시 업그레이드·자금 차감이 함께 사라짐(정합성 유지)

- 시설 객체 찾기: `UnityEngine.Object.FindObjectsOfType<UpgradeableFacility>()`에서 `id`(예 `SpaceCenter/MissionControl`)의 끝 부분을 `SpaceCenterFacility` 이름과 매칭
