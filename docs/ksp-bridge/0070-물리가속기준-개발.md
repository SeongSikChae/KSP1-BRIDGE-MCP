# 0070. 자유 낙하 물리 가속: 켜는 기준과 끄는 기준 분리 (개발)

사용자 요청: "기준 분리로 수정". `land` 자유 낙하의 물리 가속 ×2(0061 결정 11)가 켜졌다 꺼지기를 틱 단위로 반복하는 문제를 고친다.

## 원인 (태스크 a3b09a7f 실측, 2026-11-17)

- 판정: `LandMode`가 매 틱 `PhysicsWarpOk = 자세 오차 ≤ 5° && 각속도 ≤ 0.05 rad/s`를 내고, `Warp.RequestPhysics`는 그 값 하나로 켜고 끈다(0061 결정 11 "틱마다 판정하고 하나라도 어기면 바로 ×1").
- 재현(근지점 20 km 재진입, 고도 약 25 km): 이벤트 390~392 `warp_stopped` 14633.845 → `warp_started` 14634.025 → `warp_stopped` 14634.185. 진단 로그(Player.log 59426·59429·59432) 세 줄 모두 `failed: attitude`, 자세 오차 5.00/5°, 각속도 0.005~0.007 rad/s.
- 그 뒤 자세 오차는 ×1에서도 6.3°까지 커졌다(공기력으로 천천히 밀림). 가속이 오차를 만든 것이 아니라, 천천히 변하는 값이 한 기준을 지날 때 틱마다의 작은 흔들림으로 켜짐·꺼짐이 번갈아 나온 것이다.
- 처음 사례(seq 334~347, 뒤집힘 중단 직후 `land`)는 판정 값 기록이 없어 원인을 확정하지 못했다. 이 수정이 그 사례도 고친다고 보지 않는다. 같은 조건(뒤집힘 직후 각속도가 0.05 근처)이 다시 나오면 진단 로그로 따로 판정한다.

## 변경

**대상**: `src/KspBridge.Logic/Flight/Modes/IFlightMode.cs`(`ModeCommand`), `src/KspBridge.Logic/Flight/Modes/LandMode.cs`, `src/KspBridge.Logic/Flight/Warp.cs`(`RequestPhysics`)

- `ModeCommand`에 `PhysicsWarpKeepOk`(bool)를 더한다. `PhysicsWarpOk`는 지금처럼 **켜는** 조건, `PhysicsWarpKeepOk`는 **유지** 조건이다. 기본값 false(다른 모드는 물리 가속을 요청하지 않는다).
- `LandMode` 자유 낙하 분기:
```csharp
PhysicsWarpOk     = errDeg <= WarpAttDeg     && rate <= WarpRate     && !diagX1,   // start: 5 deg, 0.05 rad/s (unchanged)
PhysicsWarpKeepOk = errDeg <= WarpKeepAttDeg && rate <= WarpKeepRate && !diagX1,   // keep: 10 deg, 0.1 rad/s
```
- `Warp.RequestPhysics`: 자세 판정만 상태에 따라 고른다. 그 밖의 조건(스로틀 0, 추력 0, 스테이징 아님, 목표 시각 전)은 이산 값이라 그대로 하나다.
```csharp
// keep must include start: a mode that sets only PhysicsWarpOk (keep false) would otherwise start and stop every tick
bool attitudeOk = _physics ? (physicsKeepOk || physicsOk) : physicsOk;   // ours on: keep bound; off: start bound
bool ok = attitudeOk && throttle == 0 && thrust <= 0 && !staging && left > 0;
```
- 진단의 `failed` 목록도 `attitudeOk`로 판정한다(지금은 `physicsOk`). 켜진 상태에서는 유지 기준을 어겼을 때만 `attitude`가 찍힌다.
- `Coordinator`는 `Command.PhysicsWarpKeepOk`도 `Warp.Request`에 넘긴다(`Request(v, w, ok, keepOk, why)`).
- 진단(×2 유지 중 최댓값, 잠정값 확정의 근거): `ModeCommand`에 진단용 `PhysicsWarpAttDeg`·`PhysicsWarpRate`(double, 기본 NaN)를 더하고 `LandMode`가 판정에 쓴 자세 오차·각속도를 넣는다. `Warp`는 우리 ×2가 켜져 있는 틱마다 두 값의 최댓값을 모으고(켤 때 초기화), `StopPhysics`의 중지 로그에 `x2 peak att 7.12 deg, rate 0.0612 rad/s over 35.40 s`처럼 찍는다. 모든 중지 경로(조건·대기권 이탈·`Stop`)가 `StopPhysics`를 지나므로 ×2 구간마다 한 줄이 남는다. ×1 구간 값은 섞이지 않는다.
- 진단 문자열(`PhysicsWarpWhy`)에 유지 기준을 함께 적는다: `att 5.20/5 (keep 10) deg, rate 0.0070/0.05 (keep 0.10) rad/s`.

**끄는 기준 값(10°, 0.1 rad/s)의 근거와 한계**
- 이 판정의 목적은 ×2에서 자세 유지가 무너지는 것을 막는 것이다(0061 결정 11: ×3에서 받음각 163°까지 벌어짐). 끄는 기준은 "자세가 목표에서 분명히 벗어남"을 잡아야 하고, 공기력에 의한 느린 밀림이나 틱 흔들림에는 반응하지 않아야 한다.
- 기준은 관측된 정상 범위보다 넓고 붕괴보다 훨씬 좁아야 한다. 관측된 정상 범위(같은 재진입, ×1): 공기력 밀림 자세 오차 최대 6.3°(제어 유지), RTG 손실 충격 각속도 0.0553(0.7초 안에 0.0482로 회복). 붕괴 사례: 받음각 163°.
- 10°, 0.1 rad/s는 **×2 실측 전 잠정값**이다. 켜는 기준의 두 배라는 배수로 고른 값이며, 실측에서 나온 값이 아니다. 관측 최댓값(6.3°, 0.0553)을 덮는 가장 좁은 값(약 7°, 0.06)보다 넓게 잡은 것은, 그 관측이 ×1 한 비행뿐이라 ×2 유지 중의 흔들림 폭을 모르기 때문이다. 다른 기능의 기본값은 근거로 쓰지 않는다.
- 한계: 위 관측은 모두 ×1 구간이다. ×2에서 5~10° 오차가 유지된다는 실측은 아직 없다. 그래서 이 잠정값은 아래 검증의 실측으로 확정한다. 검증 뒤 ×2 유지 구간의 실측 최댓값(중지 로그 `x2 peak`)을 이 문서에 적고, 잠정값을 그대로 둘지 그 값에 맞춰 줄일지 사용자에게 보고한다. ×2 유지 구간에서 오차·각속도가 ×1보다 빨리 커져 유지 기준에 닿으면, 그 값과 함께 사용자에게 보고하고 기준을 다시 정한다.
- 불변식: 유지 기준은 켜는 기준을 포함한다. `Warp`가 `physicsKeepOk || physicsOk`로 보장하므로 유지 판정을 내지 않는 모드도 켜자마자 꺼지지 않는다.
- 기각: 같은 기준에 일정 시간 유지(시간 어림). 느린 밀림이 기준 근처에 오래 머물면 같은 반복이 시간 간격만 바뀌어 남는다.
- 기각: 반복 횟수 제한. 증상을 세는 것이지 원인을 고치지 않는다.

**영향**
- 켜는 조건은 그대로라 이미 켜지지 않던 상황은 바뀌지 않는다.
- 켜진 뒤 5~10°, 0.05~0.1 rad/s 사이에서도 ×2를 유지한다. 그 구간에서는 자세 오차(받음각)가 지금보다 큰 채로 ×2 낙하가 이어진다. 받음각은 저항 방향과 가열에 영향을 주고, 착지점 예측과 실제의 차이를 키울 수 있다. 다만 같은 오차는 ×1에서도 생기며(실측 6.3°), 가속 배율은 적분 간격만 바꾼다. 검증에서 그 구간의 오차·온도·착지점을 기록한다.
- 0061 결정 11의 "하나라도 어기면 바로 ×1" 문장을 이 문서로 개정한다(자세 조건만 유지 기준).

## 검증

- 빌드·테스트.
- 실측: `U5d 재진입 시험`으로 궤도 진입 → `plan_maneuver deorbit periapsis 20000` → `execute_node` + `land`.
  - 합격 조건(시간 기준이 아니라 원인 판정): 대기 안 자유 낙하의 물리 가속 중지마다 진단 로그의 값이 유지 기준을 넘었거나(자세 > 10° 또는 각속도 > 0.1 rad/s) 다른 조건(스로틀·추력·스테이징·목표 시각·경로)이 깨졌다. 켜는 기준만 넘은 값(5~10°, 0.05~0.1 rad/s)으로 꺼진 중지가 하나도 없다.
  - 재현 조건 확인: ×2 구간마다의 중지 로그 `x2 peak`로 판정한다. 어느 구간의 자세 오차 최댓값도 5° 이하이고 각속도 최댓값도 0.05 이하였으면 "수정 경로를 지나지 않음"으로 미검증 처리하고 보고한다.
  - 수정 경로를 지났으면(peak가 켜는 기준을 넘음) 그 구간의 자세 오차·각속도 최댓값을 이 문서에 적고, 온도 비율(20초 감시)·착지점과 예측 차이를 함께 기록한다. ×1 구간 비교 값은 같은 비행의 20초 감시 값을 쓴다(위 "한계").
  - 착지 정상(`landed`, 기울어짐 없음).

## 실측 결과 (2026-11-17, 같은 기체·같은 디오빗 조건 2회차)

- 대기 안 물리 가속: `warp_started` 18158.25 → `warp_stopped` 18613.85 한 구간뿐(이벤트 427·432). 중지 이유는 `target_reached`(목표 시각), 켜는 기준만 넘은 값으로 꺼진 중지는 없음 → 합격.
- 중지 로그 `x2 peak att 6.38 deg, rate 0.0964 rad/s over 455.60 s`: 자세 오차가 켜는 기준(5°)을 넘은 구간을 ×2로 지났다(수정 경로 통과). 수정 전 비행에서는 같은 구간(오차 5° 통과)에서 켜짐·꺼짐이 반복됐다(이벤트 390~392).
- 같은 비행 RTG 손실(고도 약 32 km, 표면 1214/1200 K) 때 수정 전에는 각속도 0.0553으로 ×2가 꺼졌으나, 이번에는 유지됐다.
- 각속도 최댓값 0.0964 rad/s는 잠정 유지 기준(0.1)에 가깝다. 자세 오차 최댓값 6.38°는 ×1 관측(6.3°)과 비슷하다. 잠정값을 줄일 근거는 없고, 각속도 기준은 여유가 작다는 점을 보고한다.
- 착지: `touchdown` 수직 1.938 m/s, `landed` 기울기 0.089°.
- 3회차(RTG를 노즈콘 아래 1.25 m 서비스 베이 안 스택에 넣은 기체, 같은 조건): 부품 손실 없음, ×2 한 구간 469.08 s(`target_reached`), `x2 peak att 0.68 deg, rate 0.0448 rad/s`. 앞선 비행의 5~6° 자세 오차는 반경 방향 RTG 한쪽이 타서 떨어진 직후부터 커졌다(손실 전 약 0.01°). 비대칭 공기력이 오차의 원인이었던 것으로 보인다. 기준 분리는 오차가 기준을 천천히 지나는 다른 기체에도 필요하므로 유지한다.
