# KspBridge 비행 안전 하네스 방안

## 문제·목표
- 최근 비행(궤도 이탈 귀환 2회, 방열판 테스트 계약 비행)의 실패 절반 이상이 도구가 정보나 제어 수단을 주지 않아서 생겼습니다.
- 에이전트가 게임 cfg·.craft·세이브 파일을 직접 grep해서 빈 정보를 메웠고, 그 과정에서 값을 잘못 옮기기도 했습니다.
- 목표: 기체 설계·비행에서 위험한 부분을 **도구가 먼저 알려 주고**, 반복 계산(연소 타이밍, 중력 선회)을 **도구가 대신** 하며, 운용 절차를 **스킬 문서**로 남깁니다.

## 실패 사례와 원인
| 사건 | 주 원인 | 막을 항목 |
|---|---|---|
| 부스터 분리 때 열차폐까지 분리됨(2회) | 하네스 | 2 |
| 고속 시간 가속 뒤 재진입 자세 80° 어긋남 | 하네스 | 3, 4 |
| 상승 중 피치 명령 전부 무시(1단 조향 수단 없음) | 하네스 | 1 |
| Swivel 점화 때 기체 뒤집힘 | 하네스·에이전트 | 1, 3 |
| 꼬리 날개 높이 오류로 발사대에서 넘어짐 | 하네스·에이전트 | 1, 6 |
| 순환화 계산 없이 연소해 연료 고갈 | 에이전트(도구 지원 없음) | 4, 5, 7 |
| 낙하산 조건을 잘못 잡아 8.46 G | 에이전트 | 7 |
| 관측 계약 지점 좌표를 세이브 파일에서 찾음 | 하네스 | 6 |

## 현재 코드의 공백 (확인)
| 영역 | 현재 | 공백 |
|---|---|---|
| 부품·기체 분석 (`PartsHandler`, `CraftEstimator`) | 질량·Δv·TWR | 짐벌, 반동 휠 토크, 조종면, 무게중심·양력중심, 접지점 없음 (`Gimbal`·`ReactionWheel`·`ControlSurface`·`CenterOfLift` 참조 0건) |
| 스테이지 (`StageHandler.cs:33`) | `inverseStage == s.stage && hasStagingIcon` 부품만 | 분리 때 함께 떨어지는 하위 부품(열차폐 등) 없음 |
| 자세 (`AttitudeController.TargetDirection`) | 지표 기준 피치·방위, 고정 이득 PD | 궤도 기준 자세·오프셋, 받음각 제한, 가속 후 자세 이탈 경고 없음 |
| 기동 노드 (`NodeHandler`) | 노드 생성·삭제 | 연소 시간 계산·선점화·남은 Δv 차단 실행 없음 |
| 대기 (`WaitHandler`, 최대 120 s) | 단일 조건 | 부품 손실·연료 고갈·자세 이탈 시 조기 반환 없음, 조건 조합 없음 |
| 계약 (`CareerHandler`) | 계약 목록 | 웨이포인트 좌표 없음 |
| 기체 읽기 | 없음 | 기존 .craft를 `build_craft` 설계 트리로 읽는 도구 없음 |
| 스킬 문서 | `ksp-flight-preflight`, `ksp/launch-preflight.md` (Δv 점검만) | 상승·순환화, 재진입·회수, 기체 설계 절차 없음 |

## 채택 방안 (범위 1~7 전체, 2026-11-08 사용자 결정)

### 1. 기체 분석 강화
- `build_craft` dry run, `get_stages`에 **단별 조향 능력**을 추가합니다: 짐벌 엔진과 범위(°), 반동 휠 토크(kN·m), 조종면 수.
- 단별 **조향 불가 경고**: 추력이 있는데 짐벌·반동 휠·조종면이 모두 없으면 경고합니다.
- **무게중심·양력중심**과 공력 안정성 경고(양력중심이 무게중심보다 앞이면 경고). VAB의 `EditorMarker_CoM/CoL` 계산 방식을 따릅니다.
- **발사대 접지점**: 기체 최하단 부품을 알려 주고, 엔진 노즐보다 아래로 튀어나온 부품(꼬리 날개 등)을 경고합니다.

### 2. 스테이지별 분리 부품 목록
- `get_stages`와 dry run에 **그 단에서 실제로 떨어지는 부품 전체**를 추가합니다. 분리기(decoupler) 아래 하위 트리를 따라가 모읍니다.
- 열차폐·낙하산·명령 모듈처럼 **보호 대상 부품**이 떨어지면 경고합니다.

### 3. 궤도 기준 자세 유지
- `set_attitude`에 기준 프레임을 추가합니다: `surface`(현재), `prograde`, `retrograde`, `normal`, `antinormal`, `radial_in/out`, `node`. 각 프레임에 피치·요 오프셋(°)을 줄 수 있습니다.
- SAS 모드와 달리 자체 제어기로 동작하므로 **조종사 레벨에 막히지 않습니다**.
- **받음각 제한**(`max_aoa_deg`): 대기 중에는 목표 방향을 진행 방향에서 제한 각도 안으로 자릅니다.
- 시간 가속이 끝나면 목표 자세와의 오차를 결과·비행 기록에 남기고, 큰 오차는 경고합니다.

### 4. 기동 노드 실행 도구
- 새 도구 `execute_node`: 노드 방향으로 자세를 맞추고, 연소 시간을 계산해 **노드 시각 − 연소 시간/2**에 점화하고, **남은 Δv**가 기준 이하가 되면 엔진을 끕니다.
- 연료 부족(남은 단 Δv < 노드 Δv)이면 점화 전에 거부하거나 경고합니다.
- 실행은 기존 트리거·스로틀 잠금 구조를 재사용해 MCP 호출이 끊겨도 게임 안에서 끝까지 동작하게 합니다.

### 5. 이상 감지 조기 반환·조건 조합
- `wait_until`에 **이상 감지**를 추가합니다: 부품 손실, 엔진 연료 고갈(flameout), 자세 오차 초과가 생기면 즉시 돌아오고 원인을 알려 줍니다. 비행 기록기 이벤트를 그대로 씁니다.
- `wait_until`·`add_trigger`에 **조건 조합**(AND/OR)을 지원합니다.

### 6. 상승 유도 도구
- 새 도구 `ascent_guidance`: 목표 원지점, 선회 시작 속도, 선회 강도를 받아 중력 선회를 자동으로 합니다. 받음각 제한(3번)을 사용합니다.
- 목표 원지점에 이르면 엔진을 끄고 끝냅니다. 순환화는 4번 노드 실행으로 이어 갑니다.

### 7. 그 밖의 도구
- `list_contracts`에 **웨이포인트 좌표**(천체, 위도·경도, 고도)를 추가합니다.
- 새 도구 `read_craft`: 기존 .craft를 `build_craft` 입력과 같은 설계 트리(부품, 부착 위치, 연료량, 대칭)로 돌려줍니다. 개조할 때 이 결과를 고쳐 다시 `build_craft`에 넣습니다.

### 8. 스킬 문서 (Bizadm)
- `ksp-ascent-circularize`: 중력 선회, 진행 방향 유지, 순환화 노드·연소 절차
- `ksp-reentry-recovery`: 궤도 이탈 연소, 재진입 자세, 부스터 분리 조건(추력 0일 때만), 낙하산 전개 고도·속도
- `ksp-craft-design`: 기체 설계 체크리스트(조향 능력, 안정성, 접지점, 단별 분리 부품, 열차폐 보호)
- 기존 `ksp-flight-preflight`에 "과거 비행의 자세 기록(attitude 이벤트)도 읽는다"를 보강합니다.

## 검토한 대안
| 대안 | 판단 |
|---|---|
| 스킬 문서만 보강 | 정보 자체가 도구에 없어 에이전트가 cfg를 grep하는 문제가 남습니다 |
| MechJeb 등 외부 모드 연동 | 의존성이 커지고 설치 환경이 늘어납니다 |
| **도구에 정보·제어를 넣고 스킬로 절차를 묶음** | **채택** |

## 진행 순서 (제안)
1. 2 분리 부품 목록 → 1 기체 분석 (사고 예방 효과가 크고 읽기 전용이라 위험이 적음)
2. 5 이상 감지 → 3 궤도 기준 자세 → 4 노드 실행
3. 6 상승 유도 → 7 웨이포인트·기체 읽기
4. 8 스킬 문서
- 설계·개발 문서는 이 방안 합의 뒤 같은 `feature` 이름으로 작성합니다. 범위가 커서 설계 단계에서 묶음별로 나눌 수 있습니다.

## 비범위
- 착륙 유도(동력 착륙), 랑데부·도킹 자동화
- 외부 모드(MechJeb, kOS) 연동
- 자동 기체 설계(부품 선택 추천)

## 위험
- 무게중심·양력중심 계산은 에디터 밖(dry run)에서 게임과 다를 수 있습니다. 인게임 VAB 표시와 비교 검증이 필요합니다.
- 받음각 제한과 상승 유도는 기체마다 거동이 달라 이득 조정이 필요할 수 있습니다.
- 범위가 커서 한 번에 진행하면 검토 부담이 큽니다. 묶음 단위로 구현·테스트합니다.
