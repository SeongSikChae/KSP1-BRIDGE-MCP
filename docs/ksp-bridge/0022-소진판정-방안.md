# 소진판정 방안

## 문제

`AutoStager.Spent`(src/KspBridge.Logic/Flight/AutoStager.cs)는 점화된 엔진을 KSP의 `e.flameout` 플래그만으로 다 쓴 엔진으로 판정한다. 연료 잔량은 미점화 엔진(`HasPropellantCached`)에만 본다.

```csharp
private static bool Spent(Vessel v, ModuleEngines e) =>
    e.flameout || (e.part.inverseStage >= v.currentStage && !e.EngineIgnited && !EngineModel.HasPropellantCached(e));
```

`BurnedOut`은 `(spent > 0 && burning == 0) || NextStageDecouplesFlamedOutEngine(v)`라서 연료가 남은 엔진이 일시적으로 flameout돼도 다음 스테이지가 그 엔진을 떼어 내면 분리한다. KSP는 추진제가 돌아오면 flameout을 스스로 풀지만 분리는 되돌릴 수 없다(#13).

#7 단위 5 실측(2026-11-13): `debug_engine_stop {mode flameout}`으로 연료 15%가 남은 하단 엔진을 flameout시키자 `stage_burnout` → `separate`로 바로 분리됐다.

## 목표

- 연료가 남은 엔진의 일시 flameout으로는 분리하지 않는다.
- 실제 소진은 지금처럼 분리한다(0006 burnout·tailoff·separate 동작 유지).

## 결정 (사용자 합의)

### 1. 점화 엔진 소진 판정: 연료 조건

- 점화 엔진은 `flameout`이면서 연료가 없을 때만 다 쓴 엔진으로 본다. 미점화 엔진의 기존 항(`staged && !EngineIgnited && !HasPropellant`)은 유지한다.
- "연료 없음"은 KSP가 엔진을 끄는 기준과 맞춘다. KSP는 남은 연료가 요구량 × `ignitionThreshold`보다 적으면 끄므로 아주 적은 잔량이 남을 수 있다. `amount > 0`만 보면 그 잔량 때문에 영영 분리하지 않을 수 있다. 점화 엔진은 KSP가 매 틱 갱신하는 추진제 상태를 쓰는 쪽을 우선 검토하고, 정확한 기준은 설계에서 디컴파일로 정한다.
- `ignoreForIsp` 추진제(스톡 제트 엔진의 IntakeAir로 예상, 설계에서 cfg 확인)는 연료 판정에서 빠지므로 공기 부족 flameout은 "연료 있음"(일시 정지)으로 분류된다.
- 연료가 남은 채 flameout이 풀리지 않으면 분리하지 않는다. 결정 3의 대기 상한을 넘기면 추력 없음 규칙(`plan_aborted {reason: no_thrust}`)으로 끝나 되돌릴 수 있다.
- 기각
  - flameout이 일정 시간 유지될 때만 소진으로 보는 방식: 그 시간보다 긴 일시 정지는 막지 못하고, 실제 소진 때 분리가 그만큼 늦어진다.
  - 연료 조건에 시간 보조를 더하는 방식: 멈춤은 피하지만 연료가 남은 상태로 분리하는 길이 다시 생긴다.

### 2. 적용 범위: 스테이징 판정과 `ignitable_engines` 함께

- 바뀐 판정은 `Spent`를 쓰는 스테이징 경로 전부(`BurnedOut`, tailoff의 `SpentThrust`, `NextStageDecouplesFlamedOutEngine`)에 적용된다.
- 조건 변수 `ignitable_engines`(`EngineModel.Ignitable`, 지금 `!flameout && HasPropellant`)도 같은 연료 기준으로 바꾼다. 연료가 남은 엔진의 일시 flameout은 점화 가능 엔진으로 센다. 판정 기준을 하나로 맞춘다.
- 조건 변수의 의미가 바뀌므로 0005 설계 문서의 `ignitable_engines` 설명을 고친다. `ignitable_engines`를 설명하는 도구 설명·ReadMe 문구는 없다(검색 확인).
- 기각: `ignitable_engines`를 비범위로 두는 방식은 변경이 작지만 같은 엔진이 스테이징에서는 "연료 있음", 조건 변수에서는 "점화 불가"로 갈려 기준이 둘이 된다.

### 3. 일시 정지 대기 (검토 R1 지적 1 반영)

- 문제: 엔진이 하나뿐인 단에서 연료가 남은 엔진이 flameout되면, 소진이 아니므로 스테이징 시퀀스가 시작되지 않는다. 그러면 그 틱에 "작동 엔진 없음 + 스테이징 대기 아님"이 되어 계획이 곧바로 `no_thrust`로 중단된다. 지금은 같은 틱에 `stage_burnout`이 나서 이 중단이 일어나지 않는다. 또 `none`의 점화 진입(작동 엔진 없음 + 다음 스테이지에 엔진)이 다음 스테이지를 작동시킬 수 있고, 스테이징 대기 중 스로틀 0 고정은 KSP의 flameout 해제를 막는다(KSP는 스로틀 0 틱에 해제 판정을 건너뛴다).
- 연료가 남은 채 flameout된 점화 엔진이 있으면 일시 정지로 보고 스테이징 대기(Pending)로 둔다. 그동안 다음 스테이지 점화 진입을 하지 않고, 스로틀은 Mode 값 그대로 두어 KSP가 엔진을 다시 켤 수 있게 한다.
- 대기 상한은 `staging_options`의 새 항목으로 계획마다 정한다(이름·기본값은 설계에서 정한다). 상한 안에 KSP가 풀면 계획이 그대로 이어지고, 넘기면 분리하지 않고 `no_thrust`로 중단한다.
- 기각
  - 대기 없이 즉시 `no_thrust`: 분리는 막지만 일시 flameout마다 계획이 끝나 #13의 목표("분리 대신 계속 비행")를 이루지 못한다.
  - 고정 상수 상한: API는 그대로지만 계획마다 조절할 수 없다(사용자 결정).

### 4. 공기 부족 flameout (검토 R1 지적 8 반영)

- 고도 상승으로 공기를 잃은 제트 엔진(연료 있음)도 결정 1·3대로 일시 정지로 본다. IntakeAir(`ignoreForIsp`)는 연료 판정에서 계속 뺀다.
- 지금은 이 경우 다음 스테이지가 그 엔진을 떼어 내면 분리되지만, 바뀐 뒤에는 대기 상한까지 기다린 뒤 `no_thrust`로 중단한다(동작 변경).
- 기각: IntakeAir를 연료 판정에 넣으면 지금처럼 분리되지만, 자세 변화 등으로 잠깐 공기가 부족해도 분리된다(#13이 구분하려던 경우).

## 비범위

- flameout 자체를 막거나 엔진을 다시 점화하는 동작(KSP가 스스로 푸는 것에 맡긴다)
- 연료가 남은 채 풀리지 않는 flameout의 자동 복구(대기 상한 뒤 추력 없음 중단으로 끝낸다)
- 제트 부스터 + 로켓 상단 기체에서 공기 상실 시 자동 분리(결정 4)
