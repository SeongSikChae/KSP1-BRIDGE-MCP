# 상승완료 설계

방안: `0066-상승완료-방안.md`. 바꾸는 곳은 `GravityTurnMode.Update`의 완료 판정뿐이다. 상태(`_reached`)와 저장 형식은 그대로다. 새 중단 사유는 없다.

## 구조

`GravityTurnMode.Update` 끝부분(스로틀·완료 판정)만 바꾼다.

1. 완료 원지점 `doneAp`
   - 대기가 있는 천체(`v.mainBody.atmosphere`)이고 `_reached`(목표에 한 번 닿음)면 `KeepBand · target_apoapsis`, 그 밖에는 `target_apoapsis`.
   - `KeepBand` = 0.99. 대기권 안 보충 기준(`predictedAp < 0.99 · target`)과 같은 상수로 묶는다.
   - 하한: `max(KeepBand · target, atmosphereDepth)`. 목표가 대기권 바로 위(Kerbin 70,000~70,707 m)면 99%가 대기권 안이라 원지점이 공기 속인 채 완료될 수 있어서다(구현 검토 지적, 사용자 반영 요청).
2. 대기권 밖이고 `predictedAp ≥ doneAp`면 스로틀 0, 완료.
   - `doneAp`가 목표 그대로인 경우(목표에 닿기 전, 대기 없는 천체)는 `ApThrottle`이 이미 목표 이상에서 0이므로 지금과 같다.
   - 대기가 있는 천체에서 `_reached`가 참이고 99~100%면, 지금은 최소 0.05로 보충하던 것을 0으로 바꿔 완료한다.
3. `predictedAp < doneAp`인 대기권 밖 동작(보충 연소)은 그대로다.

## 인터페이스

- 도구 응답·이벤트 형식 변화 없음. 완료가 99% 띠에서 나면 `step_completed`가 지금보다 일찍 나온다.
- 완료 조건 설명 변경(`FlightTools` `gravity_turn` 설명, `ReadMe.md` `gravity_turn` 행): "대기권 밖에서 예측 원지점 ≥ 목표(대기가 있는 천체에서 목표에 한 번 닿았으면 목표의 99%: 공기 저항이 깎은 몫), 스로틀 0".
- `until`이 있는 단계는 지금처럼 `until`이 완료를 정한다(`Coordinator`가 `_mode.Done` 대신 `Until.Eval`). 그 경우에도 99% 띠 이상에서는 스로틀이 0이다(지금은 99~100%에서 0.05로 보충).

## 데이터

- 상태 추가 없음. `Save`/`Load`는 `reached`만 그대로 저장·복원한다. 리로드 뒤 첫 틱도 같은 판정이다.

## 결정 목록

| # | 결정 | 이유 |
|---|---|---|
| 1 | 대기가 있는 천체에서 목표에 닿은 뒤의 완료 원지점은 목표의 99%(대기권 안 유지 띠와 같은 상수) | 유지 띠와 완료 기준이 달라 99~100%로 나오면 끝나지 않던 틈을 없앰(방안 결정 1) |
| 2 | 대기 없는 천체는 100% 유지 | 유지 띠가 없고, `_reached`가 예측 흔들림으로만 켜질 수 있음(계획 검토 지적) |
| 3 | 원지점 통과 중단 없음 | 대기 없는 천체·약한 상단 오판(방안 결정 2) |
