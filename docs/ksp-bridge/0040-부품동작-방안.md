# 부품동작 방안

이슈: [#15 비행 도구: 비행 중 부품 동작(KSPEvent)·action group·부속 제어·연료 전달과 부품·CommNet 상태 조회](https://github.com/SeongSikChae/KSP1-BRIDGE-MCP/issues/15)

## 문제

비행 중 부품의 동작(PAW 버튼)과 상태를 MCP 도구로 다룰 수 없다.

- HG-5 전개는 `ModuleDeployableAntenna`의 KSPEvent(Extend/Retract)이며 `set_part_field`가 다루는 editor field가 아니다.
- 비행 중 부품 event·action group 실행 도구가 없고, 안테나는 staging도 할 수 없다.
- 도킹 포트 Undock(`ModuleDockingNode` event)을 실행할 수 없다.
- 펼침 상태·CommNet 연결을 MCP로 확인할 수 없다. `get_flight`에는 부품·CommNet 항목이 없고, `get_part`는 카탈로그 기본값, `get_craft`는 editor 전용이다.
- 비행 중 탱크 사이 연료 전달 도구가 없다.

## 목표

- 활성 기체 부품의 event를 조회·실행한다.
- 자주 쓰는 부속은 필요한 경우 상위 제어로 다룬다.
- 같은 기체(도킹 결합 포함) 안에서 부품 사이 자원을 전달한다.
- 부품·모듈 상태와 CommNet 상태를 조회한다.

## 결정 (사용자 합의)

### 1. 문서·구현 분할

방안은 #15 전체로 이 문서 하나를 쓴다. 설계·개발은 아래 구현 단계마다 따로 만들고 단계별로 끝낸다.

1. 상태 조회 + 범용 event 실행
2. 부속 제어 · action group
3. 연료 전달

### 2. 부속 제어: 범용 event + 일부 상위 도구

- 범용 event 조회·실행 도구로 모든 부속 동작(안테나·태양광 패널·라디에이터 전개, 조명, Undock 등)을 실행할 수 있게 한다.
- field 값 설정이나 조건 판단이 필요한 동작(예: 엔진 추력 제한, 낙하산 안전 전개)만 상위 도구로 둔다. 대상 목록은 2단계 설계에서 정한다.

### 3. 상태 조회: 별도 도구 2개

- 부품·모듈 상태(부품 id, 이름, 모듈별 주요 상태, 부품별 자원 잔량·흐름 잠금) 조회 도구를 따로 둔다.
- CommNet 상태(연결 여부, 신호 세기, 제어 가능 상태, 경로, 안테나 출력) 조회 도구를 따로 둔다.
- `get_flight` 응답은 바꾸지 않는다.

### 4. 연료 전달: KSP처럼 시간에 걸쳐

- 게임의 Transfer In/Out처럼 일정 속도로 시간에 걸쳐 전달한다.
- 진행 상태 확인과 진행 중 전달 취소를 제공한다.

### 5. event 실행 대상: 게임 PAW 버튼과 같게

- 비행 중 PAW 버튼을 누른 것과 같은 범위에 실행한다. 대칭 부품 처리는 게임 버튼 동작을 따르며, 대칭 여부를 고르는 인자는 두지 않는다.
- 설계 단계에서 디컴파일로 확인한 게임 동작에 맞춰 처음 결정(항상 단일 부품)을 바꿨다. 구체적인 전파 범위는 설계 문서에 적는다.

### 6. action group: 비행 중 발동·토글만

- Custom01~10, Light, Gear, Brakes, Abort 등을 비행 중 발동·토글한다.
- editor에서 부품 action을 action group에 배정하는 기능은 비범위다.

### 7. 연료 전달 도구와 `set_resource`: 역할 분리

- 비행 중 전달은 새 도구로 한다.
- `set_resource`는 editor 전용으로 두고 바꾸지 않는다. 비행 중 자원량을 직접 설정하는 기능은 두지 않는다.

### 8. 실행 중인 비행 계획: 허용

- 비행 계획이 실행 중이어도 event·action group·연료 전달 요청을 받아 실행한다.
- Undock·분리처럼 기체가 나뉘는 동작은 기존 `vessel_changed` 처리를 그대로 따른다.

### 9. 대상 기체: 활성 기체만

- 모든 조회·실행은 활성 기체(도킹 결합 포함)를 대상으로 한다.
- 다른 기체는 `switch_vessel`로 전환한 뒤 다룬다.

### 10. 실행 기록

- event·action group 실행과 연료 전달 시작·종료·취소를 `get_flight_events`와 `[KspBridge]` KSP.log 줄로 남긴다.

## 비범위

- 비행 계획(`submit_flight_plan`) 단계에서 event·action group 실행. 필요하면 별도 이슈로 다룬다.
- editor action group 설정.
- 도킹 접근·결합 제어(#18).
