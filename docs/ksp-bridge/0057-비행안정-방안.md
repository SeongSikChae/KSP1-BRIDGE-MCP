# 비행안정 방안 — 4단계: land 무추력 하강 자세 상실 감지

이슈 [#24](https://github.com/SeongSikChae/KSP1-BRIDGE-MCP/issues/24) 3단계 완료 댓글의 남은 과제. 사용자 결정(2026-11-15): #24에서 이어 가고, 범위는 **자세 상실 감지·알림**만 다룬다(역류 조종면 처리·추력 자세 유지·착지 뒤 포화 정리는 이번 범위 밖, 아래 "비범위").

## 문제

- 3단계 착륙 실측: 꼬리날개가 있는 StabS가 1.5 km 홉 뒤 `land` 단계에서 추력 없이 하강하다 뒤집혀 추락했다. 감시기 경고·중단이 없었다.
- 감시기 사각지대(`FlightMonitor.Tick`):
  - `flipped`는 명령 자세가 지표 진행 방향일 때만 본다(land·역방향 하강 제외).
  - `control_lost`·`thrust_waste`는 추력이 있을 때만 본다.
  - `cmd.Aligning`(land 강제 시작 뒤 첫 정렬 전)이면 오차 타이머가 멈춘다.

## 실측 (0.2.61, 2026-11-15, 새 세이브에서 기체 재작성)

기체:
- `KspBridge-StabS`: RC-L01(`probeStackLarge`) + Mk7 노즈콘 + 점보-64 + Skipper + `tailfin` 4개(조종면, 기동각 25°). 이륙 TWR 1.44, 압력중심이 질량중심보다 3.2 m 뒤.
- `KspBridge-StabL`: StabS에서 `tailfin` 제거.

계획: `attitude` 피치 90 스로틀 1 → 원지점 1,500 m → `land`(기본값, `timeout_s` 180).

| 비행 | 결과 | 근거 |
|---|---|---|
| 1. StabS(조종면 작동) | 추락 | 정점 직후 무추력 하강에서 오차 10°(q 0.42 kPa) → 44°(q 0.88) → 170°(q 1.7), 5 s 동안 피치·요 입력 ±1 포화, 각속도 최대 1.1 rad/s. 기수 아래로 고정. `burn start why=no_margin` h 1,040 m, 하강 80 m/s, `align_err` 167.7° → `cos` < 0이라 스로틀 끝까지 0. `landing_infeasible accel`(h 826 m) 뒤 약 150 m/s로 충돌, `plan_aborted vessel_lost`. 감시기는 `oscillation` 경고 1회뿐. |
| 2. StabS(조종면 `authorityLimiterUI` 0, 고정 날개) | 추락 | 같은 경과지만 늦게 뒤집힘: 오차 13°(q 2.1 kPa) → 40°(q 2.8) → 170°(q 약 4). 휠 1.5 kN·m만 남아 요 입력이 창 내내 포화(`input_sat_ratio` 0.99). 강제 시작 뒤 스로틀 0, 충돌. 감시 이벤트 없음. |
| 3. StabL(날개 없음) | 착륙 | 하강 q 3.2 kPa·받음각 180°에서 오차 0.15°. `touchdown` 하강 0.05 m/s → `landed` 기울기 0.035°, 2.1 s. |

판정:
- 꼬리날개 기체는 꼬리부터 하강할 때 공력적으로 불안정하고, 무추력 권한(휠)으로는 q 2~3 kPa를 버티지 못한다.
- 조종면은 역류(받음각 > 90°)에서 토크 방향이 반대가 되어, 제어기가 뒤집힘을 거든다(같은 오차에 이르는 동압이 약 4배 낮음).
- 뒤집힘이 연소 시작보다 먼저 일어나, 강제 시작은 스로틀 0인 채로 끝난다. 뒤집힌 뒤에는 회복 수단이 없다.
- 착지 뒤 포화(과제 2): 스로틀 0이 되면 짐벌 토크가 사라지고 휠만 남아, 지면 접촉의 미세 각속도(0.003~0.009 rad/s)에 피치·요 입력이 ±1로 번갈아 포화된다. `landed`로 계획이 끝날 때까지(2.1 s) 이어진다.

## 결정

### 1. 감지 위치: 감시기 항목 (사용자 결정 2026-11-15)

- 감시기(`FlightMonitor`)에 무추력 자세 상실 판정을 둔다: 명령 자세가 있고 추력이 없을 때 자세 오차가 한계를 넘어 수렴하지 않으면 알린다.
- land 외 무추력 단계(`coast` 자세 유지, `attitude` 스로틀 0 등)에도 적용된다. 기존 `monitor` 설정(계획·단계별 조절, `enabled`)과 `monitor_alert`·`monitor_clear` 이벤트, `plan.monitor.alerts`를 그대로 쓴다.
- 기각: land 모드 전용 `landing_infeasible` 새 사유(land에만 적용, 감시 설정 체계 밖).

### 2. 경고 수준: 경고만 (사용자 결정 2026-11-15)

- `monitor_alert` `warn`만 내고 계획은 계속한다(`thrust_waste`·`oscillation`과 같은 경고 전용 항목). 뒤집힌 뒤에는 회복 수단이 없어 중단해도 기체는 그대로 떨어지므로, 에이전트가 원인을 알게 하는 것이 목적이다.

### 3. 설계에서 정할 것

- 항목 이름(새 항목 또는 `control_lost`와의 관계), 오차 한계·지속 시간 기본값과 조절 키, 수렴 판정(느린 무추력 선회 오탐 방지, `control_lost`의 5° 수렴 규칙 재사용 여부).
- 타이머 정지 규칙: 실측 1에서 오차가 30°를 넘은 지 약 4.4 s 뒤 강제 시작으로 `cmd.Aligning`이 켜진다. 지금 규칙(`Aligning`이면 오차 타이머 정지)과 `control_lost` 기본값(30°, 5 s)으로는 경고가 나지 않으므로, 강제 시작 뒤 추력이 0인 동안의 처리를 정한다.
- 추력 판정: 강제 시작 뒤 스로틀이 0으로 깎이는 틱(`throttle` 0, `thrust` 0)은 무추력으로 본다.
- 오탐 대조: 진공 무추력 선회(휠만), StabL 하강, 기존 2단계 실측 하강(`coast reference none`은 명령 자세 없음). 계획 문서 검토 R1 뒤 사용자 결정으로 대조 범위를 0058 "검증"(StabL 하강, 홉 정점 목표 반전, StabS 상승 회귀)으로 정했다.

## 비범위 (이번 단계에서 다루지 않음, 사용자 결정)

- 역류 조종면 처리(받음각 > 90°에서 조종면 피치·요 제어를 끄거나 반전).
- 추력으로 자세 유지(하강 중 낮은 스로틀로 짐벌 권한 확보, 연소 앞당기기).
- 착지 뒤 입력 포화 정리.
- approach·dock 저속 상대속도 목표의 앞먹임 실측.

## 완료 조건 (4단계)

- StabS 홉 → `land`에서 무추력 자세 상실이 충돌 전에 이벤트로 보고됨을 실측.
- StabL 정상 착륙, 기존 상승·하강 실측 기체에서 오탐 없음.
- `dotnet test tests/KspBridge.App.Tests` 통과.
