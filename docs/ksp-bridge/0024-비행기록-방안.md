# KspBridge 비행 기록·예측 대조 — 방안

## 문제·목표
- 2026-11-08 KB Hopper 2S 검증 비행에서 착지 추락이 두 번 났습니다. 두 번 모두 기록이 없어서 원인을 추정으로만 말할 수 있었습니다.
  - 1차: 해상 착수, 66 m/s. `burn_margin` 60 m에서 감속을 시작했는데 예측보다 덜 감속됐습니다. "해수면 추력 차이"라고 추정했지만 틀렸습니다. `Prediction.ThrustAt`은 이미 고도별 기압으로 추력을 계산합니다. 실제 원인은 아직 모릅니다.
  - 2차: 수평 흐름이 약 15~20 m/s 남은 채 retrograde 엔진으로 착지하다가 기체가 기울어 넘어졌습니다. 착지 순간의 자세·수평 속도 기록이 없었습니다.
- 목표:
  1. 비행마다 상태·제어·예측·이벤트를 남깁니다.
  2. 예측과 실제의 차이를 자동으로 대조합니다.
  3. Claude가 비행을 계획할 때 과거 기록을 근거로 여유값을 정합니다(launch-preflight 단계).

## 채택 방안
로직 DLL과 App만 바꿉니다. 로더는 바꾸지 않습니다.

1. **비행 기록기** (`Flight/FlightRecorder`, 로직)
   - 비행 하나에 파일 하나를 씁니다: `saves/<세이브>/KspBridge/flights/<UT>-<기체명>.jsonl`.
   - 기록 시작: 비행 씬의 활성 기체가 발사되었을 때(launch_craft 또는 발사대·활주로 비행 시작). 기록 끝: 회수, 파괴, 씬 이탈, 기체 전환.
   - 샘플은 기본 0.5초마다 남깁니다. 엔진이 켜져 있고 지면에서 1 km 아래면 0.1초마다 남깁니다(착지 감속 구간).
     - 위치·속도: UT, MET, 고도(ASL, 지면 기준), 수직 속도, 수평 속도, 지면 기준 속도
     - 자세·질량: 피치·방위·롤, 질량
     - 추진: 스로틀, 실제 추력(`finalThrust` 합), 측정 가속도
     - 예측: `stop_distance`·`burn_margin`·`max_accel`
     - 기타: SAS 모드·steering, g_force
   - 이벤트: 분리, 트리거 실행(이름·필드 값), API 제어 호출(스로틀·SAS 모드·자세), SAS 이벤트, 상황 변화(FLYING→LANDED 등), 부품 파괴·착수(`onPartDie`, `onCrash`, `onCrashSplashdown`), 승무원 기절.
   - 요약(비행 끝에 한 줄):
     - 비행: 기체, 승무원, 결과(recovered/destroyed/reverted/…), 최고 고도, 최대 G
     - Δv: 발사 시점 `get_stages` Δv와 실제 사용 Δv(연료 질량 변화로 계산)
     - 착지·착수 순간: 수직·수평 속도와 기울기
   - 되돌리기(revert)로 사라진 비행도 기록은 남깁니다. 실패 비행이 가장 중요한 근거 자료입니다.
2. **예측 대조** (기록기 안)
   - **감속**: 감속 시작 시점(스로틀이 0에서 0.5 이상으로 오르고 하강 중일 때)의 예측 `stop_distance`와, 실제로 수직 속도가 0이 되었거나 지면에 닿았을 때까지 내려간 거리를 비교합니다. 비율과 차이, 그 사이의 평균 기울기·평균 실제 추력과 예측 추력을 함께 남깁니다.
   - **추력·가속**: 엔진이 켜져 있는 동안 예측 추력과 실제 추력의 비율 분포를 남깁니다.
   - **Δv**: 단계별로 게임 계산값과 실제 사용량을 비교합니다.
   - 결과는 요약의 `checks[]`에 들어갑니다.
3. **MCP 도구** (App)
   - `list_flights`: 비행 목록과 요약. 기체 이름으로 거를 수 있습니다.
   - `get_flight_log`: 지정한 비행에서 구간(MET 범위)이나 이벤트 주변(전후 N초)만 잘라서 줍니다. 샘플 간격도 줄여 줄 수 있습니다(토큰 절약).
4. **계획에 사용**
   - 저장소 스킬 `ksp-flight-preflight`에 단계 하나를 추가합니다(사용자 확인 후 저장소 수정): 같은 기체나 비슷한 상황의 `checks`를 보고 감속 시작 여유와 Δv 여유를 정합니다.

## 단계별 계획 (예측 보정)
1. 기록 (이번)
2. 물리 보정: 대조 결과에서 오차가 큰 항목의 예측식을 고칩니다(수평 성분, 자세 기울기, 엔진 반응 지연, 항력 모델 등). 기록이 쌓인 뒤 따로 진행합니다.
3. 잔차 보정: 식을 고친 뒤에도 남는 오차를 기체·상황별 보정 계수로 맞춥니다(최소제곱 수준).
4. **검토 항목: ML 도입.**
   - 지금 미루는 이유:
     - 비행 수가 수십 번 수준이고 기체 설계가 매번 달라 일반화가 약합니다.
     - KSP 물리는 결정론적이라, 식을 고치는 쪽이 더 정확하고 실패 원인도 설명할 수 있습니다.
     - 모드가 net472(Unity)라 ML 라이브러리를 넣기 어렵습니다. 넣는다면 App(.NET 10) 쪽입니다.
   - 다시 검토할 조건: 기록이 수백 번 쌓였는데 2~3단계로 설명되지 않는 오차 패턴이 남을 때.
