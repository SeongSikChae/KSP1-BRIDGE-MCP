# 동력착륙 방안

## 문제

비행 계획의 Mode는 `attitude`, `gravity_turn`, `coast`, `circularize`뿐이다(0005-비행제어-설계.md "Mode"). 발사부터 궤도 진입까지만 다루고, 엔진 추력으로 감속해 지면에 내려앉는 제어는 없다. 0004-비행제어-방안.md "추후 대상"에 로켓 동력 착륙이 들어 있다. 0005는 계획 형식을 바꾸지 않고 Mode만 늘려 착륙을 받도록 해 두었다.

## 목표

- 준궤도·하강 궤적의 기체를 엔진 감속으로 지면에 내려앉힌다.
- 접지 속도와 부품 손실을 MCP 응답(`get_flight`, `get_flight_events`)으로 확인할 수 있다.

## 결정 (사용자 합의)

### 1. 시작 상태: 준궤도·하강 궤적

- 착륙 Mode는 준궤도·하강 궤적에 있는 기체에서 시작한다.
- 궤도 이탈(디오빗) 연소는 이 Mode의 범위가 아니다. 디오빗은 지금 있는 `attitude`(`reference: retrograde`)와 `periapsis` 조건으로 계획에 쓸 수 있다. 일반 궤도 기동은 #18이 다룬다.
- 기각: 궤도 상태이면 착륙 Mode가 스스로 디오빗 연소까지 하는 방식. 궤도 기동 계산이 #18과 겹친다.

### 2. 천체: 공통 로직, Kerbin 실측

- 감속 계산은 대기 유무와 관계없이 모든 천체에 같이 쓰는 로직으로 만든다.
- 이 이슈의 실측은 Kerbin 준궤도 착륙만 한다. MCP 도구만으로 Mun까지 가는 전이 도구는 아직 없다(#18). Mun 등 대기가 없는 천체의 착륙 실측은 #18 이후로 미룬다.
- 기각
  - Kerbin 전용: 대기가 없는 천체를 나중에 다시 손봐야 한다.
  - 이 이슈에서 Mun까지 실측: MCP 도구만으로 Mun에 갈 수 없어 완료 조건을 MCP 응답만으로 확인할 수 없다.

### 3. 착륙 지점: 그 자리 수직 착륙

- 수평 속도를 상쇄한 뒤 그 자리에 수직으로 내려앉는다. 목표 지점(위도·경도)을 정하지 않는다.
- 정밀 착륙은 별도 이슈 #22로 등록했다.
- 기각: 이 이슈에 정밀 착륙 포함. 예측 착지점 계산과 수평 유도가 더해져 범위와 위험이 크게 늘어난다.

### 4. 착륙 다리: Mode 인자로 자동 전개

- 착륙 Mode 인자(예: `gear_altitude`)로 정한 지면 고도 아래로 내려가면 Mode가 Gear action group을 켠다.
- 지금 있는 `ManualControl.TrySetGroup`(src/KspBridge.Logic/Flight/Control/ManualControl.cs)을 다시 쓴다. #15의 범용 action group 도구와는 따로 동작한다.
- 기각
  - `on_start`에 `gear` 동작 추가: #15의 범용 action group 실행과 겹친다.
  - #15로 미룸: 다리를 미리 펴 둔 기체만 착륙할 수 있다.

### 5. 감속: 정지 거리를 매 틱 다시 계산

- 매 틱 가용 추력·질량·중력으로 지금 속도에서 멈추는 데 필요한 거리를 구해 지면 고도(`altitude_radar`)와 비교한다.
- 감속 연소 시작 시점은 최대 추력의 일부만 쓴다고 보고 잡는다(여유). 연소 중에는 필요한 감속도에 맞춰 스로틀을 조절한다.
- 마지막 구간은 일정한 낮은 속도로 내려간다.
- 기각: 고도별 목표 하강 속도 프로파일을 PID로 따라가는 방식. 단순하지만 연료를 더 쓰고 기체마다 조정해야 한다.

### 6. 착륙 불가: 이벤트를 남기고 최대 감속 계속

- 연료·추력이 모자라 멈출 수 없다고 판정되면 이벤트(예: `landing_infeasible`)를 1회 남기고 최대 추력으로 감속을 계속한다. 충돌 속도를 줄이려는 것이다.
- 계획을 중단하고 싶으면 계획 `abort` 조건으로 지정한다.
- 기각: 계획 중단(`plan_aborted`). 스로틀이 0이 되어 충돌 속도가 커진다.

### 7. 완료: 접지·정지하면 스스로 완료

- `situation`이 `LANDED`(또는 `SPLASHED`)이고 속도가 일정 시간 작으면 스로틀을 0으로 두고 완료한다.
- 접지 순간의 수직·수평 속도를 이벤트(예: `touchdown`)로 남긴다.
- 기각: 스스로 완료하지 않고 계획의 `until` 조건에 맡기는 방식. 착륙마다 같은 조건을 사용자가 써야 한다.

### 8. 대기권: 공기 저항을 계산에서 빼고 매 틱 보정

- 정지 거리 계산에서 공기 저항을 뺀다. 저항은 감속을 도우므로 보수적인 쪽이다. 매 틱 다시 계산해 오차를 보정한다.
- 낙하산은 이 이슈의 범위가 아니다(#15 부속 제어).
- 기각: 낙하산 연동 포함. #15의 낙하산 제어와 겹친다.

## 설계로 넘기는 항목

- 정지 거리 식, 시작 여유 비율, 마지막 구간 하강 속도, 접지 속도 제한의 인자와 기본값
- 수평 속도 상쇄와 자세(surface retrograde, 저속에서 수직 전환), 자세 오차가 클 때 스로틀 처리
- 착륙 불가 판정 기준(가용 Δv·최대 감속도)과 판정이 풀릴 때 처리
- 정지 판정 속도·시간, `touchdown`·`landing_infeasible` 이벤트 필드
- 전복·부품 파손은 #14 `PartLossLog`(src/KspBridge.Logic/Flight/PartLossLog.cs)의 `part_lost`·`crash` 이벤트를 쓰고, 전복 판정을 따로 둘지 정한다
- 연소 중 스테이지 소진 시 `auto_stage`와의 관계
