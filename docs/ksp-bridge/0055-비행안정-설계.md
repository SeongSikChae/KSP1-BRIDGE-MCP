# 비행안정 설계 — 3단계-3: 자세 제어기 보정

방안: [0052-비행안정-방안.md](0052-비행안정-방안.md) 결정 3의 3번. 근거는 0052 "원인 판정 실측 결과"(원인 1·2·3 확인). 진단 도구는 [0053](0053-비행안정-설계.md).

## 범위

- 원인 1: 목표 각속도 곡선에 오차 0 근처의 선형 구간을 둔다. 선형 구간이 만드는 추종 지연은 목표 각속도 앞먹임으로 없앤다(결정 1-2).
- 원인 2: 축마다 실측 각가속도 이득을 실행 중에 추정해 바깥 루프(선형 구간 기울기, sqrt 감속 곡선)에 반영한다. 입력 정규화는 바꾸지 않는다. 전력이 없거나 꺼진 반작용휠은 가용 토크에서 뺀다.
- 원인 3: 이번에는 보상하지 않는다. 1·2를 적용한 뒤 같은 기체로 다시 재고, 지연 때문에 남는 진동이 있을 때만 따로 설계한다(사용자 합의).
- 진단 도구에 보정 상태(추정 이득·실효 `alpha`)를 더한다(기존 필드 유지, 추가만). 예외: `want_slope_at_amp`는 실제로 쓰는 곡선(선형 구간·추정 이득 반영)으로 계산하도록 바뀐다(결정 4).
- 비범위: StabR 같은 제어 능력 부족(공력 > 가용 토크)·상승 프로파일(#26), 2단계 감시기 판정, 롤 목표 없는 롤 축 제어 방식(그 축은 추정에서 빼고 지금처럼 둔다).

## 현재 제어기 (`AttitudeController.Steer`)

축마다:

- `alpha = max(가용 토크 / 관성모멘트, 1e-3)`
- `want = sign(err)·min(sqrt(2·alpha·|err|)·KStop, OmegaMax)` (`KStop` 0.8, `OmegaMax` 0.5 rad/s)
- `e = want − ω`, `a = Kp·e + Ki·∫e` (`Kp` 4, `Ki` 0.4), `input = clamp(−a/alpha, ±1)`

입력 정규화가 모델 `alpha`를 쓰므로, 실제 각가속도가 모델의 `g`배면 안쪽 속도 루프의 실효 이득은 `g·Kp`다(조종면 대기 구간 `g` 0.3~0.45 → 1.2~1.8 /s).

## 결정

### 1. 선형 구간 (원인 1, 사용자 합의: 고정 선형 구간)

- `want = sign(err)·min(g·KLin·|err|, sqrt(2·g·alpha·|err|)·KStop, OmegaMax)`, `KLin = Kp / 3 ≈ 1.33 /s`. `g`는 결정 2의 추정 이득(단위 3 전에는 1).
- 근거: 실측 진동 진폭에서 바깥 루프 이득(`want_slope_at_amp`)이 10~11 /s로 안쪽 속도 루프 대역(`Kp` 4 /s)보다 크고, 1.5 Hz 리미트 사이클과 맞는다. 바깥 루프 이득을 안쪽 실효 대역(`g·Kp`)의 1/3로 묶어 두 루프를 분리한다.
- 큰 오차에서는 지금처럼 `OmegaMax`와 sqrt 감속 곡선이 제한한다. 선형 항이 sqrt 곡선보다 작은 구간(`|err| < 0.72·alpha/g` rad)에서만 바뀌므로 가벼운 기체는 넓게, 무거운 기체는 좁게 적용된다.
- 선회 시간 영향(계산): `OmegaMax/KLin` = 0.375 rad(약 21°)보다 작은 오차는 시간 상수 `1/(g·KLin)`(g=1이면 0.75 s)의 지수 접근이 된다. StabT(`alpha` 약 2.6)의 90° 선회에서 오차 1° 도달 시간은 보정 전 약 3.4 s(정속 3.0 s + 감속), 보정 후 약 4.9 s(정속 2.4 s + 0.75·ln(21.5) ≈ 2.3 s)로 약 +45%다. 오버슈트는 없어야 한다.
- 롤 목표 없는 롤 축(`want` 0)은 바뀌지 않는다.

### 1-2. 목표 각속도 앞먹임 (검토 반영)

- 선형 구간은 비례 항뿐이라, 목표 방향이 각속도 `ω_t`로 돌면 오차가 `ω_t/(g·KLin)`에 머문다. 대기 구간(g 0.3~0.45)에서는 이 지연이 g=1일 때의 2~3배다(예: 상승 피치 프로그램 0.75°/s면 약 1.4~1.9°). 기존 sqrt 곡선은 0 근처 기울기가 커서 이 지연이 작았다.
- 대책: 피치·요 축 `want`에 목표 방향의 회전 각속도를 더한다. `want = 앞먹임 + sign(err)·min(...)`, 합은 `±OmegaMax`로 제한.
- 앞먹임 계산: 직전 틱의 목표 방향(세계 좌표 단위 벡터) `d0`를 보관하고, 목표 방향의 세계 좌표 회전 각속도 `ω_w = (d0 × d1)/dt`(작은 각에서 회전축 × 각속도)를 구한다. 이를 기체 좌표(`ReferenceTransform` 역회전)로 옮겨 x 성분을 피치, z 성분을 요 앞먹임으로 쓴다. 축 규약(x 양의 각속도는 기수(+y)를 +z로, z 양의 각속도는 기수를 −x로 돌린다)이 `err`의 피치(`atan2(dir.z, dir.y)`)·요(`atan2(−dir.x, dir.y)`) 부호와 같으므로 부호 변환은 없다. 축별 `atan2` 차분과 달리 오차 90° 근처의 특이점이 없고, 오차 0 근처에서는 같은 값을 준다(검토 반영).
- 필터: 원시 차분은 진행 방향 계열 목표의 방향 잡음을 1/dt배로 키우므로, 저역 통과(1차, 시간 상수 0.3 s)를 거친 값을 쓴다. 상승 피치 프로그램처럼 수 초 이상에 걸친 목표 회전은 그대로 통과하고 틱 단위 잡음은 걸러진다.
- 끊김 처리: 다음 때는 직전 방향을 무효화하고 필터 상태를 0으로 둔다. 계획 시작·단계 시작·단계 교체, 제어 기체 변경(`Attach`·`Retarget`·`Adopt`), 자세 제어가 멈췄던 틱(계획 없음, 자세 목표 없음, `Suspended`) 다음. 또 한 틱 사이 목표 방향 변화가 `1.5·OmegaMax·dt`(50 Hz에서 약 0.86°)를 넘으면 계단(기준 전환 등)으로 보고 그 틱의 원시 앞먹임을 0으로 둔다. 제어기가 따라갈 수 있는 최대 회전보다 빠른 목표 변화는 앞먹임으로 쫓지 않는다는 뜻이다. 앞먹임 크기는 `OmegaMax`로 제한한다.
- 롤 축은 앞먹임을 넣지 않는다(롤 목표는 대부분 고정이고, 롤 목표 없는 축은 `want` 0).
- 저주파 결합: 진행 방향 계열 목표(대기 중 `surface_prograde`·`gravity_turn`의 받음각 제한 등)는 기체 자세 진동이 받음각·양력을 거쳐 속도 방향을 흔들고, 그것이 앞먹임으로 되돌아올 수 있다. 0.3 s 필터는 수 초 주기의 결합을 거르지 못하므로, 진단 표본에 앞먹임 값을 기록해 단위 2·3 실측에서 크기를 본다. 앞먹임이 진동 진폭에 기여하면(앞먹임이 오차와 같은 주기로 흔들리면) 진행 방향 계열 목표에서 앞먹임을 끄는 것을 사용자와 정한다.
- 오차 0 근처의 바깥 루프 이득(`g·KLin`)은 그대로이므로 원인 1 대책과 겹치지 않는다.

### 2. 실측 이득 온라인 추정 (원인 2, 사용자 합의, 적용 위치는 검토 반영)

> **보류(2026-11-15, 사용자 결정):** 단위 2(선형 구간·앞먹임)만으로 StabS 상승 q 15~25 kPa 진동이 2.8°에서 0.02° 이하, StabT 유지 진동이 0.54°에서 0.001°로 줄어 이슈 완료 조건을 채웠다. 진동이 사라지자 가진이 부족해 `alpha_gain` 회귀가 성립하지 않아(결정계수 0 근처) 추정의 효과를 판별할 실측 근거가 없다. 실측 근거 없는 보정은 넣지 않는다는 0052 원칙에 따라 이 결정과 결정 4의 `gain_used`·`alpha_eff`는 구현하지 않는다. 조종면 효율이 낮은 기체에서 문제가 다시 실측되면 이 결정을 다시 연다.

- 추정: 축마다 진단 도구의 `alpha_gain`과 같은 모델. 각가속도 `y = Δω/Δt`를 `k`틱 앞 예측 가속 `x = −input·alpha`(모델 `alpha`)에 절편을 넣어 회귀한 기울기 `g`. 지수 망각 최소제곱(망각 시간 상수 약 3 s, 표본 가중치는 틱 시간 `dt`). `k` = 1~10을 같은 표본으로 모두 누적하고 결정계수가 가장 큰 `k`의 `g`를 쓴다.
- 적용: `gUsed = clamp(g, 0.2, 1.0)`를 결정 1의 선형 기울기와 sqrt 감속 곡선에만 쓴다. 입력 정규화(`input = −a/alpha`)는 모델 `alpha` 그대로다. `gUsed`는 추정 `g`를 시간 상수 약 1 s로 따라간다.
- 이렇게 두는 이유(검토 반영):
  - 조종면의 낮은 이득은 지연(3~7틱)과 함께 나타나 편향 속도 제한 효과일 수 있다. 입력을 1/g배로 키우면 속도 제한에 더 걸려 겉보기 이득이 더 내려가는 양의 되먹임이 생길 수 있다. 바깥 루프만 낮추면 입력은 커지지 않는다.
  - 폐루프 추정은 공력 토크와 상관돼 치우칠 수 있다. 과소 추정이면 바깥 루프가 느려질 뿐이고, 상한이 1.0이므로 과대 추정이어도 추정 없는 상태(단위 2, `g` = 1)보다 바깥 이득이 커지지 않는다. 실측 각가속도가 모델보다 큰 경우(`alpha_gain` > 1)는 보정하지 않는다(휠·짐벌 실측 0.87~0.96으로 해당 없음).
- 갱신 조건(모두 만족할 때만, 아니면 `gUsed` 유지): 결정계수 ≥ 0.5, 예측 가속 표준편차 ≥ 평균 크기의 1%, 망각 창의 유효 시간(가중치 합) ≥ 1 s, 한쪽 포화(포화 비율 ≥ 0.9이고 입력 부호 불변)가 아님. 실측 결정계수는 피치·요 0.69~0.99로 조건을 충족한다(0052).
- 대상 축: 피치·요, 그리고 롤 목표가 있는 롤. 롤 목표가 없는 롤 축은 추정하지 않고 `gUsed` = 1.
- 초기화(`gUsed` = 1, 누적 0): 제어 기체 변경(`Attach`가 새 기체에 붙을 때, 도킹 결합 포함), 토크 제공자 캐시 재생성(부품 수 변화: 스테이징·분리), 계획이 없던 상태에서 새 계획 시작. 실행 중인 계획을 교체할 때는 초기화하지 않는다(같은 기체·같은 조건의 보정 유지).
- 근거: 조종면이 주력인 대기 구간에서 `alpha_gain` 0.30~0.45, 동압이 내려가면 0.65~0.80으로 변한다(0052 표). 고정 계수로는 이 범위를 맞출 수 없고, 휠·짐벌(0.87~0.96)은 추정이 1 근처에 머문다.

### 3. 동작하지 않는 반작용휠 제외 (원인 2 계열)

- `AvailableTorque`에서 `ModuleReactionWheel`은 휠 상태가 동작(`wheelState` 활성)이 아니거나 기체의 `ElectricCharge` 잔량이 0이면 0으로 센다. 잔량은 기존 코드처럼 `Vessel.GetConnectedResourceTotals`로 읽는다(토크 캐시를 만들 때가 아니라 매 틱). 전력 판정에는 히스테리시스를 둔다: 잔량이 0(1e-6 이하)이 되면 끄고, 최대 용량의 1% 이상이 되면 다시 켠다(충전과 소비가 0 근처에서 맞물릴 때 휠 토크가 틱마다 들락거리지 않게). 이 상태는 제어 기체가 바뀔 때만 켠 상태로 초기화하고, 분리(부품 수 변화)로는 바꾸지 않는다.
- 근거: 단위 4의 StabC(전력 0, 휠 "대기")에서 가용 토크 15.3이 그대로 잡혀 제어기가 반응 없는 입력 −0.97을 계속 냈다.

### 4. 진단 도구 확장

- 표본에 축별 앞먹임 `Ff`(rad/s)를 더하고, 요약에 `ff_rms`(축별 앞먹임 RMS), 시계열 축 항목에 `ff`를 추가한다(결정 1-2의 저주파 결합 확인용).
- (보류: 결정 2와 함께 구현하지 않음) 표본에 축별 `GainUsed`를 더한다. 축별 요약에 `gain_used`(평균), `alpha_eff`(= `gain_used`·`alpha_model`, 평균)를 추가한다. `alpha_model`·`alpha_gain`은 지금 정의 그대로(모델 대비 실측)이므로, 보정이 맞으면 `alpha_gain`은 그대로 낮고 `gain_used`가 그 값을 따라간다.
- `want_slope_at_amp`는 실제 곡선으로 계산한다: 동작점 `e`에서 `g·KLin·e`, sqrt(`g·alpha`), `OmegaMax` 가운데 가장 작은 항의 기울기(`g·KLin`, sqrt 기울기, 0). preserve "get_controller_trace 동작"의 명시적 예외다.
- 도구 설명·ReadMe에 구현한 진단 필드(`ff_rms`·시계열 `ff`)와 `want_slope_at_amp` 정의 변경을 적는다. 기존 필드 이름·인자는 바꾸지 않는다.

## 영향

- 자세 제어 출력이 바뀐다(의도한 변경). 1·2단계 감시기 판정·이벤트는 바뀌지 않는다.
- `Routes.Version` 올림. 물리 틱마다 축 3개 × `k` 10개의 누적 갱신과 기체 전력 조회 한 번이 더해진다(할당 없음).

## 검증 (MCP 응답으로만)

보정 전 값은 0052 "원인 판정 실측 결과".

1. StabT 궤도 `prograde` 유지 20 s: 피치·요 `osc_amp_deg`가 0.50°에서 0.1° 이하, `plan.monitor`에 `oscillation` 경고 없음.
2. StabT 궤도 `radial_out` 선회(90°): `attitude_error` < 1° 도달 시간이 휠 제외만 적용한 버전 대비 +60% 이내(계산 +45%, 안쪽 루프 동특성·측정 편차 여유), `series`에서 오차가 반대 부호로 1° 넘게 넘어가지 않음(오버슈트 없음). 기준을 넘으면 `KLin` 조정(예: `Kp`/2.5) 여부를 사용자에게 묻는다.
