# KspBridge 발사 중계 — 인게임 소리 녹음 방안

선행 기능: [0026-발사중계-방안.md](0026-발사중계-방안.md) · [0027-발사중계-설계.md](0027-발사중계-설계.md)

## 문제·목표
- 지금 중계 영상의 오디오는 안내 음성과 비프음만 들어 있습니다.
  - 화면 녹화(`gfxcapture`)는 영상만 받습니다.
  - 이 PC의 ffmpeg에는 오디오 입력 장치가 없습니다(dshow 오디오 장치 0개, WASAPI 장치 없음).
- 목표: 엔진 소리, 분리음 같은 KSP 소리를 영상에 함께 넣습니다. 다른 앱 소리(알림, 음악)는 들어가지 않아야 합니다.

## 검토한 대안
| 대안 | 받는 소리 | 판단 |
|---|---|---|
| **프로세스 루프백**(Windows 10 2004 이상, `ActivateAudioInterfaceAsync` + `PROCESS_LOOPBACK`) | KSP 프로세스 소리만 | **채택**. 추가 설치가 없고 다른 소리가 섞이지 않습니다 |
| 시스템 루프백(WASAPI loopback) | 스피커로 나가는 소리 전부 | 다른 앱 소리가 섞입니다 |
| 가상 오디오 장치 + ffmpeg dshow | 장치로 보낸 소리 | 별도 설치와 장치 전환이 필요합니다 |

## 채택 방안
1. **App에 게임 소리 녹음기를 추가합니다.**
   - 화면 녹화를 시작할 때 KSP 프로세스(`KSP_x64`)의 소리를 프로세스 루프백으로 함께 녹음합니다.
   - 녹음은 중계 폴더의 `game.wav`(48 kHz, 16-bit, 스테레오)에 씁니다.
   - KSP가 소리를 내지 않는 동안에는 패킷이 오지 않습니다. 그래서 흐른 시간만큼 무음을 채워, 파일 길이가 실제 녹화 시간과 같게 유지합니다(싱크).
   - 녹음 시작 시각을 영상 녹화의 기준 시각(첫 프레임)과 같은 시계로 잽니다.
2. **합성할 때 섞습니다.**
   - 게임 소리를 녹음 시작 오프셋만큼 맞춰 놓습니다.
   - 안내 음성과 비프음이 나오는 동안에만 게임 소리를 자동으로 낮춥니다(ffmpeg `sidechaincompress`, 덕킹).
3. **녹음에 실패하면 게임 소리 없이 계속합니다.**
   - 사운드 장치가 없거나, Windows 버전이 지원하지 않거나, KSP 프로세스를 찾지 못하면 경고만 남깁니다.
   - 녹화, 카운트다운, 점화는 그대로 진행합니다.
   - 상태 조회에 `gameAudio`(녹음했는지)와 실패 이유를 보여 줍니다.
4. **설정**
   - `Broadcast.GameAudio`(기본 true): 게임 소리를 녹음할지 정합니다.
   - `Broadcast.GameVolume`(기본 1.0): 게임 소리 볼륨입니다.
   - 원본 `game.wav`는 중계 폴더에 남깁니다.

## 결정 (2026-11-08 사용자)
- 방식: KSP 프로세스만 루프백 녹음
- 섞는 방법: 안내 음성이 나오는 동안만 게임 소리를 낮춤(덕킹)
- 녹음 실패 시: 게임 소리 없이 계속
- 설정: `GameAudio`로 켜고 끄며, 기본은 켜짐

## 비범위
- 마이크 입력, 다른 앱 소리
- 게임 소리 노이즈 제거, 음량 정규화(덕킹과 볼륨 설정만 합니다)
- Windows 10 2004 미만 지원(이 경우 게임 소리 없이 계속합니다)

## 참고
- 2026-11-08 현재 이 PC에는 사운드 장치가 잠시 빠져 있습니다. 실제 녹음 검증은 장치를 연결한 뒤에 합니다.
