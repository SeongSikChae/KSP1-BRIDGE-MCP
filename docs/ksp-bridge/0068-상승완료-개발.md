## A1. 완료 원지점 99% 띠

**대상**
- `src/KspBridge.Logic/Flight/Modes/GravityTurnMode.cs`: `Update`, 새 상수 `KeepBand`, 클래스 주석의 완료 문장
- `src/KspBridge.App.Tools/FlightTools.cs`: `gravity_turn` 설명의 완료 문장
- `ReadMe.md`: `gravity_turn` 행 완료 조건 칸

**코드 초안**

```csharp
/// <summary>Reached-target band on a body with air: inside the atmosphere top up below it, above the atmosphere complete at or above it.</summary>
private const double KeepBand = 0.99;

// Update, after predictedAp / throttle / inAtmo:
if (_reached && inAtmo)
{
    target = LimitAoa(v, AttitudeTarget.SurfacePrograde(), q);
    throttle = predictedAp < KeepBand * _targetAp ? throttle : 0;
}
// Once reached, the drag after the last top-up may leave the apoapsis just under the target: the keep band completes it
// (measured: 75,971 of 76,000 m left the atmosphere, then a horizontal 5% top-up near apoapsis never reached 100%).
double doneAp = _reached && v.mainBody.atmosphere ? KeepBand * _targetAp : _targetAp;
if (!inAtmo && predictedAp >= doneAp)
{
    throttle = 0;
}
Done = !inAtmo && predictedAp >= doneAp && throttle <= 0;   // a body without air: inAtmo is always false
return new ModeCommand(target, throttle);
```

```csharp
// FlightTools gravity_turn: "completes above the atmosphere once the apoapsis is reached at throttle 0" ->
"completes above the atmosphere at throttle 0 once the predicted apoapsis is at the target (on a body with air 99% of it after the target was once reached, drag may trim it); "
```

ReadMe `gravity_turn` 완료 칸: "대기권 밖에서 예측 원지점 ≥ 목표(대기가 있는 천체에서 목표에 한 번 닿았으면 목표의 99%), 스로틀 0".

**검증**
- `dotnet build` 경고·오류 0, `dotnet test tests/KspBridge.App.Tests` 통과.
- 실측(KSP, 같은 기체 `U5d 재진입 시험`, 같은 계획 `gravity_turn` `target_apoapsis` 76000 → `circularize`, `auto_stage: true`)
  - 대기권을 벗어나기 직전(고도 65~70 km)과 직후 `get_flight` `orbit.apoapsis`를 기록한다.
  - `gravity_turn` `step_completed`가 대기권 밖(고도 > 70 km)에서 나오고, 단계가 원지점 도달 전(`time_to_apoapsis` > 0, 수직 속도 > 0)에 끝난다.
  - 대기권 밖 보충 연소는 원지점 도달 전에 끝나면 허용한다(대기권을 99% 바로 아래로 벗어나면 `ApThrottle`로 보충한 뒤 99%에서 완료하는 것이 설계 동작). 대기권 밖 스로틀이 0이었는지, 보충했다면 그 스로틀과 시간은 기록만 한다.
  - `circularize`가 이어서 궤도 투입(근지점 > 70 km)한다.
  - 띠 경로 확인: `step_completed` 직후(다음 `circularize` 연소 전, 스로틀 0이라 원지점이 그대로인 동안) `get_flight` `orbit.apoapsis`를 기록한다. 이 값이 목표의 99~100%면 띠 경로를 거친 것이다. 대기권 밖 보충 뒤 99~100%에서 완료한 경우도 띠 경로로 센다(목표에 닿은 뒤의 99% 완료 기준으로 끝났으므로).
  - 띠 경로를 거칠지는 목표값이 아니라, 목표에 닿은 뒤 대기권을 벗어날 때까지 공기 저항이 깎는 원지점의 양이 정한다. 목표를 바꾸면 스로틀 프로그램이 새 목표까지 연소하므로 완료 원지점도 따라 바뀌어 소용없다.
  - 그래서 띠 경로를 거치지 않았으면(완료 원지점이 목표의 100% 이상) 같은 기체·같은 목표(76000)로 다시 비행하되 선회를 눕힌다. `turn_end_altitude`를 45000(기본값)에서 35000으로, 그래도 거치지 않으면 30000으로 낮춘다. 그러면 더 낮고 짙은 대기에서 목표에 닿아, 대기권 이탈까지 공기 저항이 깎는 양이 커진다. 깎인 원지점이 99% 아래로 내려가면 대기권 안 보충이 99%까지 채우고 끊으므로, 대기권 이탈 때 원지점은 99% 근처로 모인다.
  - 각 재비행에서 목표에 처음 닿은 고도(`get_flight` 스로틀이 0이 된 시점의 고도)와 대기권 이탈 직전·직후 원지점을 기록해, 깎이는 양이 커졌는지 확인한다.
  - 최대 2회 더 비행해도 띠 경로를 거치지 않으면 띠 경로 미확인으로 보고하고, 기록한 깎인 양을 함께 적는다. 과열(`monitor_alert overheat`)이 나면 더 낮추지 않는다.

**실측 결과 (2026-11-16, 1회)**
- 같은 기체·같은 계획(`gravity_turn` 76000 → `circularize`, `auto_stage`). 고도 68 km에서 원지점 75,410 m(99.22%), 스로틀 0.
- `gravity_turn` `step_completed` MET 213.5초(대기권 이탈 직후, 원지점 약 48초 전). 완료 뒤 원지점 75,409 m(99.22%)로 띠 경로를 거침. 대기권 밖 보충 연소 없음(`stage_dv` 1407.3 m/s 그대로).
- `circularize` 완료, `plan_completed`. 궤도 근지점 74,804 m, 원지점 75,377 m. 재비행 불필요.
- `dotnet build` 경고·오류 0, `dotnet test tests/KspBridge.App.Tests` 44개 통과.
- 구현 검토 뒤 반영(사용자 요청): `doneAp`에 대기권 높이 하한(`Math.Max(KeepBand * _targetAp, v.mainBody.atmosphereDepth)`), `FlightTools` 설명 끝 공백 누락. 목표 76000에서는 99%(75,240 m)가 하한보다 커서 위 실측 경로의 값은 같다.
