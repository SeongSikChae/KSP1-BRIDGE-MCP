방안 `0035`의 6·7번을 다룹니다. 8번 스킬 문서는 묶음 C 구현 뒤 별도로 진행합니다(Bizadm 문서라 코드 설계가 없음).

| 항목 | 결정 |
|---|---|
| 선회 방식 | 선회 시작 속도에서 지정 각도만큼 킥 → 이후 `surface_prograde` 추종 + 받음각 제한 |

## 6. 상승 유도 `ascent_guidance`

### 구조
- 새 `Flight/AscentGuidance.cs`: `NodeExecutor`와 같은 게임 안 상태 기계(비동기). MCP 호출은 계획을 즉시 돌려주고, 진행은 `wait_until field ascent_state`로 봅니다.
- 자세는 `AttitudeController.Set(v, "own", frame, …, maxAoa)`, 스로틀은 `ThrottleLock`을 재사용합니다. 소유권 판정(`overridden`)도 `NodeExecutor`와 같은 방식입니다.
- 이상 판정은 `AnomalyMonitor.ControlLost`·`PartsDied`를 재사용합니다.
- 단 경고는 묶음 A의 `CraftAnalysis.FromVessel` + `StageWarnings`/`Drops`를 재사용합니다.

### 인터페이스
`POST /api/ascent/start`
| 인수 | 기본값 | 뜻 |
|---|---|---|
| `target_apoapsis` | 필수 | 목표 원지점 고도(m, 해수면 기준). 대기권 높이보다 커야 함 |
| `heading` | 90 | 방위(°) |
| `turn_start_speed` | 60 | 킥을 시작할 지표 속도(m/s) |
| `turn_angle` | 10 | 킥 각도(°, 수직에서 기울일 양). 선회 강도 |
| `max_aoa_deg` | 5 | 선회 중 받음각 제한(묶음 B 규칙: 동압 ≥ 1 kPa에서만) |
| `auto_stage` | true | 연소 단 고갈 시 자동 분리 |
| `ap_tolerance` | 200 | 활공 중 원지점이 목표보다 이만큼 낮아지면 재연소(m) |

`POST /api/ascent/cancel`: 스로틀 0, 자세 유지 해제, 상태 반환.

응답(start): `state`, `target_apoapsis`, `atmosphere_height`, `stages`(남은 단 Δv 요약), `warnings`.

### 상태
`idle → launching → vertical → kick → gravity_turn → coasting ⇄ correcting → done | aborted`

| 상태 | 자세 | 스로틀 | 다음 |
|---|---|---|---|
| launching | surface 90°/heading | 1 | PRELAUNCH면 다음 단을 한 번 활성화(점화). 분리 경고 검사는 자동 분리와 같음 |
| vertical | surface 90°/heading | 1 | 지표 속도 ≥ `turn_start_speed` |
| kick | surface (90−turn_angle)°/heading | 1 | 지표 진행 방향의 피치 ≤ 목표 피치 + 1° (진행 방향이 킥 각도를 따라잡음) |
| gravity_turn | `surface_prograde`, `max_aoa_deg` | 원지점이 목표에 가까우면 줄임(아래) | 원지점 ≥ 목표 → 엔진 차단 |
| coasting | `prograde` | 0 | 대기권 밖 → done / 원지점 < 목표 − `ap_tolerance` → correcting |
| correcting | `prograde` | 작게(아래) | 원지점 ≥ 목표 → coasting |

- 스로틀 감소: `throttle = clamp((target − Ap) / (max_accel · 10 s 동안의 원지점 증가 추정), 0.05, 1)`. 개발 단계에서 원지점 증가율(dAp/dt)을 측정해 정합니다.
- 대기권이 없는 천체에서는 coasting에서 바로 done입니다.
- 시작 조건: PRELAUNCH, LANDED, FLYING(상승 중 이어받기). 시간 가속 중, `execute_node` 실행 중이면 거부합니다.
- done 뒤에는 스로틀 0 잠금을 풀고 `prograde` 자세 유지는 남깁니다(이어서 `warp_to ap`, 순환화 노드 실행이 자연스럽도록). 결과에 이를 명시합니다.

### 자동 분리 규칙
- 분리 조건(둘 중 하나):
  1. 점화된 엔진이 하나도 추력을 내지 못함(모두 flameout 또는 없음).
  2. 다음 단이 떨어뜨릴 부품(`Drops`) 안의 엔진이 모두 flameout이고, 그 단이 아직 타는 엔진은 떨어뜨리지 않음(부스터 분리).
- 분리 전 검사: 그 단의 `StageWarnings`가 있으면 분리하지 않고 `aborted`(`stage_warning`, 경고 문구 포함).
- 분리 뒤 1 s 동안 다시 분리하지 않습니다. 분리 뒤에도 추력이 없고 남은 단이 없으면 `aborted`(`out_of_fuel`).
- `auto_stage=false`면 1번 조건에서 `aborted`(`flameout`).

### 중단 사유
`vessel_changed`, `overridden`(다른 도구가 자세·스로틀을 가져감), `control_lost`, `part_lost`(분리 외 부품 파괴), `stage_warning`, `out_of_fuel`, `flameout`, `cancelled`.

### 비행 필드·기록
- `FlightFields`: `ascent_state`(문자열 `==`).
- `FlightRecorder.AscentEvent(state, detail)`: 상태 전이, 자동 분리(단 번호, 사유), 중단 사유.
- `Routes` 버전 0.14.0.

### MCP 도구
- `FlightTools.AscentGuidance(targetApoapsis, heading, turnStartSpeed, turnAngle, maxAoaDeg, autoStage, apTolerance)`, `CancelAscent()`.
- 설명에 "발사대에서 바로 호출 가능, 점화 전 preflight(get_stages Δv 확인)는 호출 전에 할 것", "done 뒤 순환화는 add_maneuver_node + execute_node"를 적습니다.
- `TriggerTools.Fields`에 `ascent_state` 추가.

## 7-1. 웨이포인트 좌표 (`list_contracts`)
- `CareerHandler.Describe(Contract c)`에 `waypoints` 배열을 추가합니다(없으면 키 생략, 기존 필드 유지).
- 출처: `FinePrint.WaypointManager.Instance().Waypoints` 중 `contractReference == c`.
- 항목: `name`, `body`(celestialName), `latitude`, `longitude`, `altitude`, `on_surface`(isOnSurface), `parameter`(웨이포인트를 쓰는 계약 조건 제목, 찾을 수 있으면).

## 7-2. 기체 읽기 `read_craft`

### 인터페이스
`GET /api/craft/read?name=…&facility=VAB|SPH` → `{ name, facility, part_count, design, warnings }`. `design`은 `build_craft`의 `design` 인수에 그대로 넣을 수 있는 트리입니다.

### 변환
- .craft를 `ConfigNode.Load`로 읽어 PART 노드만 해석합니다(게임 객체를 만들지 않음).
- 부품 이름: `part = name_id`에서 `_id`를 떼어 부품 이름으로 씁니다.
- 부모·자식: `attN = 노드,부품id`·`srfN = srfAttach,부품id`로 연결을 복원합니다. 루트는 첫 PART입니다.
- 스택 자식: 자식의 `attN`가 부모를 가리키는 쪽이 자식 노드, 부모의 `attN`가 자식을 가리키는 노드를 `node`로 씁니다.
- 표면 부착:
  - `sym`으로 묶인 대칭 사본은 하나의 `radial` 항목으로 합칩니다(`symmetry` = 사본 수).
  - `angle` = 부모 좌표계에서 atan2(x, z)(첫 사본 기준), `height` = 부모 좌표계 y − 부모 메시 중심 y(`CraftBuilder.LocalBounds` 재사용).
  - 표면 부착 부품의 자식이 다시 표면 부착이면 `node: "srf"`.
- `stage`: 스테이징 아이콘이 있는 부품(엔진, 분리기, 낙하산)에 파일의 `istg`를 넣어 원래 스테이징을 유지합니다.
- `thrust_limit`: ModuleEngines(FX)의 `thrustPercentage`가 100이 아니면 넣습니다.
- `resources`: 남은 양이 가득이 아니면 `amount/maxAmount`를 넣습니다.

### 왕복 검사와 경고
- 만든 트리를 `CraftBuilder`로 dry run 해 부품별 위치·회전을 원본과 비교합니다(순서로 짝지음).
- 위치 차이 > 0.05 m 또는 회전 차이 > 2°이면 `warnings`에 `경로: 부품 이름 위치 0.32 m / 회전 5° 차이(오프셋·회전 편집)`를 적습니다.
- 트리로 표현할 수 없는 연결(표면 부착 부품의 스택 자식이 부모 노드를 못 찾는 경우 등)은 가장 가까운 표현으로 넣고 `warnings`에 사유를 적습니다.
- 대칭 사본이 서로 다른 자식을 가지면 첫 사본 기준으로 쓰고 경고합니다.

### MCP 도구
- `CraftTools.ReadCraft(name, facility = "VAB")`. 설명: "기존 기체를 고칠 때 이 결과를 고쳐 build_craft(dryRun) → 저장. warnings가 있으면 다시 만든 기체는 원본과 위치가 다르다."

## 의존성·재사용
| 재사용 | 쓰는 곳 |
|---|---|
| `AttitudeController.Set`(frame, maxAoa) | 상승 유도 자세 |

| `CraftAnalysis.FromVessel`, `StageWarnings`, `CraftEstimator.Drops` | 자동 분리 검사 |
| `CraftBuilder`(dry run), `LocalBounds` | read_craft 높이 계산·왕복 검사 |

## 비범위
- 순환화 노드 자동 생성(사용자가 `add_maneuver_node` + `execute_node`로 이어 감)
- 최대 동압 스로틀 제한, 경사 궤도 방위 계산(방위는 인수로만 받음)
- read_craft의 SPH 고유 배치(날개 미러 등) 정밀 재현 — 근사 + 경고

## 위험
- 킥 각도·선회 시작 속도는 기체 TWR에 따라 적정값이 다릅니다. 시험 비행으로 기본값을 확인합니다.
- 부스터 분리 판정은 `Drops`가 맞아야 합니다(묶음 A에서 폭발 노드 규칙으로 통일, VAB 비교 확인됨).
- 시험 비행은 무인 기체로 하고, 유인이면 메모리의 안전 수칙(하강 시간 계산, 낙하산 트리거 먼저)을 지킵니다.
