# 기체전환 개발

이슈: [#19 비행 도구: 다른 기체로 전환](https://github.com/SeongSikChae/KSP1-BRIDGE-MCP/issues/19)
방안: [0034-기체전환-방안.md](0034-기체전환-방안.md) · 설계: [0035-기체전환-설계.md](0035-기체전환-설계.md)

## 공통

- 실측은 MCP 응답(`get_status`, `get_flight`, `list_vessels`, `get_flight_events`)으로만 확인한다. 게임 화면이나 키 입력에 기대지 않는다.
- 장면을 바꾸기 전에 `get_status`로 현재 장면과 실행 중인 계획을 먼저 확인한다.
- Logic DLL을 빌드한 뒤 `reload_mod`로 교체한다. 커밋하는 단위마다 `Routes.cs`의 Logic 버전을 patch 단위로 올린다(현재 0.2.37).
- 순서: 1 → 2 → 3 → 4. 단위마다 구현 → 검증 → 커밋 여부를 확인한다.

## 단위 1. `list_vessels`를 비행 밖 장면으로 확장

**대상**
- 신규 `src/KspBridge.Logic/Flight/VesselSwitch.cs`: `ListScopeActive()`, `Candidates()` (단위 2가 같은 파일에 전환 로직을 더한다)
- `src/KspBridge.Logic/Handlers/FlightHandler.cs`의 `GET /api/vessels`
- `src/KspBridge.Logic/Flight/Targeting.cs`의 `List`: 순회 원본을 `VesselSwitch.Candidates()`로

**코드 초안**

```csharp
// FlightHandler.cs
yield return new Route("GET", "/api/vessels", (m, b, q) =>
{
    // ... include_debris 검사 기존 ...
    return Flight.Targeting.List(VesselSwitch.ListScopeActive(), d == "true");
});

// VesselSwitch.cs
/// <summary>list_vessels and switch_vessel read the same vessels (design decision 9).</summary>
internal static IEnumerable<Vessel> Candidates() => FlightGlobals.Vessels;

/// <summary>FLIGHT: the active vessel (409 not_in_flight / no_active_vessel as before);
/// SPACECENTER·TRACKSTATION: null (no active vessel, distance null).</summary>
internal static Vessel ListScopeActive()
{
    GameScenes s = HighLogic.LoadedScene;
    if (s == GameScenes.SPACECENTER || s == GameScenes.TRACKSTATION)
    {
        FlightReset.RequireSceneReady();
        return null;
    }
    return Guard.ActiveVessel();
}

// Targeting.List
foreach (Vessel x in VesselSwitch.Candidates())   // was FlightGlobals.Vessels
```

- `Targeting.List`는 이미 `active == null`을 처리한다(거리 `NaN` → `OrbitMath.Num` null, 정렬 키 `double.MaxValue`). `List.Sort`는 안정 정렬이 아니므로, 거리가 모두 같을 때 원래 순서를 지키려면 `rows = rows.OrderBy(Dist).ToList()`(안정 정렬)로 바꾼다. FLIGHT의 거리순 결과는 그대로다.
- SPACECENTER에서 `FlightGlobals.Vessels`가 비어 있다고 실측되면 여기서 대체 분기를 넣지 않는다. 설계 결정 9를 회귀해 다시 검토한다(설계 확인 항목).

**검증**
- Logic 빌드 성공
- FLIGHT: `list_vessels` 응답이 이전과 같다(필드, 거리순).
- SPACECENTER·TRACKSTATION: 저장된 기체가 나오고 `active=false`, `distance=null`이다.
- EDITOR: 409 `not_in_flight`

**선행 단위**: 없음

## 단위 2. `switch_vessel` 재로드 없는 전환과 `reset.switch`

**대상**
- `src/KspBridge.Logic/Flight/VesselSwitch.cs`: 상태, `Hook`·`Unhook`, `Switch`, `Tick`, `StatusCopy`
- `FlightHandler.cs`: `POST /api/flight/switch`
- `BridgeLogic.cs`: Hook(실패 시 unhook 목록 포함), Unhook, Tick 추가
- `FlightReset.cs`: `Status()`에 `switch`, 접근자 `SceneReady`, `Save`를 internal로
- `TimeWarpControl.cs`: 정지 부분을 `internal static void StopAll()`로 꺼냄(`Set(0, …)`이 그대로 부른다)

**코드 초안**

```csharp
public sealed class VesselSwitch
{
    private static VesselSwitch _hooked;
    private static uint? _targetId;                       // null: no switch pending
    private static string _path;                          // in_scene | reload
    private static float _deadline;                       // realtime
    private static Dictionary<string, object> _status;    // get_status reset.switch

    public static void Hook()
    {
        Unhook();
        VesselSwitch s = new VesselSwitch();
        GameEvents.onGameSceneLoadRequested.Add(s.OnLoadRequested);   // instance handler: EvtDelegate reads Target.GetType()
        _hooked = s;
    }

    public static void Unhook()   // not handed over (design decision 3)
    {
        VesselSwitch s = _hooked;
        _hooked = null;
        _targetId = null;
        _status = null;
        if (s != null)
        {
            GameEvents.onGameSceneLoadRequested.Remove(s.OnLoadRequested);
        }
    }

    private void OnLoadRequested(GameScenes scene)
    {
        if (_targetId != null && (_path == "in_scene" || scene != GameScenes.FLIGHT))
        {
            Finish("failed", "scene_changed");
        }
    }

    public static object Switch(RequestBody b)
    {
        double idArg = b.GetDouble("vessel_id");
        if (idArg != Math.Floor(idArg) || idArg <= 0 || idArg > uint.MaxValue)
        {
            throw ApiException.BadRequest("vessel_id must be a vessel id from list_vessels");
        }
        // pre-checks in the design's error-table order; none changes game state
        FlightReset.RequireNoPendingRecovery();
        if (_targetId != null)
        {
            throw new ApiException(409, "switch_pending", "a vessel switch is in progress (get_status reset.switch)");
        }
        FlightReset.RequireSceneReady();
        FlightReset.RequireStockGame("switch_vessel");
        GameScenes scene = HighLogic.LoadedScene;
        bool flight = scene == GameScenes.FLIGHT;
        if (!flight && scene != GameScenes.SPACECENTER && scene != GameScenes.TRACKSTATION)
        {
            throw ApiException.SceneNotAllowed("switch_vessel");
        }
        Vessel active = flight ? Guard.ActiveVessel() : null;   // 409 no_active_vessel
        if (Coordinator.Running)
        {
            throw new ApiException(409, "plan_running", "a flight plan is running; abort_flight first");
        }
        uint id = (uint)idArg;
        Vessel target = Candidates().FirstOrDefault(x => x != null && x.persistentId == id && x.state != Vessel.State.DEAD)
            ?? throw new ApiException(404, "vessel_not_found", "no vessel with id " + id + " (use list_vessels)");
        if (target.vesselType == VesselType.Flag || target.vesselType == VesselType.SpaceObject
            || target.DiscoveryInfo.Level != DiscoveryLevels.Owned)
        {
            throw new ApiException(409, "not_switchable", target.vesselName + " (" + target.vesselType + ") cannot be flown");
        }
        if (target == active)
        {
            _status = Row(target, "done", null, false);
            _status["already_active"] = true;
            return new Dictionary<string, object> { ["accepted"] = true, ["vessel"] = target.vesselName, ["id"] = target.persistentId, ["already_active"] = true };
        }
        string path = flight && target.loaded ? "in_scene" : "reload";
        if (path == "reload" && flight)
        {
            ClearToSaveStatus c = FlightGlobals.ClearToSave(false);
            if (c != ClearToSaveStatus.CLEAR)
            {
                throw new ApiException(409, "switch_unavailable", "cannot leave " + active.vesselName + " now: " + c);
            }
        }
        if (path == "reload")
        {
            // unit 2 only: unit 3 replaces this with the reload execution
            throw new ApiException(409, "not_supported", "switching to an unloaded vessel or from outside flight is not implemented yet");
        }
        bool warpLowered = LowerWarp();
        Control.ManualControl.StopPulse("switch");
        Begin(target, path, warpLowered);
        try
        {
            if (!FlightGlobals.ForceSetActiveVessel(target))
            {
                Finish("failed", "switch_refused");
                throw new ApiException(409, "switch_refused", "the game refused to switch to " + target.vesselName);
            }
        }
        catch (ApiException)
        {
            throw;
        }
        catch (Exception e)
        {
            Finish("failed", e.GetType().Name + ": " + e.Message);
            throw new ApiException(500, "switch_failed", "switching to " + target.vesselName + " failed: " + e.Message);
        }
        return new Dictionary<string, object>
        {
            ["accepted"] = true, ["vessel"] = target.vesselName, ["id"] = target.persistentId, ["path"] = path, ["warp_lowered"] = warpLowered,
        };
    }

    /// <summary>BridgeLogic.FixedUpdate after FlightReset.Tick, and StatusCopy. Never throws.</summary>
    public static void Tick()
    {
        if (_targetId == null)
        {
            return;
        }
        try
        {
            bool ready = HighLogic.LoadedScene == GameScenes.FLIGHT && FlightReset.SceneReady;
            Vessel v = ready ? FlightGlobals.ActiveVessel : null;
            bool onTarget = v != null && v.persistentId == _targetId;
            if (Time.realtimeSinceStartup > _deadline)
            {
                // paused game (timeScale 0): the switch happened but unpacking waits for physics
                Finish(onTarget ? "done" : "failed", onTarget ? null : "timeout", unpacked: onTarget ? !v.packed : (bool?)null);
                return;
            }
            if (!ready)
            {
                return;
            }
            if (_path == "in_scene" && !Candidates().Any(x => x != null && x.persistentId == _targetId))
            {
                Finish("failed", "vessel_lost");
            }
            else if (onTarget && !v.packed)
            {
                Finish("done", null, unpacked: true);
            }
            else if (_path == "reload" && v != null && !onTarget)
            {
                Finish("failed", "wrong_vessel");
            }
        }
        catch (Exception e)
        {
            Finish("failed", e.GetType().Name + ": " + e.Message);
        }
    }

    /// <summary>Warp-to pending, a non-zero rate, or rails rate still easing down (Warp.cs easing: HIGH and CurrentRate > 1).</summary>
    private static bool LowerWarp()
    {
        TimeWarp w = TimeWarp.fetch;
        if (w == null)
        {
            return false;
        }
        bool warping = Warp.Pending || TimeWarp.CurrentRateIndex > 0
            || (TimeWarp.WarpMode == TimeWarp.Modes.HIGH && TimeWarp.CurrentRate > 1f);
        if (warping)
        {
            TimeWarpControl.StopAll();
        }
        return warping;
    }
}
```

- `Begin`은 `_targetId`, `_path`, `_deadline`(in_scene 30 s, reload 300 s), `_status`(`pending`)를 두고 `FlightEvents.Add("switch_started", -1, {id, vessel, path})`를 부른다.
- `Finish(state, error, unpacked)`는 `_status`에 state·error·unpacked를 쓰고 `switch_done` 또는 `switch_failed`(error) 이벤트를 남긴 뒤 `_targetId = null`로 둔다.
- `switch_refused`·`switch_failed` 오류 응답에도 `warp_lowered`를 넣는다(`ApiException`에 부가 데이터를 싣는 기존 방식이 없으면 메시지에 적는다. 구현 때 `Api.cs`를 확인한다).
- `in_scene`에서 `wrong_vessel`을 판정하지 않는 이유: `ForceSetActiveVessel`이 같은 프레임에 활성 기체를 바꾸므로 다른 기체가 활성이 되면 `timeout`으로 드러난다(설계 남은 위험).

```csharp
// FlightReset.cs
internal static bool SceneReady => !_sceneLoading;
internal static void Save() => GamePersistence.SaveGame("persistent", HighLogic.SaveFolder, SaveMode.OVERWRITE);   // was private
// Status():
["switch"] = VesselSwitch.StatusCopy(),   // copy, serialized on the HTTP thread

// BridgeLogic.cs
FlightReset.Hook();
VesselSwitch.Hook();
// ... failed start: UnhookAfterFailedStart("vessel switch", VesselSwitch.Unhook);
// Stop(): after FlightReset.Unhook, in its own try/catch
FlightReset.Tick();   // never throws
VesselSwitch.Tick();  // never throws
```

`StatusCopy()`는 `Tick()`을 먼저 불러 제한 시간과 완료를 판정한다(timeScale 0이면 FixedUpdate가 돌지 않는다).

**검증**
- Logic 빌드 성공. `reload_mod` 뒤 `get_status.reset.switch == null`
- 실측(비행 중 로드 범위 안 기체: 분리한 단, 또는 연속 발사로 가까이 둔 두 기체)
  - `switch_vessel` → `accepted`, `path=in_scene` → `get_status.reset.switch.state=done`, `unpacked=true`, `get_flight`가 새 기체를 가리킨다.
  - `get_flight_events`에 `switch_started`, `switch_done`이 있다.
  - 계획 실행 중 → 409 `plan_running`
  - 활성 기체 id → `already_active`
  - 없는 id → 404 `vessel_not_found`
  - 로드 범위 밖 id → 409 `not_supported`(단위 3 전), `reset.switch`는 바뀌지 않는다.
  - 시간 가속 중 → `warp_lowered=true`

**선행 단위**: 1(같은 파일, `Candidates`·`ListScopeActive`)

## 단위 3. 장면 재로드 전환

**대상**: `VesselSwitch.Switch`의 단위 2 임시 거부를 지우고 reload 실행 추가, `Tick`의 reload 판정 실측

**코드 초안**

```csharp
// replaces the unit 2 not_supported throw; inside the same try/catch as in_scene
if (path == "in_scene")
{
    // ... unit 2 ...
}
else if (flight)
{
    // ClearToSave already checked: SetActiveVessel saves persistent and calls StartAndFocusVessel(Game.Updated(), idx)
    if (!FlightGlobals.SetActiveVessel(target))
    {
        Finish("failed", "switch_refused");
        throw new ApiException(409, "switch_refused", "the game refused to switch to " + target.vesselName);
    }
}
else
{
    int idx = FlightGlobals.Vessels.IndexOf(target);   // Tracking Station Fly order
    FlightReset.Save();
    FlightDriver.StartAndFocusVessel("persistent", idx);
}
```

- `Begin`을 실행 전에 부르므로 `onGameSceneLoadRequested(FLIGHT)`가 와도 `scene_changed`가 되지 않는다(`OnLoadRequested` 조건).
- 저장이나 `StartAndFocusVessel`이 예외를 던지면 단위 2의 catch가 `failed`로 끝내고 500 `switch_failed`로 응답한다.
- FLIGHT의 stock 경로는 저장 전에 이전 기체 `MakeInactive`를 한다. 그 뒤 예외가 나면 이전 기체가 비활성으로 남을 수 있다. 이 상태는 응답 메시지와 `reset.switch.error`로 알리고 되돌리지 않는다.
- 이전 Logic의 계획 상태: 사전 검사로 실행 중인 계획이 없으므로 FLIGHT 재진입 뒤 `Coordinator.Resume`할 대상이 없다.

**검증**
- Logic 빌드 성공
- 실측 A(비행 중, 로드 범위 밖 궤도 기체): `get_status`로 장면과 계획을 확인한다. `switch_vessel` → `path=reload` → `reset.scene_ready=false` → 이후 `reset.switch.state=done`이 되고 `get_flight`가 새 기체를 가리킨다.
- 실측 B(Space Center): `get_status` 확인 → `leave_flight` → SPACECENTER에서 `list_vessels` → `switch_vessel` → `done`. 응답 id와 전환 뒤 `get_flight` 활성 기체 id가 같다(인덱스 순서 확인 항목).
- 실측 C: 대기권 안 비행 중 로드 범위 밖 기체로 요청하면 409 `switch_unavailable`(`NOT_IN_ATMOSPHERE`)
- 설계 확인 항목: 재로드 뒤 `get_flight_events`에 `switch_started`가 남는지 기록한다. 남지 않으면 `Finish`의 `switch_done` 하나만으로 충분한지 사용자와 정한다.

**선행 단위**: 2

## 남은 위험

설계 "남은 위험" 절과 같다(전환 대기 중 다른 도구 허용, `get_flight.plan`의 이전 계획 표시, 사람이 다시 전환할 때 timeout까지 pending).
