# 추적소이동 설계

이슈: [#23 장면 도구: Tracking Station으로 이동](https://github.com/SeongSikChae/KSP1-BRIDGE-MCP/issues/23)
방안: [0037-추적소이동-방안.md](0037-추적소이동-방안.md)

## 게임 동작 (디컴파일, Assembly-CSharp)

- Space Center 건물 클릭
  - `SpaceCenterBuilding.OnLeftClick`은 `GetStructureDamage() < 70f`일 때만 `EnterBuilding()`→`TrackingStationBuilding.OnClicked()`로 들어간다. 70 이상이면 시설 메뉴(수리 등)를 띄운다.
  - `OnClicked`는 `HighLogic.CurrentGame.Parameters.SpaceCenter.CanGoInTrackingStation`이 true면 `GamePersistence.SaveGame("persistent", HighLogic.SaveFolder, OVERWRITE)` → `HighLogic.LoadScene(GameScenes.TRACKSTATION)`을 부른다. false면 "FacilityLocked" 대화상자를 띄운다.
- 비행 일시정지 메뉴(`PauseMenu`)의 Tracking Station 버튼
  - `Parameters.Flight.CanLeaveToTrackingStation`과 `Parameters.SpaceCenter.CanGoInTrackingStation`이 모두 true일 때만 버튼이 있다.
  - `ClearToSave()`가 CLEAR면 `GameEvents.onSceneConfirmExit.Fire(HighLogic.CurrentGame.startScene)` → `saveAndExit(TRACKSTATION, HighLogic.CurrentGame.Updated())`를 부른다.
  - `saveAndExit`: 대화상자 닫기 → `FlightGlobals.ClearpersistentIdDictionaries()`(public 아님) → `GamePersistence.SaveGame(state, "persistent", folder, OVERWRITE)` → `HighLogic.LoadScene(TRACKSTATION)`.
  - CLEAR가 아니면 저장하지 않고 떠나는 확인 대화상자를 띄운다(이 도구는 이 경로를 쓰지 않는다).
- 참고: 지도의 "View in Tracking Station"(`OrbitTargeter`)은 시설 작동 검사 → `MapView.ExitMapView()` → `SpaceTracking.GoToAndFocusVessel(v)`(ClearToSave, 조종 중립, 저장, LoadScene, 도착 뒤 그 기체 선택)이다. 게임 설정은 보지 않는다. 이 도구는 이 경로를 쓰지 않는다(결정 2).
- 비행 고도계의 Space Center 버튼(`AltimeterSliderButtons`)에는 Tracking Station으로 가는 경로가 없다.

## 도구·API

| MCP 도구 | HTTP | 비고 |
|---|---|---|
| `open_tracking_station()` | `POST api/scene/tracking_station` 본문 `{}` | 신규, 인자 없음. 기존 POST 도구처럼 `new { }`를 보낸다 |

### 응답

- 접수: `{accepted: true, from: "FLIGHT"|"SPACECENTER"}`. 완료는 `get_status`에서 `reset.requested_scene == "TRACKSTATION"`이고 `reset.scene_ready == true`일 때다(기존 `FlightReset` 추적이 TRACKSTATION의 `onLevelWasLoadedGUIReady`로 로드를 끝낸 것으로 본다).
- 이미 Tracking Station: `{accepted: true, already_open: true}`. 아무것도 하지 않으므로 폴링하지 않는다. `reload_mod` 뒤에는 `requested_scene`이 null일 수 있으므로, 도구 설명에 "already_open이면 get_status.scene만 확인한다"를 적는다.

### 오류

사전 검사(순서대로, 모두 상태를 바꾸기 전)

| 코드 | HTTP | 조건 |
|---|---|---|
| `recovery_pending` | 409 | 회수 대기 중(`RequireNoPendingRecovery`) |
| `switch_pending` | 409 | 기체 전환 대기 중(`VesselSwitch.RequireNotPending`) |
| `scene_loading` | 409 | 장면 로드 중(`RequireSceneReady`) |
| `no_game`·`not_supported` | 409 | `RequireStockGame("open_tracking_station")` |
| `scene_not_allowed` | 409 | FLIGHT·SPACECENTER·TRACKSTATION 이외 장면 |
| `no_active_vessel` | 409 | FLIGHT에서 활성 기체 없음(`Guard.ActiveVessel`) |
| `tracking_station_unavailable` | 409 | SPACECENTER: `CanGoInTrackingStation == false`. FLIGHT: `CanLeaveToTrackingStation == false`, `CanGoInTrackingStation == false`, 또는 `ClearToSave(false) != CLEAR`(상태 이름). 메시지에 이유 |

실행 단계(사전 검사 뒤)

| 코드 | HTTP | 조건 |
|---|---|---|
| `tracking_station_failed` | 500 | 저장·장면 로드 중 예외. 메시지에 예외와, 비행이면 계획을 이미 중단했는지(RCS 펄스는 없을 때 아무것도 하지 않으므로 메시지에 적지 않고 `get_status.translate`로 확인) |
| `tracking_station_failed` | 500 | 호출 뒤 TRACKSTATION 로드 요청이 관찰되지 않음(`_requestedScene != TRACKSTATION` 또는 `!_sceneLoading`). 메시지는 위와 같다 |

비행 경로는 stock 메뉴 순서대로 `onSceneConfirmExit`를 저장보다 먼저 발생시킨다. 저장이나 로드가 실패해 500으로 끝나도 이 이벤트는 이미 나간 뒤이며, 수신자(다른 모드 등)가 장면 이탈이 확정된 것으로 처리했을 수 있다. 되돌리지 않는다.

## 구조

`FlightReset`에 `OpenTrackingStation()`을 둔다(`leave_flight`의 `Leave`와 같은 클래스, 같은 장면 로드 추적).

```text
OpenTrackingStation():
  RequireNoPendingRecovery
  VesselSwitch.RequireNotPending
  RequireSceneReady
  RequireStockGame("open_tracking_station")
  scene = HighLogic.LoadedScene
  TRACKSTATION → {accepted, already_open}
  SPACECENTER:
    CanGoInTrackingStation 아니면 409 unavailable
    try { Save(); HighLogic.LoadScene(TRACKSTATION) } catch → 500 failed
    로드 요청 미관찰 → 500 failed
    → {accepted, from SPACECENTER}
  FLIGHT:
    v = Guard.ActiveVessel()
    CanLeaveToTrackingStation·CanGoInTrackingStation 아니면 409 unavailable
    ClearToSave(false) != CLEAR 이면 409 unavailable (상태 이름)
    aborted = Coordinator.Running; aborted 이면 Coordinator.Abort("tracking_station", null, null)
    ManualControl.StopPulse("tracking_station")
    try {
      GameEvents.onSceneConfirmExit.Fire(HighLogic.CurrentGame.startScene)
      GamePersistence.SaveGame(HighLogic.CurrentGame.Updated(), "persistent", HighLogic.SaveFolder, OVERWRITE)
      HighLogic.LoadScene(TRACKSTATION)
    } catch → 500 failed (aborted 여부를 메시지에)
    로드 요청 미관찰 → 500 failed (aborted 여부를 메시지에)
    → {accepted, from FLIGHT}
  그 밖 → SceneNotAllowed
```

- 로드 요청 관찰: `HighLogic.LoadScene`이 `onGameSceneLoadRequested`를 그 자리에서 발생시킨다고 보고 호출 직후 `_requestedScene == TRACKSTATION && _sceneLoading`을 확인한다. 개발 단계에서 실측한다. 동기가 아니라고 실측되면(정상 이동인데 500이 나면) 이 판정을 지우고 설계를 회귀한다.
- `ClearpersistentIdDictionaries`는 public이 아니라 부르지 않는다. 기존 `leave_flight`도 부르지 않는다. 다음 장면 로드가 사전을 다시 만든다.
- 시간 가속은 건드리지 않는다(`leave_flight`·stock 메뉴와 같다).
- 계획 중단 사유는 `tracking_station`이다.

## get_status

새 필드는 없다. `scene`, `reset.scene_ready`, `reset.requested_scene`, `reset.loading_seconds`로 확인한다.

## reload_mod

상태를 따로 두지 않으므로 인계할 것이 없다.

## 결정 목록

1. 도구는 `open_tracking_station`, HTTP는 `POST api/scene/tracking_station`(본문 `{}`)이다.
2. 비행에서는 stock 일시정지 메뉴의 Tracking Station 버튼을 따른다(설계 회귀로 지도 경로에서 변경). 게임 설정 두 개와 `ClearToSave`를 검사하고, `Game.Updated()`로 저장한 뒤 로드한다. 도착한 뒤 기체를 선택하지 않는다.
3. Space Center는 건물의 `CanGoInTrackingStation`을 따른다. 건물 구조 손상(70 이상) 검사는 하지 않는다(사용자가 반영하지 않기로 함, 남은 위험).
4. 이미 Tracking Station이면 `already_open`을 돌려주고 아무것도 하지 않는다.
5. 실행 중인 계획은 사전 검사를 통과한 뒤 `tracking_station` 사유로 중단한다(방안 3).
6. 거부 코드는 `tracking_station_unavailable` 하나로 묶고, 실행 실패는 `tracking_station_failed`(500)로 묶는다. 메시지에 이유와 실제로 중단한 것을 적는다.
7. `FlightReset`에 둔다. 새 상태는 없다.

## 개발 단계 확인 항목

- TRACKSTATION 로드가 `onLevelWasLoadedGUIReady(TRACKSTATION)`로 끝나 `reset.scene_ready`가 true가 되는지
  - 실측(Logic 0.2.41): Space Center·비행 양쪽에서 이동 뒤 `get_status` `scene TRACKSTATION`, `reset.requested_scene TRACKSTATION`, `reset.scene_ready true`
- `HighLogic.LoadScene` 호출 직후 `_requestedScene`이 이미 TRACKSTATION인지(접수가 500 없이 되면 확인된 것)
  - 실측: Space Center·비행 모두 200 `accepted`(500 없음). 동기 로드 요청 판정을 유지한다
- 비행에서 이동한 뒤 Tracking Station의 `list_vessels`가 채워지는지(#19)
  - 실측: 2행(궤도·발사대 기체), `active=false`, `distance=null`. 이어서 `switch_vessel`(궤도 기체)이 `path reload`로 `done`

## 남은 위험

- Space Center 건물 구조 손상 70 이상에서도 이동한다(stock 클릭은 시설 메뉴를 띄움).
- `GetSpaceCenterFacility`를 쓰지 않으므로 시설 관련 로그 잡음 문제는 없어졌다.
