# 입력 잠금 조회 개발 계획

이슈 #6. 게임 입력이 막히는 증상(예: 비행 중 우클릭 카메라 조작 불가)의 원인을 화면 없이 확인하도록, 현재 `InputLockManager` 잠금을 `get_status`로 읽는다. 사용자 지시("이슈 등록 후 추가")로 방안·설계를 건너뛰고 개발 계획부터 잡는다.

## 공통

- 읽기 전용. 잠금을 걸거나 풀지 않는다.
- Logic 쪽 `BridgeLogic.Status()`에 필드를 더한다(로더 `KspBridge.Mod` 변경 없음, `reload_mod`로 반영).
- 모든 씬에서 나온다. 잠금이 없으면 빈 배열.

## 작업 단위

### 1. `input_locks`

- **대상**: `src/KspBridge.Logic/InputLocks.cs`(새 파일), `src/KspBridge.Logic/BridgeLogic.cs`(`Status`), `src/KspBridge.Logic/Routes.cs`(Version), `src/KspBridge.App.Tools/FlightTools.cs`(`get_status` 설명)
- **코드 초안**:

```csharp
/// <summary>get_status.input_locks: the game's current input locks (InputLockManager.lockStack), read only.</summary>
public static class InputLocks
{
    private static KeyValuePair<ulong, string>[] _bits;   // built on first use (no static initializer that could poison the type)

    /// <summary>Single-bit ControlTypes members (group members such as ALL_SHIP_CONTROLS overlap); aliases of one value are joined "A|B".</summary>
    private static KeyValuePair<ulong, string>[] Bits() => _bits ?? (_bits = Enum.GetNames(typeof(ControlTypes))
        .Select(n => new KeyValuePair<ulong, string>((ulong)(ControlTypes)Enum.Parse(typeof(ControlTypes), n), n))
        .Where(p => p.Key != 0 && (p.Key & (p.Key - 1)) == 0)
        .GroupBy(p => p.Key).Select(g => new KeyValuePair<ulong, string>(g.Key, string.Join("|", g.Select(p => p.Value).OrderBy(n => n, StringComparer.Ordinal))))
        .OrderBy(p => p.Key).ToArray());

    public static List<object> Describe()
    {
        List<object> locks = new List<object>();
        foreach (KeyValuePair<string, ulong> l in InputLockManager.lockStack.OrderBy(p => p.Key, StringComparer.Ordinal))
        {
            List<string> controls = new List<string>();
            ulong rest = l.Value;
            foreach (KeyValuePair<ulong, string> b in Bits())
                if ((l.Value & b.Key) != 0) { controls.Add(b.Value); rest &= ~b.Key; }
            if (rest != 0) controls.Add("0x" + rest.ToString("X"));   // bits without a member name are not hidden
            locks.Add(new Dictionary<string, object> { ["id"] = l.Key, ["mask"] = "0x" + l.Value.ToString("X"), ["controls"] = controls });
        }
        return locks;
    }
}
```

```csharp
// BridgeLogic: a lock-listing failure must not hide editor (open_editor polls editor.ready)
public IDictionary<string, object> Status()
{
    Dictionary<string, object> s = new Dictionary<string, object> { ["editor"] = EditorScene.Status() };
    try { s["input_locks"] = InputLocks.Describe(); }
    catch (Exception e) { s["input_locks"] = null; s["input_locks_error"] = e.GetType().Name + ": " + e.Message; }
    return s;
}
```

- `get_status` 설명: `input_locks [{id, mask, controls}]`. `mask`는 원값(hex, 비트 판정용), `controls`는 막는 ControlTypes 개별 비트 이름(별칭은 `A|B`, 이름 없는 비트는 hex). 카메라 조작은 `CAMERACONTROLS`(단일 비트 0x400, 디컴파일 확인).
- 출력 크기: `ALL_SHIP_CONTROLS` 같은 넓은 잠금은 `controls`가 수십 개로 펼쳐진다. 판정은 `mask`로도 할 수 있게 두고, 펼친 이름은 그대로 낸다(어떤 조작이 막혔는지 바로 읽기 위함). 잠금 수는 보통 몇 개라 부담은 작다.
- **검증**:
  - 에디터: `input_locks`가 배열(창이 백그라운드면 `EditorDriver_AppFocus` 같은 포커스 잠금이 보일 수 있음).
  - 비행: 계획 `coast` warp-to 중(긴 `step_time` 목표로 warp-to를 수 초 유지하며 반복 조회) `TimeWarpTo`가 보이고 `controls`에 `CAMERACONTROLS`가 없음(디컴파일: `WARPTO_LOCK`은 카메라 제외), 해제 뒤 사라짐.
  - 별칭이 있는 비트가 있는지 1회 기록(`controls`에 `|`가 나오는지). 값 0인 잠금은 `controls: []`, 이름 없는 비트는 hex(코드 리뷰).
  - `input_locks_error` 경로는 코드 리뷰(예외를 일으킬 방법이 없음).
  - 우클릭 카메라 증상이 있는 상태에서 `CAMERACONTROLS`를 막는 잠금이 있는지 기록(없으면 잠금 외 원인).
  - App 테스트 통과(도구 목록 변화 없음).
