# KspBridge 핫 리로드 — 설계

선행: `0013-핫리로드-방안.md` (채택: A 로더 + 교체 가능한 로직 DLL)

사용자 결정: 비행 중 교체 시 트리거·스로틀 고정·자세 유지를 해제하고 해제 목록을 보고, 교체는 `reload_mod` 도구로만

## 1. 프로젝트·파일 배치
| 프로젝트 | 출력 | 배포 위치 | 내용 |
|---|---|---|---|
| `src/KspBridge.Mod`(로더, 기존 이름 유지) | `KspBridge.Mod.dll` | `GameData/KspBridge/Plugins/` | `KspBridgeAddon`, `HttpServer`, `MainThreadDispatcher`, `Json`, `ApiException`, `RequestBody`, `Route`, `Settings`(포트), `ILogic`·`LogicHost` |
| `src/KspBridge.Logic`(신규, net472) | `KspBridge.Logic.dll` | `GameData/KspBridge/PluginData/` | 나머지 전부: Handlers, Attitude, Craft, Flight, Guard/Career, Routes(로직 경로) |
- KSP는 `PluginData` 폴더의 DLL을 자동 로드하지 않음 → 로더만 로드함
- 로직은 로더 어셈블리를 참조(공유 타입). 로더는 로직을 참조하지 않음

## 2. 로더↔로직 계약
```csharp
public interface ILogic                       // 로더 어셈블리
{
    string Version { get; }
    IEnumerable<Route> Start(LogicContext ctx); // 이벤트 구독 등 초기화, 로직 경로 반환
    void FixedUpdate();                         // 자세·스로틀 고정·트리거
    IList<string> Stop();                       // 해제한 항목 목록 반환(트리거 n개, 스로틀 고정, 자세 유지, 이벤트 구독)
}
public sealed class LogicContext { public MainThreadDispatcher Dispatcher; public Settings Settings; }
```
- 로직 DLL에 `ILogic` 구현 클래스 하나(`KspBridge.Logic.BridgeLogic`) — 로더가 리플렉션으로 찾아 생성
- `[KSPAddon]` 사용 금지(로직에서). MonoBehaviour 없음(현재도 정적 클래스 위주)

## 3. 로드·교체 절차 (메인 스레드)
1. 시작: 로더 Awake에서 HTTP 서버 시작 → `LogicHost.Load()`
2. Load: `File.ReadAllBytes(PluginData/KspBridge.Logic.dll)` → `Assembly.Load(bytes)` → `ILogic` 생성 → `Start(ctx)`로 경로 수집
3. Reload(`POST /api/reload`):
   - 새 어셈블리 로드·인스턴스 생성까지 먼저 시도. 실패 → 기존 로직 유지, 500 + 오류
   - 기존 로직 `Stop()` → 해제 목록 확보
   - 새 로직 `Start(ctx)` → 라우트 테이블 원자 교체. Start 실패 → 기존 로직을 다시 Start하고 오류 반환
   - 응답: `{logic_version_before, logic_version_after, released:[...], load_count}`
4. 로더 고유 경로(로직 교체와 무관): `GET /api/status`(로더·로직 버전, load_count, 로직 로드 오류), `POST /api/reload`
5. 로직 로드 실패 상태에서도 로더 경로는 응답 → 다른 경로는 503 `logic_not_loaded`

## 4. 로직 쪽 정리 의무 (Stop)
- GameEvents 구독: 현재 람다로 `Add`만 함 → 델리게이트를 필드에 보관해 `Remove`
  - AttitudeController, ThrottleLock, TriggerManager의 Hook
- `OnFlyByWire` 제거: AttitudeController.Release, ThrottleLock.Clear
- 트리거 목록 비우기, Prediction 캐시 정리
- 정적 상태는 어셈블리마다 별개이므로 구 버전 정적 필드는 Stop 이후 사용되지 않음

## 5. 위험과 확인 항목
- Mono에서 같은 이름 어셈블리를 `Assembly.Load(byte[])`로 반복 로드 가능한지 → 구현 첫 단계에서 확인(안 되면 빌드마다 어셈블리 이름에 빌드 번호를 붙임)
- 구 버전 어셈블리는 메모리에 남음 → `load_count` 표시, 많아지면 KSP 재시작 권장
- 로더 수정(HTTP 서버, 계약 인터페이스) 시에는 여전히 KSP 재시작 필요 → 로더는 최소·안정 유지
- 디버그: 바이트 로드는 pdb를 못 읽어 예외 스택에 줄 번호가 없을 수 있음

## 6. 빌드·도구
- Logic 빌드 후 `GameData/KspBridge/PluginData/`로 복사(로더 DLL 복사는 변경 시에만)
- MCP 도구 `reload_mod()` → `POST /api/reload` (Destructive: 비행 중 트리거 등 해제)
- `get_status` 응답에 loader_version, logic_version, load_count 추가

## 7. 검증
- 단위 테스트: reload_mod → HTTP 매핑
- 게임: ① KSP 시작 시 로직 로드·기존 도구 정상 ② 로직 버전 문자열만 바꿔 빌드 → reload_mod → status에 새 버전, load_count 2, 기존 도구 정상 ③ 비행 중 트리거·스로틀 고정 건 상태에서 reload → released 목록 확인, 해제 확인 ④ 깨진 로직(Start 예외) 배포 → reload 실패, 기존 로직 유지
