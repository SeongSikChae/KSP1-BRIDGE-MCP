# KspBridge 발사대 화면 셋팅 설계

선행: [0032-발사화면-방안.md](0032-발사화면-방안.md)

## 구조
기존 도구와 같은 세 층을 씁니다.

| 층 | 파일 | 역할 |
|---|---|---|
| App(MCP) | `src/KspBridge.App/FlightTools.cs` | 도구 `setup_launch_ui` → `POST /api/ui/launch` |
| Logic(라우트) | `src/KspBridge.Logic/Routes.cs` | 라우트 등록 |
| Logic(처리) | `src/KspBridge.Logic/Handlers/UiHandler.cs` (새 파일) | 게임 UI API 호출 |
| 테스트 | `tests/KspBridge.App.Tests/FlightToolsTests.cs` | 도구 → HTTP 매핑 |

- 비행 중 도구라서 새 도구 클래스를 만들지 않고 `FlightTools`에 넣습니다.
- 라우트 `Version`은 `0.10.0` → `0.11.0`으로 올립니다(새 라우트 추가).

## 인터페이스
- MCP: `setup_launch_ui()` — 인수 없음.
- HTTP: `POST /api/ui/launch`, 본문 `{}`.
- 응답:

```json
{
  "maneuver_mode": {"ok": true},
  "deltav_info": {"ok": true},
  "resources": {"ok": false, "error": "resource app is not ready"}
}
```

- 오류:
  - 비행 장면이 아니거나 활성 비행체가 없으면 기존 `Guard.ActiveVessel()`의 오류
  - UI 모드 컨트롤러가 아직 없으면 `409 scene_not_allowed`

## 처리 순서 (메인 스레드, 항목별 try/catch)
1. **메뉴버 모드**: `FlightUIModeController.Instance.SetMode(FlightUIMode.MANEUVER_INFO)`. 호출 뒤 `Mode`가 `MANEUVER_INFO`가 아니면(모드 확인 콜백이 거부) 실패로 보고합니다. 스테이지 영역 전환(`stagingQuadrant`)은 하지 않습니다.
2. **스테이지 Δv 상세**: `StageManager.Instance`에서 `EnableDeltaVTotal(true)`, `EnableDeltaVHeadings(true)`, `EnableInfoPanels(true)`, `ToggleInfoPanels(true)`.
3. **자원 창**: `ResourceDisplay.Instance`가 있고 `IsShowing`이 false이면 `appLauncherButton.SetTrue(true)`. 없으면 `"resource app is not ready"`로 실패.


## 결정
- 메뉴버 모드 + 좌측 스테이지 상세 패널, 스테이지 영역 강제 펼침 없음(방안 회귀 1·2)
- 도구 호출 때만 적용, 자동 적용 없음
- 항목별로 실패를 모아 보고하고, 전체를 실패시키지 않음
- 상태 저장·되돌리기 없음

## 의존성
- KSP `Assembly-CSharp`: `FlightUIModeController`, `KSP.UI.Screens.StageManager`, `KSP.UI.Screens.ResourceDisplay`, `KSP.UI.Screens.ApplicationLauncherButton`
- 새 패키지 없음

## 검증 계획
- `dotnet build`(솔루션), `dotnet test`(App 테스트: 도구가 `POST /api/ui/launch`로 가는지)
- 인게임: `reload_mod` → `revert_to_launch`로 UI를 처음 상태로 → 엔드포인트 호출 → KSP 창만 캡처(PowerShell, 클라이언트 영역)해 메뉴버 패널, 좌측 스테이지 상세, 자원 창이 모두 보이고 서로 가리지 않는지 확인
