# D01_02 궤도가 바뀌었을 때의 처리

## 상황

`R01-R3`: 원인을 고친 뒤에도 `warp` 도중에 추력 없이 궤도가 `D01_01`의 기준을 넘게 바뀌었을 때 계획을 어떻게 할지 정해야 했다. 지금은 아무 알림 없이 다음 단계로 넘어가므로, 뒤의 `execute_node`가 바뀐 궤도에서 가속 전 궤도로 계산한 노드를 연소한다(#57 첫 관측에서는 원지점에 둔 노드가 실제 원지점과 맞지 않아 `execute_node`를 중단했다. #57 본문).

## 전제

| 전제 | 출처 | 확인 |
| --- | --- | --- |
| 기준점 코드의 `warp`는 시작·완료 궤도를 비교하지 않고, 궤도가 바뀌어도 단계를 완료해 다음 단계로 넘어간다 | 기준점 `b9b4da6`의 `src/KspBridge.Mod.Modules.Warp/WarpSession.cs`(실패 사유는 기체 없음과 목표 오류뿐) | 읽음 |
| 바뀐 궤도에서 다음 `execute_node`가 가속 전 궤도로 계산한 노드를 연소하게 된다 | #57 본문(원지점에 둔 노드가 실제 원지점과 맞지 않아 `execute_node`를 중단함) | 읽음 |
| 단계가 실패하면 계획은 `step_failed`로 끝나고 다음 단계를 실행하지 않는다 | `src/KspBridge.Mod.Modules.Warp/WarpStep.cs` 68~69줄(`StepResult.Failed`), `src/KspBridge.Mod.Core/Coordination/Coordinator.cs` 331줄(`Finish(EndReasons.StepFailed, …)`) | 읽음 |

## 결정

- 단계 `warp`를 실패시켜 계획을 `step_failed`로 끝낸다. 실패 사유에 시작·완료 때의 Ap·Pe를 적는다.

## 이유

- 사용자가 말하지 않음

## 버린 안

| 안 | 버린 이유 |
| --- | --- |
| 이벤트로만 알리고 계획은 다음 단계로 이어 간다. Planner가 이벤트를 읽어야 바뀐 것을 안다 | 사용자가 말하지 않음 |
